# 界面与交互约定

React 19、TypeScript、HeroUI v3 与 Tailwind CSS v4 构成 UI。主要用户是长时间处理对账、核销、异常与导出的内部财务人员，界面优先保证扫读效率和可追溯性。风格是紧凑、清晰的财务工作台：浅色背景、白色表面、低饱和边框，蓝色主操作，绿色成功、橙色提醒、红色失败。颜色和尺寸以 [styles.css](../web/src/app/styles.css) 等实际样式为准，文档不复制整套 token。

## 公共边界

页面持有 API 和业务状态；公共表格、抽屉、按钮、分段组件只接收 props 并回传事件。普通页复用 FinanceTable；进项发票使用表的两层分组由本页原生语义表格承载，复用公共控件和财务列样式。关联台分组布局由关联台拥有；现金可以复用纯 UI，但不接入普通页面持久 session。

表格保留清晰的列对齐、金额精度、日期单位、可读空值和真实业务统计。服务端分页/排序由服务端拥有，页面不能对当前页冒充全量排序或总数。宽表通过横向滚动保持可达；需要文本复制的调用方显式启用选择能力。小屏侧栏和抽屉不遮挡主要操作。

## 普通页面的表格与操作层级

普通页面由应用壳显式开启 `data-finance-presentation`，样式集中在 `financePresentation.css`，关联台路由不启用。表头和正文使用相同 `columnRole`：比较型金额与数量右对齐并使用等宽数字；公司、项目、摘要、票号和账户名称左对齐；独立日期、短状态、方向、选择与操作居中。详情键值表不属于比较型表格，其字段值继续左对齐。

流水金额放在首行，14px、600 字重；方向和银行账户放在次行，12px 辅助文字。银行简称来自设置中的银行全名与真实尾号精确映射，未配置简称时显示原名称，不通过删除“银行”猜测简称。尾号保留前导零。显示简称不改变筛选、汇总身份、原始详情或导出字段。

进项支付状态列固定约 148px，给项目与摘要保留阅读空间；销项收款状态含已收、待收金额，保留其所需宽度。宽表不能为了塞进视口而截断关键值；沿用横向滚动。次级工具栏按钮使用白底、清晰细边框和蓝色文字，悬停与键盘焦点有反馈且不改变控件尺寸；主操作仍用实心蓝色，行内详情和展开入口保留文字操作层级。

进项发票使用表的一级表头为进项发票（4 列）、支付状态（1 列，纵跨两行）、OA（2 列）、流水（3 列）。分组标题居中，叶子表头与正文按列语义对齐，开票日期入口执行日期排序。两层表头整体固定，共用正文滚动容器，分页在滚动区外；列宽由同一 colgroup 定义。组边界贯穿表头和正文，正文统一底色，支付状态只通过文字 chip 表达。空结果跨全部 10 列，不改变表头结构。

## 分段、计数与状态

`SegmentedControl`/`SegmentGroup` 复用 HeroUI 受控选择；`Tabs` 用于有内容 panel 的切换。选项 key、业务计数和选择值来自页面，公共组件不请求 API、不计算数量、不接管草稿或页面挂载。重复选择不触发新操作，键盘和焦点语义保持原生可达。

选中态采用清晰底色与文字对比，同工具栏控件保持等高。计数绑定 API 总数而非已加载行数；初次未知不能显示为确定的 0。刷新期间保留最后已知展示计数和稳定宽度，成功响应更新它；查询错误仍明确可见。该展示保留不用于计算、导出或业务判断。

有从属关系的切换采用上层贴边、下层内嵌的结构；共同控制同一张表时，工具栏、表格和分页共享外框。设置、抽屉、现金详情与编辑器连接各自的内容区域；并列条件不伪装成父子关系。分面计数仍按模块查询合同计算，视觉层级不改变统计口径。

未选中项之间有细分隔，选中背景直接绘制在控件上，不使用横跨选项的移动底块。名称和数量紧密居中，计数组以完整标签预留六位数字宽度，更长数值自然扩展并保持可达。公共样式只命中本层列表的直接选项，不能穿透影响嵌套控件。外框不创建新的滚动或裁切边界；宽表仍由表格自身滚动。

loading、empty、error 相互区分。请求乱序不能覆盖当前筛选，失败不能用空列表伪装。异步任务展示自己的真实状态，成功写入后重新 GET；不能增加跨页面等待或自动循环刷新。

## 详情、编辑与导出

详情采用统一抽屉，关闭、返回、确认、错误提示与键盘焦点行为一致。表单保持用户草稿，提交中阻止重复点击；后端拒绝时保留可修正信息，不替用户猜值。业务权限在页面与 API 一致执行。

发票金额、不含税金额、税额和税率只显示服务端返回的原件值；前端不补算缺失字段，不添加推算标记。缺失值显示“—”，真实零值保留；税额“*”及免税、不征税等原文保留。业务合计与已收、待收金额继续按模块合同计算。

金额使用各模块规定的币种、精度、正负和统计单位。0、未知、缺失和不适用不能互相替代。不同币种不能直接相加；账户余额不完整时不能给出伪完整合计。

导出由模块定义数据范围、过滤、字段、数量上限和权限；不能把浏览器已加载片段当全量文件。OA 付款、流水待找发票、进项发票使用、销项发票收款、外部往来款的导出沿用打开抽屉时已生效的分类、搜索、日期与列筛选，包含所有匹配分页数据。抽屉只显示业务对象数量和一个导出按钮，不另设条件或预览；页面查询未完成时不可打开。计数失败不显示为零，关闭会取消计数请求；失败通过同一按钮重试，下载期间防止重复请求。下载响应的 `X-Export-Count` 表示该文件实际包含的业务对象数量，成功提示以它为准。下载成功、失败、等待与取消需可观察。附件复用既有下载/预览边界，不把内部存储 key 或凭据当公共地址。

动画尊重 reduced-motion，避免以过渡掩盖等待。共享组件调整回归普通页、关联台、现金和窄屏场景，优先复用现有交互测试。

## OA、流水与发票来源详情

各页面与关联台的 OA、流水、发票详情共用 `SourceDetailDrawer`、`EntityDetailContent` 和 `source_record_details.py` 来源字段投影。页面负责鉴权 API、精确身份查询与请求取消；公共抽屉只管理展示和流水编辑保护。每次打开只读取一条原始单据，发票包含同票全部商品行，OA 包含全部费用明细，拆分流水指向原始父交易。缺失来源明确提示不可用，不能用列表摘要补齐。`document_id/document_kind` 用于验证单一来源身份，不展示内部 ID。

除关联台外，列表的数量入口显示“共 N 条/笔/张”，包含首项，流水按原始交易身份去重。点击数量入口在原始行下方展开配对成员；进项发票的发票入口新增其余原件十列行，OA、流水入口以及其它页面使用来源区。每个列表仅一个活动父行，进项的发票行与来源区共用展开状态并切换视图；再次点击或“收起”关闭。替换列表结果后清除旧展开状态。展开直接使用列表同快照摘要，不新增请求、不改变筛选、排序、分页、统计或导出。

原始行和其展开内容共用淡蓝灰背景与 3px 蓝灰左边线，颜色只表示当前展开范围；组外记录不着色。边线不占列宽，悬停轻微加强当前行，焦点和勾选仍表达各自状态；收起期间保留分组提示，退出完成后清除。来源区保留内缩间距和独立来源列表，不按横向位置暗示一对一配对。多个独立正式关系保留关系标识，拆分父流水不重复计数或相加原额。宽表的展开区保持在可见滚动区域内，窄屏来源列纵向排列，名称换行、金额对齐。展开 220ms、收起 170ms，快速反向操作从当前帧继续，遵守减少动画偏好。键盘收起后焦点回到数量入口。

展开后的每个成员带详情 icon，点击只打开该单据公共详情抽屉；缺失身份或不完整摘要明确报错，已知不可用详情禁用入口。不保留集合详情抽屉、单据切换导航或一次展示多条来源正文的旧链路。原件零值、负数和精度保留，缺失字段不补造；原件详情与业务汇总分离。流水标签由银行 owner 投影，子项标签注明“子项 N”。抽屉最大宽度 800px，字段值左对齐、长文字自然换行，正文只有一个纵向滚动区域。

流水规则批量处理使用本模块的批次展开状态：多个批次可独立展开或收起，单列分类导航与连续批次列表构成同一工作区。展开按需读取批次明细，选择范围绑定账户和月份，收起保留选择并显示已选数量。批次默认收起，减少动态效果时直接切换；收起动画结束后卸载明细，滚动由列表统一承担。具体查询与提交合同见[模块说明](modules/bank-flow-rule-batches/README.md)。

流水拆分操作区按需加载，收起保留草稿，未保存关闭需确认，保存期间禁止关闭。关闭或打开其他单据取消上一请求，迟到响应不能覆盖当前详情。
