# 银行流水拆分

银行原始流水保持金融事实与导入身份。拆分是银行 owner 持久化的用途子项，不新增银行交易笔数，不改原金额、余额、日期、流水号或去重键。

## 事实与业务口径

- 未拆分使用原流水；已拆分的用途消费者只使用当前子项，禁止父子叠加。子项稳定 UUID、标签 code、正数两位小数金额、顺序属于银行 owner；同一币种与收支方向，合计严格等于原金额。
- 用途按持久化标签配置解释；不根据本金/利息名称、金额差额或固定 custom code 猜测。OA、项目、借款归属仍由明确关联决定。
- 外部往来只计算对应用途子项。收款本金 1000000 与支出中本金 1000000 对齐，利息 1497.22 不计入往来差额；本金平衡仍须属于同一明确往来关系。
- 成本排除配置为外部往来的子项，保留同组其他成本候选。1001497.22 拆为本金 1000000、利息 1497.22，已有关联内 OA 1497.22 与有效成本来源唯一等额时自动计入成本，无需进入待分配或再次保存。金额不一致或来源归属有歧义时才进入既有待分配；金额相同不建立跨关联的自动匹配。有效人工决策继续保留。
- 历史外部往来人工成本及不计成本决策通过一次性事务工具撤销并保留完整审计；保留 OA、流水、发票与正常成本决策。混合 case 无法逐部分保留同一 fingerprint 时整个决策回到待确认。
- 已核销的银行事实需先撤销核销才可拆分，避免把同一核销额复制到多个子项。成本分配不等同于金融核销。

## 页面

列表在原银行容器内展示每个子项的标签与金额。同一关联 case 的银行父容器可跨 OA 对齐段，OA/发票对应结构保持；不同 case 不合并成一条虚假关系。选择与关联提交使用子项身份、子项金额。

所有真实银行详情共用字段/内容表格，新增“流水子项拆分”字段。加号添加标签选择器与金额；标签左列主标签、右列子标签；右列可显示同一叶子 code 的完整子级路径。整组保存，删除到空时需明确选择恢复后的整笔标签。

修改事实只在保存成功后生效。版本冲突要求重新读取；失败保留草稿并显示错误。多个银行编辑器共享一次批量读取；保存一笔不丢其他笔草稿。关闭后重开读取持久化事实。

## 边界

银行 owner 负责校验、版本、事务、存储与审计。关联 owner 负责当前成员引用与历史撤回有效性；往来 owner 负责关系及利率/备注的明确归属迁移；成本 owner 撤销失效决策；批次 owner 标记旧快照失效。列表查询只读 canonical 数据，不新增 read model 或后台 worker，不写隐藏 fallback。

主事实表 app.bank_transactions；拆分事实 app.bank_transaction_split_sets/items；统一用途视图 app.bank_transaction_units。导入、余额、银行总笔数、身份审计仍读主事实；配对、用途分类、成本、往来、发票资金关联和 OA 核对读用途视图。

技术与验证见 [开发说明](../dev/bank-transaction-splits.md)。

## 2026-09-24 拆分后的核对范围

- 主金额保持默认文字色、两位小数；原行内逐项展示完整主/子标签与异色金额。无子项 checkbox，关联选择保留为可键盘操作的子项按钮，抽屉仍是编辑入口。
- 已有关系全部银行成员均为拆分用途、同一收支方向、金额完整时，按配置 external_turnover 角色分为往来与其他用途。只有其中一个完整用途组与 OA（无 OA 时发票）总额一致，核对才使用该组。两个组都相等、均不相等、存在未知金额、混合方向或未拆分成员时，保留完整核对范围并显示真实差异。未拆分逻辑保持。
- 这是同一已有关联的核对投影，不更改正式成员，不把原流水金额改成利息，不按相同金额搜索别的 OA。OA 付款、进项使用、销项收款、关联台分区与详情采用同一选择规则；原银行容器仍展示全部用途。
- 拆分分类保存完整实例含往来第三层；只存叶子 code 不足以表达银行往来归属。历史缺失归属根据已确认原事实显式修正，不按户名推测。
