# 税金抵扣与 ETC

## 税金抵扣目标

税金抵扣页面用于比较销项税额、进项税额、计划抵扣和已认证结果。它需要支持月度视图、试算、已认证发票导入和结果回写。

## 已认证发票导入

- 使用真实模板解析已认证发票。
- 导入结果要持久化，不能只存在页面状态。
- 已认证结果参与税金抵扣计算和页面抽屉展示。
- 导入必须遵守预览、确认、逐行结果和幂等防重规则。

## ETC 目标

ETC 相关能力覆盖：

- ETC 发票导入。
- 票根网手工粘贴或文件导入。
- 信用卡账单 PDF 文本提取。
- ETC 对账任务。
- ETC 历史批次修复。
- 进项发票与 ETC 统一身份。

## 边界

- ETC 票据管理继续使用独立流程，不放进通用异常处理入口重做。
- ETC 发票作为进项发票的一类来源，需要统一身份和重复防重。
- ETC 对账任务内的文件生命周期必须可追溯。
- 补充凭证是对未匹配信用卡项的覆盖依据，不作为批量导入资料池主流程；用户应在未匹配信用卡行内上传补充凭证，系统原子完成上传、解析、绑定和审计。补充凭证金额与信用卡项不一致或无法识别金额时，必须填写差异说明；允许继续提交 OA，OA 补充金额按被覆盖的信用卡项金额计算，凭证解析金额、差额和说明必须保留在对账记录中。
- ETC 对账任务只展示一个用户可见的 ETC 业务批次。导入批次和 OA 提交批次是技术子资源，不应在页面上变成两个并列业务批次。详细设计见 [`2026-05-19-etc-business-batch-oa-auto-detection-design.md`](../superpowers/specs/2026-05-19-etc-business-batch-oa-auto-detection-design.md)。
- 同一个对账任务只能存在一个 active ETC 业务批次；同一个业务批次允许多次补充 ZIP 导入，补充导入必须合并到该业务批次的导入记录和发票集合。
- ETC 对账任务创建 OA 草稿后，不再以用户手动确认为正常主路径。系统进入 OA 自动检测，后台检测到 OA 流程状态已归一化为 `in_progress`（展示值为 `进行中`）后，自动进入已提交链路。
- 人工“已提交 OA / 未提交 OA”只作为异常兜底入口，仅在 `oa_detection_timeout`、`oa_detection_conflict`、`oa_detection_unavailable` 等检测异常状态展示；人工兜底必须填写原因并写审计。
- 进入 `oa_submitted` 或 `manually_marked_submitted` 后，业务批次进入不可物理删除的提交链路。未提交、已释放或创建失败的批次可以按受控删除规则清理，删除时必须释放任务上的 OA/ETC 批次链接，并允许移除已导入 ETC 发票后重新导入。
- 删除权限按业务批次提交状态判定：已提交批次不可删除，只有未提交或已释放批次可以删除。删除未提交 ETC 批次是破坏性删除，批次内 ETC 发票、导入批次容器、附件和统一进项发票中的 ETC 导入来源必须一并清理；发票行级 `submitted` 标记不能单独把未提交批次升级为已提交批次。批次已被 OA 自动检测为提交、人工兜底标记提交、存在提交确认时间或已关联 OA/工作台记录时，必须阻止物理删除。
- 创建 OA 草稿后如发现导入不足、金额错误或不准备提交，用户必须先执行“撤销草稿/释放发票”。系统不删除 OA 源系统草稿，只解绑本地 active 草稿、释放发票占用、保留旧技术子批次审计，并回到允许补充导入和重建 OA 草稿的未提交状态。

## 验收标准

- 税金抵扣结果能区分计划和已认证事实。
- ETC 导入和对账文件不会因页面刷新丢失。
- 历史批次修复有任务状态和审计。
- 与关联台、成本统计和发票库存统计的口径一致。
