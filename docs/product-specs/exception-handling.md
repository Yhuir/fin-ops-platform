# 异常处理

## 目标

异常处理覆盖 OA、银行流水、发票三类对象，不只处理单栏异常。系统应把异常从自由备注升级为结构化 case、规则分类、处理动作和审计历史。

## 当前阶段选择

采用生产级 A，保留完整工作流 C 的升级边界：

- 当前阶段落地规则目录、分类器、结构化处理动作、审计历史、前端统一处理弹窗。
- 后续可升级负责人、SLA、任务池、跨角色协作和状态机。

## 基本口径

- 收入侧只看收入流水和销项发票。
- 支出侧看 OA、支出流水和进项发票。
- ETC 继续沿用 ETC 票据管理流程，不在异常处理里重新做独立入口。
- 免 OA 项必须有结构化字段和 tag，不能只靠备注表达。

## 处理结果

异常处理动作可以生成：

- 人工关联。
- 后续台账。
- 待开票。
- 待付款。
- 往来登记。
- 非税收入。
- 退款、预收、预付等业务状态。

## 验收标准

- 异常 case 能追溯来源对象、规则、动作、操作者和时间。
- 处理后的对象不继续污染未配对区。
- 撤销处理后可以回到正确区域并刷新 read model。
- 前端弹窗内容由规则目录驱动，不硬编码业务分支。
