# 免 OA 流水批量处理

## 目标

免 OA 流水批量处理用于把不需要 OA 单据参与闭环的银行流水成批提交到关联台，例如手续费、工资、过节费、奖金、税款、代理国库税收收缴、社保款、内部往来款。

免 OA 批次使用银行明细标签的稳定 `category_code` 作为批次类型和业务判断依据。页面展示、搜索和折叠摘要需要携带并展示银行明细标签的 `category_primary_label`、`category_sub_label` 和 `category_label_path`；这些字段只作为结构化展示/搜索维度，不替代 `category_code`。

免 OA 页面不维护独立标签事实源。“免 OA 流水标签管理”只保存一个全局的标签准入范围，用来决定银行明细页“自动标签规则”中的哪些可用标签进入免 OA 页面；标签名称、层级、停用状态和输出路径始终以银行明细自动标签规则为准。

## 本期范围

纳入：

- 全局选择进入免 OA 页面展示和生成候选批次的银行明细可用自动标签。
- 已提交免 OA 批次的历史展示和撤回；即使后续从免 OA 标签准入范围移除，对已提交批次的可见性和撤回入口仍保留。

不纳入：

- 在免 OA 页面新建、编辑或停用银行明细自动标签规则。
- 默认勾选任何免 OA 标签；首次进入由用户自行选择。
- 外部往来台账闭环。
- 现金往来特殊处理。

## 状态

| 状态 | 含义 | 主切换 |
| --- | --- | --- |
| `draft` | 当前可提交批次 | 未提交 |
| `conflict` | 数据不满足提交条件或存在多解 | 未提交 |
| `stale` | 来源流水或标签变化，已提交依据不再可信 | 未提交 |
| `submitted` | 已提交并写入 active relation | 已提交 |
| `withdrawn` | 已撤回 | 历史 |

## 计数口径

- 顶部“未提交”数字 = 当前月份和账户筛选下 `draft + conflict + stale` 的批次数，不是流水条数。
- 顶部“已提交”数字 = 当前月份和账户筛选下 `submitted` 的批次数，不是流水条数。
- 主标签和子标签列展示全局准入标签及已提交历史批次涉及的标签；每个标签同时展示当前状态下的批次数和流水条数，格式为“X 批 / Y 条”。
- 主标签批次数/流水条数按其子标签下批次聚合；子标签批次数按批次归属标签计数，流水条数按批次 `row_count` 或 `tag_counts` 累加。
- 单边免 OA 批次按 `batch_type + scope_month + account_key` 分组；`account_key` 使用银行名称和账号后四位，格式为 `bank_name:account_last4`。同月同分类但不同账号必须拆成不同批次。
- 内部往来款保留跨账户配对逻辑，不按单账户强拆。

## 页面结构

- 右上角提供“免OA流水标签管理”按钮，点击打开右侧抽屉。
- 抽屉展示所有银行明细自动标签规则中的可用标签，并按 `output_primary_label` / `output_sub_label` 展示层级关系。没有子标签时，子标签显示为“主标签本身”。
- 抽屉支持多选、全选、清空；点击主标签会选中或取消其全部子标签，子标签也可单独选中或取消。变更必须点击“保存”后生效。
- 抽屉中的主/子标签随银行明细“自动标签规则”实时更新。停用标签不再可选；如果历史配置中仍引用停用标签，页面只提示并在保存时清理。
- 页面主体为三栏结构：左栏主标签，占桌面宽度 18%；中栏子标签，占桌面宽度 18%；右栏为剩余宽度流水区域。
- 左栏展示主标签和计数；中栏展示当前主标签下的子标签和计数。
- 右栏按银行账户划分区域，每个区域显示“全选 / 清空”。金额单元格显示收/支 tag、金额、银行+后四位 tag；不再单独展示“收/支”列。
- 右上角“提交批次”只提交当前已选流水，不提交未选流水。

## 关键约束

- 一次提交只允许包含一个选中的主/子标签、一个月份、一个银行账户区域内的流水；不能跨月份、跨主/子标签、跨银行账户提交。
- 前端在用户已勾选 A 银行区域流水时阻止继续勾选 B 银行区域，并提示“请先清空已选银行区域”。后端仍必须再次校验同一银行、同一月份和同一标签。
- 后端不按银行账户拆分用户一次提交。用户需要按银行区域多次选择并提交，每次提交生成一个批次。
- 允许用户在同一银行区域内只选择部分流水提交。
- 提交必须写入 `WorkbenchPairRelationService`，`relation_mode=no_oa_bank_batch`。
- 撤回必须调用免 OA 批次撤回 API，不能绕过批次直接普通取消 relation。
- 内部往来款必须校验收入/支出、金额、不同账户、时间窗口和多解冲突。
- 已配对区中 `row_count >= 2` 的免 OA 批次默认输出摘要折叠，原始流水保留在 `collapsed_rows.bank`。
- `row_count = 1` 的已提交免 OA 批次不折叠，但普通银行流水行仍必须保留免 OA tag、批次来源元数据和撤回批次动作。

## 验收标准

- 未提交/已提交双栏或双态视图清晰。
- 批量提交、撤回、分类变更全部刷新关联台和搜索。
- stale 批次不会让用户无法撤回 active relation。
- 搜索可命中折叠明细。
