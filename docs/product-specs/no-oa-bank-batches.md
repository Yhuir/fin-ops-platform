# 免 OA 流水批量处理

## 目标

免 OA 流水批量处理用于把不需要 OA 单据参与闭环的银行流水成批提交到关联台，例如手续费、工资、过节费、奖金、税款、代理国库税收收缴、社保款、内部往来款。

免 OA 批次使用银行明细标签的稳定 `category_code` 作为批次类型和业务判断依据。页面展示、搜索和折叠摘要需要携带并展示银行明细标签的 `category_primary_label`、`category_sub_label` 和 `category_label_path`；这些字段只作为结构化展示/搜索维度，不替代 `category_code`。

## 本期范围

纳入：

- 手续费。
- 工资。
- 过节费。
- 奖金。
- 税款。
- 代理国库税收收缴。
- 社保款。
- 内部往来款。

不纳入：

- 借入、借出、质保金、投标保证金、履约保证金、已开发票未收款等往来类标签。
- 外部往来台账闭环。
- 现金往来特殊处理。

## 状态

| 状态 | 含义 | 主切换 |
| --- | --- | --- |
| `draft` | 当前可提交批次 | 未提交 |
| `conflict` | 数据不满足提交条件或存在多解 | 未提交 |
| `stale` | 来源流水或标签变化，已提交依据不再可信 | 未提交 |
| `submitted` | 已提交并写入 active relation | 已提交 |
| `withdrawn` | 已撤回 | 历史 |

## 计数口径

- 顶部“未提交”数字 = 当前月份和账户筛选下 `draft + conflict + stale` 的批次数，不是流水条数。
- 顶部“已提交”数字 = 当前月份和账户筛选下 `submitted` 的批次数，不是流水条数。
- 左侧免 OA 分类固定展示全部标签；每个标签同时展示当前状态下的批次数和流水条数，格式为“X 批 / Y 条”。
- 分类批次数按批次归属标签计数；分类流水条数按批次内该标签对应的 `row_count` 或 `tag_counts` 累加。
- 单边免 OA 批次按 `batch_type + scope_month + account_key` 分组；`account_key` 使用银行名称和账号后四位，格式为 `bank_name:account_last4`。同月同分类但不同账号必须拆成不同批次。
- 内部往来款保留跨账户配对逻辑，不按单账户强拆。

## 页面结构

- 页面主体为三栏树状结构：左栏分类、中栏批次、右栏流水。
- 左栏保持固定分类和计数。
- 中栏宽度与左栏一致，仅显示批次时间、银行+后四位、流水条数、分类，以及“提交批次”和“撤回批次”操作。
- 右栏流水金额单元格显示收/支 tag、金额、银行+后四位 tag；不再单独展示“收/支”列。

## 关键约束

- 提交必须写入 `WorkbenchPairRelationService`，`relation_mode=no_oa_bank_batch`。
- 撤回必须调用免 OA 批次撤回 API，不能绕过批次直接普通取消 relation。
- 内部往来款必须校验收入/支出、金额、不同账户、时间窗口和多解冲突。
- 已配对区中 `row_count >= 2` 的免 OA 批次默认输出摘要折叠，原始流水保留在 `collapsed_rows.bank`。
- `row_count = 1` 的已提交免 OA 批次不折叠，但普通银行流水行仍必须保留免 OA tag、批次来源元数据和撤回批次动作。

## 验收标准

- 未提交/已提交双栏或双态视图清晰。
- 批量提交、撤回、分类变更全部刷新关联台和搜索。
- stale 批次不会让用户无法撤回 active relation。
- 搜索可命中折叠明细。
