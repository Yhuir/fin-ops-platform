# 外部往来款管理

## 目标

外部往来款管理页面通过银行明细已经完成的外部往来三层标签实时汇总、管理除内部往来款外的往来事项。银行明细是打标签事实入口；本页面只消费银行明细的主标签、子标签、子子标签和台账动作类型，不再提供单条流水二次打标签入口。

## 数据范围

纳入银行明细中已经形成 `外部往来款付款` / `外部往来款收款` 三层标签，且标签 code 位于“外部往来款标签设置”准入范围内的流水。缺少子子标签的外部往来候选应留在银行明细 `待确认` 中处理，不进入本页面作为待分类编辑项。本页面结合单条流水、对方、历史余额、冲抵关系和人工确认形成台账事实。

“外部往来款标签设置”抽屉只保存银行明细自动标签规则的稳定 `code`，展示时实时从银行明细自动标签规则解析当前主/子标签名称。银行自动标签改名后，本页面抽屉和流水列应展示新名称；规则停用或不再属于外部往来后，该 code 不再生效，保存设置后清理历史引用。抽屉不保存 `个人往来`、`公司往来`、`银行往来`、`业务往来`，这四类子子标签仍由银行明细的候选确认或人工补分类产生。

外部往来三层标签语义：

- 主标签：`外部往来款付款` 或 `外部往来款收款`。
- 子标签：付款含借出款、归还借款、保证金付款、付押金；收款含借入款、收回借款、退保证金、退押金、退款。
- 子子标签：`个人往来`、`公司往来`、`银行往来`、`业务往来`。
- 台账动作类型：`pending_collection`、`collected`、`pending_repayment`、`repaid`，由银行明细自动标签规则推导或配置，不在本页面编辑。

台账方向语义：

- `pending_repayment`：形成待还款。
- `repaid`：形成已还款。
- `pending_collection`：形成待收款。
- `collected`：形成已收款。

不纳入第一版：

- 内部往来款。
- 没有银行流水来源的手工项。
- 银行贷款计划、利息计划、自动扣账计划。
- 在往来款管理页面直接新建无流水来源台账。

## 关系状态

- `suggested`：系统建议关系，只在台账待确认，不进关联台同一行。
- `deterministic`：系统完全闭合且无歧义，可进关联台同一行。
- `confirmed`：人工确认关系，可进关联台同一行。
- `conflict`：冲突/异常关系，不进关联台同一行。

## 页面筛选

页面主台账只展示小类筛选：

- 小类：`全部`、`个人往来`、`公司往来`、`银行往来`、`业务往来`。

`全部 / 借出 / 借入` 大类按钮不在页面展示。进入本页的流水已经默认是外部往来流水，借入、借出、还款、收款语义由银行明细三层标签和 `turnover_action_type` 判断；再用大按钮切换会和四类小类、金额列方向重复。后端查询参数仍保留 `direction=all|borrow_in|borrow_out`，用于 API 兼容、导出或自动化测试。

`业务往来` 固定归入借出/待收款语义，不归入借入/待还款语义。银行明细传来的三层标签必须进入小类筛选，金额列和汇总则以 `turnover_action_type` 为准。

## 自动闭合口径

只有完全闭合且无歧义的关系才能自动确认：

- 同一对方户名。
- 同一往来类型。
- 方向语义正确。
- 金额完全抵扣。
- 不存在另一种合理组合。
- 没有标签、主体、类型冲突。

银行明细标签或外部往来动作类型变化后，系统按同一对方户名、同一子子标签、方向语义和金额冲抵规则重建往来关系。完全闭合且无歧义的关系可以自动同步到关联台；未闭合关系保留余额，不伪装成 OA/发票闭环。

## 验收标准

- 顶部汇总只展示四项：待还款金额、已还款金额、待收款金额、已收款金额；每项 block 内按 `个人往来`、`公司往来`、`银行往来`、`业务往来` 展示拆分金额。
- 页面不展示已闭合金额、待人工确认数量、当前筛选文案、冲突/异常数量、账单行数或分组余额区域。
- 页面不展示 `全部 / 借出 / 借入` 大类按钮；账单表支持按个人、公司、银行、业务往来小类切换。
- 账单表不单独展示 `银行明细标签` 和 `开户机构` 列；流水行的主/子/子子标签 chip 以及银行+后四位 chip 放在对应的借款金额或还款金额单元格下方，合计行金额下不显示日期 chip。
- 还款备注必须显示在对应还款或收款流水项上，不能只在关系合计行拼接展示。
- 页面不展示往来款子标签下拉或页面级保存修改按钮；银行明细保存和确认后的三层标签会同步反映到本页面。
- 银行明细标签确认、人工补分类、撤销和往来关系人工确认/撤销会同步影响关联台展示。
- 往来款归并不等于 OA/发票闭环，页面必须明确标识。
