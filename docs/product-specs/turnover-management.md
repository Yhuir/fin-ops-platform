# 往来款管理

## 目标

往来款管理页面通过银行明细自动主标签实时汇总、管理除内部往来款外的往来事项。银行明细页面只负责自动识别 `往来款` 主标签；往来款管理页面是唯一允许人工细分往来款子标签的入口。

## 数据范围

纳入银行明细中已经自动打出 `往来款` / `外部往来款` / `外部往来候选` 主标签的流水。银行明细页只负责粗筛候选，不在单条流水层面提供人工子标签选择、保存或清空入口；本页面结合单条流水、对方、历史余额、冲抵关系和人工确认形成台账事实。

进入页面但尚未细分的流水显示为 `待分类`。用户在往来款管理页按单条流水选择完整叶子子标签，可以连续修改多条流水，最后通过页面级 `保存修改` 按钮批量提交。批量保存必须是原子事务：任意一条流水版本冲突、标签非法、权限失败或流水不存在时，本次修改全部失败，不允许部分成功。

- 借入：个人暂借款、公司暂借款、银行往来款。
- 借出：个人往来款、公司往来款、银行往来款、货款往来款。
- 业务往来：质保金、投标保证金、履约保证金、已开发票未收款。业务往来归入借出大类。

子标签语义：

- 借入 + 收入流水 = 待还款。
- 借入 + 支出流水 = 已还款。
- 借出 + 支出流水 = 待收款。
- 借出 + 收入流水 = 已收款。
- 业务往来使用待收款/已收款语义。

不纳入第一版：

- 内部往来款。
- 没有银行流水来源的手工项。
- 银行贷款计划、利息计划、自动扣账计划。
- 在往来款管理页面直接新建无流水来源台账。

## 关系状态

- `suggested`：系统建议关系，只在台账待确认，不进关联台同一行。
- `deterministic`：系统完全闭合且无歧义，可进关联台同一行。
- `confirmed`：人工确认关系，可进关联台同一行。
- `conflict`：冲突/异常关系，不进关联台同一行。

## 页面筛选

页面有两层筛选：

1. 大类：`全部`、`借出`、`借入`。
2. 小类：`全部`、`个人往来`、`公司往来`、`银行往来`、`业务往来`。

`业务往来` 属于 `借出`；当大类为 `借入` 时，业务往来应隐藏或禁用。已保存的子标签必须同时进入大类筛选和小类筛选。

## 自动闭合口径

只有完全闭合且无歧义的关系才能自动确认：

- 同一对方户名。
- 同一往来类型。
- 方向语义正确。
- 金额完全抵扣。
- 不存在另一种合理组合。
- 没有标签、主体、类型冲突。

批量保存子标签成功后，系统立即按同一对方户名、同一小类、方向语义和金额冲抵规则重建往来关系。完全闭合且无歧义的关系可以自动同步到关联台；未闭合关系保留余额，不伪装成 OA/发票闭环。

## 验收标准

- 顶部汇总只展示四项：待还款金额、已还款金额、待收款金额、已收款金额。
- 页面不展示已闭合金额、待人工确认数量、当前筛选文案、冲突/异常数量、账单行数或分组余额区域。
- 账单表支持按借出/借入大类和个人、公司、银行、业务往来小类切换。
- 往来款管理页保存的子标签会同步反映到银行明细页面。
- 子标签批量保存和人工确认、撤销会同步影响关联台展示。
- 往来款归并不等于 OA/发票闭环，页面必须明确标识。
