# 银行明细

## 目标

银行明细页面用于查看所有导入流水，展示系统自动分类，并作为免 OA 批次、关联台和其他下游流程消费银行流水标签的事实入口。

左侧账户余额和总余额是银行账户事实口径：每个账户余额来自该账户按交易时间排序的最新一笔非空流水余额，总余额等于各账户最新余额之和。账户身份优先使用完整账号；缺少完整账号时才退回银行 + 尾号。日期、关键字、分类筛选和自动标签规则变化只影响流水列表、交易数量和标签统计，不得改变账户最新余额或总余额；只有新增、删除、重导流水或原始余额字段变化才允许余额变化。

## 分类口径

- 银行明细标签优先由 app 自动分配；当同一次自动识别命中多个普通标签且无法唯一判定时，银行明细行进入 `待确认` 状态，用户只能从本次命中的候选标签中确认一个。未命中自动规则的流水进入 `待分类` 人工补分类入口，用户可从当前启用的全部银行明细标签中选择一个；该入口与自动候选确认使用独立后端接口和审计动作，不能复用自动确认的候选语义。
- 往来款子标签只能在 `往来款管理` 页面按单条流水维护。银行明细页面只展示往来款管理保存后的子标签结果，不提供编辑入口。
- 银行明细页面右上角提供 `自动标签规则` 按钮，打开加宽右侧抽屉，用表格形式管理文本类自动标签、命中规则、停用状态和优先级。
- 无自动标签且未人工补分类的流水分类显示为 `待分类`；完成人工补分类后，人工选择结果作为当前有效分类参与 `category_code`、`category_label`、`category_counts` 和下游展示。旧版本迁移前的人工分类历史仍只作为审计/归档事实保留，不参与当前有效分类。
- 关联台特殊规则不再给银行流水打标签；只保留周洁莹 OA 附件发票“冲”自动闭环，且该规则不是银行流水标签。
- 标签以稳定 `code` 作为系统身份。改名后银行明细、免 OA 批次、关联台、待找发票规则等当前页面和引用关系都按同一个 `code` 实时显示新名称。
- 自动标签支持结构化 `输出主标签 / 输出子标签`。`code` 仍是唯一稳定身份；`category_label` 保持兼容的叶子展示名，新增的主/子标签字段用于页面展示、筛选、导出和下游展示，不替代 `code`。

## 免 OA 自动分类规则

以下分类会进入免 OA 流水批量处理。自动判断必须保持收敛，不能用宽泛词造成误打标；未命中时保持 `-`，等待通过其他业务流程处理。自动分类按优先级执行：先识别内部往来款，再识别文本类标签；已经命中内部往来款的流水不能被手续费、工资、税款等文本规则覆盖。

| 分类 | 自动判断逻辑 |
| --- | --- |
| 手续费 | 对方户名、摘要或备注包含“手续费”，或对方户名、摘要或备注包含“短信服务费”。普通“服务费”不自动归为手续费；用途和明细扩展字段只含“手续费”也不自动归为手续费。 |
| 工资 | 摘要、用途、备注或明细字段包含“工资”。 |
| 过节费 | 摘要、用途、备注或明细字段包含“过节费”。普通“慰问金”“节日慰问金”等不自动归为过节费。 |
| 奖金 | 摘要、用途、备注或明细字段包含：奖金、绩效奖、年终奖。 |
| 代理国库税收收缴 | 摘要、用途、备注或明细字段包含：代理国库税收收缴、国库税收收缴。单独“税收收缴”不自动归为代理国库税收收缴。 |
| 社保款 | 摘要、用途、备注或明细字段包含：社保款、社保费、社会保险费、缴纳社保。普通“社会保险”不自动归为社保款。 |
| 税款 | 摘要、用途、备注或明细字段包含：税款、缴纳税款、电子缴税、税库银、税务局、完税。普通“税费”和“扣税”不自动归为税款。 |
| 内部往来款 | 先于其他自动标签识别。必须命中跨流水确定性配对：公司账户之间、收入/支出方向相反、金额相等、不同银行账号或账户、交易时间差不超过 48 小时。配对检测使用当前日期范围外扩 48 小时的完整银行流水上下文，不受页面账户筛选、关键字筛选或分页影响；按月读模型重建时需要包含月初/月末 48 小时边界上下文。单边、同账户、金额不等、超过 48 小时或存在多解时不在银行明细误打标签，等待免 OA/关联台流程处理。 |

## 自动标签规则管理

自动标签规则的事实源是设置中的 `bank_transaction_tags`。系统不新增平行规则表，避免标签名称、下游引用和自动命中逻辑分裂。普通文本规则的初始口径来自 `/Users/yu/Desktop/sy/财务运营平台/银行明细标签/银行流水标签ui2.numbers`；导入/替换时移除旧 app 内普通规则，只保留文件规则并尽量复用相同主/子标签的稳定 `code`。用户后续仍通过 `自动标签规则` 表格维护这些规则。

- `内部往来款` 固定显示在可用区第一行，优先级为 `1`，灰色不可交互，不允许改名、停用或排序。
- 可用区内每个可编辑标签默认优先级为 `2`。用户可把普通规则改为更大的整数优先级；保存后系统按优先级自动归位。普通规则优先级 `1` 保留给 `内部往来款`，不允许普通规则使用。
- 普通规则按优先级层级执行：同一优先级全部尝试命中；该层级命中 1 个标签时自动写入结果，命中多个标签时只把该层级命中的候选交给用户确认；只在当前层级完全无命中时才继续检查更低优先级层级。
- 停用区显示已停用标签。停用后该标签不再参与未来自动命中；如果历史流水重算后没有其他规则命中，类型显示 `-`。
- 在银行明细 `自动标签规则` 抽屉停用标签时，系统会在同一次保存中解除该标签在待找发票规则中的引用、同步版本、写审计，并触发银行明细和待找发票等派生数据刷新；不能让用户在两个页面之间手工来回修补引用。
- 设置页直接保存银行明细标签字典时，仍必须拒绝“停用标签但待找发票规则继续引用”的不一致配置。
- 未被引用但已经打在历史银行流水上的标签允许停用，后续由 read model/lifecycle 重算收敛。
- 新增标签由后端生成稳定 `custom_...` code；前端不得为新标签提交自造 code。
- 重命名只修改主标签名称或子标签名称，不改变 code。普通维护 UI 在表格中直接编辑主标签和子标签；下游当前页面和规则引用按 code 实时解析新名称。
- 可用规则必须填写主标签名称；子标签名称可为空。显示时按 `[主标签名称, 子标签名称].filter(Boolean).join(" / ")` 输出：主子都存在时显示 `主 / 子`，只有主标签时只显示主标签；后续补充子标签后同一 code 立即显示为 `主 / 子`。
- 可用规则唯一性按 `主标签名称 + 子标签名称` 组合判断：同主同子不允许重复；同主不同子、不同主同子、不同主不同子都允许。停用区允许保留历史重复显示名称，但再次启用时必须重新满足可用区唯一性。
- 普通维护 UI 不展示或编辑账户范围和正则条件；保存时统一写入 `account_scope={"type":"any","values":[]}` 和空 `regex_any`，避免不可见条件影响规则行为。
- 规则保存使用版本号乐观锁，成功后写审计，并标记银行明细、免 OA、关联台、待找发票、成本统计和搜索等派生数据 dirty；保存接口不得在请求热路径同步全量重算历史流水。

每条可编辑文本规则的底层模型是生产级规则模型。事实源仍是设置中的 `bank_transaction_tags`，不新增平行规则表。底层模型需要保留规则 ID、版本、审计、命中后停止、复核流转和命中说明等系统字段，但普通规则维护 UI 不直接展示这些系统字段。

普通 UI 是加宽的 xlsx 风格表格，不使用卡片展开编辑。桌面宽度下应能看到主要规则列而不依赖左右滑动；同一 `优先级 + 主标签` 的多条子标签规则使用纵向合并主标签单元格展示，编辑合并主标签会同步修改该组所有子标签规则。包含、不包含等多词条字段在单元格内完整换行显示，点击后用多行弹窗逐行维护，不用 `共 N 项` 或省略号替代正文。普通 UI 展示和允许编辑的字段包含：

| 字段 | 说明 |
| --- | --- |
| 启用状态 | 控制规则是否参与未来自动命中。 |
| 优先级 | 控制普通规则的执行层级。普通规则必须为大于等于 `2` 的整数；同级规则不互相抢占。 |
| 适用方向 | `收入`、`支出` 或 `不限`，在规则头部主子标签后用 toggle 编辑。 |
| 匹配字段 | 用户从系统提供的语义字段中选择，不直接选择各银行原始字段名。 |
| 精确命中字样 | 可为空；有值时必须与选中语义字段完整文本相等才命中。 |
| 包含任一 | 可为空；有值时选中语义字段包含任一字样即命中。 |
| 必须同时包含 | 可为空；有值时所有字样都必须出现在选中字段集合内。 |
| 不包含字样 | 可为空；有值时选中语义字段包含任一排除字样则整条规则不命中。 |
| 主标签名称 / 子标签名称 | 命中后的银行明细标签。主标签必填，子标签选填；普通维护 UI 不再暴露独立的“标签名称”，也不在展开区提供额外输入行。 |

主/子标签字段使用以下合同：

- 规则配置：`output_primary_label`、`output_sub_label`。
- 兼容字段：后端仍生成并保存 `label`，但它是由 `output_sub_label || output_primary_label` 派生的叶子名称，不再由普通 UI 单独输入。
- 自动命中结果：`category_primary_label`、`category_sub_label`、`category_label_path`。
- 银行明细行：`auto_category_primary_label`、`auto_category_sub_label`、`auto_category_label_path`，以及同口径的 `effective_*` 和兼容别名 `category_*`。
- 旧字段 `category_code`、`category_label`、`category_path`、`auto_category_label`、`effective_category_label` 必须保留，供旧页面、导出和下游兼容消费。
- SQL 读模型处于 `refreshing`、`stale` 或 `schema_mismatch` 时，接口仍应返回 `read_model.bank_detail_rows` 中最后一版可用投影，并保留非 fresh 状态触发后台刷新；只有 scope 缺失或读模型仓库不可用时才返回空刷新态。页面展示刷新/升级提示时不能清空已有账户和流水。

命中逻辑为：先检查适用方向；普通维护 UI 保存的账户范围固定为不限；再在选中语义字段上执行 `(精确命中任一 OR 包含任一 OR 必须同时包含) AND NOT 不包含`。可用标签必须至少填写一种正向条件；`不包含` 只能作为排除条件，不能单独构成命中；停用标签可保留空规则用于历史展示。规则匹配不使用置信度分数；不确定流水应进入明确的复核或待确认状态，而不是生成不可审计的 confidence。

规则执行顺序：

1. `内部往来款`：固定优先级 1，命中后停止。仍使用跨流水确定性配对，不靠单条文本猜测。
2. 明确业务标签：手续费、税款、薪资社保福利、明确收入、货款、工程服务费和普通费用等，作为普通候选规则执行。多个普通规则同时命中时不得按顺序猜测单一结果，必须只把命中的标签作为候选项返回给用户确认。
3. `外部往来款`：作为最后候选规则，只在未被明确业务规则命中的流水中识别个人、公司、银行外部往来候选。银行明细页不细分借入款、借出款、还款、退款、保证金或押金；后续细分由 `往来款管理` 台账确认并写回同一银行流水标签事实源。
4. 未命中：显示 `-`，进入人工维护规则池。

外部往来候选规则至少覆盖 `往来款`、`暂借款`、`借款`、`还暂借款`、`归还借款`、`还借款`、`保证金`、`押金`、`退款`、`退回`、`返还`、`代垫`、`垫付`、`代付`、`代购`、`贷款扣款`、`批量还款`、`借据号`、`还息`、`贷款本息`、`收回贷款本息`、`本息`。为了不抢明确业务标签，外部往来候选应排除 `本公司帐户/本公司账户`、`货款`、`预付货款`、`工程款`、`劳务费`、`技术服务费`、`工资`、`社保`、`公积金`、`税款`、`纳税`、`电子退库`、`结息`、`活期利息`、`存款利息`。

匹配前统一做文本标准化：去首尾空格，合并换行和连续空格，`--`/`_` 视为空，`帐户/账户` 等价，全角/半角和中英文括号等价，大小写不敏感。命中结果应保留命中规则、字段和关键词，用于复核和调试展示。

由于每家银行流水字段不一致，规则只暴露稳定语义字段，导入适配层负责把不同银行原始字段映射进这些语义字段：

| 语义字段 | 来源口径 |
| --- | --- |
| 对方户名 | `counterparty_name`。 |
| 对方账号 | `counterparty_account`、`counterparty_account_no` 等。 |
| 对方开户行 | `counterparty_bank`、`counterparty_bank_name` 等。 |
| 用途/交易用途 | `purpose_text`、`purpose` 等。 |
| 摘要 | `summary_text`、`summary` 等。 |
| 备注/附言/客户附言 | `note_text`、`remark`、`note`、`customer_note` 等。 |
| 明细扩展字段 | `detail_text`、`detail_fields`、`summary_fields` 等导入扩展字段。 |
| 全部文本 | 去重合并后的所有语义文本，用于用户明确希望跨字段宽匹配的规则。 |

## 字段展示

银行明细主表使用 MUI Table，不使用 DataGrid。右侧流水表固定展示以下列：

- 对方户名：包含交易时间，以及显示在交易时间下方的 OA/发票关系标签。
- 类型：窄列，只显示自动标签或 `-`。
- 金额。
- 余额。
- 用途/交易用途。
- 摘要。
- 备注/附言/客户附言。

银行原始文本字段按导入来源映射到三槽展示。只要导入行携带 `bank_text_fields`，三槽只读取真实银行字段；缺失字段显示为空或 `-`，不能用其他槽位的 `summary/remark` 交叉补值。

| 银行 | 展示字段 |
| --- | --- |
| 工行 | 用途、摘要、附言 |
| 光大 | 摘要 |
| 建行 | 摘要、备注 |
| 交行 | 摘要 |
| 民生 | 客户附言，没有摘要 |
| 平安 | 摘要、交易用途 |

长文本在单元格内换行；页面应尽量避免横向滚动。带时区后缀的交易时间（如 `2026-04-23 17:33:58+08:00`）展示为 `2026-04-23 17:33:58`。

## 候选确认

- 当 `category_resolution_status=needs_confirmation` 时，类型列显示 `待确认`，点击后只列出 `auto_candidate_categories` 中的候选标签。
- 用户选择候选后，系统保存一次来源为 `auto_confirmation` 的独立确认事实，写入候选列表、当前自动标签规则版本和审计信息；确认结果作为 `manual_confirmation` 生效，优先于自动结果。
- 已确认行显示确认后的有效标签和 `撤销`。撤销只撤销本次自动候选确认，后续读模型刷新后回到当前自动规则的结果；不得恢复为“全部标签可选”的人工分类器。
- 后端确认接口必须重新用当前流水和当前规则计算候选集；请求中的 `category_code` 不在当前候选集、标签不存在或已停用时必须拒绝。
- 确认或撤销只标记银行明细 read model 和相关下游派生数据 dirty/enqueue，不在请求热路径全量重算。

## 人工待分类

- 当 `category_resolution_status=unmatched` 且没有有效分类时，类型列显示 `待分类`，点击后按“主标签 / 子标签”两列展示当前启用的全部银行明细标签。
- 用户选择标签后，系统保存来源为 `manual` 的人工分类事实，写审计动作 `bank_detail_category_manually_assigned`，并触发银行明细 read model 及相关下游派生数据刷新。
- 人工待分类接口只能处理当前自动规则未命中的流水；`needs_confirmation`、`auto_matched` 和 `internal_transfer` 等状态必须拒绝走人工待分类入口，避免绕过自动候选确认或覆盖确定性自动结果。
- 人工分类后的行显示有效标签和 `撤销`。撤销只清除来源为 `manual` 的人工补分类事实；自动候选确认的撤销仍使用候选确认撤销接口。

## 导出

银行明细页面提供同步 XLSX 导出，导出口径必须和当前页面筛选一致，但不受当前分页限制。

- `GET /api/bank-details/transactions/export?mode=all`：导出当前筛选命中的全部银行流水。
- `GET /api/bank-details/transactions/export?mode=account&account_key=...`：导出当前筛选命中的指定账户流水。
- 筛选参数复用页面查询：`date_from`、`date_to`、`keyword`、`category_code`、`category_primary_label`、`category_sub_label`，当前账户导出还必须携带有效 `account_key`。
- 全部银行导出包含 `全部流水` sheet 和每个银行单独 sheet；当前账户导出只包含该账户银行 sheet。
- 导出列使用专业 Excel 字段，不导出 UI chip/tag 样式。列顺序为：交易时间、银行、账号尾号、对方户名、收支方向、收入金额、支出金额、余额、自动分类、自动分类主标签、自动分类子标签、OA 关系、发票关系、用途/交易用途、摘要、备注/附言/客户附言、流水 ID。
- 交易时间导出同样去除 `+08:00` 等时区后缀。金额列为数值格式，表头冻结并启用筛选。
- 同步导出上限为 `20000` 行；超过时返回 `400 bank_detail_export_row_limit_exceeded`，提示用户缩小日期范围、选择具体银行或增加搜索条件。
- 导出下载必须写审计动作 `bank_detail_export_downloaded`，记录模式、筛选条件、行数、sheet 名称和文件名。

## 联动

银行明细自动分类和银行原始字段变化后必须触发：

- 银行明细自身刷新。
- 免 OA 批次列表刷新。
- 需要消费银行流水自动标签的关联台 read model 刷新。
- 待找发票、成本统计、搜索等依赖银行明细标签的派生数据刷新。

## 验收标准

- 页面没有旧版保存分类按钮或未保存分类拦截；多命中自动规则行只允许从本次命中候选集中确认一个标签，未命中自动规则行允许通过 `待分类` 从当前启用标签中人工补分类，两种写入路径必须分离。
- 页面没有往来款子标签编辑下拉或保存按钮；往来款管理保存后的子标签只作为展示和筛选结果出现。
- 页面右上角有 `自动标签规则` 按钮；抽屉右侧滑出，桌面加宽为表格工作区，移动端占满宽度。
- 抽屉以表格形式新增、改名、编辑规则、排序、停用和重新启用文本类标签；`内部往来款` 固定在可用区第一行、优先级 1 且不可交互。
- 类型列只显示自动标签、`待确认`、`待分类` 或已人工补分类标签；未命中且未处理的流水不得伪造“未分类”标签。
- 后端自动候选确认接口不得接受全量标签兜底；未命中流水的人工补分类必须走独立接口、独立审计动作和 `manual` source。
- 已提交或已配对流水的自动分类变化时，下游批次/关系进入需复核状态，而不是静默篡改历史。
