# 页面数据完整性统计

本文定义业务页面标题统计的当前有效口径。标题统计用于快速判断页面自身拉取的数据是否完整；它不是统一事实源的替代品，也不能由统一事实源回填。

## 适用页面

- 银行明细
- OA 待付款核对
- 外部往来款管理
- ETC 票据
- 税金抵扣
- 待找发票
- 进项发票使用情况
- 销项发票收款情况
- 关联台
- 成本统计

## 数据边界

- 每个页面的统计只能来自该页面自己的 direct-canonical 主查询；不得调用 Audit、跨页统计 API 或统一事实源来补数。
- 页面不展示独立 Audit 按钮，也不发起 Page Audit 请求。App Health 的 System Audit 在后台 registry 边界内编排各页面 canonical proof，用于将 expected set、关系成员和统计结果进行对账；它不进入业务页面热路径。
- 统计覆盖该页面未应用月份、搜索、筛选、排序和分页前的完整数据范围。改变这些查询条件时，标题统计不变化。
- 数量按页面合同中的业务身份去重。折叠组、关系行和当前分页行数不得冒充 OA、流水或发票数量。

## 展示口径

- 只显示笔数、条数、张数、组数、批数等数量，不显示金额。
- 数字使用完整十进制和千分位分隔符，不使用“万”等缩写。
- 标题同行直接展示该页面合同要求的核心数量；只有仍有辅助数量的页面才提供简洁 Popover。没有辅助数量时不显示空 Popover 或展开箭头。
- 所有拥有页面访问权限的用户都能看到统计；System Audit 只在管理员可见的 App Health 运维页执行。
- 合法空集显示 `0`。direct-canonical 查询失败或返回字段不可用时显示不可用值 `—`，不得用旧数或假 `0` 兜底。

## 直读与对账

- 所有统计都由页面 owner 的 direct-canonical 查询边界独立重算，不依赖 projection、freshness、dirty scope、refresh worker 或 Redis。允许页面沿用已经存在的非阻塞 statistics 辅助请求，但不得为本合同新增跨页统计请求。
- 生产验收必须同时满足：页面主响应成功、统计恒等式成立、筛选前后统计逐字段一致、App Health System Audit 的内部合同通过、通用 outbox 与 required worker 无阻塞问题。

## 页面字段合同

| 页面 | 标题统计 | 辅助统计 | 身份与闭合规则 |
|---|---|---|---|
| 关联台 | OA、流水、进项发票、销项发票 | 已完成 OA、进行中 OA、支出流水、收入流水、手工导入发票、OA 解析新增发票 | 顶部发票数按 canonical 发票 ID 计数，不使用 ETC 折叠后的展示对象数；同 ID 已完成 OA 优先于进行中记录 |
| 成本统计 | 流水、支出、收入 | 无 | 删除“OA 配对成本组”“有成本标签流水”及加工维度数量；五个视图使用同一组基础流水统计，流水总数 = 支出 + 收入 |
| 银行明细 | 流水、支出、收入 | 已分类、未分类 | 删除“已关联/未关联”；流水总数 = 支出 + 收入，已分类 + 未分类 = 流水总数 |
| OA 待付款核对 | 已完成 OA、进行中 OA、进项发票 | 无 | 同 ID 已完成 OA 优先于进行中记录；不展示付款或关系状态数量 |
| 外部往来款管理 | 往来流水、支出、收入 | 无 | 仅按页面往来流水集合计数；总数 = 支出 + 收入 |
| ETC 票据 | 进项发票、ETC 发票 | 无 | 两项都从 `app.invoices` canonical 集合计数；ETC 只认非空 `etc_invoice_id`，不以批次、文件、标题或文本猜测 |
| 税金抵扣 | 当前月份进项发票、当前月份销项发票 | 无 | 按页面月份内 canonical 发票 ID 计数；不展示认证或勾选状态数量 |
| 待找发票 | 流水、OA、进项发票、销项发票 | 支出、收入 | 统计全期间 canonical 页面事实，不展示已找到/待找数量；流水总数 = 支出 + 收入 |
| 进项发票使用情况 | 进项发票、已完成 OA、进行中 OA | 支出流水、收入流水 | 发票数为 canonical 进项发票总数，不使用当前筛选或关系行数；同 ID 已完成 OA 优先 |
| 销项发票收款情况 | 销项发票、收入流水、蓝字发票、红字发票 | 无 | 红蓝按 canonical 销项发票含税总额符号互斥分类；蓝字 + 红字 = 销项发票总数 |

`手工导入发票`与`OA 解析新增发票`是来源分解，不是互斥覆盖全集：同一 canonical 发票可能同时拥有人工导入与 OA 附件来源证据；`OA 解析新增发票`只计 OA 解析创建且没有人工导入来源的发票，避免重复解释。
