# 导入、预览确认与 ETC 业务批次

本文维护文件导入、预览确认、幂等防重、外部文件生命周期和 ETC 业务批次的当前业务口径。

## 导入通用流程

1. 上传文件并创建导入任务。
2. 后端解析文件，生成 preview rows、错误、摘要和 source version。
3. 用户确认导入，系统执行幂等写入。
4. 写入后触发 dirty scope、read model refresh 和前端刷新事件。
5. 文件对象和导入记录进入可追溯生命周期。

导入确认必须能防止重复提交、重复文件和半写入状态。失败时要保留足够的错误信息用于人工修复。

## 文件生命周期

- 原始文件保存在对象存储或兼容存储中，业务记录只保存对象引用、checksum、大小、文件名和导入批次。
- 不允许测试或自动化流程依赖真实业务文件。
- 删除、重置和回滚必须同时考虑对象存储、数据库记录和 read model。

## ETC 业务批次

ETC 批次覆盖票据导入、OA 自动检测、人工兜底和撤销草稿：

- 自动检测以 OA、发票、流水和业务规则为事实源。
- 人工批次必须记录操作者、范围、原因、状态和审计。
- 撤销草稿不应破坏已确认业务事实。
- 迁移或 dry-run 需要输出受影响批次、对象数量和可回滚边界。

## 导入后的影响

| 导入类型 | 受影响页面 |
| --- | --- |
| 银行流水 | 银行明细、关联台、往来款、成本统计 |
| OA 单据 | 关联台、OA 待付款、ETC 批次 |
| 进项/销项发票 | 待找发票、税金抵扣、成本统计、关联台 |
| ETC 票据 | ETC 批次、税金抵扣、关联台 |
