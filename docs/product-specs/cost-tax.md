# 成本统计、项目归因与税金抵扣

本文维护成本统计、项目成本归因、税金抵扣、已认证发票和发票使用/收款 read model 的当前业务口径。

## 成本统计

- 项目成本三个视角共享同一成本集合：按项目（项目→银行主标签→银行子标签→成本明细）、按流水标签（主标签→子标签→明细）、按银行账户（账户→项目→主标签→子标签→明细）。分类使用来源银行流水，原 OA 费用类型保留在凭据详情。
- 每个成本行是一项 OA 成本、一笔真实支出来源和金额。账户、标签、付款月份从来源读取，不能分别选择。一个 OA 成本可以新增多行，同一来源可分给多个 OA 单元，但不能超额或重复提交同一对象与来源。
- 全部 OA 完成且 active 正式关系完整才能进入成本。记 O=OA合计、B=支出原额、R=同关系明确付错退款、N=B-R、C=成本、X=非成本；C+X=N。普通收入不冲减成本。N=0无成本/任务，N<0明确错误。
- O=N 时原 OA 各单元金额固定；O!=N 时沿用人工确定各单元最终成本。金额相等不证明来源唯一；单支出来源，或单正成本单元且无歧义退款/非成本时可自动确定，其余等待人工。
- 待分配抽屉在 OA 单元下新增来源行，填写金额并选择支出。每笔支出的成本+退款冲减+非成本=原额；每笔退款完整归属原支出；每个 OA 单元来源合计=目标。退款和非成本分别填写真实来源，禁止按比例或凑数推荐。
- 每条成本按来源真实付款日期归月。600 元跨月付款为 8 月建行350、9月民生250时形成两条；退款冲减原付款月份，银行流水视角仍在真实退款日记收入。
- 金额已知、来源未知时保留 source_pending 成本行和全部期间金额，指定年月排除并显示月份未定金额。金额未知不把 OA 或银行原额伪装成本。资料缺失可保存来源决定但仍 pending；补齐后重新 GET。事实变动使旧决定失效，保留审计，不沿用 stale 值。
- 无 active OA 关系的支出仅在命中用户明确配置的无 OA 虚拟项目标签时进入成本，直接使用该支出账户/银行标签/日期；同标签不可重复归属不同虚拟项目。
- 原银行流水“按标签/按时间”继续共用真实银行集合，净支出=支出-收入；不改变银行明细维护、账户余额、导入或关联行为。
- 三个成本视角、详情、导出使用相同政策。项目月/年汇总导出同时保留来源成本明细。数据读取是 PostgreSQL 一致性快照，不新建 Cost cache/read model/worker。

完整 I/O 与状态见[成本模块](../modules/cost-statistics/README.md)。

## 项目归因

项目归因至少需要考虑：

- OA 单据项目、发票项目、银行流水摘要/对手方、人工修正关系。
- 日常报销明细拆分、缺失项目、冲突项目和撤回关系。
- source version、归因来源和审计记录。

## 税金抵扣

税金抵扣页面关注可抵扣发票、已认证发票和发票使用状态：

- 认证状态、税额、发票类型和使用状态必须由统一 policy 判定。
- 发票关系确认/撤回会影响税金抵扣和成本统计。
- backfill/refresh 需要按月份或发票对象范围执行，避免逐行重建。
