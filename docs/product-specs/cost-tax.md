# 成本统计、项目归因与税金抵扣

本文维护成本统计、项目成本归因、税金抵扣、已认证发票和发票使用/收款 read model 的当前业务口径。

## 成本统计

成本统计页面面向项目和期间展示费用、发票、流水和核销关系：

- 项目范围、金额归因和下钻口径必须来自统一 cost attribution policy。
- 页面负责筛选、排序、分页、导出 shape，不重新定义项目归因。
- OA 成本归集以 active 正式 Workbench relation 作为付款证据边界：关系中必须同时存在至少一条银行支出和至少一张明确处于完成状态、且有完成时间的支付申请或日常报销。relation 位于 `paired` 或因冻结条件未满足而位于 `unpaired` 都不改变该证据资格；是否存在发票不影响资格。无 OA 的流水、candidate/singleton、仅 bank+invoice 的关系、收入流水均不进入 OA 成本归集。
- `按项目`、`按银行`、`按OA费用类型` 的年/月范围按 OA 完成时间判断，金额按 OA 当前事实归集：支付申请以整张 OA 当前金额作为一个归集单元；日常报销必须逐个使用 canonical `expense_items`，按每个子付款项的当前金额、项目、费用类型和内容形成归集单元。不得用整张报销金额替代子付款项，不得按流水金额比例、顺序或子集猜测拆分；一组多 OA、多流水关系仍逐个按 OA 归集单元金额统计。
- 同一关系组全部付款流水属于同一银行账户时，归集单元可归入该账户；出现多个账户或无法唯一确认账户时，统一归入 `混合支付账户`，不得猜测某个 OA 对应其中某条流水。右栏展示的是 `OA 成本归集明细` 和 `归集金额`，关联付款流水只作为付款证据；详情同时展示关系组 OA 归集合计、银行支出合计及差异。
- OA 或日常报销子付款项缺少稳定 ID、正数金额、项目、费用类型或完成时间时，该归集单元必须明确排除并返回质量统计，不能回退到流水金额、报销表头或“成本待分配”。同一 OA 或同一子付款项同时出现在多个 active 正式关系中属于数据完整性冲突，整次响应失败，禁止重复计成本。
- 成本归集不读取发票金额、票据金额或旧 relation 特殊金额策略覆盖 OA 当前金额；这些字段由各自 owner 页面解释，不能污染本页的 OA 归集口径。
- 成本统计 API 每次请求都在一个 PostgreSQL `REPEATABLE READ READ ONLY` snapshot 中读取 canonical 银行流水、OA、active 正式关系、标签和设置；同一响应内不会混用不同提交时点。
- 成本统计不依赖其它页面 payload/read model，不使用 Cost version、freshness、scope、dirty、outbox、worker 或 Redis cache。
- 银行、OA、关系或设置写入只提交各自 owner facts，不 fan-out 成本统计刷新；下一次访问或浏览器刷新直接读取已提交事实。
- 页面成功响应即代表本次查询基于完整 snapshot 计算完成；读取失败返回明确错误，不能把旧数据或空数据伪装成 fresh。
- 页面存在两套不可混用的事实集：`按项目`、`按银行`、`按OA费用类型` 消费按 OA 完成时间归属的 OA 成本归集单元；`按时间`、`按标签` 消费按流水时间归属的完整银行收入与支出。因此两组金额和期间均不要求相等。API只暴露当前 view 的 bounded `rows`，产品口径不依赖已删除的旧 full-array DTO 字段。
- 五个视图都提供当前视图内搜索。搜索必须先作用于当前视图事实行，再计算 summary、facets、row count 和 cursor 分页；`按项目`、`按银行`、`按OA费用类型` 因而只搜索已进入 OA 配对成本的 allocation，不能把未配对银行流水混入结果。搜索词规范化后最长 200 字符，并绑定分页游标。
- `按时间` 明细只显示 canonical 银行事实：交易时间、对方户名、银行标签、金额、流水摘要；没有 OA 关系时不得伪造为“未配对OA”或“未分类”。
- 本口径统计的是“已完成 OA 且有正式付款关系证据的当前确认成本”，不是现金实付进度。若一张 OA 只有部分付款，但系统没有 canonical 部分付款金额事实，仍按 OA 当前全额归集；供应商退款或冲正也不会自动冲减 OA 成本。需要现金实付或退款冲减口径时，必须另行引入明确、可审计的业务事实，不能从 N:M 关系猜测。
- 全流水统计不显示“总金额”或净额。页面顶部、主标签和子标签分别显示支出金额与收入金额，二者均为正数绝对值；支出金额是当前可见支出流水绝对金额之和，收入金额是当前可见收入流水绝对金额之和。收入用绿色、支出用橘色；明细逐行保留资金方向和该笔金额。
- 主标签和子标签分别显示收支金额及收支笔数，不显示合并金额和占比。收入与支出都进入同一成本统计标签选择规则；旧显式规则升级时保留原支出选择并一次性加入当前有效收入标签，未分类选择保持不变。
- 主标签和子标签按“仅支出、收支都有、仅收入、零金额”排序；同组内依次按总金额、笔数降序和标签名升序。标签卡片中支出在上、收入在下，金额为零时只隐藏金额，不隐藏标签或笔数。
- 明细分页使用表格内部滚动接近底部自动加载；正常态不显示手动“加载更多”按钮。下一页失败只在当前明细区提供重试，不清空已加载内容或刷新整页。
- `按时间` 和 `按标签` 导出都必须包含收入与支出明细、资金方向，以及分方向金额/笔数摘要；OA 项目类导出保持 OA 配对支出口径。

## 项目归因

项目归因至少需要考虑：

- OA 单据项目、发票项目、银行流水摘要/对手方、人工修正关系。
- 日常报销明细拆分、缺失项目、冲突项目和撤回关系。
- source version、归因来源和审计记录。

## 税金抵扣

税金抵扣页面关注可抵扣发票、已认证发票和发票使用状态：

- 认证状态、税额、发票类型和使用状态必须由统一 policy 判定。
- 发票关系确认/撤回会影响税金抵扣和成本统计。
- backfill/refresh 需要按月份或发票对象范围执行，避免逐行重建。
