# 成本统计、项目归因与税金抵扣

本文维护成本统计、项目成本归因、税金抵扣、已认证发票和发票使用/收款 read model 的当前业务口径。

## 成本统计

成本统计页面同时提供项目成本观察维度和银行流水收支分析，但不取代银行明细的账户余额、账户筛选和流水维护职责。

- `项目成本`分组包含`按项目`、`按费用类型`、`按银行账户`。
- 三个视图消费同一个成本事件集合；同一 scope/query 下根层成本金额和成本明细人口必须一致，只改变分组和下钻路径。
- `按项目`路径为项目→费用类型→成本明细；`按费用类型`路径为费用类型→成本明细；`按银行账户`路径为银行账户→项目→成本明细。
- `银行流水`分组包含`按标签`、`按时间`。两个视图消费相同的 canonical 银行流水集合：`按标签`路径为主标签→子标签→流水明细，`按时间`直接列出当前范围流水。
- 流水金额按真实方向统计：`净支出=支出合计-收入合计`，支出和收入分别保留正数展示；不得将收入按绝对值加到支出。原始`按银行`视图仍不恢复，因为其账户维度与银行明细重复。

银行账户归属：

- 有 OA 成本关系仅查看关系内真实支出流水的非空账户；恰好一个不同账户时归该账户。
- 没有可识别支出账户或有多个不同支出账户时归`银行账户未确定`。
- 收入和“付错退款”的账户不参与归属。
- 无 OA 成本行使用来源支出流水自己的账户；空账户归`银行账户未确定`。
- 账户归属是关系层成本观察维度，不得解释为某个 OA 单元来自某条银行流水。

成本人口：

- active 正式关系必须同时存在银行流水和 OA；只要一张 OA 未明确完成，整组不进入成本，也不能落入无 OA 虚拟项目。
- 全部 OA 完成后，关系净支出 `N = 支出原额合计 B - 同关系明确“付错退款”收入合计 R`；普通收入不冲减。
- OA 合计 `O = N` 时，不区分关系拓扑，按 canonical OA 单元原金额自动形成成本。
- `O != N` 时进入人工分配。支付申请整张 OA 是一个单元；日常报销按 canonical `expense_items` 逐项输入。人工保存满足 `C + X = N`，首次为空、不预填、不推荐、不做比例或资金来源映射。
- 人工分配中的 OA 单元展示 OA 类型与 OA 费用类型；关系内流水只展示自身 canonical 银行标签路径。不得用 OA 费用类型、流水摘要或备注互相补写标签。流水无有效标签时保持为空，不显示猜测值。
- `N = 0` 不形成成本；`N < 0` 明确失败。事实变化使旧人工分配失效，禁止沿用旧值 fallback。
- 项目或稳定身份缺失的关系 fail closed；费用类型缺失显示“未填写 OA 费用类型”，不猜测“其他”。
- 没有 active OA 关系的支出流水，只有命中用户在“无 OA 成本范围”中明确配置的虚拟项目标签时才进入成本；默认项目数组为空，费用类型为“无 OA 分类”，同一标签只能属于一个虚拟项目。

详情与读取：

- OA 成本详情展示 OA 单元成本、银行总支出、付错退款、净支出和人工非成本金额/原因；不展示虚构资金来源分配。
- 两个流水视图和无 OA 成本行通过银行流水详情 endpoint 展示真实银行事实；项目成本 OA 行继续使用 allocation 详情。
- explorer、详情、预览和导出每次都在单个 PostgreSQL `REPEATABLE READ READ ONLY` snapshot 中读取 canonical facts；不使用 Cost read model、worker、dirty scope、outbox 或 Redis cache。
- 搜索先作用于当前视图事实，再计算 summary、facets、row count 和 cursor；明细固定每页 20 条，显式翻页，滚动不加载。
- `time|bank_tag` 是当前正式只读 view；旧 `bank` view、`time-tag-rules` API 和对应 App Settings family 已删除，不提供兼容读取或隐藏 fallback。

## 项目归因

项目归因至少需要考虑：

- OA 单据项目、发票项目、银行流水摘要/对手方、人工修正关系。
- 日常报销明细拆分、缺失项目、冲突项目和撤回关系。
- source version、归因来源和审计记录。

## 税金抵扣

税金抵扣页面关注可抵扣发票、已认证发票和发票使用状态：

- 认证状态、税额、发票类型和使用状态必须由统一 policy 判定。
- 发票关系确认/撤回会影响税金抵扣和成本统计。
- backfill/refresh 需要按月份或发票对象范围执行，避免逐行重建。
