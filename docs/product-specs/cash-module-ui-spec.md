# 现金模块 UI 与交互详细设计

更新日期：2026-09-07。工作分支：`codex/cash-ledger`。

状态：**R1–R7 已接受；本轮只实施并验证后端，现金 UI 尚未实现或接入真实 API。** 本文用于后续 Figma Make 修订和前端开发，不修改现有 Figma、不创建现金前端页面。后端实施/发布状态见实施计划。

文档分工：[总设计](cash-module-design.md)拥有业务规则和未决选择；本文拥有页面、字段呈现、操作与状态；[技术设计](../dev/cash-module-technical-design.md)拥有接口和存储边界；[实施计划](../dev/cash-module-implementation-plan.md)拥有执行顺序、测试和交付。需求变化时同步修改所有受影响章节，不复制成多套规则。`U-*` 是便于设计、开发和测试互相定位的说明编号，不是新增审批门禁或冻结合同。

## 1. 已确认业务与设计建议的区别

### 1.1 已确认，原型与实现不得自行改变

- 现金是现有 App 内一个独立页面，只有“可用 / 不可用”两个页面权限档位。现金页获权账号可以使用其各 Tab；只有 `YNSYLP005` 在现有权限设置中修改其他账号的页面权限，现金设置不新增角色管理。
- 3 个一级 Tab：账簿报表、每月任务、基础设置。账簿报表有 4 个同级账簿：往来账总表、现金流水、有票支付、刘树刚账；默认打开往来账总表。
- 现金流水 Tab 完整显示全部未删除的手工和任务现金流水，不以是否进入某本往来账为条件；逐笔手工录入，不支持 Excel 批量录入。
- 删除任一手工或任务现金流水，全部现金账表、相关子表、余额、任务和结算贡献一致更新；不逐表重复删除，不误删其他流水或独立事项。
- 往来总表按每次往来处理列行，外部人员整行蓝色、公司淡黄色；刘树刚新增借款/代付整行橘黄色，归还/冲抵绿色。颜色对应处理方向，不对应完成/未完成；这是用户本次采纳的业务定义，不声称 Excel 原文已明确两色区别。
- 所有现金业务操作不写 App 全局操作历史，不向其他页面提供现金内容；现金不读取普通银行明细、发票、往来或其他财务池。
- 唯一业务资料例外是 OA 项目的 ID、编号、名称、真实阶段，只读。自由新增/改选项目使用当前 OA 候选；既有现金事项真实结算沿用其本地历史项目、只读不可改，即使项目结束或 OA 断线也可办理。现金仅管理新增候选阶段，绝无项目状态写回 OA 的操作。
- 以已有满意原型为视觉基础，沿用现有 App 外壳、紧凑工具栏、通栏表格、右侧抽屉。不得改成大卡片、仪表盘、海报式页头或新品牌。

### 1.2 本文可以直接用于设计的建议

下文提供各表列、表单分组、按钮位置、默认筛选与错误反馈。R1–R6 的金额、状态、删除、归属和日历规则，以及 R7 的既有事项历史项目结算边界均已确定；尺寸、间距和低频字段摆放仍是 UI 建议。具体账户、期初金额、任务金额/日期和允许 OA 阶段由用户使用时配置，技术字段校验依技术设计完善，不再把已接受业务列为待定。

本版不提供 Excel 导入、附件上传、OCR、导出、回收站、现金操作历史、外部通知、银行付款、OA 审批、通用配色规则或报表搭建器。为将来扩展留结构位置，不绘制已可操作的假功能。

### 1.3 使用时配置与实施前技术核查

用户使用时填写具体现金/储蓄账户、期初现金和未结往来、起算日期、任务目标/日期、OA 允许阶段、人员与卡片别名。未中标等阶段由用户在设置中选择，已结束不进入自由新增/改选下拉；R7 只沿用真实既有事项的历史项目。允许不选项目，不以现在提供真实姓名、卡号、金额或配齐全部任务为前置条件。

开发者仍需核实真实 OA 字段/字典及技术 DTO、完成本文与实际组件的映射和测试。支付办理说明中现行/拟调整方案的正式采用情况留作参考内容配置；不影响已接受的账务规则，不建设审批或在线 CMS。细节外的新业务变更才需另行确认。

### 1.4 七组已接受方案的 UI 落点

业务依据见[总设计§10.1](cash-module-design.md#101-七组已确认规则)。以下已融入各节正文和 Make 外发说明，不保留“单次/分次”“软删/硬删”等并行模式。业务方案接受不等于立即开始代码或修改线上原型。

| 区域 | 当前明确呈现 |
| --- | --- |
| 往来总表 | 每次往来处理一行，原事项详情集中看归还进度；常规无往来收支留在现金流水；个人新增本金橘黄、归还/冲抵绿色 |
| 总表金额 | 冲账明确无票/其他非现金；还款与报账回款引用已有现金；票抵单列；真实花销读唯一费用事实，不让用户在五列分别填同一笔钱 |
| 有票支付 | 提供、使用、用于抵债、实际回款是明确动作；使用可暂无抵债对象，用于抵债时复用该次使用；提供/使用/回款各显示自己的金额和关联 |
| 个人矩阵 | 标题明确实际代付/新增借款，按实际月份；账单月份在详情，提前还只标记；两张同银行卡别名区分，公司用途不混入个人本金 |
| 录入/归属 | 一笔现金一个项目，可无项目、可分配同项目多个事项；不支持跨项目现金分摊。直接费用与已有费用关联分开，避免重建费用 |
| 每月任务 | 当月目标、实际累计、剩余分开；新记录/关联已录二选入口，支持分次而不设模式切换；未知目标同一确认表单补齐，核对任务无金额 |
| 逾期待办 | 原任务区域内筛选/分组，不新增一级Tab；按原归属月保留未办/部分办理；当月调整和未来模板修改清楚区分 |
| 纠错/删除 | 普通单笔删除沿用原确认；仅源事项冲突时展开关联处理，保留真实其他流水；源借款不存在时收款可显示未分配，不自动改成新债务 |
| 余额/提醒 | 负余额提示核对但不阻断保存、不造钱补平；起算前未知；提醒只在现金页；短月采用当月最后一天，显示具体日期，不假装银行约定已被修改 |
| 历史项目结算 | 期初非现金旧义务可识别真实历史项目，既有事项的现金结算只读沿用本地项目；自由新增现金候选不放开 |

没有新增大卡片、审批页、信用卡管理页、回收站、通知中心、成本页面、配色引擎或外部连接。三类一级导航和四本账保持不变。原型只用虚构案例演示已接受规则，不上传真实现金正文。

### 1.5 历史项目结算（R7，已确认）

仅从现金模块既有事项办理真实收付时，沿用该事项本地保存的项目，显示只读“沿用历史事项项目（不可改选）”；不进入新项目下拉，不要求 OA 在线，项目已结束/已从 OA 删除也可办理。自由新增仍使用当前 OA 候选，不能任意选结束项目；历史结算不能夹带新事项、补绑定来源事项、改项目或混项目。完整交互见 §7.3，业务依据见[总设计§10.2](cash-module-design.md#102-r7-已确认历史项目结算不是自由新增项目)。这是一条同模块历史结算路径，不新增项目镜像、权限层或流水来源类型；本轮只更新文档，不实际修改 Make 或代码。

## 2. 导航、首屏和扩展位置

### 2.1 导航树（U-NAV）

```text
现有 App 侧栏：现金账（一个页面权限）
├─ 账簿报表
│  ├─ 往来账总表〔首次默认〕
│  ├─ 现金流水
│  ├─ 有票支付
│  └─ 刘树刚账
│     └─ 表格视图：年度还款矩阵 / 现金归还 / 有票直接冲 / 无票报销冲抵
├─ 每月任务
│  ├─ 本月处理〔默认〕
│  └─ 任务配置
└─ 基础设置
   ├─ 现金账户与期初〔默认〕
   ├─ 费用类型
   ├─ OA 项目与可选阶段
```

明确数量：3 个一级 Tab、4 个账簿 Tab、2 个任务子视图、4 个设置子视图；不是 13 个按钮同栏平铺。个人账的 4 种表格视图用小型选择器，不再堆第三条横向通栏 Tab。年份、月份、账户是筛选，不新增年度/月度 Tab。

### 2.2 首屏结构

```text

账簿报表       每月任务       基础设置

分类图例 / 本表汇总和口径说明（紧凑的一至两行，不是卡片）
┌─────────────────────────────────────────────────────────────┐
│ 固定表头                                                    │

└─────────────────────────────────────────────────────────────┘
共 N 条                         每页条数                   分页
```

- 页面标题只表示当前位置，不增加“智能资金中枢”等宣传文案。若需隐私提示，使用低强调的一句“本页面仅记录独立现金账”。
- 账簿区主操作是“新增流水 ▾”，菜单为“记录收入 / 记录支出 / 现金账户互转”；账簿特有的事项操作放在其表格工具栏或详情中，避免双份新增按钮。
- 任务区主操作随子视图变化：本月处理以行操作为主，任务配置提供“新增任务”。设置区仅显示当前配置相关操作。
- 不把全池现金余额搬到往来总表当应收/应付，不在没有定义金额口径时放“净利润”等统计。
- 各视图保留本页面会话内自己的筛选条件；首次进入默认总表，切回已访问视图可保留条件但写后必须重读有效事实。
- 未来账簿在同一级扩展。Make 可用非交互标注说明可扩展位置；生产页面不放虚线空卡、不可用“待开发”Tab 或空接口。窄屏用既有 Tabs 的溢出方式或“更多”，不挤缩字体。

## 3. 视觉、尺寸与现有组件复用

以下已有值来自总设计中已核验的现有样式；拟议尺寸只指导原型，不覆盖现有组件的实际约束。批准实施时以现有组件能力为准，不另建 UI 框架。

| 项目 | 设计要求 |
| --- | --- |
| 外壳 | 复用现有侧栏、页面容器和导航，不把 Make 示例的 App.tsx/全局 CSS 整体搬入 |
| 基础颜色 | 已核验变量：`--fp-primary: #1d4ed8`、`--fp-surface-muted: #eef3f8`、`--fp-text-primary: #1f2937`、`--fp-page: #f6f8fb`；表头使用现有浅底色 |
| 字体 | 系统字体；标题约 20px、正文 14px、表格 13px；金额等宽数字、右对齐 |
| 表格 | 复用 FinanceTable 展示 primitive，分页放 footer；固定表头和内部滚动，contained 模式由页面提供有界高度；常规约 44px、紧凑约 36px 是设计建议，不是该组件内置业务能力 |
| 金额 | 人民币两位小数，沿用现有无千分位格式；超精度输入明确校验错误，不在展示时截断输入冒充有效金额；数值上限由技术设计规定 |
| 按钮 | 现有主次按钮、小圆角；删除用危险操作样式但不占据页面主要视觉；图标按钮具备文字可访问名 |
| 抽屉 | 复用 AppDrawer 的 width、footer、headerActions、ariaBusy、closeDisabled 等现有参数；普通录入建议约 560px，明细多列可建议约 720px，受视口限制，不做全新弹窗系统 |
| 间距 | 优先沿用现有 token；原型建议同组控件 8px、表单组间 16px、内容区 16–24px，不堆大量空白 |
| 长文本 | 项目/用途行内截断，详情可完整读；不得仅靠悬停才能获得关键字段；金额不截断为省略号 |
| 颜色可读性 | 总表整行底色要保持文字可辨、图例有文字；悬停与选中不覆盖分类含义，不使用颜色作为唯一状态载体 |

FinanceTable 不承担业务 rows、排序、API 请求或查询缓存；这些由现金局部视图及 API client 负责。筛选弹层沿用 Portal，避免被表格滚动容器裁切。PageRouteHost 只挂载当前路由，退页即卸载现金页面；App 外层虽已有全局 Provider，现金 rows、草稿、详情与抽屉内容仍不得写入其全局 store/overlay。

### 3.1 响应布局建议

- 桌面 1440px 原型：完整侧栏与表格，右侧抽屉不改变当前表格筛选；主列表保持主要工作面积。
- 常见笔记本 1280px 原型：筛选可换一行，低频筛选收进“更多筛选”；所有金额列仍可通过横向滚动查看，不能静默删除列。
- 约 768px 以下：使用现有 App 的侧栏收起方式，主操作/标签不换成大卡片；抽屉约占满可用视口，表单改一列；表格保留横向滚动和固定关键标识。
- 约 390px 窄屏：按钮可换行，确认/取消在可见底部，表单错误不能被键盘或固定页脚遮挡；无需在本任务创造一套移动卡片账本。
- 以上断点是设计建议，不声称现有 App 已有相同 CSS 断点；如果现有布局变量已能满足，则直接复用。

### 3.2 键盘与读屏

- Tab 顺序依可见布局；Tab 切换、菜单、下拉、分页可用键盘，选择和当前排序有语义说明。
- 打开抽屉后焦点进入标题或首个可编辑字段；关闭后回到触发按钮。删除后原按钮已不存在，则回到列表标题或相邻可操作行，不落到隐藏元素。
- 抽屉有名称、说明和焦点约束；Escape 请求关闭，有未保存内容时提示确认离开，不保存草稿到浏览器磁盘。
- 表单错误贴近字段，并提供可聚焦的错误摘要；提交中和成功/失败反馈可被读屏读出；不连发重复提示。
- 删除确认默认焦点放取消或非危险区域，不让回车意外删除；一次明确确认即可，不新增输入口令、005 审批或二次复核页。

## 4. 通用表格行为（U-TABLE）

| 操作 | 输入与交互 | 成功结果 | 失败与关联范围 |
| --- | --- | --- | --- |
| 查询 | 选择期间和当前表支持的条件，点击查询；关键词回车同效 | 页码回到 1，列表/汇总/条数对应同一组已应用条件 | 原条件草稿保留，结果区显示读取失败；不能把旧结果标成新查询成功 |
| 重置 | 点击重置 | 恢复本表默认条件并查询第 1 页 | 默认范围按下文建议定案，不重置其他 Tab、账户配置或任务 |
| 排序 | 仅明确可排序表头可点；建议日期降序、稳定次序 | 展示排序方向，页码回到 1；余额保持其业务账序含义 | 未支持的排序不做假按钮；不能在当前页客户端排序冒充全结果排序 |
| 分页 | 页码、每页条数；建议默认 50、上限 200 | 在相同条件下读取目标页，汇总不是仅当前页合计 | 错误显示重试；删除最后一页唯一行后定位最近有效页并重读 |
| 刷新 | 刷新当前表 | 同条件重新读取当前结果 | 只刷新当前现金视图，不刷新普通 App 数据或触发 OA 财务同步 |
| 查看详情 | 点击明确的详情按钮或业务标识 | 右抽屉显示完整字段和相关子表；关闭回原筛选/页码 | 对象已删除/无权/读取失败分别提示，不补入示例详情 |
| 清除筛选项 | 删除已应用筛选标签 | 应用新条件并回到第 1 页 | 每个标签显示可读值，不能把真实姓名/搜索词写入全局 URL 或分析日志 |

共同约定：

- 筛选状态和金额只留现金页面内存。浏览器 URL 如需直达，只使用非敏感的页面/视图信息；不把姓名、项目、金额、搜索词写进查询字符串。内部记录 ID 的路由与日志处理以技术设计为准，不另加外部分享功能。
- 初始加载、再次查询、空结果和错误必须区分。刷新期间可保留旧表的视觉位置并明确“正在更新”，但禁用会用旧版本提交的关联/删除动作；响应回来后整体替换同次结果。
- 已删流水不贡献列表、汇总、详情或历史筛选选项；同项目还有其他有效现金事项/流水时，该项目筛选仍存在。
- 历史项目筛选取现金记录中的历史资料，包含已结束/从 OA 删除的项目；新增录入的项目候选另用当前 OA 允许阶段，两个选择器不能复用同一数据语义。
- 空值 `—` 表示没有该项或不适用，不等于数值零。真实零显示 `0.00`。失败、未确认金额口径不可显示 `0.00` 冒充结果。

## 5. 往来账总表（U-TURNOVER）

目的：打开现金页面后，优先查看公司、外部人员与刘树刚三类往来及其结算；此表不是另一套现金录入池。普通工资、房租、水电等直接收支仅在完整现金流水中展示；实际属于垫款/借款的按明确往来归属进入总表，不按费用名称一刀切。

主表每次业务处理一行。借出 1000、收回 200、收回 300 展示三次处理，原借款详情集中显示原额 1000、已还 500、未还 500。同一来源事项及首次现金不重复列本金；一笔现金分给多个同项目事项时，处理明细按各自分配额列行，现金流水仍是一条。

### 5.1 主表字段与筛选

| 区域 | 建议内容 | 说明 |
| --- | --- | --- |
| 默认范围 | 当前业务年份 | 按实际处理日期筛选；期初未结只承接一次，详情显示截至所选期末的未结情况，不把期初再列为本年新增 |
| 筛选 | 年份/期间、往来类别、对象、历史项目、费用类型、处理状态、关键词 | 未结/部分结算/结清按原额与有效分配展示；已删除或撤销贡献不参与计算 |
| 左侧识别列 | 日期、项目、报销人/往来对象、费用类型、费用内容、往来类别 | 报销人与债权债务对象不一定相同，不擅自合并；正式表头由字段确认收口 |
| 金额列 | 收入、支出、冲账、还款、报账提现、真实花销、票抵 | 收入/支出仅取义务建立/归还/公司应收结算的现金份额；费用事件行现金列为空，可从详情查看关联流水；冲账不含票抵，真实花销取唯一费用净额，不求混合大总计；完整现金看现金流水 |
| 状态/说明列 | 有票回款情况、备注 | 回款状态与实际回款金额区分；长说明展开详情 |
| 操作列 | 详情；符合事项规则时的“登记处理” | 不提供逐报表“删除现金流水”接口或只删总表行的按钮 |
| 排序 | 日期、经确认可比较的独立金额列 | 派生未结额等只有定义明确才排序；合并单元格不用作 App 交互结构 |
| 汇总行 | 分类/已定义金额的本次范围合计 | 未结事项的期间口径单独标明；不能默认把所有列相加当余额 |

颜色覆盖行内全部普通单元格和固定列，并使用文字列/图例辅助。刘树刚新增借款/代付用橘黄，归还/有票或无票冲抵用绿色；其他两类按外部蓝色、公司淡黄。颜色不反映是否完成，也不自动用于现金流水表。

### 5.2 详情和处理

详情按三个紧凑区域组织：

1. 原事项：业务类型、对象、日期、项目、原始金额/事项说明、已确认的未结金额。
2. 现金记录子表：实际日期、收/付、金额、账户、来源、关联任务；可打开同一流水详情。某条现金删除后这里也不能保留其正文或金额。
3. 处理明细子表：日期、处理类型、处理金额、是否涉及现金、相关流水、票据/说明。非现金行明确“无现金收付”。

“登记处理”输入目标事项、处理类别、日期、金额、说明及必要关联，动作分成“关联实际收付”与“登记非现金冲抵”，不做一个隐藏副作用的“设为已结清”按钮。票抵必须选明确债务目标；仅票据使用无债务目标时在有票支付登记，不创建假债务。

真实花销来自独立费用事项的金额减费用退款，不让用户在五个观察列分别录入同一笔钱。直接费用付款可在统一表单创建一条费用事项；如果费用已在账单用途登记，则选择已有费用，不再创建。借款本金、个人代付本金、归还本金、账户互转不自动成为费用；公司报销回款结清应收，不再次确认费用。

同一现金可同时反映义务资金和费用两个固定观察口径。例如真实代付 100，建立借款 100，并标记支付已登记费用 100，现金仍为 100、费用只确认一次。总表现金列只取义务贡献，费用/费用支付/费用退款行现金列为“—”，通过详情查看同一流水，不再计第二次现金。真实费用退款若同时归还借款，同一收款可分别关联费用退款和现金归还，两列各自生效，现金只一笔。

结果：已批准的事项与汇总同步更新。失败：保留输入并指出超额、并发变更、对象已删除或已关联等原因；不只改界面状态。现金路径复用统一收付/关联操作，非现金路径不改变现金流水或账户余额，详见第 9 节。

## 6. 现金流水（U-FLOWS）

目的：像普通 App 的银行明细一样查完整逐笔记录，但数据完全来自现金模块。所有未删除手工和任务流水都在这里，工资/房租等不因未进入往来总表而缺失。

### 6.1 列表和汇总

| 区域 | 建议内容 | 特别规则 |
| --- | --- | --- |
| 默认范围 | 当前月份；可切全年或明确起止日期 | 所有记录按实际业务日期，任务归属月份另列，不混淆 |
| 筛选 | 期间、现金账户、收/付/互转、来源、历史项目、人员、费用类型、关键词 | “手动录入 / 每月任务”是记录来源，不是现金账户；关联任务可作为详情或低频筛选 |
| 主列 | 日期、类型、项目、人员、费用类型、费用内容、金额、收入、支出、现金账户、来源、备注、操作 | 顺序可按已认可原型微调；长备注进详情；必要创建人/创建时间建议在详情，不从全局历史补取 |
| 互转显示 | 类型“现金账户互转”，金额为转移金额，账户为“A → B” | 全池视图的池外现金收入/支出列不把互转计两次；分账户的流入/流出与全池池外收支明确命名；借款及还款等真实池外收付不能因不是经营性业务而漏计 |
| 余额 | 分账户视图可显示该账户逐笔账序余额；全账户视图在汇总/详情分账户展示 | 不在混合账户行显示一个含义不明的“余额”；互转详情展示两端变动；金额排序不重算账序余额 |
| 操作 | 详情、编辑、删除 | 手工和任务流水均可纠错；编辑同样处理源事项、结算、月任务和余额影响，不能只改列表金额 |
| 排序 | 日期、金额；来源/账户如支持须由接口全范围排序 | 默认日期降序，稳定次序；不把当前页排序冒充全量排序 |

汇总分开呈现：

- 账户/期间余额：期初、本期流入、本期流出、期末；使用账户与时间边界，期初只承接一次。
- 全池收支：池外实际收入、池外实际支出；互转净额为零，可独立展示转移金额说明但不计为真实花销。
- 筛选合计：当前项目/人员/关键词等命中的收入、支出和条数；明确标签“筛选合计”，不把它冒称真实账户余额。

账户尚未起算的历史期间显示“尚未启用/无已知余额”，不显示未来期初或 0。期间跨起算日时标出“自起算日起的记录”，区间开始时的余额为“—”，并单独展示已知起算金额和此后的净变动。跨账户覆盖范围不同须说明，不能画一个不真实的整年余额。所有年份记录仍可逐年查询；单次范围/页大小上限是查询控制，不是删掉早期流水。负余额正常显示并提示“账面为负，请核对或补录”，不阻断保存、删除或更正，不自动生成收入补平。

### 6.2 流水详情

- 基本信息：实际日期、方向、金额、收付账户；互转显示转出与转入。
- 业务信息：项目历史名称、人员、费用类型、内容、备注；保留这笔记录当时的项目名称，不在读取时用 OA 当前名称覆盖。
- 来源：手动录入或每月任务；任务名称、归属月份；已手工录入后关联任务的仍显示“手动录入”，另显示“已关联任务”。
- 关联子表：事项名称/对象、处理类型、分配金额、相关账簿；点击打开对应现金事项，不跳普通财务页面。
- 必要录入人/时间：如确认需要，由本条现金记录显示，不提供全局操作历史链接。
- 删除放在抽屉底部次要危险操作区；点击使用第 8 节统一确认，不另造一套详情删除逻辑。

关联子表先显示总数和最多20条预览，提供分页查看全部；不是只能有20条关联。删除确认同样只展示有界影响摘要，真正删除覆盖全部实际关联。收到删除成功后重读现金局部视图，不根据摘要逐行猜删。完整字段与下钻参数见[技术设计§8.7](../dev/cash-module-technical-design.md#87-响应字段选择器和下钻闭环)。

## 7. 逐笔录入与现金账户互转（U-ENTRY）

### 7.1 普通收款/付款抽屉

抽屉标题为“记录收入”或“记录支出”，说明“记录已经发生的现金收付”。不显示导入文件、自动付款或智能推断按钮。

| 分组 | 输入字段建议 | 是否已确定 |
| --- | --- | --- |
| 实际收付 | 实际日期、金额、收款账户或付款账户 | 日期、正金额与现金账户必需；人民币两位小数；实际日期不能晚于上海今天，不早于账户起算日；账户为实物现金/纳入管理的储蓄账户 |
| 业务归属 | OA 项目、报销人/经办人员、费用类型、内容 | 一笔现金一个项目，允许不选项目，不造“其他项目”；收/付的费用类型与内容必填，人员可空且不是可信录入 actor；互转不提供分类控件且分类必须为 null |
| 往来/费用关联 | 往来对象/类别、一个或多个同项目事项及分配金额、明确新增事项或已有费用 | 以相关事项数组呈现，可多行；不支持跨项目现金分摊，不默认每笔收付都建债务，也不重复建立已有费用 |
| 补绑定真实来源 | 已独立登记但现金迟录的借款，选择已有事项而非新建 | 对应 origin_items；无来源现金、非期初且实际日期/方向/项目匹配才绑定，保留原ID/原额/日期；既有费用付款用expense_payment，不补绑成新费用 |
| 补充 | 备注 | 最多 2000 字；不预加附件 |
| 系统信息 | 手动录入来源、必要录入人 | 只读；用户不能通过表单修改可信身份或伪装任务来源 |

自由新增的项目选择显示“名称 · 编号 · 当前阶段”，同名项目靠稳定编号/标识区分；只列当前允许阶段且非已结束的项目。空/未知阶段不进入候选。下拉加载中、无匹配、无允许项目、OA 读取失败分别显示，不能把读取失败显示成“没有项目”。从既有事项办理的历史结算使用 §7.3 只读项目，不调用此候选选择器，也不将候选失败自动降级成历史模式。

提交操作：

1. 用户填写后点击“保存”；前端提示具体字段问题，后端再次校验。提交中按钮禁重复点击，表单不被重置。
2. 服务端成功后关闭抽屉，提示“流水已保存”，重读当前现金视图；其他已访问现金账表与任务不能复用提交前的数据。
3. 自由新增项目的阶段或允许范围已变化时，说明“该项目已不在可选范围，请重新选择”，保留其他字段；不得静默选第一个项目或自动改用历史结算。历史结算只核对其真实既有事项及本地版本，不受当前 OA 阶段限制。
4. 数据库/网络/权限失败按第 12 节展示。响应结果不确定时允许用同一次提交身份核实/重试，不立刻再新建一条。
5. 取消或关闭有未保存内容时，一次确认是否放弃；仅保留当前页面内存，离开/退出身份边界时清空。

金额输入不能靠展示时四舍五入通过校验；人民币两位小数已经确认，内容上限 1000 字、备注 2000 字、名称 120 字等工程校验按技术设计执行。后端拒绝超精度/非法值，UI 显示对应字段错误；null 金额显示“—”，不是“0.00”。复用现有金额展示函数，但仅传已验证的金额字符串，不改普通页面行为。

复合录入相关事项用可增减明细行表示，每行明确新增/关联/补绑定、事项类型、对象、同一项目、金额和说明；同次保存全部成功或全部不变。分配区域分别显示“义务可分配额”和“费用可归属额”，各自不超过同一现金金额，二者不能相加再当现金额度；无票冲抵可用费用另按费用口径校验，不与费用支付相加重复占额。跨项目选择给明确提示，不能复制现金绕过。真实现金超过某项可归还额时，保留真实金额和明确未分配部分，不自动超额冲减债务。

编辑最初建立借款的流水时，详情显示对应源事项与后续分配影响。无冲突的源金额/日期/项目同时校正；例如 1000 改 800、已真实还 200，后续还款不变、剩余变 600。缩为 100 而已分配 200 等事实冲突，按第 8 节的同一纠正区域明确调整关联，不能自动截额或默默转成独立债务。

### 7.2 现金账户互转

从“新增流水 ▾ → 现金账户互转”进入，不设含义不明的独立右上角主按钮。字段：实际日期、转出账户、转入账户、金额、说明；两端须为现金模块账户且不同。互转不提供分类，分类必须为 null；不创建债务/费用事项、分配或收付任务认领。

输入下方固定短说明：“只记录两个现金账户之间已发生的转移，不执行银行转账，不计入全池收入或开销。”保存成功是一笔互转事实，两端余额同时更新。失败两端均不变。删除也同时撤销两端账面影响。

信用卡还款不因发生银行转出就自动选择互转。只有两端均属于已确认现金账户范围才适用；其他偿债按实际支出和事项归还处理。

### 7.3 既有事项的历史项目结算（U-HISTORICAL-SETTLEMENT）

入口位于往来/票据/个人账的既有事项详情“登记实际收付”，或任务办理抽屉中明确选择“办理已有事项”。不是自由新增表单的任意放行开关，也不增加结束项目下拉选项。

| 交互 | 输入与显示 | 成功或失败结果 |
| --- | --- | --- |
| 进入历史结算 | 明确选择本次要结算的现金事项；读取其 ID、版本和本地项目历史名称 | 项目为只读“沿用历史事项项目（不可改选）”；无项目事项明确显示无项目，不造项目；不为显示当前阶段请求 OA |
| 填实际收付 | 实际日期、正金额、现金账户、费用类型、内容等沿用现金校验；本次结算目标均须已存在且与锚定事项同项目 | 一条真实现金及明确结算同事务保存；项目从服务端既有事项取得，不接受前端任意填写历史名称/ID |
| 多个目标 | 在同项目既有事项中选择实际结算目标，按适用义务/费用口径显示分配 | 不允许 related_items 新建、origin_items 补绑定、改项目或混项目；锚定事项必须参与真实结算，不能只借其项目资格录无关现金 |
| 事项变化/被删 | 保留草稿，说明事项已变化或不可用，要求重读/重选 | 不伪造新事项、不转无项目、不调用旧 OA 快照兜底；全次不半保存 |
| OA 结束/断线/源项目消失 | 继续显示本地历史项目和来源事项 | 历史结算仍可办理；普通自由新增有项目时仍需要 OA 当前资格，不能因此放开候选 |

该路径对应 `project_mode=existing_item`，普通自由新增对应 `selection`；它们只是项目归属输入方式，流水来源仍是手动录入或每月任务，不增第三种现金来源。任务“新记流水”可使用同一既有事项结算表单；“关联已录流水”仍不新建现金、不重复结算。切换到自由新增必须作为明确的新录入上下文重新选择项目，不能保留历史项目值悄悄提交。

## 8. 删除现金流水（U-DELETE）

### 8.1 入口和确认内容

- 入口为现金流水行“删除”和流水详情“删除”。其他账表可打开关联流水详情到达同一操作；不新增逐账本删行。
- 一次确认框标题“删除这笔现金流水？”；展示实际日期、收/付/互转、金额、账户、来源，避免删错目标。
- 展示该笔已知的任务和事项关联，说明“会同步移除所有现金账表中的这笔流水及其金额影响，并更新相关余额和任务状态”。受影响明细多时使用可展开列表，不要求用户逐项勾选。
- 固定提示“删除记账记录不会撤回实际银行付款。删除后应用内不可恢复。”删除会物理移除在线数据库的现金业务正文，不设回收站或私有操作历史；仅留防止旧请求复活的最少无业务内容身份。不能声称同时清除了既有受保护备份，也不显示恢复按钮。
- 主次操作为“取消 / 确认删除”。不要求 005 特批，不把有关联记录一律隐藏删除按钮。

### 8.2 成功、失败和一致性

| 场景 | 用户看到的结果 | 禁止行为 |
| --- | --- | --- |
| 取消 | 回到原表/详情，数据不变 | 不提前删除或改变任务状态 |
| 删除中 | 显示处理中，禁重复提交 | 不先乐观删行宣称成功 |
| 成功 | 关闭目标详情，提示成功；当前列表/汇总/条数重读；其他现金视图再次进入时重读 | 不把旧响应填回；不保留含原文的“已删除详情” |
| 唯一任务收付删除 | 实际累计归零，保留月目标并回到未处理；目标未知则提示填写 | 不删除模板和月份实例，不自动补造流水 |
| 分次任务/事项删除一笔 | 保留其他金额，仅移除目标贡献，重判剩余状态 | 不将所有已付清零，不删独立借款或其他非现金冲抵 |
| 往期流水删除 | 后续月份的期初、逐笔余额、期末也按剩余事实显示 | 不只改当前月份合计 |
| 流水被另一人改动 | 明确提示“记录已变化，请刷新后再确认” | 不悄悄覆盖最新版本、不自动换目标 |
| 已被删除 | 目标不再可读，刷新到剩余结果；重放语义与技术设计一致 | 不泄露已删正文、不重复调整金额 |
| 删除失败且确认未提交 | 提示未删除，原记录及关联保持不变，可重试 | 不用后台补偿逐表修账 |
| 网络中断、提交结果未知 | 明确“结果尚未确认”，核实同一请求结果后显示成功或失败 | 不直接声称失败、不重新生成或冲回流水 |
| 成功后重读失败 | 说明“删除已成功，列表更新失败，请刷新”；不恢复旧目标行 | 不把读取失败说成删除失败，不拿旧行当有效事实 |

### 8.3 来源事项纠错区域

普通收付/还款删除仍是一次简洁确认；只有删除或编辑最初建立借款的来源会影响义务真实性、或已有分配与新金额冲突时，在同一纠正抽屉展开相关区域，不增加审批页或“凡关联都不能删”的限制。

| 用户确认的事实 | 同一纠正界面的输入 | 一次保存结果 |
| --- | --- | --- |
| 最初借款不存在 | 明确取消错误源事项，查看后续真实现金/非现金及待调整分配 | 删除错误来源现金和仅由其建立的借款；保留真实后续收款，解除错误归还分配并显示未分配，不自动建新债务或退款 |
| 借款真实，来源流水重复/录错 | 明确选择正确来源，或明确确认该义务独立成立；金额/日期/项目按实际纠正 | 错误现金删除或修改，真实义务保持明确来源；后续真实事实保留，不后台猜“保留债务” |
| 源金额减少后低于已结算额 | 列出受影响分配，用户明确更正/撤销错误分配或选择真实的新目标 | 只调整错误关联，真实现金仍保留，未分配金额如实显示；未解决的事实冲突不伪装成功 |
| 有后续真实非现金处理 | 区分错误债务关联与独立真实使用/冲抵事实，明确正确去向 | 不误删真实票据提供/使用或其他独立记录，不伪造债务承接，不自动截额 |

界面同时显示“保留的实际现金”“移除或更正的分配”“保留/移除/改源的事项”，结果必须与服务端同一事务一致。操作失败保留输入且所有事实不变；负余额只是核对警示，不是新的阻断条件。

父事项误录需删除而仍有真实子事项时，在同一纠正抽屉明确解除/改正子事项的父引用；真实费用、票据来源、公司应收或其他独立事项保持存在。不能为删除父项一并删真实子项，也不额外创建纠错页面。

## 9. 事项、非现金处理与已有流水关联（U-SETTLEMENT）

### 9.1 事项详情内的共用操作

| 动作 | 输入 | 成功与联动 | 失败/范围限制 |
| --- | --- | --- | --- |
| 新建需要跟踪的事项 | 事项类型、对象、日期、项目、原始金额、内容，明确独立义务或现金来源 | 出现在适用往来/票据/个人账；只有同时发生收付才走统一流水操作；费用也作为独立费用事实一次记录 | 不给每笔支出自动生成债务，不从有票自动推导公司应收 |
| 关联已录现金 | 选择现金池内有效流水、目标事项、分配金额 | 保留原流水，新增明确关联，不产生第二条现金；相关事项/报表更新 | 错方向、超额、被占用或并发删除提示原因；不从普通银行明细选择 |
| 登记实际收付 | 统一收付表单及必要分配 | 一次保存现金及关联，关联失败不得只留现金半笔结果 | 不在账表内另做金额保存链路 |
| 登记非现金冲抵 | 目标义务事项、有票/无票或其他明确冲抵类型、实际日期、金额、来源/说明 | 处理明细与目标未结额更新，现金流水/现金余额不变；票抵不再累计到无票冲账 | 超来源可用额、超目标未结额、对象/项目不符则明确拒绝，不自动截额 |
| 修改/撤销错误关联 | 目标关联及最新版本，必要更正输入 | 只更正/撤销错误分配，实际现金保留；来源/目标余额与相关账表同时更新 | 不将“解除关联”和“删除流水”混名，不误删独立真实票据使用/其他事实 |

事项可编辑，错误非现金分配可更正/撤销；详情显示受影响来源和目标，用户一次明确保存，不建设批量删除或审计平台。票据“已使用但未抵债”改为抵债时，在原使用记录中补目标并改用途，不追加另一条同额使用；移除错误抵债但票仍真实使用时保留使用占用，只解除债务结算。

### 9.2 已录流水选择器

用现有抽屉内的选择区域或单个选择对话框，避免抽屉套抽屉套抽屉。显示日期、方向、账户、金额、来源、当前操作对应的已归属/可归属额度、内容；支持日期/账户/关键词与分页。义务操作显示“义务可分配额”，费用支付/退款显示“费用可归属额”，不能用跨口径相加的余额。

只展示现金池内未删除事实。一笔现金可分给多个同项目事项，但最多关联一个月任务；不支持跨项目现金分摊。无资格候选显示具体原因，不暴露普通财务池数据。用户明确点选，不用同日同额自动匹配。确认前重新验证最新事实，候选读取后被删除/修改时明确提示重选。任务认领已有现金只增加任务关系，已有结算不重复创建。

候选接口按操作类型返回相应额度、当前版本与明确不可选原因，计算含已绑定原事项份额，不能只用当前页结算相减。义务与费用是同一流水的两个固定观察口径，不相加成双倍现金；任务认领另有目标上下文，能给多个事项分配不代表能完成多个任务。票据来源显示来源可用额，债务目标显示目标未结额。关联后的流水/事项版本一起更新，旧表单须刷新，不能仅凭处理记录版本提交。

## 10. 有票支付与刘树刚账

### 10.1 有票支付（U-TICKETS）

目的：追踪票从谁来、如何使用、给谁抵账、是否等待真实回款。它不是现有 App 发票池的另一个入口。

| 区域 | 表格/控制建议 |
| --- | --- |
| 筛选 | 年份/期间、提供人、抵账对象、历史项目、处理状态、关键词 |
| 主表列 | 提供日期、票据/用途说明、提供人、提供金额、已使用金额、来源可用金额、使用概况、抵账对象概况、已抵金额、回款情况/实际回款金额、备注、详情 |
| 汇总 | 提供金额、使用金额、票抵金额、实际回款分列；待回款只来自明确公司应收，不合并成万能“余额”，不照搬 Excel C19 的局部合计 |
| 排序/分页 | 仅提供日期、提供金额、来源可用额可排序；处理状态仅筛选，不提供任意状态/使用日期排序；统一分页 |
| 详情主区 | 原事项、提供人、票据用途、金额、相关项目、当前事实状态 |
| 使用/冲抵子表 | 每次使用日期、使用/冲抵类型、对象、金额、说明；明确是否产生债务变化；多次使用和多个对象均可分页展开 |
| 实际回款子表 | 日期、金额、现金账户、流水来源及详情入口；已删流水不出现 |

主表一行对应票据来源，可有多次使用、多个抵账对象和不同处理进度；使用概况/对象概况显示数量与简短摘要，完整日期/对象在详情子表，不把一行伪装成单一使用日期或单一处理状态。

行/详情操作采用四个明确业务动作及纠错，不做通用状态引擎：

1. 提供：填来源、提供人、金额；现金及欠款不变。
2. 使用：选择来源、日期、用途、金额，可分次/多目标，总额不超过来源可用额；允许没有债务目标，不创建债务填空。
3. 用于抵债：必须明确来源、目标义务、分配金额；属于一次票据使用，同时占用来源并减少目标未结。已有使用改为抵债时编辑同一记录补目标，不再生成同额使用。
4. 公司实际回款：必须有明确公司应收，选择/建立真实应收后统一记录现金或关联已录回款；有票本身不自动生成公司应收。

“票已给，等待回款”有明确说明位置，但不等于已到账。每项成功只更新对应事实，失败保留输入且事实不变；编辑/撤销错误使用或结算按第 9 节办理。独立票据提供/使用不因某笔现金回款删除而全部消失。有票先抵个人欠款 100、公司后来实际回款 100，只结公司应收，不能再把个人欠款减 100。

### 10.2 刘树刚账（U-PERSONAL）

共用筛选为年份、相关银行/卡或账单、历史项目、关键词；具体哪些子表适用项目筛选按已有字段确定。四视图共享同一业务数据，不各保存一份流水。

| 视图 | 列和汇总 | 操作与注意事项 |
| --- | --- | --- |
| 年度还款矩阵 | 表内标题“实际代付/新增借款”；银行/账单别名、1–12 月新增本金、提前还信息、全年合计，另列起算未结和当前未结 | 按实际发生月展示且仅计个人承担本金；点击月份看账单/本金来源，不混入公司 ETC 等公司用途 |
| 现金归还 | 实际日期、项目、对象、账户、金额、归属账单/事项、来源、备注、详情 | 查看/关联已有现金或登记真实收付；不重复记账；删除到统一现金详情操作 |
| 有票直接冲 | 日期、票据提供/用途、项目、归属事项、冲抵金额、说明、详情 | 登记非现金冲抵，不生成现金；错误分配可更正/撤销，真实票据使用保留 |
| 无票报销冲抵 | 日期、费用内容、项目、归属事项、冲抵金额、备注、详情 | 与有票和现金分开；不为了三表统一而制造现金 flow |

矩阵宽表允许横向滚动，左侧银行/账单标识固定；月份本身顺序固定，不提供把 12 月排到 1 月前的排序。明细表支持日期、金额排序及统一分页。矩阵如银行/账单超出可视行数可分页，但月份列始终完整；不要全浏览器聚合所有记录。

月度单元格详情包含实际发生日期、账单月份、卡片别名、个人承担本金、公司/个人用途明细、相关现金或非现金记录。11 月实际代付 12 月账单时，现金与新增本金计入 11 月，详情账单月份为 12 月并标“提前还”，12 月和全年合计不重复加同额。提前还是说明/筛选属性，不另加一列可再次求和的金额。

未还金额 = 起算未结 + 起算后个人新增本金 − 现金归还 − 有票冲抵 − 无票冲抵，均按对应实际日期和分配额统计。个人账有独立起算日期，未配置时显示“个人账起算未配置”，完整期初/未结不伪装为 0；起算前月份未知，覆盖后无记录月份才为 0，起算当月只显示已知范围。不能用最早借款日期猜历史完整。起算已含旧欠款不再计为新增本金，不读取普通 App 成本或 ETC 数据。

两张建行卡与用途明细在账单详情呈现，不公开原始卡号。最小现金本地账单别名字典只含银行、别名、启停和稳定标识，在账单录入选择器旁提供管理入口，不增加一级 Tab 或信用卡产品。矩阵按该标识归组，同期多账单汇总到实际月份并可下钻，不能按银行名或姓名合并。

用途明细显示费用/个人本金等明确性质、项目、金额、说明；单次复合现金只有一个可空项目，可关联同项目多个事项。不支持一笔现金跨项目分摊，不用 UI 复制真实流水绕过。一笔账单包含多个用途时，各用途的费用与个人本金分别记一次，同一费用已存在则关联，不再建立新费用事实。

尚未实际代付的个人账单只作为月任务计划目标，不提前建已发生个人债务。真实借款已成立但现金迟录时，通过origin_items补绑定原事项；真实费用已发生则先登记费用，后续现金用expense_payment关联，不重建费用。来源标识区分随现金新建与补绑定的既有借款，删除后者现金仅解除来源、不自动删除真实借款。

| 查看处理明细 | 月任务 | 展示所有有效关联现金、归属事项及说明 | 记录已删时不显示旧金额；分次状态由剩余实际金额决定 |
| 解除误认领的手工流水 | 已关联 manual 来源流水、目标任务/月及最新版本 | 仅解除任务关系，现金和已有事项分配保留，来源仍手工，任务按剩余累计重判 | monthly_task 来源不能直接解除成无来源流水；错任务归属通过删除错误记录并明确重录真实业务纠正 |

确认抽屉将“新记一笔”与“关联已录流水”做清晰选择，不先生成再查重。统一允许分次，不另设单次/分次模式。实际累计为 0 显示未处理，低于目标为部分办理，达到目标为已完成；部分办理行仅提供继续办理剩余和查看明细，不提供“未还”覆盖按钮。超出目标同时显示“超出计划”和差额，不截断真实现金、不自动增大计划。多出来的金额不能自动超额结算债务，应明确保留未分配部分。

模板默认目标只用于显式预填；当月目标、实际本次金额、实际累计分开。未知目标在首次确认的同一表单补齐，不拿 0 或上月数额默认；核对任务不要求金额。一笔现金最多关联一个月任务，已手工记录关联后保持原来源且不重复结算。月处理明细分页显示全部，累计取完整有效事实而非首 50 条。删一笔按剩余累计重判；首次确认结果未知时用同一提交身份核实/重试。

跨月未完成保留在逾期待办，按原归属月、原目标和日期继续办理，只从模板生效月起，不追造启用前历史。过去已形成的办理/待办保留原值；读取列表不造现金，不用今天模板重写过去。UI 对应既有月实例和必要快照，不新增通知平台。

提醒仅在现金页内：显示提醒日期和到期/逾期文字，进入、重新聚焦或跨业务日期时更新，不反复弹窗；未收/未付/未还仍保留待办。关闭现金页不发系统、邮件或 OA 通知，其他页面/全局侧栏不显示任务内容或金额。

每月 1 日提前两天的任务在上月出现提醒，但归属月份仍是下月。不存在的 29/30/31 日使用当月最后一天，界面明确显示该月实际计划日期；当月调整允许跨到归属月边界前后各 31 天，归属月份保持不变。提前提醒天数为 0–31，提醒日由调整后的具体日期减该天数计算；超界不自动钳值。这是已批准规则，不是静默兜底，也不改银行还款约定；不自动顺延节假日。

### 11.3 任务配置（U-TASK-CONFIG）

表列：任务名称、收入/支出/核对类别、每月执行日、提前提醒天数、生效月份、结束月份（若配置）、启用状态、默认账户/金额说明（若已设置）、操作。支持类别/启用状态/关键词筛选，按名称/执行日排序；任务多时分页。

“新增 / 编辑任务”抽屉：内容、类别、每月执行日 1–31、提前提醒天数 0–31、生效范围、启停、可选默认月目标/账户和办理说明。默认月目标只是显式预填，实际办理仍确认目标与本次金额，不自动付款或静默生成流水。

保存前明确“普通模板修改从下月或用户选择的更晚月份生效；本月请使用调整本月”。停用从下月起，本月及过去已形成的待办/办理保留原值，不删除处理记录或流水；初版不提供模板硬删，使用启停与生效范围。不因月末未办理而丢弃逾期任务。

保存成功刷新任务配置和受影响的现金月待办；失败保留输入、显示具体原因。模板修改、启停不写全局历史、不创建普通后台 job。

### 11.4 现金账户与期初（U-SET-ACCOUNTS）

表列：账户名称、类型（现金/储蓄）、启用/起算日期、确认期初金额、状态、说明、操作；当前余额若展示单独命名，不能覆盖期初。支持名称/状态筛选；小字典按名称排列，有界加载，增长时使用现有分页。

账户、费用类型和任务配置的接口从初版即提供分页；少量记录时可以不显示多页按钮，不先实现无界返回再等数据多了更换接口。

操作与结果：

- 新增账户：类型 kind 必选现金/储蓄，再填写名称、起算日期、期初金额、说明；不提供信用卡类型。保存后仅供现金录入选择，不读取普通银行账户余额。
- 编辑名称/说明：按最新版本保存，历史记录继续关联同一账户 ID，显示当前字典名称；不能改账户 ID 使历史悬空。
- 停用/启用：停用后不作为新录入账户候选，已有流水和历史余额保留。若有关联任务默认账户，任务办理显示需要重新选择，不能偷偷换账户。
- 期初更正：允许更正起算日期和金额，一次确认说明影响全部后续余额；新起算日不得晚于已有有效流水而排除旧记录，更早补录先更正起算日和期初；不增加多期初覆盖值兜底。
- 账户删除：本版不提供账户硬删，误建账户可停用；不能把现金流水删除能力扩大成删除账户及其历史。

失败时字典不假保存，保留草稿；没有启用账户时在录入内说明“请先配置现金账户”，不自动创建“默认现金账户”。

同一设置子视图内增加小分组“个人账起算”，不是新Tab：先声明个人账起算日期，再手工登记该日未结事项；无旧欠款不造0金额事项，不要求先录完才能保存日期。coverage只表示声明的记账范围，不证明资料已录齐。个人起算与现金账户余额分开；未设/起算前未知，覆盖后无已录贡献为0。更正日期不能排除已有本金/结算；期初事项日期同事务同步，金额不自动改。仅个人业务需要时引导，不阻挡无关现金录入。

同一“登记期初未结”表单覆盖公司/外部/个人的真实旧义务。仅 `is_opening=true` 的 loan / company_receivable 非现金登记，可从 OA 全部项目资料（all）识别真实历史项目，包括已结束，不按新增现金的允许阶段过滤。表单显示“登记起算前未结，不产生现金流水”，保存真实 OA ID/名称历史资料及期初义务；不生成 flow，不开放普通流水的结束项目选择，也不能用于新费用/非期初事项。保存后从该事项办理 R7 真实结算，沿用已保存本地项目，无需再读 OA。

首次现金模块为空时，使用这条期初登记路径建立结束项目旧欠款，再从事项登记实际归还，不能要求先存在现金流水。如果 OA 项目已消失且现金本地没有其快照，显示“缺少可核实的历史项目资料”，保留表单并停止该项目登记；不造项目、不相似名称匹配，也不悄悄改为无项目。OA 读取故障和确实无资料分别提示；这是已有期初功能的闭环，不增加新 Tab、导入平台或审批。

### 11.5 费用类型（U-SET-CATEGORIES）

表列：名称、适用收入/支出/往来范围、启用状态、说明、操作；范围采用技术设计的明确 group 字段，按名称/范围/状态筛选，名称排序，数量增长使用分页。

操作为新增、编辑、启停。分类显示当前字典名；已有引用时改业务含义应新建分类，不能把历史收入改成支出或把非现金改成现金，历史引用不级联删除。无可用分类时，收/付款提示先配置；互转不提供分类且必须为 null，不暗补“其他”，不复用普通账自动分类规则。

### 11.6 OA 项目与可选阶段（U-SET-PROJECTS）

同一设置视图分成两块紧凑区域，不拆成两个全局页面：

1. **新增流水允许阶段**：从 OA 真实阶段字典呈现复选项，显示目前保存版本；已结束项只读不可选，并说明原因；首次必须明确保存允许范围，新阶段不自动允许。用户在这里编辑的是本地选择规则，不是 OA 项目状态。
2. **OA 项目列表**：编号、名称、真实阶段、能否用于新录入、不可选原因；显示“本次读取时间”、总数与分页。筛选为项目关键词、真实阶段、可选/不可选，列表包含已结束以及空/未知阶段项目。

已只读看到的十个阶段名称是投标前、招投标阶段、合同签订阶段、采购阶段、实施阶段、结算阶段、试运行、质保期、未中标、已结束。它们是当时 OA 事实，不是硬编码菜单；原始字段、编码和完整分页仍需开发者核验。未中标等可配置阶段由用户在设置中勾选，不能等同已结束或自动放行。

| 操作 | 结果 | 失败反馈 |
| --- | --- | --- |
| 打开/刷新 OA 项目 | 按当前 OA 资料显示项目/阶段与本次读取时间；不写 OA | 超时/无权限/源异常分别提示；不是空列表成功；可重试 |
| 搜索/筛选/分页 | 显示对应结果与准确总数；阶段选项不因当前页无该阶段就消失 | 无匹配与源失败区分，不能把第一页说成全部 |
| 保存允许阶段 | 只保存现金配置；后续新增候选按新范围 | 配置并发冲突需重新读取后确认；OA 字典异常不猜代码 |
| 查看不可选原因 | 如已结束、阶段未允许、阶段未知 | 不提供修改项目阶段、手工覆盖阶段或写回按钮 |

项目历史报表不依赖此列表在线。项目结束、从 OA 消失或 OA 临时不可用时，历史现金照常查看、筛选和删除，既有事项仍可按 §7.3 只读继承本地项目办理真实结算。自由新增/改选项目仍需当前资格复核；R7 不让设置中的已结束项目变成可选，不提供编辑 OA 名称、项目删除或状态维护入口。

首次阶段状态按独立 project_selection_configured 布尔值判断，不按允许数组为空或 settings.version > 1 判断；修改个人起算不会误标阶段已配置。用户明确保存零个允许阶段后显示“当前不允许任何项目”，不再提示尚未设置。OA 缺编号/阶段显示“—/阶段缺失”与不可选原因，不虚构值；来源故障显示独立错误。复合录入新选项目的事项与主流水同样校验，不能让子表绕过资格限制。

### 11.7 支付办理说明（U-SET-GUIDE）

以紧凑对照表展示类别、概要、现行办理方式、拟调整方式、申请人、渠道、所需单据、收款方说明；可按类别筛选或搜索文字。该表行数有限，可自然滚动，不为了格式统一硬造服务端分页。

点击某行可展开完整说明，特别是卡片别名、分账用途、储蓄卡去向和日期浮动。明确标注“参考说明，不会提交 OA 或执行付款”。现行/拟调整方案是否已正式采用待确认，不让 Make 标成系统强制规则。

初版只读说明，由项目文档维护，不预建编辑器、发布审批和 CMS；办理方式是否采用不改变现金自动记账规则，也不授予 OA 写回权限。

## 12. 全局交互状态与隐私边界（U-STATES）

| 状态 | 必须显示 | 可操作项与禁止事项 |
| --- | --- | --- |
| 首次加载 | 现有表格加载样式和“加载中” | 不先展示虚假余额/示例行，不让用户操作尚未加载对象 |
| 初始无数据 | “暂无现金流水/暂无事项”等对应文案 | 有权者可新增；不是报错；现金尚未配置账户时给明确设置入口 |
| 账户未配置或全停用 | 说明本次录入没有可用现金账户 | 引导“现金账户与期初”，返回后可继续表单；不自动造默认账户，不强制配齐所有任务 |
| 费用类型未配置 | 明确区分尚未配置与列表读取失败 | 收/付款要求配置后选择，互转无分类且为 null；不暗补“其他”或阻止不需要该分类的操作 |
| 项目允许阶段尚未保存 | 提示尚未设置新增项目可选范围 | 有项目录入引导设置；无项目录入允许继续，不默认允许全部阶段，不阻断历史账查询 |
| 筛选无结果 | “没有符合当前条件的记录” | 重置/修改筛选；不把实际有记录的账户余额改成零 |
| 读取失败 | 当前区域失败原因和重试 | 不回退普通池、旧项目快照或静态假数据 |
| 提交中 | 目标操作进行中 | 禁双击，不关闭成功提示；不锁住所有无关 App 页面 |
| 字段错误 | 字段具体原因，金额精度/日期/必填按已定规则 | 保留输入，聚焦首个错误，不用宽泛“操作失败”替代 |
| 版本冲突 | 记录或配置已变更，需要重读 | 保留可安全保留的草稿；不覆盖别人修改，不自动按最新版本提交 |
| 关联失效 | 已选流水/事项被删除或不可用 | 保留其他输入，重选/取消；不创建替代流水 |
| 账面负余额 | 实际负金额和“请核对或补录”的警示 | 不阻断收付、编辑或删除，不造收入补平，不加审批 |
| 月任务目标未知 | “待填写本月金额”，实际金额与目标分开 | 首次确认同一表单填写；不拿上月或 0 替代，核对任务不受此限制 |
| 月任务超出计划 | 已完成状态、完整实际累计与超计划差额 | 不截断现金、不改月目标、不自动超额分配债务 |
| 个人账起算未配置 | “请先设置个人账起算日期，再登记起算未结”，未知汇总为“—” | 先保存日期后录期初，不要求资料录齐作为前置条件；不猜 0、不添新 Tab、不阻断无关现金记录 |
| 历史事项结算、OA 不可用 | 项目显示本地历史名称和“沿用历史事项项目（不可改选）” | 继续办理既有同项目事项；禁止夹新事项/来源补绑定/改项目，不显示候选接口错误作为此表单阻断 |
| 无现金页面权限 | 侧栏不展示；直达显示无权限 | 不先拉取现金正文；不因拥有普通页面权限而放行 |
| 会话失效/撤权/换账号 | 关闭现金抽屉并清除现金内容，沿用现有登录/无权反馈 | 延迟请求不得重新填回；不保留敏感草稿到全局缓存或浏览器磁盘 |
| 保存成功，当前列表刷新失败 | 区分“已保存”与“展示更新失败” | 只重试读取，不重复新增；删除成功同理 |

没有页面缓存/read model 的产品状态，不显示“投影刷新中”“后台重建中”“已提交全局任务”等假状态。普通的读取中不伪装刷新队列。所有提示仅在现金页面内，错误信息不得回显完整 SQL、凭据、请求体或已删除业务原文。

首次使用只引导补齐本次操作实际需要的设置，不设计“必须完成全部账户、费用、12 项任务、所有说明才能录第一笔”的强制向导。配置缺失、数据为空、加载失败是三个不同状态，不能合并成一个“初始化未完成”总门禁。

旧响应隔离：查询条件切换、Tab 切换、提交成功、删除、撤权、退出登录后，先前在途响应不得覆盖更新的页面状态；取消请求或按当前请求身份忽略旧结果。成功删除后再收到删除前的列表时必须忽略，不产生“删完又回来”的视觉假象。此规则是局部页面正确性，不需要全局事件总线、跨页广播或常驻缓存。

离开现金页面不继续请求任务、账簿和 OA 项目，不给其他页面侧栏 badge、全局通知或全局搜索传现金摘要。同一个 App 复用基础组件不意味着共享财务数据。

> 一级导航为“账簿报表 / 每月任务 / 基础设置”。账簿区第二层为“往来账总表 / 现金流水 / 有票支付 / 个人专账（示例姓名）”，首次默认往来账总表。任务区有“本月处理 / 任务配置”，设置区有“现金账户与期初 / 费用类型 / OA 项目与可选阶段 / 支付办理说明”。年份/月度是筛选，不是新 Tab。个人账四个表格视图用小型选择器。为未来账簿保留同级扩展空间，不放可点击的假功能。
>
> 往来总表只列公司、外部人员及个人专账往来，每次业务处理一行；普通无往来工资/房租等留在完整现金流水。整行颜色为外部蓝色、公司淡黄色、个人新增借款/代付橘黄色、个人归还/冲抵绿色，人物用虚构姓名；颜色不表示完成状态。同一来源事项及首次现金不重复显示本金。同项目多事项分配按各份额展示，现金仍一条。
>
> 现金流水独立展示全部未删除手工/任务流水及来源、日期、金额、账户、项目和关联详情，可逐笔新增、编辑、删除，没有 Excel 导入。使用实物现金和纳入管理的储蓄账户，信用卡是账单，不把额度当现金。互转只记录两受管理账户之间的真实转移，不增加池外现金收支。人民币两位小数、无千分位；余额与筛选合计分开，起算前显示未知，负余额警示但不阻断。允许更正期初并说明后续影响，真实退款另录实际收付。
>
> 单笔删除有确认、取消、成功、失败、版本变化和结果未知状态。线上业务正文物理删除，应用内不可恢复、不设回收站；不能声称清除既有备份。成功后所有现金账表、子表、余额、任务同步反映剩余事实。源借款根本不存在时移除错误源现金/源事项，保留真实后续现金并解除错误分配；义务真实但来源错误时明确换正确来源或确认独立义务，不能自动保留假债务。有金额冲突才在同一纠正区域明确调整分配，不凡有关联都禁删。
>
> 保留冲账、还款、报账提现、真实花销、票抵等观察列，但不让用户五次录同一金额。冲账是不含票抵的明确非现金冲抵；还款是已有现金归还，报账提现是公司真实到账；真实花销来自唯一费用事实减费用退款，不把借款本金/还本金/互转当费用。提供票不改现金或欠款；票使用可无债务目标，票抵必有明确目标，同次使用改为抵债只能编辑该记录，不能再占一次票额。公司回款只结明确公司应收，不再冲个人欠款。
>
> 同一代付 100 可建立借款 100 并支付已登记费用 100，现金仍 100、费用只一次。义务可分配额和费用可归属额是两个固定观察口径，不能相加；同一退款兼还款亦只一笔现金。往来表现金列仅计义务贡献，费用事件现金列留空、详情跳同一流水。仅真实既有借款迟录现金使用来源补绑定；已有费用用支付关联，不另建费用或补绑成新费用。尚未实际代付账单只是任务计划。父项纠错可在同抽屉解除真实子事项引用，不连带误删真实子项。
>
> 个人矩阵表内标题为“实际代付/新增借款”，按实际发生月份列个人承担本金；账单月份单独显示。11 月代付 12 月账单计 11 月并标提前还，12 月不重计。卡片用稳定虚构别名区分，简单别名管理放在账单选择器旁，无新信用卡页面。复合录入可用相关事项数组表示费用/本金/结算，同一费用已有则关联；一笔现金一个可空项目，允许同项目多个事项，不支持跨项目现金分摊。
>
> 个人账独立起算在现有账户与期初小分组：先声明日期，再录该日未结，不要求先录完才能保存，不加Tab。起算范围不证明资料已齐；未设置/起算前显示未知，不按最早借款猜0。已有真实借款可补绑定迟录现金，既有费用用支付关联不重建。OA阶段是否配置用独立状态；已有实际办理的月任务不能清空目标，可更正为正数。
>
> 首次没有任何现金记录但示例结束项目有旧欠款时，在现有期初表单登记真实起算未结。只有期初借款/公司应收的非现金登记可从 OA 全部项目识别已结束项目，不套新增现金候选限制、不产生现金；随后从已建事项办理真实归还并沿用本地项目。项目已从 OA 消失且本地无快照时显示资料缺失，不虚构项目或悄悄挂无项目。全部用虚构资料演示，不新增 Tab 或审批。
>
> 本月处理有六收入、六支出和其他核对跟进，不把工资全部改支出。顶部仅状态数量及收入/支出实际，目标和剩余逐行显示。任务按月目标和有效实际判断未处理/部分办理/已完成，统一分次、超计划显示差额而不截现金；未知目标首次同表单填写，核对无金额。确认选择“新记一笔 / 关联已录流水”，一笔现金最多一个月任务，原来源不变且不重复结算；手工流水误认领可解除，任务来源不能解绑成无来源。未收/未付/未还只在实际为零时可用；部分办理行只继续办理剩余/查看明细。删后重判，跨月未办保留原归属月。模板普通修改下月或更晚生效，停用从下月起、本月保留；本月日期可在归属月边界前后各 31 天调整但月份不变。提前提醒 0–31 天，页内进入/聚焦/跨日更新，不外发、不反复弹窗；短月使用末日并显示具体日期。
>
> OA 设置只读显示全部项目及其真实阶段，含已结束；本地只管理自由新增候选，已结束不进入下拉，未知阶段不自动放行。绝不出现修改项目阶段或回写 OA 按钮。既有事项真实结算改用其本地历史项目，显示“沿用历史事项项目（不可改选）”，项目结束、源删除或 OA 断线仍可办理；仅可同项目已有事项，不夹新事项、来源补绑定、改项目或混项目。不能把自由新增的候选失败自动切换成历史结算，不用假选项兜底。
>
> 增加一个虚构演示：示例历史项目已结束，从其既有借款详情登记实际归还，项目只读；即使模拟 OA 不可用，现金与归还仍一次保存，原借款余额同步更新。随后从自由新增打开项目下拉，仍找不到该结束项目；试图夹带新事项、改项目或选另一项目的事项应给明确错误。任务办理既有事项同样遵守此路径，原手动/任务来源不变。
>
> 为每个主表设计加载、空结果、错误、筛选/排序/分页、详情；为表单设计提交中、校验错误、冲突和未保存关闭。覆盖桌面、笔记本、窄屏和键盘焦点。只引导本次录入必要配置，不要求配齐所有任务。仅用虚构数据在浏览器内存演示，只复制本脱敏说明，不上传真实 Excel、整份本地业务文档、银行卡号或生产截图，不接任何真实服务、不公开发布。R1–R7 均用于演示；原型演示不是应用代码实施或上线。

批准实现后，页面和局部组件按业务自然拆分，不要求每个编号单独建文件。共享依赖只用现有 UI/认证请求基础；现金 API client 是现金数据入口，不能直接引用普通银行/发票/项目财务 client。组件/页面状态不进入全局业务 store。
