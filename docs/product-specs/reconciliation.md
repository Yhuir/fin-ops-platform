# 银企核销与台账

## 目标

系统以银企核销为财务运营平台的第一阶段闭环：把发票、银行流水、OA 单据、线下记录、内部抵扣和后续台账串成可追溯的处理链。

## 核心对象

- 客商：匹配规则和台账追踪的中心主数据。
- 发票：区分销项和进项，保留原始金额、已核销金额、未核销金额。
- 银行流水：区分收入和支出，保留账号、日期、摘要、对方户名和未核销金额。
- 核销单：每次自动或人工核销形成独立单据。
- 核销明细：表达一对一、多对一、一对多、线下补录、内部抵扣等关系。
- 后续台账：把未闭环事项转成催款、催票、退款、预收、预付、待付款、外部往来等可跟踪事项。
- 审计日志：记录所有人工动作和高风险系统动作。

详细字段见 `../architecture/data-model.md`。

## 销项场景

- 正常：销项发票与收入流水金额、客商、时间范围匹配后核销。
- 少付款：支持差额原因，例如手续费、抹零、税差、汇率差等。
- 多票一付：多张销项发票可匹配一笔收入流水。
- 无票收款：进入预收、待开票或非税收入等结构化台账。
- 溢收款：核销已开票部分，剩余金额形成预收/退款/后续处理项。

## 进项场景

- 正常：进项发票与支出流水匹配。
- 多付款/缺票：超出发票金额部分进入预付、催票或异常处理。
- 少付款/组合支付：支持部分付款和多笔流水合并。
- 一付多票：一笔付款可关联多张进项发票。

## 台账与提醒

台账不是备注系统，而是未闭环事项的事实模型。台账至少需要支持：

- 来源对象和来源金额。
- 客商和项目。
- 待处理金额。
- 预计处理日期和负责人。
- 状态、备注、最新跟进。
- 到期和逾期提醒。

## 验收标准

- 所有核销动作都有核销单和核销明细。
- 未闭环差额不丢失，必须进入异常处理或台账。
- 人工动作全部落审计。
- 撤回后业务对象金额、状态、read model 和搜索缓存一致。
