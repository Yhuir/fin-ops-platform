# 银行明细自动标签规则 Excel 表格与平级优先级设计

## 背景

银行明细页 `自动标签规则` 已经规划为右侧加宽抽屉和表格化维护。本次是在该方向上的产品级补充：规则表格需要更接近 `银行流水标签ui2.numbers` / xlsx 的视觉和编辑心智，而不是普通后台表格。用户明确不接受救急方案，要求生产级整合实现。

本设计只覆盖 `自动标签规则` 抽屉和普通文本规则优先级语义的增量调整。候选确认、文件规则替换、read model 一致性和确认事实源仍沿用 `docs/superpowers/specs/2026-05-29-bank-auto-tag-rules-table-redesign.md` 的主体设计。

## 覆盖关系

本文件是 `docs/superpowers/specs/2026-05-29-bank-auto-tag-rules-table-redesign.md` 的增量覆盖文件。两份设计冲突时，本文件优先：

- 覆盖主设计中“条件词条超过阈值显示预览和 `共 N 项`”的口径。最终实现必须完整展示所有词条，不折叠、不省略。
- 覆盖主设计中普通规则优先级递增展示的口径。最终实现为内部往来优先级 `1`，xlsx 普通规则默认全部优先级 `2`。
- 覆盖主设计中上移/下移排序的口径。最终实现取消上移/下移，以可编辑优先级和稳定顺序自动归位。
- 保留主设计的文件规则替换、候选确认、人工确认事实源、read model、权限、审计和 dirty 刷新要求。

## 已确认需求

- 在 `main` 工作。
- 抽屉 UI 要改成 xlsx 样式。
- 同一主标签包含多个子标签时，主标签单元格要纵向合并，占满对应子标签所有行的高度。
- 合并主标签不是纯视觉效果；编辑合并主标签时，必须同步修改该组所有子标签规则的 `output_primary_label`。
- `选择查询的项` 多选框内要包含 `全选` / `清空` 控制，不能放在多选框外另占表格高度。
- 多选框选项样式参考截图：checkbox 列表，已选项有明显选中背景，顶部或底部固定操作区均可，但必须在下拉框内部。
- `全选` 表示选中所有可见语义字段，不保存隐藏的 legacy `all_text`。`清空` 表示清空可见语义字段；后端仍需校验保存时至少选择一个匹配字段。
- 规则词条如果多行必须全部显示，不能省略、不能用 `...` 折叠；包含、必须同时包含、精准命中、不包含字样都要完整换行展示。
- 不同主标签 row group 使用不同颜色区分；颜色必须明显、专业、可读，不使用过淡到难以辨认的颜色。
- 不做手机端专门体验。桌面宽屏表格编辑是验收重点；窄屏只需不崩溃、不遮挡核心操作。
- 取消上移/下移按钮。
- 改为可编辑优先级。保存后系统按优先级自动排序，把规则移动到合适位置。
- `内部往来款` 固定优先级 `1`，系统只读，永远第一行。
- 根据 xlsx，普通规则默认全部优先级 `2`，不是递增的 `2/3/4/5/...`。
- 平级的意思是：相同优先级的普通规则都要尝试命中；如果同优先级命中多个标签，才交给用户手动确认。
- 主标签合并只在同一优先级层级内发生。如果同一个主标签下的子标签被用户改成不同优先级，UI 应按优先级拆成两个主标签组，不能跨优先级合并。
- 优先级执行采用低数字优先：
  - 优先级 `1` 命中内部往来后停止；
  - 从普通规则的最低数字优先级开始；
  - 某个优先级层级一旦有命中，就停止检查更低优先级层级；
  - 该层级命中 1 个规则时自动命中；
  - 该层级命中多个规则时进入 `needs_confirmation`，候选只包含该层级命中的标签。
- 新增规则默认在当前表格底部增加空行，主标签/子标签为空，优先级默认 `2`；保存成功后自动归位。

## 不做

- 不恢复旧的任意人工分类下拉。
- 不使用上移/下移作为优先级控制。
- 不把普通规则默认优先级保存成行号。
- 不用 CSS 隐藏重复文本伪装合并主标签。应使用真实 `rowSpan` 或等价语义结构。
- 不省略多行词条，不用 chip 数量摘要代替完整词条。
- 不为手机端设计第二套卡片/折叠交互。
- 不引入 DataGrid 取代当前 MUI Table 技术路线。
- 不新增第三方拖拽或表格库，除非现有代码已经依赖且确有必要。
- 不把 `全选` 保存为 legacy `all_text`。`all_text` 只作为历史数据兼容字段读取，不作为新 UI 的可见选项或保存结果。

## 推荐方案

采用真实分组表格：

- 后端继续返回规则列表；前端在抽屉内按 `priority -> output_primary_label -> stable_order` 分组。
- 每个主标签组渲染为一组 `<TableRow>`。
- 组内第一行渲染主标签 `<TableCell rowSpan={group.rows.length}>`，后续子标签行不再重复渲染主标签单元格。
- 主标签单元格内放一个可编辑输入。修改时更新该组所有 draft rules 的 `outputPrimaryLabel`。
- 优先级列每个子标签行都显示可编辑数字输入，普通新建默认为 `2`。
- 保存前按 `priority` 升序自动排序；同优先级内按主标签组的首次出现顺序排序，组内按规则稳定顺序排序。不要按中文标签字母顺序重排文件规则，否则会破坏 xlsx 的业务排列。
- 表格删除上移/下移操作，只保留停用、恢复、新增和保存。
- 主标签组颜色由稳定 hash 或循环 palette 决定，同一主标签在当前表格中保持一致。

## UI 结构

桌面抽屉继续保持宽屏工作区。表头建议为：

| 列 | 行为 |
| --- | --- |
| 流水类型 | 可编辑方向，下拉或分段控件。 |
| 主标签 | 合并单元格，组级编辑，同步组内所有子标签。 |
| 子标签 | 行级编辑。可为空，表示主标签本身作为叶子标签。 |
| 选择查询的项 | 行级多选，`全选/清空` 在下拉框内部。 |
| 包含 | 完整展示多行词条，点击进入多行编辑。 |
| 必须同时包含 | 完整展示多行词条，点击进入多行编辑。 |
| 精准命中 | 完整展示多行词条，点击进入多行编辑。 |
| 不包含字样 | 完整展示多行词条，点击进入多行编辑。 |
| 优先级 | 数字输入，普通默认 2；内部往来只读 1。 |
| 操作 | 停用/恢复/删除新建草稿。无上移/下移。 |

词条展示要求：

- 单元格内以换行列表完整显示所有词条。
- 不用 `共 N 项` 替代正文。
- 不使用 `text-overflow: ellipsis`、固定单行、隐藏 overflow。
- 行高可以随词条数量增长，这是预期行为。

组色要求：

- 使用有限个专业高对比色，例如偏蓝、青、绿、琥珀、紫、玫红的中等饱和背景。
- 颜色必须保证深色文字可读。
- 同一主标签组内主标签单元格和该组行左侧/背景有一致视觉识别。
- 不同组相邻时要明显可辨，但不能影响表格内容阅读。

停用区要求：

- 停用区仍然可访问，保持主设计中的 active/archived 维护能力。
- 停用规则不参与自动命中。
- 停用规则如果缺失优先级，展示时按普通默认 `2` 兼容；如果已有历史优先级，可以保留展示，但恢复到可用区时必须满足普通规则优先级大于 `1`。
- 停用区可以复用同一表格结构，但不需要强制展示系统规则。

## 优先级与命中语义

后端评估普通规则时必须按优先级层级执行：

```text
for priority in sorted(active ordinary priorities):
    matched = all rules at this priority that match row
    if matched is empty:
        continue
    if matched has one item:
        return auto_matched(item)
    return needs_confirmation(matched)
return unmatched
```

这意味着：

- 同优先级内没有先后抢占。
- 更低优先级只有在更高优先级完全无命中时才参与。
- `needs_confirmation` 候选不得混入更低优先级命中的标签。
- 内部往来仍在普通规则之前执行，命中后不再进入普通规则。

文件规则替换时，普通规则默认写入优先级 `2`。如果后续用户在 UI 中修改优先级，保存后按用户的优先级进入同一评估算法。

## 数据与 API 调整

- `GET /api/bank-details/auto-tag-rules` 返回的普通规则 `priority` / `priority_label` 必须统一体现普通默认 `2`。
- `PUT /api/bank-details/auto-tag-rules` 接收并持久化用户编辑的优先级。
- 后端校验：
  - `internal_transfer` 不允许从请求体编辑。
  - 普通规则优先级必须为整数且大于等于 `2`。如果用户提交 `1`、`0`、负数、小数、非数字字符串，返回结构化校验错误。
  - 未填写优先级的新普通规则默认 `2`。
  - 同主标签+同子标签组合仍必须唯一。
- 前端保存 payload 不再依赖数组位置表达优先级。
- 普通规则需要保留稳定顺序字段或等价排序依据。优先级相同时，保存和再次打开不能因为 label 排序导致 xlsx 原始业务顺序被打散。
- 兼容历史数据：如果旧普通规则没有 priority，显示和保存时按 `2` 处理；如果旧数据有递增 priority，文件替换入口要把 xlsx 普通规则写成 `2`。

## 测试要求

后端：

- 文件规则替换后，所有普通文件规则 priority 均为 `2`，内部往来显示 priority `1`。
- 同优先级多个命中返回 `needs_confirmation`，候选只包含该优先级内命中的规则。
- 更高优先级已有命中时，不把更低优先级命中加入候选。
- 普通规则提交 priority `1` 被拒绝。
- 普通规则 priority `0`、负数、小数、非数字字符串被拒绝；缺失值只在新增/历史兼容路径默认成 `2`。
- 旧无 priority 规则按 `2` 兼容。

前端：

- 表格渲染同主标签的合并主标签单元格，重复子标签行不重复显示主标签输入。
- 同一主标签跨不同优先级时拆成多个组，不跨优先级 rowSpan。
- 修改合并主标签会同步组内所有规则保存 payload。
- 多选框下拉内部包含 `全选` / `清空`，点击后更新选中字段。
- `全选` 保存为所有可见语义字段列表，不保存 `all_text`。
- 上移/下移按钮不存在。
- 优先级输入存在；新增规则默认 priority `2`。
- 系统行优先级 `1` 只读，不随保存 payload 提交为普通规则。
- 普通规则提交优先级 `1` 时，前端应阻止或展示后端结构化错误。
- 多行词条完整显示，不出现省略号或 `共 N 项` 替代正文。
- 不同主标签组有明显不同背景色或视觉标识。

## 验收标准

- 用户打开 `自动标签规则` 后看到的是类似 xlsx 的表格，不是卡片或普通重复主标签表格。
- 同主标签多子标签时，主标签视觉上合并为一个纵向单元格。
- `选择查询的项` 的 `全选/清空` 在多选框下拉内部。
- 多行词条完整可见。
- 不同主标签组颜色明显区分。
- 内部往来优先级为 `1`，普通文件规则默认全部为 `2`。
- 修改优先级保存后自动归位，不再需要上移/下移。
- 平级命中逻辑符合候选确认设计。
