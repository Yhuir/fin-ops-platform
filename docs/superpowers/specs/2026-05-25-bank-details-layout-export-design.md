# 银行明细表格排版与导出设计

## 背景

银行明细页面已经改为只展示系统自动分类，且银行原始文本字段按三槽展示：

- 用途/交易用途。
- 摘要。
- 备注/附言/客户附言。

本轮目标是在不恢复人工打标签、不复刻银行原始 Excel 样式的前提下，提升银行明细表格的财务表格可读性，并新增专业 Excel 导出。

真实银行字段口径固定如下：

| 银行 | 真实字段 |
| --- | --- |
| 交行 | 摘要 |
| 工行 | 用途、摘要、附言 |
| 光大 | 摘要 |
| 建行 | 摘要、备注 |
| 民生 | 客户附言 |
| 平安 | 摘要、交易用途 |

## 范围

本设计覆盖：

- 银行明细右侧流水表的视觉整理。
- 表格列之间的淡分隔线。
- 银行明细导出入口、导出 API 和 Excel 工作簿结构。
- 导出权限、审计、错误反馈和测试策略。

本设计不覆盖：

- 新增或恢复人工分类。
- 改变自动分类规则。
- 改变免 OA 批次提交规则。
- 复刻用户提供的原始银行 Excel 版式。

## 表格视觉设计

继续使用现有 MUI Table，不切回 DataGrid。

表格应呈现为稳定的财务明细表：

- 表头使用固定浅灰背景，表头文字与列内容保持一致的对齐方式。
- 列之间增加淡竖分隔线，建议颜色为 `rgba(15, 23, 42, 0.08)` 或等价设计 token。分隔线只用于结构提示，不使用重边框。
- 行背景保留轻微斑马纹，但降低灰度，避免与选中态、hover 态竞争。
- 单元格统一顶部或中线对齐，避免同一行各列视觉漂移。
- 文本三列长内容允许换行，不能横向撑破表格。

列内结构：

- 对方户名列：对方户名为主文本；交易时间单独一行；`无oa/有oa`、`无发票/有发票` 显示在交易时间下方。
- 类型列：窄列居中，只显示自动标签或 `-`，tag 尺寸保持小。
- 金额列：固定两行结构。第一行显示收支方向小标和金额，第二行显示银行来源，例如 `民生银行 9486`。
- 余额列：右对齐，使用等宽数字。
- 用途/摘要/备注三列：内容顶部对齐，长文本自然换行，空值显示 `-`。

## 导出入口设计

在银行明细表格工具栏增加 `导出` 按钮。按钮打开轻量菜单：

- `导出当前筛选 - 全部银行`
- `导出当前筛选 - 当前账户`

当前选中的是“全部流水”时，`当前账户` 菜单项置灰，并提示需要先选择具体银行账户。

导出使用当前页面筛选条件命中的全部流水，不只导出当前页。筛选条件包括：

- `date_from`
- `date_to`
- `keyword`
- `account_key`

`全部银行` 导出不传 `account_key`。`当前账户` 导出传当前选中账户的 `account_key`。

## Excel 导出设计

导出文件不复制页面 UI 样式，不包含 chip、tag 视觉样式或页面内控件。导出应为专业表格：

- 冻结首行。
- 开启自动筛选。
- 表头使用清晰底色和加粗字体。
- 日期列统一显示为 `yyyy-mm-dd hh:mm:ss`。
- 金额列使用数字格式 `#,##0.00`。
- 文本列自动换行。
- 设置合理列宽。

导出列：

| 列名 | 说明 |
| --- | --- |
| 交易时间 | 去掉时区后缀的交易时间 |
| 银行 | 导入银行名称 |
| 账号尾号 | 银行账号尾号 |
| 对方户名 | 银行流水对方户名 |
| 收支方向 | `收入` 或 `支出` |
| 收入金额 | 收入流水金额，支出为空 |
| 支出金额 | 支出流水金额，收入为空 |
| 余额 | 流水余额 |
| 自动分类 | 自动标签文本；无自动标签时为 `-` |
| OA 关系 | `有oa` 或 `无oa` |
| 发票关系 | `有发票` 或 `无发票` |
| 用途/交易用途 | 银行真实用途槽 |
| 摘要 | 银行真实摘要槽 |
| 备注/附言/客户附言 | 银行真实备注槽 |
| 流水 ID | 系统流水 ID |

全部银行导出：

- Sheet 1：`全部流水`。
- 后续 Sheet：按银行拆分，例如 `工行`、`光大`、`建行`、`交行`、`民生`、`平安`。同一银行多个账号仍放同一个银行 Sheet，并用 `账号尾号` 区分。

当前账户导出：

- 只生成当前账户所属银行 Sheet，并且只包含该账户流水。
- 不额外生成总表，避免重复。

文件名：

- 全部银行：`银行明细_当前筛选_全部银行_YYYYMMDD-YYYYMMDD.xlsx`。
- 当前账户：`银行明细_<银行><账号尾号>_YYYYMMDD-YYYYMMDD.xlsx`。

## 后端/API 设计

新增只读下载接口：

```text
GET /api/bank-details/transactions/export
```

参数：

- `date_from`
- `date_to`
- `keyword`
- `account_key`
- `mode=all|account`

后端必须复用现有银行明细查询、时间格式化、自动分类、OA/发票关系标签和银行字段拆分逻辑。不能在导出路径重新实现一套字段映射或分类规则。

导出不受页面分页限制。后端按筛选条件取全部命中行，但同步导出设置硬上限 `20000` 行。超过上限时返回 400，错误码 `bank_detail_export_row_limit_exceeded`，消息提示用户缩小日期范围、选择具体银行或增加搜索条件。本轮不做异步导出队列。

`mode=account` 必须携带有效 `account_key`。缺失或找不到匹配账户时返回 400，错误码 `bank_detail_export_account_required` 或 `bank_detail_export_account_not_found`。

## 权限与审计

权限沿用现有访问体系：

- `full_access`、`admin`、`read_export_only` 可以导出。
- `denied` 不允许导出。

导出应记录结构化审计事件，至少包含：

- 操作人。
- 导出时间。
- 导出模式：全部银行或当前银行。
- 筛选条件。
- 导出行数。
- 文件名。

审计接入现有 `AuditTrailService.record_action()`，不新增平行日志系统。事件建议为：

- `action`: `bank_detail_export_downloaded`
- `entity_type`: `bank_detail_export`
- `entity_id`: 文件名
- `metadata`: 导出模式、筛选条件、行数、sheet 名称、文件名

审计写入是导出请求的一部分。审计写入失败时不返回文件，按服务端错误处理，避免无审计的数据下载。

## 错误处理

前端：

- 导出中按钮显示 loading 或禁用态。
- 导出失败显示明确错误提示。
- 当前账户导出在未选择具体银行账户时不可触发。

后端：

- 参数非法返回 400。
- 无权限返回 403。
- `mode=account` 缺少账户、账户不存在或账户与筛选不一致时返回明确 400 错误码。
- 导出超出 `20000` 行上限时返回 `bank_detail_export_row_limit_exceeded` 和用户可读消息。
- 生成 Excel 失败返回 500，并记录服务端错误。

## 测试策略

后端测试：

- 导出 API 使用当前筛选条件导出全部命中行，不受分页影响。
- `mode=all` 生成 `全部流水` 加按银行拆分 Sheet。
- `mode=account` 只生成当前账户所属银行 Sheet。
- Excel 导出列为纯文本/数字数据列，不包含 UI chip/tag 样式。
- 导出继续遵守真实银行字段口径：交行只有摘要，工行三列都有，光大只有摘要，建行摘要/备注，民生只有客户附言，平安摘要/交易用途。
- 超过 `20000` 行返回 `bank_detail_export_row_limit_exceeded`。
- `mode=account` 缺少或传入无效 `account_key` 返回对应 400 错误码。
- 无权限用户不能导出。
- 导出审计事件包含 actor、筛选条件、行数和文件名。

前端测试：

- 工具栏展示导出按钮。
- 全部银行导出发送当前日期范围和搜索词，不传 `account_key`。
- 当前账户导出发送当前日期范围、搜索词和 `account_key`。
- 未选择具体银行账户时当前账户导出入口不可用。
- 下载成功后使用后端文件名。
- 下载失败显示错误提示。

验证：

- 运行银行明细后端导出相关单元测试。
- 运行银行明细前端 API 和页面测试。
- 运行前端构建。

## 待确认风险

- 如果未来生产需要超过 `20000` 行的银行明细导出，应单独设计异步导出任务和下载中心，不在本轮同步导出里扩展。
