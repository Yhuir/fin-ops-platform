# 银行明细紧凑分组标签筛选面板设计

## 背景

银行明细页面已把原来的多行标签 chip 收纳为一个 `标签筛选` 入口，但当前 hover 小窗仍然不够直观：视觉像目录树，行距偏大，数量徽标显得重，且 `未分类` 和部分主标签的点击语义不清晰。

本轮目标是在不改变现有筛选合同的前提下，弃用 TreeView/目录树式外观，保留现有层级数据模型，重做为一个小尺寸、财务筛选菜单式的 MUI 分组面板。

## 范围

本设计覆盖：

- 银行明细流水表工具栏的标签筛选 hover/focus/click 小窗。
- `全部`、`未分类`、主标签、子标签四类筛选项。
- 紧凑视觉、层级表达、当前选中状态。
- 列表请求、分页重置、导出继承、测试验证。

本设计不覆盖：

- 自动标签规则匹配逻辑。
- 后端标签事实源。
- 手工逐条打标签。
- 银行流水表格主体重构。
- 新增搜索型 command palette。标签规模继续增长后可单独评估。

## 产品目标

- 小窗看起来像“筛选菜单”，不是文件树。
- UI 尺寸小，避免大面板、大行距、大圆形数量徽标。
- 主/子标签层级一眼可见。
- `未分类` 即使不是标签，也必须可点击筛出未分类流水。
- 主标签必须可点击，筛出该主标签下所有子标签流水。
- 子标签点击筛出精确标签流水。
- 打开小窗不压缩流水表首屏空间，小窗内部滚动。
- 主要使用 MUI 组件、主题 token 和少量 `sx`，不以自写 CSS 为主导。

## 入口

工具栏保留一个稳定入口按钮：

```text
标签筛选：全部 431
标签筛选：未分类 44
标签筛选：薪资社保福利 49
标签筛选：薪资社保福利 / 工资 32
```

按钮显示当前筛选摘要和当前命中数量。按钮、导出、搜索继续在同一行内布局，标签不再平铺占据表格上方空间。

## 小窗结构

面板使用 MUI `Popper` 或 `Popover` 承载，内容使用 MUI `List`、`ListItemButton`、`Stack`、`Typography`、`Chip` 或轻量文本徽标组合实现。不要使用 `RichTreeView` 的默认树外观。

推荐结构：

```text
全部                                      431
未分类                                     44

薪资社保福利                              49
  工资                                    32
  社保                                     2
  福利                                     4
  公积金                                   4
  过节费                                   7

内部往来款                                56

税款                                      17
  增值税                                  17
```

层级规则：

- 顶部固定显示 `全部` 和 `未分类`。
- 主标签整行显示，字重比子标签略高，右侧显示主标签合计数量。
- 子标签始终显示在所属主标签下方，左侧缩进。
- 即使一个主标签只有一个子标签，也显示该子标签，保证“主标签汇总”和“精确子标签”语义清楚。
- 默认展开所有有命中数量的主标签。
- 0 条子标签默认隐藏；当前已选中的 0 条项必须保留显示，避免筛选状态消失。
- 当前选中项整行浅色高亮。
- 数量靠右对齐，使用小号文本或小 `Chip`，禁止大圆形徽标视觉。

## 紧凑视觉口径

- 面板宽度：约 `300-340px`。
- 最大高度：约 `320-360px`，超出后面板内部滚动。
- 主标签行高：约 `30-32px`。
- 子标签行高：约 `26-28px`。
- 主标签字号：约 `14px`。
- 子标签字号：约 `13px`。
- 数量字号：约 `12-13px`。
- 面板外层 padding 小，避免大留白。
- 分组间距小而清晰，可以用细 `Divider` 或 `Stack` 间距，不要卡片套卡片。
- 不新增大段 CSS；优先使用 MUI `sx` 和已有 class 的小幅调整。

## 交互语义

- Hover、focus、click 打开小窗。
- 鼠标从按钮移动到小窗时不应立即关闭。
- 点击小窗外、按 `Esc`、选择筛选项后关闭小窗。
- 窄屏或触控场景不依赖 hover，点击按钮即可完整使用。

筛选语义：

- 点击 `全部`：清空标签筛选。
- 点击 `未分类`：筛选无有效标签流水。
- 点击主标签：筛选该主标签下全部流水。
- 点击子标签：筛选该具体标签流水。

筛选后行为：

- 流水表回到第一页。
- 当前账户、日期范围、搜索关键词保持不变。
- 入口按钮摘要和数量更新。
- 导出请求继承当前筛选。

## 数据模型

当前筛选应使用结构化状态表达：

```ts
type BankCategoryFilter =
  | { kind: "all" }
  | { kind: "uncategorized" }
  | { kind: "primary"; primaryLabel: string }
  | { kind: "tag"; code: string; primaryLabel: string; subLabel: string | null };
```

面板数据从现有事实派生：

- `categoryOptions` 提供标签 `code`、主标签、子标签和展示顺序。
- `categoryCounts` 提供子标签计数和 `uncategorized` 计数。
- 主标签计数等于其下子标签计数合计。
- `全部` 数量使用当前列表总数 `rowCount`。
- `未分类` 数量使用 `categoryCounts.uncategorized`。

请求映射：

- `all`：不传任何标签筛选参数。
- `uncategorized`：传现有约定 `categoryCode: "uncategorized"`。
- `primary`：传 `categoryPrimaryLabel`，不传 `categoryCode`。
- `tag`：传 `categoryCode`，并保留当前实现里用于展示/导出一致性的 `categoryPrimaryLabel`、`categorySubLabel`。

## 边界

- 标签字典为空时，小窗仍显示 `全部` 和 `未分类`。
- 已选标签在字典刷新后消失时，回退到 `全部`。
- 主标签重名时，UI key 必须稳定不冲突；请求仍按后端现有主标签名称合同处理。
- 读模型刷新、stale、schema mismatch 的提示保持现状。
- 后端只允许为既有 `uncategorized` 语义修正，不新增查询参数。
- 不引入 Ant Design 等大体量外部 UI 库；如果引入第三方库，必须先证明 MUI 组合无法满足要求。

## 测试策略

前端测试覆盖：

- 面板不再暴露 TreeView/目录树外观依赖，测试可以改为 `menu`、`listbox` 或具名 `list`，不再要求 `role="tree"`。
- 面板内能看到 `全部`、`未分类`、主标签、子标签。
- `未分类` 是可点击项，点击后请求包含 `category_code=uncategorized` 并筛出未分类流水。
- 主标签是可点击项，点击后请求包含 `category_primary_label`，不包含 `category_code`。
- 子标签点击后请求包含具体 `category_code`。
- 筛选切换重置到第一页，保留账户、日期、搜索关键词。
- 入口按钮摘要和数量与当前筛选一致。
- 导出请求继承 `未分类`、主标签和子标签筛选。
- 标签字典刷新导致当前项消失时安全回退到 `全部`。

验证命令：

```bash
cd web && npm test -- --run BankDetailsApi.test.ts BankDetailsPage.test.tsx
cd web && npm run build
git diff --check
```

如进行人工验收，重点检查：

- 小窗宽度和行高足够紧凑。
- 数量徽标不再是大圆圈。
- 主标签和子标签层级清晰。
- `未分类`、主标签、子标签都能点击并关闭小窗。
- 流水表上方空间没有被标签区重新占用。

## 验收标准

- 标签筛选入口保持单按钮。
- 小窗改为紧凑 MUI 分组筛选面板。
- 默认展开所有有命中数量的主标签。
- 只有一个子标签时也显示子标签。
- `未分类` 可点击筛选。
- 主标签可点击筛选其下全部流水。
- 子标签可点击精确筛选。
- 列表请求、按钮摘要、导出请求一致。
- 未引入大 UI 依赖和大段自写 CSS。
