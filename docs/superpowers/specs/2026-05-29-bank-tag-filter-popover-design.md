# 银行明细标签筛选 Hover 小窗设计

## 背景

银行明细页面的标签筛选目前以平铺 chip 展示。标签数量增长后，筛选区会占用多行高度，压缩右侧流水表的首屏空间。页面已经具备结构化标签字段和筛选合同：

- 标签事实源为银行明细自动标签规则中的稳定 `code`。
- 标签展示支持 `输出主标签 / 输出子标签`。
- 银行明细列表和导出请求类型已经支持 `category_code`、`category_primary_label`、`category_sub_label`。

本轮目标是把标签数量统一收纳到一个小窗中，清晰展示主/子标签层级，并把页面垂直空间还给流水表。

## 范围

本设计覆盖：

- 银行明细流水表工具栏的标签筛选入口。
- 标签筛选 hover/focus/click 小窗。
- 主标签、子标签、全部、未分类的筛选语义。
- 标签树数据派生、当前筛选摘要、导出筛选继承。
- 前端测试和验证策略。

本设计不覆盖：

- 改变自动标签规则事实源。
- 新增后端标签字段。
- 改变自动分类命中逻辑。
- 恢复人工逐条打标签。
- 大范围重做银行明细表格。

## 产品目标

- 标签筛选区常驻高度稳定为一行。
- 小窗中主/子标签层级清晰，适合财务用户快速选择。
- 点击任意标签都能立即筛选流水表。
- 主标签既能展开查看子标签，也能筛选该主标签下全部流水。
- 使用 MUI 和 MUI X 现有组件能力为主，不以手写 CSS 为主导。
- 交互需要兼顾 hover、点击和键盘访问。

## 入口设计

在银行明细流水表工具栏中，把现有多行标签 chip 列表替换为一个常驻按钮：

```text
标签筛选：全部 · 431 条
标签筛选：未分类 · 107 条
标签筛选：费用 · 153 条
标签筛选：费用 / 手续费 · 113 条
```

按钮负责展示当前筛选摘要和当前筛选命中数量。标签不再平铺在页面上，流水表上方空间只保留该按钮、导出按钮和搜索框。

## 小窗设计

使用 MUI `Popover` 承载小窗，使用 `@mui/x-tree-view` 的 `RichTreeView` 展示竖向层级。

树结构：

```text
全部
未分类
费用 153
  手续费 113
  管理 9
  办公 12
  房屋使用费 4
货款 53
  设备采购 16
  材料费 37
薪资社保福利 38
  工资 32
  社保 2
  福利 4
```

层级规则：

- 第一层固定为 `全部`、`未分类` 和主标签。
- 子标签缩进在对应主标签下。
- 有子标签的主标签显示展开箭头。
- 无子标签的标签作为主标签叶子显示。
- 当前选中节点保持高亮。
- 小窗宽度保持紧凑，建议 360-420px。
- 小窗高度超过限制时只在小窗内部滚动，不影响流水表滚动。

视觉策略：

- 以 MUI/MUI X 组件默认交互和主题 token 为主。
- 必要时允许少量 `sx` 或局部 CSS 调整尺寸、滚动高度和按钮对齐。
- 不新增大段 CSS，不把样式作为主要实现手段。

## 交互语义

- Hover 按钮打开小窗。
- Focus 按钮打开小窗。
- 点击按钮也能打开或保持小窗，兼容触控板和窄屏。
- 鼠标进入小窗后保持打开。
- 鼠标离开按钮和小窗后延迟关闭，避免误关。
- `Esc` 关闭小窗。
- 键盘用户可以通过树组件方向键导航，通过 `Enter` 选择。

筛选语义：

- 点击 `全部`：清空标签筛选。
- 点击 `未分类`：筛出无有效标签流水。
- 点击主标签文本：筛出该主标签下全部子标签流水。
- 点击主标签展开箭头：只展开或收起，不改变筛选。
- 点击子标签：筛出该具体标签流水。

筛选后行为：

- 流水表刷新到第一页。
- 当前账户、日期范围、搜索关键词保持不变。
- 常驻按钮更新当前筛选摘要和数量。
- 导出继续继承当前筛选条件。

## 数据模型

前端当前筛选状态从单一 `selectedCategoryCode` 扩展为结构化状态：

```ts
type BankCategoryFilter =
  | { kind: "all" }
  | { kind: "uncategorized" }
  | { kind: "primary"; primaryLabel: string }
  | { kind: "tag"; code: string; primaryLabel: string; subLabel: string | null };
```

树节点从现有数据派生：

- `categoryOptions` 提供 `code`、`outputPrimaryLabel`、`outputSubLabel` 和展示顺序。
- `categoryCounts` 提供叶子标签数量和 `uncategorized` 数量。
- 主标签数量等于其下所有叶子标签数量合计。
- `全部` 数量使用当前列表总数 `rowCount`。
- `未分类` 数量使用 `categoryCounts.uncategorized`。

节点 ID 需要避免冲突：

- `all`
- `uncategorized`
- `primary:<normalized-primary-label>:<stable-suffix>`
- `tag:<code>`

筛选请求：

- `all`：不传 `categoryCode`、`categoryPrimaryLabel`、`categorySubLabel`。
- `uncategorized`：沿用现有未分类筛选语义；实施前以当前 `fetchBankDetailTransactions` 调用为准。
- `primary`：传 `categoryPrimaryLabel`，不传 `categoryCode` 和 `categorySubLabel`。
- `tag`：传 `categoryCode`；如现有导出合同需要，导出请求也同步带上 `categoryPrimaryLabel`、`categorySubLabel`。

## 边界和错误处理

- `tagDictionary` 缺失或加载中时，按钮仍显示 `标签筛选：全部`，小窗只显示 `全部`、`未分类`。
- 读模型状态为 `refreshing`、`stale` 或 `schema_mismatch` 时，保持现有提示和已有标签树，不清空页面。
- 标签规则保存后刷新页面数据时，当前筛选优先按稳定 `code` 恢复。
- 如果选中的标签 code 已停用或消失，回退到 `全部`。
- 子标签为空时不显示空层级，主标签本身作为可选节点。
- 主标签重名时 UI 节点 ID 必须稳定且不冲突，筛选合同仍按后端现有主标签名称处理。
- 窄屏不依赖 hover，点击按钮打开小窗。

## 测试策略

前端测试覆盖：

- 页面不再渲染大量平铺标签筛选按钮，工具栏只保留一个标签筛选入口。
- 打开小窗后能看到 `全部`、`未分类`、主标签和缩进子标签。
- 点击 `全部` 清空标签筛选并回到第一页。
- 点击 `未分类` 触发未分类筛选并回到第一页。
- 点击主标签发送 `category_primary_label` 并回到第一页。
- 点击子标签发送具体 `category_code` 并回到第一页。
- 当前筛选摘要和数量显示正确。
- 导出请求继承当前主标签或子标签筛选。
- 标签字典刷新后，当前筛选可以正确显示或安全回退。

验证命令：

```bash
cd web && npm test -- --run BankDetailsPage.test.tsx BankDetailsApi.test.ts
cd web && npm run build
```

如启动本地服务，应在宽屏下人工检查：

- 标签区不再占用多行。
- 流水表首屏上移。
- 小窗主/子标签层级清晰。
- hover、点击、键盘选择都可用。

## 依赖

新增依赖：

```text
@mui/x-tree-view
```

理由：

- 项目已经使用 MUI 和 MUI X。
- 树组件自带选择、展开、焦点和键盘行为。
- 比手写树结构更符合少写 CSS、保持可访问性的目标。

## 验收标准

- 银行明细标签筛选入口稳定为一个按钮。
- 标签小窗竖向树结构清楚表达主/子层级。
- 主标签可展开，也可筛选该主标签下全部流水。
- 子标签可筛选具体标签。
- 当前筛选摘要、流水列表、导出请求三者一致。
- 不改变后端标签事实源和自动分类规则。
- 不以大量手写 CSS 实现主要交互。
