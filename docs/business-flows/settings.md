# 设置

## 页面目的

设置页维护平台级配置，包括项目范围、其他账户访问级别、银行账户映射、标签规则、待找发票规则、OA 申请人凭据和数据重置入口。唯一管理员 `YNSYLP005` 固定且不可通过 APP 修改。

## 主要数据

- 项目、银行账户映射、OA 导入范围和页面配置。
- 其他 OA 用户的逐页面访问集合；管理员身份不属于可写设置。
- 银行标签、自动标签、待找发票规则、免 OA 和外部往来款标签范围。
- OA 申请人凭据。
- 数据重置任务和进度。

## 页面流程

- 进入页面后先加载普通设置；只有管理员再独立加载访问账户 ACL，两个请求和错误状态互不污染。
- “访问账户”只对固定管理员 `YNSYLP005` 可见，是唯一人工 ACL 入口。左栏从 OA 搜索/新增/删除账户并显示姓名，右栏勾选 17 个可分配页面；从列表删除或清空全部页面即 denied，页面不允许编辑管理员。
- 保存 ACL 携带当前 `expected_version`；`409` 保留草稿并要求重新加载。semantic no-op 不产生持久化、audit 或 OA I/O；真实变化才同步两个专用 OA 角色。
- 修改关联台、项目、银行账户、标签、规则等配置后点击保存，保存成功后页面反馈“已保存关联台设置”。
- 点击同步项目后，从 OA 或配置来源刷新项目范围。
- 新建项目时填写项目信息并保存；删除本地项目或状态覆盖时，系统更新项目配置。
- 管理 OA 申请人凭据时，管理员可以保存或删除目标申请人的凭据；普通设置内容不展示密码或令牌。
- 执行数据重置时，需要选择范围并确认；页面展示任务进度和结果。
- 当页面未授权、登录失效或系统健康写门禁阻断时，对应页面或保存动作被阻止并提示原因。

## 状态和异常

- 加载失败时，页面提示无法获取设置。
- 普通账号只有勾选 settings 页面后才能进入并保存普通设置；页面授权不授予 admin-only 能力。
- 非管理员账号不能维护 OA 申请人凭据、访问账户、数据重置或操作历史。
- 普通账号手工向普通设置接口注入 ACL 字段必须得到明确 `400`；调用专用 ACL 接口必须得到 `403`。
- OA roles/permissions 仅作为身份信息；即使仍带 `finops:app:view` 或业务角色，账号不在 canonical ACL 中也必须 denied。ACL provider 缺失/失败对非管理员同样 fail closed。
- 删除账号后，同一 OA 身份下一次 session 或 direct API 判断立即拒绝；直达 `/fin-ops/` 由 `SessionGate` 阻断。OA 菜单以角色投影后的新 router/session 为验收边界，不承诺旧页面 DOM 无刷新瞬时消失。
- OA 同步或 PostgreSQL/补偿失败时，页面必须展示专用 API 的 `502` / `503` 错误，不能显示“保存成功”。
- 数据重置是高风险操作，需要权限、确认、进度和结果反馈。

## 输出和影响

普通设置保存可以影响标签判断、项目归因、OA 范围、导入要求和已登记的数据刷新合同。ACL 保存只影响 session 的页面集合、侧栏/路由/API 可达性与 OA 两角色菜单投影；它不新增或改变 read model、worker、dirty scope、cache key 或其他页面 API response。数据重置会使相关页面旧结果失效，需要重新准备数据后再展示。

## 相关页面

- 银行流水导入：依赖银行账户映射。
- 银行明细、免 OA、外部往来款、待找发票：依赖标签和规则。
- 关联台、成本统计、发票相关页面：依赖项目、权限和业务规则。
- 进项发票使用情况：依赖 OA 申请人凭据执行反提 OA。
