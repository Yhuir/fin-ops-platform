# 批量账务

## 页面目的

批量账务用于把符合批量账务条件的银行流水与日常报销 OA 行人工建立关系，并支持撤回。它服务于批量核销场景，避免逐条在关联台中重复处理。

## 主要数据

- PostgreSQL canonical 可处理银行流水、已完成日常报销 OA 主单、OA 附件发票和 active batch-accounting 关系。
- 未提交和已提交两个处理池。
- 关系金额校验、差额说明、提交和撤回原因。

## 页面流程

- 进入页面后，页面展示未提交或已提交的批量账务数据。
- 点击“刷新”重新获取当前数据准备结果。
- 点击“未提交”或“已提交”切换处理池。
- 在左侧选择银行流水后，右侧展示没有关联银行流水的已完成日常报销 OA 主单；仅有发票关系的 OA 仍可选择。关键字搜索和分页由服务端完成。
- 在未提交池中勾选 OA 行，填写必要差额说明后点击“关联 OA 项与流水”，系统写入批量账务关系。
- 在已提交池中选中已有关联后点击“撤回关联”，填写撤回原因，再点“确认撤回”。
- 已提交关系存在金额差异时，页面会显示差异提示，帮助用户核对原因。

## 状态和异常

- 页面只区分 loading、ready/empty 和 error，不展示 read-model refreshing/stale 状态。
- 未选择流水、未选择 OA、金额不一致且无差额说明、缺少撤回原因或账号只读时，操作按钮不可用。
- 关系/version 冲突要求刷新重试；query/command 服务不可用时展示后端错误，不显示假空集。
- submit/withdraw 成功后页面只重新 GET 一次；若该 GET 失败，写入仍然成功，页面提示用户手动刷新。

## 输出和影响

提交后，`app.workbench_pair_relations` 中的 active batch relation 成为正式关系事实；撤回后 canonical relation 取消并释放银行流水和 OA。其它页面在自己的正常读取边界收敛，批量账务页面不主动刷新或等待它们。

## 相关页面

- 关联台：展示批量账务写入后的关系。
- 银行明细：体现流水处理状态。
- 成本统计：消费批量账务关系带来的项目和费用归因。
- OA 待付款、进项/销项发票页面：可能受同一关系链变化影响。
