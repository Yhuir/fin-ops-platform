# 导入架构修复验证记录

日期：2026-09-21。实施基线：`501f72273`。范围与验收要求见 [实施计划](import-architecture-implementation-plan.md)。本记录只包含脱敏结果，原始发票、流水、来源文件与逐条取证留在本地，不发布到公开仓库。

## 实际变更

- 普通流水、发票、ETC 使用持久导入任务，准备、待确认、正式提交和失败恢复有明确状态。只在正式事务提交后报告成功；预览不创建财务事实。
- 普通导入使用请求内实例，避免共享快照覆盖新数据。去重针对业务项；同文件再次上传仍与当前事实比较。上传请求重发与主动再次导入分别处理。
- 原件登记与任务受理同事务；领域事实、批次、行证据、必要审计及任务结果同事务。并发领取采用数据库锁和领取版本，旧 worker 不能提交已被接管的任务。
- ETC 一次解析 ZIP/XML 后保存 manifest，确认不重新解压。metadata、附件、批次成员和已有 canonical 发票的受控关联一起提交，不取得正式发票财务字段的写权限。
- 取消、重新预览、重复确认和提交回执丢失均有明确结果；页面读取失败不再次发起导入。全局任务直接呈现持久任务。
- 删除旧 import outbox 执行入口、重复后台进度状态、整文件去重阻断和旧 ETC business-batch 预览确认入口。共享 OA 手工导入和税务认证调用方同步迁移。
- 关联台追加发票入口按价税合计与 OA 付款项比较，修复未税金额导致的虚假缺口；未知价税合计不猜值，金额/关系不变。
- 修复负借方/贷方与文本零解析、未知税额误记零、OA OCR 财务字段顺序和已存在税务金额被覆盖的问题。历史金额修复仅接受已登记税务原件的精确证据与 CAS。
- 生产原件只读预检发现税务导出末尾的标准“合计行”被误当作缺号码业务行。修复只识别明确汇总标记、合法金额字段的尾行，并逐列核对金额、税额和可选价税合计；缺号码业务行、伪汇总、非法金额及不一致的控制合计仍明确报错。三个原件核对登记 SHA/大小后分别解析 699、167、249 张，控制合计与表头/明细身份核验通过；解析服务 56 项回归通过。

以下是隔离 PostgreSQL、固定合成业务数据的五次独立样本，p95 为 nearest-rank（五次样本取最大值）。ETC 使用内存对象存储，不包含生产对象存储网络耗时。
