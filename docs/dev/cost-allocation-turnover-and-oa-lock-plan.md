# 成本自动分配、外部往来人工分配与 OA 金额锁定实施计划

日期：2026-09-21。状态：**实施完成，正在验证与发布**。

本任务不使用 GSD，不创建 GSD 阶段或流程产物。本文记录已确认设计与实施验收；最终上线结果见末尾执行记录。当前入口见[成本模块](../modules/cost-statistics/README.md)、[边界与 I/O](../modules/cost-statistics/boundary-io.md)、[现有自动来源方案](cost-statistics-automatic-source-allocation-plan.md)。

## 1. 目标、范围和需要纠正的认识

目标：普通支出中能够唯一逐笔对应的成本自动完成，**不进入“待分配”，也不进入其“已完成”列表**；外部往来支出进入人工分配，只有已确认的费用计入成本；每个 OA 成本单元支持明确保存“按 OA 原额分配”的选择。保存、刷新、再编辑、范围切换、导出、事实变更与关系撤回形成同一闭环。

本次主要 owner 是成本统计；银行分类 owner 仅补充已有批量分类端口的结构化输出。不会新建贷款模块、另一套成本台账、通用规则引擎、缓存、read model、worker、依赖或异步补偿链。

需要明确纠正：

1. 外部往来经常有利息，并不意味着每笔都有利息。纯本金必须可以保存为零成本并完成任务。
2. 金额相等、页面同行不等于原始付款凭据已证明逐笔归属。新增自动规则是一项明确的业务推导政策，只作用于已经正式关联的成员，不创建或改写原始配对关系。
3. “唯一”本次定义为：在正式来源约束和当前关联范围内，**唯一的完整逐笔一对一对应**。不声称排除了任意拆金额矩阵的全部数学解。上一轮“存在任何金额组合就不自动”的泛化说法不继续采用，否则简单高性能目标会被组合搜索破坏。一对多/多对一保留原有明确证据能力，单靠金额组合仍仅提供人工建议。
4. checkbox 不决定流水是不是外部往来，也不修改 OA 原额。勾选的外部往来仍须人工确认。
5. 极高性能和“其他页面绝无 bug”不能靠口头保证。采用小范围修改、固定查询形状、独立测量与跨页面回归；没有实测不宣称达标。
6. 这不是只增加一个 UI 控件：保存的约束选择会影响 API、持久化、范围合并和金额校验，必须一起完成。
7. 自动成本无需占用人工任务列表，但必须保留成本明细、来源和后续调整入口。已有人工决定不能因为现在也能自动对应，就被隐藏或删除；只有纯自动、没有待处理问题的结果退出这两个列表。

范围限制：沿用现有正式关联及 OA 审批资格。不扩展无 OA 外部往来人工建成本，不修改银行金额、银行标签、关联拓扑、外部往来本金结清、发票抵扣和成本标签体系。

## 2. 最终业务规则

### 2.1 规则优先级

按顺序执行，只有一个成本结果集合：

1. 校验当前成员、OA 资格、来源与既有分配有效性；沿用已有权限和版本/指纹保护。
2. 有效人工决定优先；不能被自动规则覆盖或重复累加。失效决定保留待核对，不自动恢复原值。
3. 未人工确认的外部往来支出不生成正式成本，保留待分配。这个限制高于所有自动来源规则，包括同额单笔、正式历史子组和混合审批的部分自动分配。
4. 普通支出先使用现有明确来源规则，再对尚未解决的普通独立组使用新增唯一逐笔一对一规则。
5. 无法明确的部分保持待分配；人工保存后完整分配满足金额校验，进入人工任务的已完成。纯自动完整结果只进入成本统计/明细/导出。既有审批中部分保存语义保留。

自动读取不写分配记录、不触发前端自动 PUT。沿用内部 version=0 表示尚未保存人工决定，不能据此直接过滤所有 version=0 任务：尚待人工的新任务也是 version=0。首次人工编辑仍经原保存入口。

### 2.2 普通唯一逐笔分配

- 在已正式关联的 OA 成本单元与支出来源中处理，先排除已被有效人工决定覆盖的来源。
- 唯一性基于完整正式关系及已有证据限定的独立子组判断，再投影到当前成本范围和展示筛选。月份、搜索、分页或缩小标签范围不能通过隐藏其他候选把歧义变成唯一；继承现有“未保存歧义任务不能因范围缩小自动确认”的合同。
- 复用现有正式来源/历史子组约束；明确冲突不可被同额绕过。已知币种、方向、账户或来源证据冲突继续按现有事实处理，不新增日期窗口或凭据必填门槛。
- 在一个独立组内，正数 OA 单元与支出数量一致，金额按分精确对应；每个金额在两侧均唯一、且对应不违反已有归属约束时，整组自动完成。
- 重复金额有明确逐笔来源时保留现有自动能力；只有重复金额而无来源证明时继续人工。
- 新增规则不先贪心消费局部同额行。一个尚未解决组不能完整证明逐笔对应时，仍用既有人工/建议能力；明确独立子组可以分别处理。
- 新增自动规则不消费 relation_display_groups 或前端表格顺序；不把 suggest_source_allocations 的组合枚举放入统计热路径。
- 7×7 截图样例在没有历史人工决定且满足规则时，应产生七条来源成本，合计 507083.00；待分配、已完成及两者计数都不包含该组，成本明细仍可追溯和调整。截图显示已完成，生产实际是否有历史人工记录需只读核对；若已有有效人工决定，保留人工已完成，不能用合成样例替代生产结论。

### 2.3 外部往来人工分配

- 使用银行分类 owner 的结构化往来语义识别，不按“借款”等字符串、金额大小或 OA 备注猜测。不能只硬编码一个 external_turnover 标签代码漏掉自定义规则。
- 全局项目成本范围继续由现有设置控制；纳入的是用户选择的外部往来支出标签，不隐式重置空范围或其他标签选择。
- 未保存的来源建议不计成本。纯利息 OA 可以保持锁定；本息 OA 可以解除锁定后分出本金。
- 完整无退款任务逐笔满足：成本＋非成本＝支出。退款保持原来的逐笔归属与净额规则。
- 成本 0、全额非成本是合法已完成结果；原因必填，不能把零成本误当作尚未填写。
- 混合普通支出/往来支出时，有独立来源证明的普通部分继续按原规则；共享 OA/来源无法分开时仅相关部分待人工，不能通过滤掉往来来源重新凑平普通 OA。
- 无 OA 虚拟项目的整笔成本路径必须排除外部往来支出，防止绕过人工要求。原有普通无 OA 成本不变。
- 无 OA 的外部往来仍不产生现有 OA 分配任务；此次不能暗加一个猜测项目的替代入口。

### 2.4 按 OA 原额分配

- 粒度为 OA 成本单元：支付申请是其 OA 单元，报销是已有费用子单元。一个单元多条来源合计接受同一个锁定约束，人工补充成本没有 OA checkbox。
- 新的普通完整任务默认勾选；外部往来新任务也可按用户要求默认勾选，等待用户明确取消。已有普通差额/部分分配任务按原适用状态生成初始值，不把过去可处理的情况强行锁死。
- 勾选：该单元在完整有效来源上的成本合计必须等于 OA 原额。不勾选：成本目标取明确来源分配之和，允许零；不解除来源容量、来源身份、两位小数和审批资格约束。
- 范围内保存要合并保留的范围外有效决定后再校验 OA 单元总目标。不能拿当前范围的 600 元强行与完整 OA 的 1000 元比较，也不能覆盖范围外已经保存的 400 元。
- 既有混合审批/部分保存允许先确认已完成份额。锁定表示完整目标不变；部分保存仍按现有不超目标规则，未完成份额继续待分配。未完成 OA 不能通过取消勾选转换为人工成本或非成本。
- 重新勾选若与草稿矛盾，只显示具体差额，不覆盖输入；切换本身不写库、不改变统计。
- 保存后重开、刷新、网络结果核实、范围切换均恢复已保存选择；作用于同一 OA 单元的锁定值不能按来源重复保存成互相冲突的值。

### 2.5 人工任务列表与成本结果分离

| 当前结果 | 成本统计 | 待分配 | 人工已完成 |
| --- | --- | --- | --- |
| 普通支出完整自动，无人工决定和待处理问题 | 正常计入 | 不出现 | 不出现 |
| 普通支出有歧义、未满足现有资格或尚未处理完 | 只计符合原有部分入账规则的已确定份额 | 出现 | 不出现 |
| 外部往来尚未人工确认 | 往来部分不计入 | 出现 | 不出现 |
| 有效人工决定，完整处理 | 只计确认成本，纯本金允许为零 | 不出现 | 出现 |
| 人工决定失效或尚未完整处理 | 按现有有效性/部分保存规则计入，不沿用失效金额 | 出现 | 不出现 |

- Policy 内部保留全部关系的分配解析结果；只由一个人工列表可见性规则派生列表成员。当前 `manual_allocation_tasks` 同时被 `list_tasks`、`get_task` 和保存查找使用，实施时明确区分全量解析结果与列表投影，不能直接全局过滤该集合。
- 列表可见性依赖当前待处理状态及真实人工决定，不使用 `row_kind=manual_allocation` 判断人工来源：该值目前指人工补充成本项，普通 OA 也可能经过人工分配。
- 服务端先决定人工列表成员，再计算 pending/allocated 数量、搜索结果数和分页；保持现有搜索计数合同。列表、入口角标与质量提示共用该口径，不在前端隐藏行来修补数量。
- 混合关系按关系计一次任务；存在待处理部分就保留任务，自动解决的部分可作上下文展示。隐藏纯自动关系不能漏掉同组待处理部分，也不能把已确定成本重复计入。
- 自动成本详情复用已有 `reconciliation.relationCaseId` 定位关系；有编辑权限时提供“调整分配”，复用既有表单和 GET/PUT。直接打开指定关系不要求它先出现在任务列表。读取、进入编辑、取消均不写记录、不改变计数；首次有效保存后按完整/部分结果进入人工已完成/待分配。
- 自动规则依赖的正式关系、成员、分类或金额变化后，按当前事实重新计算。普通关系失去唯一对应时转待分配，受影响成本不继续沿用旧自动值；歧义消除且没有人工决定时自动解决并退出人工列表。正式关系撤回后停止生成该关系成本及任务，历史审计保留。
- 不新增自动任务表、自动完成持久化标记或另一套状态机；不为隐藏列表删除历史人工分配记录。这里的“已完成”明确指已人工处理的任务，不是全部成本的处理历史。

### 2.6 界面文字与排版

本次界面采用简短字段、金额、状态与操作，不增加常驻说明段、规则提示条、教学文案、公式、解释性 tooltip 或内部技术字段。业务规则保留在文档和服务端校验中。

| 位置 | 界面文字 | 排版与交互 |
| --- | --- | --- |
| 人工任务页签 | 待分配 / 已完成 | 沿用现有布局与计数，不增加页签副标题 |
| OA 原额 | OA 金额 | 保持只读，不重复显示同一原额 |
| OA 单元 checkbox | 按 OA 原额 | 位于该 OA 单元身份/金额区域，同一单元多来源只显示一次 |
| 来源成本输入 | 分配金额 | 沿用现有来源行，金额右对齐，两位小数 |
| 非成本区域 | 不计成本 / 原因 | 复用现有区域，不增加本金/利息专属卡片或教学例子 |
| 成本详情编辑入口 | 调整分配 | 复用现有操作区，仅有编辑权限时显示 |
| 提交操作 | 保存 | 沿用已有保存中、成功与错误反馈，不增加成功说明段 |

- 沿用现有表格、间距、字体和抽屉，不因本次功能重排整页；窄宽度允许控件自然换行，长项目/费用名称不能挤压金额输入或遮挡 checkbox。
- 删除本次受影响区域内重复解释新规则的文案；不扩大为全站文案清理。不另加“自动分配说明”“本金不计成本说明”或“取消勾选后……”等常驻文字，也不以额外提示图标替代长文。
- 必要错误反馈保留，按具体失败就近显示一条短消息，例如“与 OA 金额相差 ¥1,000,000.00”“超出流水金额”“数据已更新，请重新加载”。正常状态不显示这些消息，不同时重复行内和顶部同一错误。
- 无说明段不等于隐藏失败：读取失败、金额错误、保存结果待核实和草稿冲突必须可见。控件保留关联 label、键盘操作和可访问名称；不靠颜色或无名称图标表达状态。

### 3.1 拟扩展合同（下列名称为新设计，不是现有字段）

- 复用 GET/PUT /api/cost-statistics/manual-allocations/{case_id}，不新增第二套保存 API。
- 任务列表响应结构沿用，allocated 数量及成员明确改为人工已完成；详情/保存的合法对象不被列表可见性限制。成本详情复用现有 relationCaseId；不为展示“系统自动/人工确认”另增说明文案、DTO 字段或存储标记，不从补充成本行类型反推人工记录。
- GET 单元增加 lock_oa_amount:boolean；任务/来源增加服务端派生的人工原因，沿用 pending_reasons 表达 external_turnover_requires_confirmation。锁定必须由同一领域状态生成，不让前端根据金额再次判断。
- PUT 增加 oa_amount_locks:[{unit_id,locked}]，覆盖当前可编辑 OA 单元，拒绝重复、未知 ID、缺失或非布尔值；人工成本项不进入该数组。其余金额继续只存在于 allocations 和 source_allocations。
- 现有分配表新增一个 oa_amount_locks JSONB 元数据列，单元 ID→boolean；不新建表，不保存第二份金额、OA、银行或关系快照，不新增索引。
- 复用既有 relation/source/scope/allocation 版本、member locks 与审计事务；不增加 hash、签名、审批层或额外的客户端版本系统。
- API 参数错误 400、权限不足 403、实际事实/并发冲突 409；数据库异常不能转空列表或沿用旧数据。
- 旧页面缺少必填新字段时明确提示刷新后提交，不在后端猜默认值，也不维护新旧两条保存分支。前后端同批发布。

## 4. 持久化、旧记录和规则启用

1. 执行时分配下一个可用 migration 编号，不能预占其他任务正在使用的编号。数据库变更只增加约束元数据，不删除/重写原始金额与正式关系。
2. 旧锁定状态没有用户历史选择，不能伪造“用户曾勾选”。采用一次性迁移初始化：在现有分配记录与 canonical 单元可核对时，已确认单元金额等于原额初始化 true，不等初始化 false，确保旧有效金额保持。这是迁移初值，不是追溯用户意图。
3. 已失效/缺失单元的旧记录保持现有 stale/不入账处理，锁定初始化为明确的未锁定值并记录迁移计数；不得据此让它重新有效。上线读取不执行旧记录推断。旧 NULL 来源按已有正式合同处理，不借本次恢复多对多猜测。
4. 迁移先在一次性隔离数据库验证，覆盖完整、部分、范围外、失效、人工补充和 NULL 来源历史记录；迁移前后有效成本逐关系对账。无法核对的真实历史记录在只读影响清单列出，禁止静默改本金或批量设置零成本。
5. 现有有效人工分配继续优先；此前未持久化的自动外部往来成本在新政策下转为待人工，可能降低总成本。这是预期业务变化，发布前必须列出金额和记录范围，不能作为技术回归偷偷掩盖。
6. 通过现有项目成本范围设置选中目标外部往来支出标签，保持其他选择与版本校验；不使用代码在每次 GET 自动把标签加回。历史也受同一规则影响，不能只测当前月。
7. 不改变新标签默认未选、空范围有效、退款跟随原支出、无 OA 普通成本映射规则。检查现有往来无 OA 映射，被新人工政策排除的金额单独列明。

- 将全量关系解析结果与人工任务列表投影明确分开；删除自动结果进入人工已完成的旧成员规则。列表计数/搜索/分页和角标统一消费投影，详情/保存仍查询全量结果，成本聚合不受列表过滤影响。
- 保持“完整正式事实→来源计算→成本范围投影→页面筛选”的顺序；不在截取后的当前页或当前月份上重新推断唯一来源。
- 将全组 amounts_fixed 作为编辑锁定的权威来源替换成每单元 lock_oa_amount；算法如仍需判断总额相等，应使用本地数值判断，不保留第二套可编辑锁定状态。
- 覆盖元数据缺失、部分分配、零成本、退款、mixed 组；不把所有 mixed 组或缺日期组一概排除。
- 验收：七组普通逐笔自动计成本，两个人工列表均不可见且不计数；本息同额/不同额都人工；已人工决定不被覆盖；状态、列表和成本合计分别符合合同。

### 步骤 4：迁移、保存、审计、范围合并

- 增加第 3.1 节元数据列及一次性初始化，更新 migration 注册/测试清单；不覆盖其他迁移编号。
- GET/PUT/DTO/存储同批替换；新增字段进入保存结果核实比较与审计内容，避免“金额相同但锁定选择没保存”被误报成功。
- 保存先锁定并重读当前事实，保留范围外有效来源及锁定选择，再对完整 OA 目标和当前来源容量校验，最后原子写分配与审计。
- 保存返回统一领域生成的任务；移除 save 尾部临时拼接状态导致 GET/PUT 返回不同规则的部分，不新增另一条补偿路径。
- 验收：PUT→持久化→GET→统计/导出→编辑重开完全一致；审计失败回滚；并发旧版本拒绝且不重复计额；旧浏览器明确失败，不静默丢字段。

## 7. 性能设计与测量目标

- 新增唯一逐笔路径用整数分/Decimal 和金额桶，在已取得的独立组内近似 O(n+e)，e 为已有明确来源证据；不增加指数级搜索、全量 OA×银行矩阵或逐笔分类 SQL。
- 保留单快照、批量分类/历史/分配读取。新增往来语义和锁定列随原查询读取；常规接口 SQL 往返数不因本功能增加。
- 人工列表先筛成员再生成分页 DTO，不对隐藏自动组构建表单/组合建议。自动成本仍须参与统计，隐藏列表不等于可以省略其成本计算；不宣称只改显示就消除全量计算耗时。
- 新增规则不依赖打开抽屉。既有昂贵组合建议只在详情对未解决部分运行，保留现有资源边界；未能证明唯一就是待人工业务状态，不是异常被吞掉后的兜底。
- checkbox/输入不触发 GET/PUT；使用既有来源描述预计算，不在每次键入重建所有行的日期/标签格式。
- 本机独立 release build：7×7 规则计算 p95 目标 <10ms；100 行表单输入/勾选 p95 目标 <100ms；详情 responseEnd 到可操作界面目标 <150ms。
- 同数据规模的本机 HTTP 目标：任务详情 p95 <300ms，成本根/任务列表 p95 <1000ms；单并发与 4 并发分别报告。已有规模可能无法达到绝对目标，必须报告真实瓶颈，不借本次承诺重写全库聚合。
- 同一环境改前后至少 30 次读请求，剔除首次启动样本并单列冷读；UI 每动作至少 20 样本。先测 7×7、重复金额、100×100 普通组和代表性全量关系；只在发现问题时扩大测试。
- 对没有预期业务变化的读取，总耗时 p95 不应有可重复的 >10% 回退；若有，定位 SQL/纯计算/渲染后修正。此处是交付实测目标，不添加生产运行时性能门禁。
- 不在生产反复保存虚假财务分配做压测。保存延迟/并发/事务失败使用隔离真实 PostgreSQL。

14. 原银行两个视角金额、银行余额、正式关系成员/状态、往来台账、发票/税金页面原 API 形状和值不受成本保存影响。
15. 纯自动结果占多数、多页混合任务：列表 items、counts、row_count、cursor 和入口角标一致；无前端过滤造成的空页/漏页。混合关系的自动部分不遮蔽其待处理部分，按关系计一次。
16. 从自动成本详情直接调整：GET/取消不新增记录；保存后单次计入人工已完成，成本替换而非叠加；人工修改后重读不被自动规则覆盖。已有人工作业的截图关系继续出现在人工已完成。
17. 纯自动→事实变化后歧义→待分配→事实恢复后自动：列表数量与成本同步变化；人工记录失效继续待核对，不直接恢复自动。关系撤回不留孤立成本/任务。
