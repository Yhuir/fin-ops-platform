# 导入失败任务处理闭环

日期：2026-09-22。状态：代码与测试已实现，按正式发布流程交付；不使用 GSD。

> 9 月 22 日部分记录描述最初的管理员方案；当前实现以文末「共享处理修订」为准。

## 范围与边界

现有 App Health 增加有界任务列表和按需详情；管理员命令归属导入模块，健康 GET 和 Audit 保持只读。个人 owner 权限不放宽。复用 PostgreSQL job/version/result_payload、预览生命周期和 append-only 审计，无迁移、备份、新 worker/read model。

确认已知只表示已读；管理员结束处理保存独立 disposition，不伪造成功。失败结束保留 failed 和错误；待复核放弃复用 session/file/batch discard，同事务取消任务、记录 disposition 与审计。不得对执行中任务执行该操作。所有重试/重新预览/确认拒绝明确结束的任务，成功任务后续意图保持原合同。

## 执行与验收

1. 核实任务来源与错误；详情分开历史错误和当前文件/批次证据，未知不推断。
2. 管理员分页列表/详情/结束命令；版本冲突、幂等重放、事务审计。
3. UI 详情、继续导入或结束入口；提交成功后回读，旧响应不能覆盖；网络结果不明先核实。
4. 当前任务状态脱离整页旧缓存；保持轮询频率和库存缓存；移除旧20条样本与重复查询。
5. 核对个人导入、银行/发票/ETC、其他后台任务和操作历史；覆盖七类测试、并发、回滚、分页、缓存和失败路径。
6. lint、前后端测试/build、关键 E2E、docs；commit/push main，正式脚本部署；线上版本、任务链路和性能实测。

实际业务是否继续不能自动猜测；生产任务只按明确证据和授权处理。主数据库不得删除；任务临时测试数据和文件结束后精确清理。

## 文档影响

更新导入、App Health、权限审计与操作历史的 I/O、状态及测试说明；不修改财务事实口径。最终记录验证命令、性能、发布版本及未决业务处理。

## 已实现的 I/O 和清理

- 管理员接口：`GET /api/imports/jobs`、`GET /api/imports/jobs/{uuid}`、`POST /api/imports/jobs/{uuid}/dispose`。命令输入为任务版本、动作、原因、可选说明；输出为持久化处理记录和版本，不更改原失败结果。
- 导入 service 负责状态和审计，repository 负责 SQL/事务；App Health 仅承载入口与读数。沿用既有文件/ETC 生命周期，不复制导入实现。
- 删除 `dashboard_import_jobs`、dashboard 内旧 import_jobs DTO 和样本组件；统一任务查询，不保留并行旧路径。
- 版本冲突、并发重试与结束、重复提交、响应丢失都显式处理。读取失败保留错误并阻止未知结果再次提交，不自动伪造完成。
- 保留所有财务事实、正式导入记录和普通 owner 权限；无新增表、迁移、worker、依赖或任务备份。

## 再审阅结论

模块边界清晰，无通用调度框架或额外严格门禁；列表/文件分页，详情按需请求；旧样本链路已移除。自动恢复只处理可验证的技术状态，不能自动判断“是否仍需导入”。真实失败任务只有在原文件状态和业务意图明确后才能结束处理，不能为消除提醒冒充成功。性能通过实测报告，不承诺所有网络条件下的绝对耗时，也不承诺未来所有故障永不发生。临时测试集群和本任务日志在验证结束后精确清理，主数据库和平台备份不属于清理对象。

## 共享处理修订（2026-09-23）

目标：全局失败数量能定位到所有平台用户可处理的同一任务；跨用户处理从预览到正式提交完整闭环。用户明确要求不用 GSD，不增加角色、严格门禁、缓存或备用链路。

实施顺序与验收：

1. 列表/详情与命令限定银行/发票/ETC 类型，取消管理员与创建人限制；其他任务保持个人访问。`domain` 先筛选再分页；默认 20 条，文件详情 20 条，摘要不读原件。
2. session/file/batch 仍通过 import workflow 和 domain service；一个共享任务必须精确对应其原始 session/creator。私人未登记草稿不共享。已有 schema 不变。
3. 重新预览、确认、重试使用同一个 durable job/version/lease；创建人不变，操作人快照和 request ID 入 payload。worker 重新校验实际操作人的平台授权；事实、终态及成功审计同事务。原创建人的页面权限不再阻挡接手者。
4. 统一列表/详情抽屉复用现有预览 UI；全局失败域按类型打开，导入页打开相同组件。任务预览不覆盖上传草稿，不开放原页面或设置的其他能力。银行 task 的映射只经窄只读端口取得。
5. 写后回读，现有全局健康/任务轮询驱动状态更新；丢失响应先读取当前任务，不盲目重复提交。普通确认已知不能清除共享失败任务；结束处理保存 disposition、实际处理人和原失败历史。
6. 全仓扫描旧 owner/admin 分支、客户端、测试和文档；删除只在共享导入链生效的旧限制，保留财务 provenance 和其他模块原权限。回归覆盖七类测试（均适用），包含非管理员且没有导入页权限的账号、私人草稿、域筛选分页、跨用户确认/幂等、审计与回滚、浏览器抽屉流程、既有银行/发票/ETC。
7. lint、后端完整回归、前端完整回归/build、关键浏览器流程、docs/diff 检查；提交并推送 main，通过既有部署入口发布，再核对版本、4 个 worker、只读任务及预览链、接口耗时。真实错误文件不为验证而自动确认或结束；无数据库备份，临时测试库验证后停止并精确删除。

设计再审阅：只复用原队列、服务和预览组件；权限简单但仍校验身份、任务归属关系和事务版本。自动恢复仅适用于可证明的技术故障，不能自动补造发票、替用户决定原文件是否继续，也不能保证未来绝无故障。性能以线上样本为证据，不把网络或大文件解析时间混同摘要查询耗时。其他页面通过原 API/状态/权限回归保护，不以承诺替代实测。

本轮验证：隔离 PostgreSQL 上的后端全量 4,506 项测试通过；前端 109 个测试文件、1,473 项测试通过；银行/发票/ETC 和跨用户共享任务 24 项浏览器测试通过；TypeScript/Vite 生产构建、lint、docs 和 diff 检查通过。跨用户 PostgreSQL 用例证明 A 上传、B 重新预览、C 确认后只写入一份发票，原创建人保持 A，完成审计分别记录 B/C 和各自 request ID。七类测试均适用，覆盖业务状态、服务事务、API/权限、后台任务、前端交互、端到端链路及既有模块回归。此前 4,500/1,469 是上一轮管理员方案的数字。

生产验证包含真实历史任务的只读详情/预览、4 个 worker 和版本核对、接口性能采样，以及一个不含财务业务数据的合成文件，验证预览→重新处理→结束→幂等重放→待办移除。合成任务保留正常审计记录，不执行财务确认；真实历史失败任务保留原状态，不据此推断已完成。线上操作人使用本机既有管理员登录态；普通账号的跨用户权限由隔离 PostgreSQL API 和浏览器测试验证，不冒充生产普通账号测试。生产 release 与实测数据在交付报告提供。
