# OA、发票与银行来源详情

2026-09-27。本合同限定右侧抽屉的原始信息区，不改变列表、关联判断、成本核对或用户确认的拆分操作。实施不使用 GSD；验证结果另据实际执行记录，不以本文表示已发布或已通过。字段取舍依据已检查的导入/OA映射，不表示逐条重读全部历史文件并证明所有历史数据；已知无法区分真实时间与解析补值的历史 `trade_time` 不进入来源详情。

## 来源与展示

- 原始详情仅展示具有上传文件或 OA 来源依据的字段。数据库中存在值、字段位于 `raw_payload` / `normalized_payload`，均不能单独证明它来自源系统。
- 缺失保持缺失；真实零值和 `false` 保留。状态码只在状态字段中按确定映射翻译，备注等普通文本不做全局状态翻译。日期/时间格式化不增加来源精度。金额仅整理无效尾零，不四舍五入丢失真实小数。
- 发票直接读取源发票字段；不得以内部 `status` 替代来源发票状态，不以对手方替代缺失销购方，不补零税额，不用金额加税额重算来源合计。详情组含多条来源记录时，逐行展示各自金额，顶层不把聚合金额冒充单条来源值。
- 银行详情删除内部 `pending` 状态、默认币种、导入时所选银行及推导账号后四位。历史 `trade_time` 可能由解析器补入午夜，详情使用确定的 `txn_date` 并标为“交易日期”；`booked_date` 仅使用实际保存值，不用交易日期替代。原始文本字段可按原标签展示。
- OA 流程状态只取明确的 `detail_fields["流程状态"]`，不使用内部 completed/in_progress 或批准默认值。删除推断费用类型、以修改时间充当审批完成时间、附件/明细数量、合计和差额。OA 单号若明确只是 Mongo 文档 ID 且并非真实流程请求/实例编号，也不展示为业务单号。费用明细使用实际 `fee_content`，不回退到可能拼接或推断的 `expense_content`。明确标为“明细合计”的 OA 顶层金额不作为原始金额展示。
- 来源不可用时明确反馈；不能从列表摘要、旧对象详情或其它含义的字段填补。不能通过隐藏所有详情制造完成状态，仍需验证真实字段保留。

## 模块和 I/O

| 边界 | 输入 | 输出与约束 |
| --- | --- | --- |
| `services/source_record_details.py` | 已有银行/发票/OA记录与来源字段 | 纯详情投影，不读取数据库、HTTP、文件或外部 OA；不参与匹配、分类和金额合计 |
| 既有页面详情 query/service | 已授权对象 ID、所属页面上下文 | 保留有界只读快照、身份与权限；只替换详情组装，不改变列表/导出/关系计算 |
| `GET /api/bank-transactions/{id}/source-detail` | 银行身份和既有银行读取授权 | 委托已有 canonical 有界读取，返回 `detail_available` 与 `sections`；权限沿用 bank-transactions 既有页面集合，不包含仅现金授权 |
| `BankTransactionDrawer` | 交易 ID、关闭和保存回调 | 按 ID 读取来源详情；不再接收列表组装的 `sections`；取消旧请求并按 ID 接受当前响应；失败不回退旧值 |
| `EntityDetailContent` 与页面映射 | 已组装公开字段 | 负责字段名与显示格式，不推断业务值；成本核对等非来源内容保留所属模块规则 |

银行拆分仍使用父交易原始金额与父身份，编辑区继续使用原拆分 API、版本和权限。来源详情请求与拆分请求各自负责，不能把“来源详情一次读取”描述为整个抽屉只有一次请求。共享抽屉关闭遵循[既有 X 关闭合同](right-drawer-dismissal.md)。

直接覆盖入口为关联台、银行明细、流水规则批次、批量账务、待找发票、进项使用、销项收款及OA待付款。成本与往来自身的业务计算/关系 section 不套用来源过滤；共享公共 renderer 仅调整无损格式，不改变这些业务字段。各入口保留原权限；不增加访问外部 OA 的页面热路径，不绕过 OA tenant 或页面授权。

OA 待付款对象详情先按 tenant/month 定位 descriptor，复用既有一次 `load_facts` 批量读取，直接选择指定 OA/银行/发票事实并应用来源投影。移除旧 summary→对象详情 builder；列表仍由原 assembler 组装；关系详情的公开分区统一经过 `source_relation_sections`，不把计算汇总或对手方替代的销购方当作原始字段。进、销项前端删除 `summaries` 回填分区的旧逻辑，空分区不会重新拼造详情。

## 旧路径删除

删除详情中的内部状态替代、缺失日期替代、销购方替代、金额/税额补值与组聚合、OA 推断字段及数量/差额展示。移除银行列表拼装 `sections` 的 props 和调用点，移除不再使用的详情专用辅助函数。列表业务状态、关系事实、成本计算及导入内部状态继续由原 owner 维护，不能由来源投影修改。

## 性能与数据安全

复用已有只读快照和批量读取，不逐字段或逐成员查询，不扫描全库、不重新解析文件、不访问外部 OA。纯投影线性处理当前详情。没有数据库迁移、历史数据清洗、备份、新依赖、缓存或 Worker。完成后清理任务临时数据；禁止删除主数据库。

验证前后记录来源详情请求数、查询数、详情 P50/P95；不能将局部投影耗时当作网络端到端耗时。生产验收只读详情和可逆 UI，不提交真实关联、拆分或财务修改。
