## 1. 本轮结论：先完成后端，再做前端，合理

后端先行适合本功能：账户余额、任务分次、来源纠错、非现金冲抵和多账查询先通过真实 API/数据库验证，前端随后接入同一套接口。无需为了后端验收创建临时现金网页，也不需要先把 Make 示例代码搬入 App。

- **后端可作为一个完整开发任务交付**，内部按 B01–B10 小步实现和正常 Git 提交；不是一个巨型 service 或一次不可审查的大补丁。
- “次日前端”可以作为用户安排，但**不能保证后端一天完成**。耗时取决于 OA 原始字段核查、现有连接/权限配置和真实 PostgreSQL 并发与回归结果；不能为赶日期省掉这些实际验证。
- 后端完成指可供前端接入的真实 API、存储、业务闭环及服务器侧验证完成，**不等于现金页面可用或整个模块上线**。浏览器交互、导航、设置页权限勾选、现金页端到端和页面耗时由 F 阶段负责。
- 后端阶段不修改现金页面外观、不登记现金导航或权限 checkbox、不增加前端临时页面。用户已授权后端独立部署；新增 API 仍必须登录并拥有 cash 页面权限。005 默认管理员可用，其他账号不自动获授 cash。
- 业务R1–R7已确认；OA真实字段/阶段编码/字典/分页仍是开发者必须完成的只读技术核查，不能用已有的固定`active`代替。

### 1.1 必须坚持、也必须纠正的绝对化理念

1. **同进程同库不能理论保证零 bug、零资源影响。** 通过受限数据库角色、连接预算、明确 I/O、旧页回归和同时负载测量降低并验证风险，而不是口头保证。
2. **禁止跨池读取，就不能自动跨池查重。** 保证现金不自动复制入普通池、多报表不复制现金；不能暗中查普通金额/hash 判断人为重复。
3. **旧代码按替代关系清理，不是凡旧必删。** 普通页面仍使用的 cash-special、二态项目设置和历史迁移不能因名字相似删除；真正被现金新实现替代的临时/假数据链在同次接线中移除。
4. **禁止兜底不等于禁止明确错误处理。** 权限拒绝、事务回滚、冲突、超时提示和表单草稿保留是正确行为；普通池、假数据、0、上月金额或旧 OA 状态作为替代结果才是禁止的兜底。
5. **不写全局历史不等于撤掉身份/授权。** 现金业务及现金配置均不写全局 requested/completed；005 在平台设置更改页面 ACL 的既有安全审计保留，不包含现金正文。
6. **按需读取 OA 不是瞬时推送。** 保存新项目归属以服务端只读复核时刻为准，OA 与现金库不构成跨系统事务；不新增同步平台或分布式事务。
7. **删除现金不等于撤回真实支付或删除全部关联业务。** 正文物理删除、最少技术身份防旧请求复活；源借款按 R5 明确纠正，其他真实现金/独立非现金事实保留，不能自动造债务。
8. **临时备份清理不能删除主库或唯一恢复资料。** 只清理本任务明确创建且已不再用于恢复的临时 dump/副本；常规备份/PITR、原 Excel 和主数据库不删。
9. **后端交付和页面交付不同。** API 测试不能代替真实浏览器的删除确认、撤权清理、旧响应回填和 receipt→DOM 耗时；F 阶段不能被省略。

### 1.2 保留的最少结构

同一个 PostgreSQL 的 cash schema、一个现金运行角色与有界连接入口；route → service → repository；OA 集成 owner 的项目只读方法；主键/事务/唯一约束/必要版本检查。持久化为技术设计中的 8 类核心表，加稳定账单分组小字典 cash.bill_labels 和最少已删身份 cash.deleted_submission_ids，共 10 表；不为减少表数把稳定身份塞进名称/任意 JSON。3 个一级 Tab、4 本同级账簿由前端实现，不预建报表平台。

不新增第二数据库、微服务、RLS 平台、消息总线、worker、页面 read model、Redis 缓存、通用幂等平台、回收站、私有审计、OCR、导入、外部通知或在线说明 CMS。为删除防复活留下技术设计 §4 已说明的最少身份，不保存业务正文，也不扩成通用审计库。

### 2.1 已确认的验收例子，不代表测试已经通过

| 例子 | 正确结果 |

### 2.3 R7已确认：历史项目结算闭环

用户已接受[历史项目结算规则](../product-specs/cash-module-design.md#102-r7-已确认历史项目结算不是自由新增项目)。自由新增/改选为selection，当前项目必须真实非结束且允许；既有事项真实结算为existing_item，由服务端沿用本地项目ID/名称，不请求OA、不受当前允许集合影响。锚点必须实际参与正额现金分配，事务内校验版本/方向/额度及全部目标同项目；禁止夹带新事项、补本金、混项目或伪造项目。任务new_flow复用同一命令，已有流水认领不改项目或重复分配。

首次使用cash为空时，R3期初旧未结的项目识别须单独落实：仅非现金opening义务可从OA all识别真实历史项目（含结束），不产生flow、不开放普通现金新增。源已消失又无可信本地快照时明确资料缺失，不能猜ID或偷改无项目。R7随后才沿用该真实本地事项。此为已有期初功能的细化，不加新表/模式平台或业务审批轮次。

project_mode只决定首次资格路径，不持久化。重试核对最终项目/现金/原分配等已存业务事实；相同结果零写返回，不同结果409，不能承诺识别未保存的原请求模式。原付款已结清锚点不妨碍返回原未变结果。B05/B06/B07/B09与F03/F05据此实施；当前没有剩余业务选项需要重复确认，但OA/PG真实事实仍须B01核实。

### 2.4 本轮技术复审的具体补齐项

- B04：个人账独立起算存现有settings字段，先设日期再录opening，无首用循环；阶段configured用明确布尔值，个人配置不误标OA设置。

- B07：actual>0不可清空月目标；B08补实际日期、is_opening及无账单组筛选，个人矩阵下钻不误用账单月。
- B09/F05：技术TC21–TC27覆盖上述具体修正；TC28覆盖已确认R7、首次期初历史项目识别与同结果重放。本轮只定义测试，不提前假报通过。无新增表、worker、缓存或通用引擎。

- **责任**：cash repository/migration、依赖组装、route/access/audit、Health/reset/log owner。

- **动作**：运行角色与迁移 owner 分离；检查 PUBLIC/default GRANT、角色继承、视图/definer 旁路；普通角色无 cash，现金角色无普通财务/audit/job；不 SET ROLE、不回退普通 DSN；cash 与普通 pool 总额不超过现有预算。配置缺失只让现金请求明确失败，不使普通页面启动依赖现金配置。
- **兼容检查**：新增 page key 可能改变 `ASSIGNABLE_PAGE_KEYS`、session/ACL/settings 响应和 `/api/background-jobs` 权限集合。逐项验证旧前端不会因新增 key 崩溃、显示无组件入口或保存旧设置时误丢现金授权；不因“任一页面获权”放开普通 jobs。后端完成不等于可以独立滚动发布到生产。
- **验证**：真实测试 PG 双向拒绝及 cash 自身访问成功；成功/失败/配置/删除请求全局 audit 零新增；普通写的审计故障保护不变；005 唯一管理、cash-only 普通 API/jobs 拒绝；旧 session/settings/ACL 响应与现有前端兼容测试；reset 不触达 cash、日志不泄露正文/业务 ID。
- **完成条件**：安全入口和旧客户端兼容有真实证据，无现金公开 UI；现金依赖故障时普通银行等请求正常；不因未做新前端就声称新权限 checkbox 已交付。

#### B03 OA 项目只读 API 与阶段配置

- **依赖**：B01 OA 映射、B02。
- **责任**：OA owner 窄只读方法、现金 route/service、settings repository。
- **输出**：真实 `projects all/selection`、阶段字典、准确 total/page/read_at；现金允许阶段集合 GET/PUT/CAS。全列表包含结束/异常项目，候选仅允许且非结束；首次显式空集合合法。
- **动作**：仅投影项目资料，OA I/O在现金事务外；selection新增/改选及嵌套新事项用稳定ID校验，事务内再次检查配置版本。期初非现金义务从all识别真实历史项目而不按允许阶段过滤；existing_item本地结算不请求OA。已有同内容重放先认领结果，不因后来阶段变化否认已存事实。只改备注/历史删除不依赖OA。
- **验证**：空/未知/新增阶段、结束、字典未使用选项、分页完整、源超时/无权、并发改配置、同名不同 ID；OA 零写、普通财务池零访问；所有历史查询在 OA 断线下正常。
- **完成条件**：真实源样例已核对，错误不伪装空成功；OA 边界明确只读例外，不修改旧普通项目二态语义。

#### B04 账户、分类与首次设置 API

- **依赖**：B02；可与 B03 并行。
- **责任**：现金 settings route/service/repository。
- **输出**：账户/起算/期初、分类启停、账单分组字典等明确 API；cash.bill_labels 仅银行/别名/启停及稳定 ID，不保存卡号/信用额度、不导入账单；金额/NULL/版本规则按技术设计；办理说明首版静态只读，无 CMS。无真实金额种子、无 Excel 导入。
- **动作**：人民币两位；账户现金与信用卡账单分开；期初及起算可明确更正，新起算日不得悄悄排除已有流水；引用后不硬删账户/分类，停用保留历史；初始空配置和配置读取失败区别返回。
- **验证**：空配置→必要配置→可录首笔；同银行两张卡以不同分组 ID 区分，跨月同组稳定、改别名/停用不拆散历史；负余额不拒绝真实输入但返回核对提示；早于/跨起算点显示未知/覆盖范围；更正期初影响后续全部余额而不改普通池。
- **完成条件**：前端可直接消费首次设置状态与明确错误，不需要开发者手工往数据库塞默认资金。

#### B05 手工现金与复合事项写入核心

- **依赖**：B03/B04；与事项结算共用同一 UoW，先实现最少现金主命令，B06 补完整关联规则。
- **责任**：现金 route/service/repository、金额/日期原语与测试。
- **输出**：收款/付款/池内互转 create/get/edit；稳定提交 ID、版本、严格 Money 和可信 actor；单项目或无项目、同项目有界 `related_items`；不保留旧单对象别名。
- **动作**：一个正金额和明确账户两端；按稳定ID顺序锁账户；现金与必要事项/分配由调用方同一事务提交。现金真实金额与分配额区分，未分配部分保留；不为分配复制现金、不自动把支出认费用。FlowCreate严格区分selection/existing_item，后者锚点必须实际正额参与、不可夹带新事项，详细字段只依技术§8.2。复合重放比较最终业务事实与原关联，不新增mode存储，旧编辑不可upsert。
- **验证**：收/付/反向并发互转、非法精度/范围/空值、同额不同 ID、重复/响应丢失/不同内容冲突、跨年/起算边界、嵌套项目、半写失败整体回滚。
- **完成条件**：普通手工主命令真实 API 可用；任何关联分支未接完时明确列未完成，不提供模拟成功。后端整体验收仍依赖 B06/B07，不能提前称现金业务完成。

#### B06 事项/结算、物理删除与源纠错闭环

- **依赖**：B05；任务在 B07 复用本步事务内方法，不能另造一套结算。
- **责任**：现金事项/结算 service、统一 UoW/SQL、flow 删除命令。
- **输出**：借款、票据来源、公司应收、费用、账单等技术设计明确 type；固定 kind 的结算；事项/来源/目标选择器及有界完整下钻；统一现金删除、独立非现金更正/撤销、R5 来源纠正 API。
- **动作**：票据使用可没有抵债目标，票抵必须有来源和目标；使用改抵债更新原处理，不重复占来源；现金还款只引用唯一 flow。金额/状态与版本传播按技术 §5，稳定顺序锁来源、目标与现金，在一条事务里撤旧贡献、校验并写新贡献，不在单行 CHECK 中伪装跨行 SUM。
- **删除**：物理移除目标现金正文及专属贡献，写最少已删身份；保留独立真实事实。cash.deleted_submission_ids 按对象 type/id 区分，覆盖现金和可独立删除/新建的事项；不能只保护 flow 而让原事项创建重试复活。创建等待删除后提交也须认出已删身份。删除范围读取全部关联，不能只删详情预览的 20 条。
- **源纠错**：来源 1000→800、已还 200 得 600；来源不存在时移除错误源义务、解除错误现金归还关系而保留真实现金；义务仍真实时按明确输入换源或确认为独立。超额或真实非现金后续需要明确改分配，不能自动截额/造债务/全禁删除。
- **历史项目**：实现opening旧未结识别真实OA历史项目→本地事项→R7真实现金结算；普通新增仍拒绝结束项目。已有事项在OA断线/源删除/阶段未配置时可结算；资格、金额、版本只查现金事实，不在错误后换selection模式兜底。
- **验证**：票据可用额/并发超额、非现金现金不变、费用只一次/退款不超额、公司回款不二抵个人；现金和独立事项删除与创建/编辑/分配并发、响应丢失重放、同 ID 跨对象类型不混淆、原详情不再返回正文、关联超预览上限、失败全回滚；R5 三类源纠错及独立处理保留。
- **完成条件**：仅 API 即可完成收付→归还/冲抵→纠错/删除全链，不依赖后台修复、前端补偿或人工 SQL；旧请求不能重建删除正文/贡献。

#### B07 分次月任务、历史快照与提醒查询

- **依赖**：B06；只复用已存在现金/结算事务方法。
- **责任**：任务 route/service、现金 repository；不新增 worker。
- **输出**：模板 CRUD/启停、月实例调整、分次实际确认/关联已有流水、未办/核对、当月及逾期待办分页查询；`planned_amount` 与实际累计分开，一 flow 最多一任务。
- **动作**：目标未知时必须显式填写，不将默认/上月金额当实际；到目标完成、超出明确展示且不截断实际现金，分配仍受债务上限。首次重放先认领原提交；已手工录入仅补任务关系，来源仍手工、原分配不重建。
- **历史**：使用模板生效范围和月实例快照。模板修改/停用时，在同一事务集合补齐“旧启用有效范围 ∩ 截至当前月”内缺失月份再改未来模板；不覆盖已有/明确调整实例，不追造停用期间；重新启用明确新生效月。GET 组合既有实例与当前有效缺项，零写、不造现金。
- **日历**：Asia/Shanghai；短月明示月末；提醒日按计划日减0–31天，调整计划日期可到归属月前后各31天，仍保留原month；模板通常改下月/原本更晚月份，停用从下月起，本月和既有明确实例保留，精确算法只在技术§7.3维护。未办/部分办理跨月保留，核对不要求金额；关页不通知。
- **验证**：同月分次、未知目标/超目标、关联已有 flow、重复/并发确认、模板长期未改/修改/停用/重启、过去/未来实例、跨月/闰年/短月；删除一笔后重算剩余与状态；当月目标/模板写/确认并发不覆盖旧快照；补月份只一组 SQL 且有耗时测量。
- **完成条件**：API 可正确返回本月、提前窗口和逾期待办；task/flow/分配同事务，所有 GET 零写、全局 job/history 零新增。这里只交付计算/API，不宣称页内提醒画面已完成。

#### B08 全部报表、详情与筛选 API

- **依赖**：B06/B07；基础现金读可在 B05 后提前实现，最终按本项一次整合验收。
- **责任**：现金查询 service/repository/DTO；不建持久化报表行。
- **输出**：往来账总表、完整现金流水、有票支付、个人矩阵/三子表；账户余额/筛选合计/分页、详情预览及所有关联下钻、历史项目选项。技术 §8 是唯一响应字段定义。
- **动作**：总表每次处理一行、原事项与来源 flow 不双计；常规非往来收支仍在完整流水。R1/R2 固定金额来源、个人橘黄增/绿色减分类由事实给出；矩阵按实际月，账单月独立。现金 flow 多分配不放大，同额不同记录不去重。
- **一致性**：列表/汇总/总数在同一短只读快照；账序余额不随金额排序/项目关键词过滤重算；历史项目来自现金 ID/名称快照，含结束/源删除，不读 OA；所有账表排除已物理删除事实且保留其他真实记录。
- **验证**：四账与个人子表的行粒度/金额、删除后当月和后续期初、NULL/未知起算、后页/同额排序、筛选范围、20 条以上下钻、选择器额度；OA 断线历史可查可筛。
- **完成条件**：前端需要的全部真实查询和写后查询齐备，无浏览器全量算账、N+1 OA/SQL 或假 DTO。

#### B09 后端整合、旧链清理与真实测试

- **依赖**：B02–B08。
- **责任**：各后端 owner、既有共享边界测试；无需现金前端临时页。
- **输出**：七类中本阶段适用的核心/服务/API/读侧/服务级业务链/旧功能回归结果；旧替代路径清理结果和未测清单。
- **验证**：第 5 节真实 PG 权限/事务/并发、全局 audit/普通池零污染；手工/任务→四账→物理删除→全部查询一致；非现金更正、项目结束历史；普通银行/往来/成本/发票/导出/ACL/reset/jobs/cash-special 仍正常。后端共享 ACL 改动须跑现有前端消费测试/构建，但不顺带开发现金页面。
- **完成条件**：真实测试库验证已执行，普通旧页面风险被相应回归覆盖；缺测试数据库/OA 映射不能用 mock/skip/生产 DSN 冒充完成。新现金浏览器用例明确交由 F05，不称本阶段已覆盖。

#### B10 服务器性能测量与后端交接

- **责任**：现金查询/事务/连接 owner、实施文档。
- **输出**：第 6 节服务器性能报告、API/字段/错误示例、测试命令与结果、受控环境配置方式、B 交付清单及 F 接入注意事项；不输出凭据/真实现金 payload。

### 3.4 一个后端任务应如何执行与交付

依次完成 B02 安全/存储、B03/B04 基础输入、B05/B06 金额/纠错、B07 月任务、B08 全部查询、B09/B10 验证交接；B01 源核查贯穿其真实依赖。B03 与 B04 可以由不同 owner 并行，任何任务/报表不能通过另写一套结算绕开 B06。

交付时列出实际改动文件、每项完成/未完成、测试分类和命令、真实 PG/OA 核验范围、性能实测与剩余风险；更新本计划的实际执行记录。核心事务可以不依赖前端点击验证；本轮用户额外明确要求生产部署和验证，因此部署不能被静默省略，也不能在权限/凭据不足时假称完成。若真实 PG/OA/发布验证未完成，报告具体剩余项。

## 6. 性能目标、测量与阶段归属

### 6.1 设计约束

- cash 报表只读 cash.*，OA 请求单独，外部网络不在 SQL 行锁内。
- 服务端 SQL 筛选/分页/集合聚合；列表/合计/总数同一短只读快照，不逐行读 OA/事项，不在 Python/浏览器全量算账。
- 技术 §8.8 的页大小、日期跨度、SQL/锁/连接/OA 超时是测量起点；普通查询默认 50/最大 200、详情预览 20 但可分页查看全部，预览上限不限制真正删除关联。普通期间 366 天的建议不禁止明确父事项/月任务的跨年有界下钻。
- 连接总额不超现有预算；局部 SQL/锁超时不放宽现有更严限制，不改全局 PG 参数。模板补月用集合 SQL/月唯一键，一次短事务，不逐行网络调用。
- 索引先覆盖日期/id、账户日期、任务/月唯一和事项/来源/现金关联；后续依 EXPLAIN，不为每个筛选预建复合索引。
- 不先增缓存、分区、物化视图、报表副本或 worker；减少列/行→SQL/索引→事务/分页→复测。不能为耗时返回旧值/0 或漏所需字段。
