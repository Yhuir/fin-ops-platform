# 拆分流水选择与本息关系闭环

日期：2026-09-24

## 问题与根因

原流水 `txn_imported_0299` 金额 1,001,497.22，持久化子项为本金 1,000,000.00 和利息 1,497.22。修复前生产 `CASE-AUTO-0257` 的正式银行成员只有利息子项，同时包含本金和利息两条 OA。因此页面原金额与关系核对金额不同，并非原银行事实被改成了利息金额。

旧 UI 把子项标签悬浮入口兼作选择入口，并禁用了有拆分标签的父卡片选择；用户难以区分整笔选择与单子项选择。金额展示仅修正卡片不能修复错误正式成员，也不能把原金额当作所有子项已经关联的证明。

## 本轮边界

- 银行 owner 在原有当前页批量投影中附加完整子项 active `relation_case_id`；未占用明确为 null。完整子项仍是展示/选择候选，GET 不建立关联。
- 前端整行点击原子选择全部可用子项；部分已选再次点击补齐。子项标签只展示与悬浮金额，显式“选择子项”菜单负责单项选择。其他 active owner 不可静默跳过或抢占；撤销仍要求当前关系精确成员集合。
- 预览返回 `bank_split_versions`，确认传回同一版本。提交解析与事务内既有成员锁完成后复核版本，事实变化返回冲突；使用既有幂等、权限、事务、审计边界。
- 领域核对显式区分 `bank_original_total`（父身份去重展示）、`bank_related_total`（正式成员方向净额）、`bank_total`（现有明确用途核对范围）、`evidence_required_total`（该范围内按标签规则要求的票据金额）。真实 `invoice_total/evidence_total` 不加本金、不被改写。普通未拆分行沿用原票据核对；混合原流水与拆分子项支持同组核对；特殊往来结清保留原合同。
- 本金是否要求发票取自既有标签配对规则，不按标签名称、金额、对手方或代码常量猜测。SQL 分区与领域异常使用相同票据差额语义，异常代码集合不增加。
- 成本 owner 先复用已有唯一来源分配算法证明整组本金 OA 的所有单元均由本金来源覆盖，再排除该 OA。全组金额、每个来源和每个 OA 单元必须完整覆盖；冲突引用、历史归属、重复金额等歧义保持待分配。自动利息不要求人工保存，不创建人工决定。

不新增表、迁移、后台任务、缓存、read model、依赖或第二套匹配算法。原银行金额、余额、导入身份、OA/发票财务事实不变。

## 已替换旧链路

删除标签点击切换子项选择、拆分卡片禁止整行选择的旧分支；异常 Popover 不再把用途核对额冒充原流水金额。保留仍服务未拆分和明确用途核对的原有逻辑，不能以“删旧代码”为由删除其他页面的有效行为。

## 发布复核发现与补齐

首轮发布后，正常 confirm 补齐本金成员，关系金额已闭合，但成本仍未增加。进一步只读核查发现先前合并历史交叉记录了本金 OA→利息来源、利息 OA→本金来源。旧独立本金组路径仅看标签，错误排除利息 OA。现统一复用现有来源算法证明完整覆盖，失败保持待分配，不在读取时改写历史。

追加真实 PostgreSQL 回归覆盖：错误历史保留两个 OA；正常 cancel 后 confirm 的新历史前态为空；原审计保留；三个成本视角自动增加 1,497.22，人工待分配与已完成均不增加，主流水金额/余额不变。生产纠正采用既有 cancel-link（解除整个正式关系）后重新 confirm，不能用 withdraw-link 逐层恢复错误前态。
