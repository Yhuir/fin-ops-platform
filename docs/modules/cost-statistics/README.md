# 成本统计模块

## 当前设计

成本统计是直接事实源读取页面，不再是 read model 消费者。

每次页面访问、手动刷新、详情查询或导出请求都执行一次独立读取：

1. PostgreSQL 开启 `REPEATABLE READ READ ONLY` 事务；
2. 在同一快照内读取银行流水、OA、正式关联关系、银行标签/确认与设置；
3. `CostStatisticsPolicy` 在内存中按现有业务口径生成五种视图、统计、详情与导出；
4. API 返回本次快照结果，不等待 worker、不入队、不读取旧 Cost 投影。

因此页面读取不受 Cost 版本、dirty scope、outbox 或 worker 状态控制。写操作仍由各自业务模块写入统一事实源；下一次成本统计请求自然读取提交后的事实。

五个视图使用同一组银行成本事件和同一个当前视图搜索合同：搜索在聚合和 cursor 分页之前执行。所有年/月范围统一按银行交易日期；分页在表格内部接近底部时自动加载，局部错误只重试下一页，不触发整页 reload。

五个视图共用同一有界内容高度和表内滚动合同。`按项目`、`按银行`、`按费用类型`、`按标签`在宽度充足时把范围选择和搜索放在同一行；窄内容区允许搜索顺序折行，但时间范围控件不得压缩或截断。`按时间`保留左侧常驻时间栏。空结果只由表格内容区呈现，不在表格上方增加会造成布局位移的第二个提示。

active 正式关系中只要存在一张进行中 OA，该关系整体不进入成本统计，也不能转入无 OA 虚拟项目。全部 OA 已完成时，每条支出流水独立作为正成本事件；同一关系内只有明确标记为“付错退款”的收入才作为负成本事件。每个银行事件再按该关系 OA 原始金额比例分摊到项目和费用类型，按分采用最大余数法保证分摊合计严格等于该事件金额；金额分母为零只做内部除零保护，不新增页面状态。

没有 active OA 关系的支出流水，仅在其实际标签被用户选中时进入用户命名的虚拟项目，费用类型统一为“无 OA 分类”；候选标签只来自当前实际存在的无 OA 支出流水，纳入时仍逐笔复核无 active OA 关系。规则默认名称和标签都为空，并对全部历史期间生效。已有 OA 的同标签流水绝不进入虚拟项目。

三种归因视图的右栏统一叫“成本明细”。OA 分摊行打开分摊详情，明确展示 OA 原始金额、分摊比例、当前银行事件原金额、关系总支出、付错退款、实际现金成本、与 OA 总额的差额及现金比例；无 OA 行和另外两个视图打开真实银行流水详情。详情类型由每行 `row_kind` 决定，不能再按当前页签推断。

`按项目`、`按银行`、`按费用类型`中的 OA 分摊行使用 OA 申请人作为人员身份；日常报销的“报销成员”和支付申请的“申请人”统一输出为“申请/报销人”。无 OA 行、`按时间`和`按标签`展示银行流水的真实对方户名。OA 未提供申请人时保持空值，不用对方户名或占位符伪装。

## 入口

- 页面：`/fin-ops/cost-statistics`
- API：`/api/cost-statistics/explorer`、`export-preview`、`export`、`bank-transactions/{id}`、`allocations/{id}`
- 标签规则：`GET|PUT /api/cost-statistics/tag-rules`
- Audit：`cost-statistics` 页面审计，直接验证 canonical relation 完整性
