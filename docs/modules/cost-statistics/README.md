# 成本统计模块

## 当前产品模型

成本统计有两个业务分组。

`项目成本`保留三个视图：

- `按项目`：项目 → 银行主标签 → 银行子标签 → 成本明细。
- `按流水标签`：银行主标签 → 银行子标签 → 成本明细。
- `按银行账户`：银行账户 → 项目 → 银行主标签 → 银行子标签 → 成本明细。

三个视图消费同一个成本事件集合，期间、搜索和合计口径一致，只改变分组维度。`按银行账户`不是银行流水浏览器。

`银行流水`包含两个视图：

- `按标签`：主标签 → 子标签 → 银行流水明细。
- `按时间`：当前范围 → 银行流水明细。

两个视图消费同一个 canonical 银行流水集合，支出、收入和净支出分别统计；`净支出=支出-收入`。页面只展示支出与收入，净支出保留在 API、导出和校验合同中。银行明细仍负责账户余额、账户维度筛选和流水维护；成本统计不恢复与其重复的原始`按银行`视图。

每条已确认成本行对应一个 OA 单元、一笔来源支出流水及其成本金额。银行账户、主标签、子标签和成本月份全部从该笔来源读取；不能独立选账户或标签。600 元由 8 月建行 350 元、9 月民生 250 元支付时，形成两条分别归入对应月份与账户的成本行。未确定来源的已知成本仅进入全部期间并计入 `undated_amount`，不伪造日期或银行。

页面与导出接受 `time|bank_tag|project|cost_tag|bank_account`。旧 `bank` view 与旧“按标签/按时间标签规则”仍不存在。

五个视图的页头统一只展示银行流水、支出流水和收入流水。左中栏使用 HeroUI `ListBox`：名称完整换行，金额使用 HeroUI“支/收”短 Chip，不显示展开按钮、百分比、归集数或净额；项目显示主标签数，标签显示明细数或项目数，银行账户只显示项目数。

## 读取与写入边界

成本统计是 canonical direct-read 页面，不是 read model 消费者。每个 explorer、详情、预览或导出请求：

1. 在 PostgreSQL `REPEATABLE READ READ ONLY` 事务中读取本次范围所需事实；
2. 项目成本 view 由 repository 批量读取银行流水、OA、active relation、人工分配和无 OA 设置；流水 view 只读取范围内银行流水与批量有效标签投影；
3. `CostStatisticsPolicy` 分别生成唯一成本事件集合或真实银行流水集合并完成聚合；
4. query service 负责视图筛选、稳定 cursor 分页和 API DTO；
5. route 只处理 HTTP、权限和错误映射。

普通读取不使用 Cost queue、worker、Redis、dirty scope 或旧投影。复杂关系人工分配与无 OA 虚拟项目仍是当前成本人口的正式输入；保存成功后当前页面重新读取 canonical facts。

## 成本口径

- active 关系只要有 OA 审批状态未完成，整组不进入成本人口，也不能落入无 OA 项目。已完成 OA 的审批完成时间允许为空，不阻断单据或同组成本；年月仍按来源付款日期。
- 全部 OA 完成后，关系净支出 `N = 支出合计 - 明确“付错退款”`。
- `O=N` 时各 OA 单元原金额是不可改动的目标；`O!=N` 时保留人工确定最终成本的规则。金额相等不证明多对多来源唯一。
- 只有单来源，或单正成本单元且无歧义退款/非成本时自动确定来源。否则进入待分配，用户可以新增来源行。
- 待分配详情可提供 `suggested_source_allocations`，仅作用户确认前的草稿。在当前有效关联范围内，把明确 OA 引用作为候选约束；枚举整笔流水到单元、固定单元共用一笔流水的组合，仅对所有候选互相独立且存在唯一完整分配的部分预填。金额组合是待确认建议，不等于已核实付款事实；界面同行或贪心配平不能证明唯一。模糊组保持未填写，既有会话草稿和保存决定不被覆盖；预填本身不写库、不完成任务、不改变统计。
- 人工分配满足 `C+X=N`；每笔支出的成本、退款冲减与非成本合计等于原额；每个 OA 单元的来源合计等于目标；每笔退款须完整归属到原支出。同一对象与来源组合不重复。
- 来源保存与任务完成分开；银行标签、账户或日期缺失时保存有效分配，任务仍 pending。补齐资料后重新读取即可。
- 月份按来源付款日期；退款冲减原付款月份，原银行流水收入日期不变。
- `N = 0` 不形成成本；`N < 0` 明确失败。禁止比例猜测、默认项目或旧值回退。
- 无 active OA 关系的支出只有命中用户配置的无 OA 虚拟项目标签时才进入成本人口，费用类型固定为“无 OA 分类”。

## 性能合同

- 每次请求一个数据库快照；集合式批量读取，不做逐行或逐关系 I/O。
- 三个项目成本视图复用同一成本构建链；`按银行账户`只增加线性账户归属与分组，不读取银行明细 read model。
- 两个流水视图复用同一批量银行读取与标签投影，在 OA/关系/人工分配查询前返回；不逐行分类。
- 项目成本批量加载来源银行有效标签，完整读取跨月关系后再筛成本日期；不逐行分类。
- 抽屉列表返回轻量摘要，展开时单独 GET 一个关系；未打开抽屉时没有额外全量任务计数请求。任务资格仍需扫描 active 关系，性能由实测约束，不以响应分页冒充数据库分页。
- 搜索先过滤当前视图事实，再计算汇总、分面和分页。
- 右栏固定每页 20 条，显式上一页/下一页；滚动不触发请求。
- 导出受 `COST_STATISTICS_EXPORT_ROW_LIMIT` 保护。
- 性能以本地/生产多次测量的 p50、p95、max 为证据；没有数据支持时不增加缓存、索引、worker 或新表。

## 入口

- 页面：`/fin-ops/cost-statistics`
- Explorer：`GET /api/cost-statistics/explorer`
- 导出：`GET /api/cost-statistics/export-preview`、`GET /api/cost-statistics/export`
- 详情：`GET /api/cost-statistics/bank-transactions/{id}`、`GET /api/cost-statistics/allocations/{id}`
- 无 OA 规则：`GET|PUT /api/cost-statistics/no-oa-rules`
- 人工分配：`GET /api/cost-statistics/manual-allocations`、`GET|PUT /api/cost-statistics/manual-allocations/{case_id}`
