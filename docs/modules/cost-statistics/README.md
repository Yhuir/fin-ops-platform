# 成本统计模块

## 当前产品模型

成本统计有两个业务分组。

`项目成本`保留三个视图：

- `按项目`：项目 → 成本主标签 → 成本子标签 → 成本明细。
- `按成本标签`：成本主标签 → 成本子标签 → 成本明细。
- `按银行账户`：银行账户 → 项目 → 成本主标签 → 成本子标签 → 成本明细。

三个视图消费同一个成本事件集合，期间、搜索和合计口径一致，只改变分组维度。`按银行账户`不是银行流水浏览器。

`银行流水`包含两个视图：

- `按标签`：主标签 → 子标签 → 银行流水明细。
- `按时间`：当前范围 → 银行流水明细。

两个视图消费同一个 canonical 银行流水集合，支出、收入和净支出分别统计；`净支出=支出-收入`。页面只展示支出与收入，净支出保留在 API、导出和校验合同中。银行明细仍负责账户余额、账户维度筛选和流水维护；成本统计不恢复与其重复的原始`按银行`视图。

`按标签`左栏中，“外部往来款付款”和“外部往来款收款”固定为列表末尾两项，付款在上、收款在下；只存在一项时该项置底，两项都不存在时保留原排序，不补空项。其他主标签相对顺序保持不变。期间和搜索结果均应用此规则；两项仍独立下钻，子标签排序与收支统计不变。

每条已确认成本行对应一个 OA 单元或人工成本项、一笔来源支出流水及其成本金额。银行账户和成本月份从来源读取；OA 行默认沿用来源银行标签，也可人工指定每条来源行的成本标签；人工补充行继续使用自选成本标签。两者仅影响成本统计。600 元由 8 月建行 350 元、9 月民生 250 元支付时，形成两条分别归入对应月份与账户的成本行。未确定来源的金额只保留在待分配任务，不进入正式合计；有真实来源但缺日期的成本保留全部期间口径，不伪造日期。

页面与导出接受 `time|bank_tag|project|cost_tag|bank_account`。旧 `bank` view 与旧“按标签/按时间标签规则”仍不存在。

五个视图的页头统一只展示银行流水、支出流水和收入流水。左中栏使用 HeroUI `ListBox`：名称完整换行，金额使用 HeroUI“支/收”短 Chip，不显示展开按钮、百分比、归集数或净额；项目成本三个视角的列表项仅显示名称和金额，计数保留在栏标题；银行流水视角保留行内子标签/流水计数 Chip 与收支双金额。

## 读取与写入边界

成本统计是 canonical direct-read 页面，不是 read model 消费者。每个 explorer、详情、预览或导出请求：

1. 在 PostgreSQL `REPEATABLE READ READ ONLY` 事务中读取本次范围所需事实；
2. 项目成本 view 由 repository 批量读取银行流水、OA、active relation、人工分配和无 OA 设置；流水 view 只读取范围内银行流水与批量有效标签投影；
3. `CostStatisticsPolicy` 分别生成唯一成本事件集合或真实银行流水集合并完成聚合；
4. query service 负责视图筛选、稳定 cursor 分页和 API DTO；
5. route 只处理 HTTP、权限和错误映射。

普通读取不使用 Cost queue、worker、Redis、dirty scope 或旧投影。复杂关系人工分配与无 OA 虚拟项目仍是当前成本人口的正式输入；保存成功后当前页面重新读取 canonical facts。

## 成本口径

- active 关系逐 OA 判断审批资格。已完成 OA 可独立按已确认来源计入成本，进行中 OA 保留在关系与待分配证据中，不阻断已完成部分，也不能落入无 OA 项目。完成时间允许为空；年月仍按来源付款日期。
- 关系净支出 `N = 支出合计 - 明确“付错退款”`。
- 每个 OA 单元独立保存“按 OA 原额”开关。普通完整等额任务默认勾选，原本可编辑的非等额/部分任务保留原行为；外部往来默认勾选。取消后仅改变成本分配金额，不修改 OA 原始金额。锁定时当前范围成本加范围外已确认成本须等于 OA 原额；部分审批仍遵循原有金额上限。
- 选入项目成本范围的外部往来支出必须人工确认，依据银行 owner 输出的 turnover_role 判断，不按标签文本猜测。独立普通来源组件仍可自动计入；与外部往来共享的组件保持待确认。无 OA 外部往来不由虚拟项目规则自动全额计入。贷款利息可计成本，本金通过“不计成本”排除；OA 仅含利息时保持锁定，OA 含本息时取消锁定。
- 完整正式来源组件内，普通支出与 OA 单元可唯一逐笔等额对应时自动分配；金额重复且无明确来源关系、只有组合金额或仅展示同行时仍待人工。自动结果读取时生成，不写人工表，不进入待分配或已完成列表；成本明细可直接“调整分配”，保存后才成为人工记录。
- 待分配详情可提供 `suggested_source_allocations`，仅作用户确认前的草稿。在当前有效关联范围内，把明确 OA 引用作为候选约束；枚举整笔流水到单元、固定单元共用一笔流水的组合，仅对所有候选互相独立且存在唯一完整分配的部分预填。金额组合是待确认建议，不等于已核实付款事实；界面同行或贪心配平不能证明唯一。模糊组保持未填写，既有会话草稿和保存决定不被覆盖；预填本身不写库、不完成任务、不改变统计。
- 人工分配满足 `C+X=N`；每笔支出的成本、退款冲减与非成本合计等于原额；每个 OA 单元的来源合计等于目标；每笔退款须完整归属到原支出。同一对象与来源组合不重复。
- 来源保存与任务完成分开；银行标签、账户或日期缺失时保存有效分配，任务仍 pending。补齐资料后重新读取即可。
- 月份按来源付款日期；退款冲减原付款月份，原银行流水收入日期不变。
- `N = 0` 不形成成本；`N < 0` 明确失败。禁止比例猜测、默认项目或旧值回退。
- 无 active OA 关系的支出只有命中用户配置的无 OA 虚拟项目标签时才进入成本人口，费用类型固定为“无 OA 分类”。

## 性能合同

人工分配上方不显示常驻解释文案，用统一表格展示当前正式关系的 OA／流水对应。详情与关联台复用同一分组算法及正式历史读取；一对一同行，一对多/多对一合并单元格，多对多保留共有关系块。下方草稿仅决定成本分配，不改变上方对应关系；保留原始序号、流水浅灰背景和中央分隔线。打开、重新展开、页面/范围/领域刷新及窗口重新聚焦时读取新事实；关系变化保留脏草稿并停止旧草稿保存，显式重读后重新核对。

保存按钮左侧仅在现有草稿校验完全通过时显示深绿色“分配金额一致”；总额相等但逐单元或逐来源不闭合时不显示，保存中及保存错误时隐藏。提示不改变保存权限、成本准入或统计金额。

- 每次请求一个数据库快照；集合式批量读取，不做逐行或逐关系 I/O。
- 三个项目成本视图复用同一成本构建链；`按银行账户`只增加线性账户归属与分组，不读取银行明细 read model。
- 两个流水视图复用同一批量银行读取与标签投影，在 OA/关系/人工分配查询前返回；不逐行分类。
- 项目成本批量加载来源银行有效标签，完整读取跨月关系后再筛成本日期；不逐行分类。
- 抽屉列表返回轻量摘要，展开时单独 GET 一个关系；未打开抽屉时没有额外全量任务计数请求。任务资格仍需扫描 active 关系，性能由实测约束，不以响应分页冒充数据库分页。
- 搜索先过滤当前视图事实，再计算汇总、分面和分页。
- 右栏固定每页 20 条，显式上一页/下一页；滚动不触发请求。
- 导出受 `COST_STATISTICS_EXPORT_ROW_LIMIT` 保护。
- 性能以本地/生产多次测量的 p50、p95、max 为证据；没有数据支持时不增加缓存、索引、worker 或新表。

## 项目成本范围（2026-09-11）

右上角“项目成本范围”按银行有效标签代码选择来源。首次迁移选中已有支出/通用规则，内部往来款和未标记默认未选，新增标签不自动加入。普通收入标签展示禁用复选框；付错退款仍先冲减原支出，不由收入开关控制。

勾选只编辑草稿，保存后统一更新三个成本视角、明细、导出和待分配数量。空选择为有效零成本范围；无 OA 来源还需满足虚拟项目映射和无 active OA 关系。范围不改配对、不删分配、不改变来源 fingerprint，重新勾选按当前事实恢复成本。两个原始银行视角不受此配置影响。

## 五视角紧凑工作区（2026-09-14）

五个视角填满页面剩余高度，各列表和明细独立内部滚动，栏标题、表头及分页保留。项目成本与银行标签共用 `CostStatisticsHierarchy`，由页面提供展示内容、加载状态、空态及选择回调；按时间保持单表。布局按实际内容宽度适配，层级宽度不足时逐级下钻，明细在内部水平滚动。普通列表项最低 42px，长名称、双收支和摘要自然撑高，不截断财务信息。银行标签计数使用行内 Chip，方向/账户/银行标签保留语义标识；五视角日期均为单行次要文本。项目成本身份列 190px（含项目名时 220px），金额列 155px；超长账户限定在金额列换行。上游选择变化重置下游滚动，翻页回到明细顶部，滚动不触发请求。

工作区规则只在成本统计根节点挂载时约束祖先，不修改公共 FinanceTable、分页或 App Shell 默认行为。已移除银行流水旧高度上限、独立标签分栏与日期 Chip 分支，不改变 API、金额、权限、导出或分配抽屉样式。


## 当前分配范围

项目成本标签选择也约束待分配表格、来源菜单、任务数量及保存校验。范围外流水不显示，也不显示“范围外”；原始银行/关联事实不删除。金额按范围内净支出闭合，排除标签不要求重复填写非成本原因。取消标签保留已保存来源决定，重新勾选恢复有效决定，新增未分配来源保留待办。具体保存合并、退款归属与范围版本 I/O 见 [boundary-io.md](boundary-io.md#待分配范围闭环2026-09-11)。

## 人工补充成本（2026-09-13）

待分配及已完成任务的“新增人工成本”在现有表格增加一行：已有项目、成本项、当前范围内支出来源、成本标签、分配金额。一行对应一笔来源；多项目、多来源可新增多行。项目使用同步 OA 主单/费用明细和项目设置中的真实 ID，只读搜索选择，不创建 OA 或项目。标签从有效银行标签目录选取，保存为成本分类，银行事实不改写；停用选项仅允许原明细保留，不能新选。

人工行与 OA 行共同计入 C；C+X=N 且逐来源核对通过时显示绿色“分配金额一致”。该提示不代表 OA 原金额变成流水金额，也不代表已经保存。成本详情仍保留真实 OA/流水差额。来源付款日期、账户决定人工成本的月份与账户视角，三个成本视图/搜索/详情/导出共用同一成本集合。

单条支出明确关联多 OA、全部单元可归属、无退款且 O<N 时，按 OA 原额预填建议，差额留待人工选择补充成本或不计入成本。预填不写入，不按差额捏造项目或费用。截图 3425.41 与 3617.41 的差额 192.00 需按实际用途填写。

### 混合审批状态的部分分配（2026-09-13）

- 成本 repository 在同一快照读取正式 OA，以及 OA admission owner 中尚未进入正式表的关系成员。正式记录优先，不写回 OA，也不新建镜像。
- 同组有未完成 OA 时允许部分保存：已完成单元的来源金额不得超过原额，进行中单元金额为零。未处理金额保留为剩余，不自动创建人工成本或非成本。
- 共用单条支出且能覆盖完整 OA 原额、无退款时，已完成单元按原额生成唯一来源成本。多个来源按正式独立子组判断，已完成且来源确定部分自动计入；共享且有歧义的来源继续人工，不按相同金额、日期或显示位置猜测。
- 逐支出不得超分、逐退款必须闭合、逐单元来源合计必须等于本项金额。审批完成后保留已保存部分，补齐剩余；状态变化、关系撤回、范围切换均通过下一次 canonical 读取反映。

## 确定来源自动分配（2026-09-14）

自动来源在 Cost Policy 中按当前正式事实生成，列表、详情、三成本视图与导出一致；不依赖打开抽屉、不自动 PUT、不新增数据库记录或后台任务。已完成列表包含自动任务，版本0显示“自动分配”，仍可通过原接口首次人工保存。有效人工决定优先，失效人工决定继续重核，不自动填补已有人工决定的剩余金额。

当前完整关系仅有一笔支出时，它对应全部已关联 OA 的固定目标；历史中曾经只关联部分 OA，不等于最终支付只属于那部分 OA。多笔支出才使用正式历史子组区分来源，明确引用冲突仍停止自动判断。

部分自动结果保留固定 OA 目标；已确定来源进入统计，未处理金额留在 pending。详情只对剩余成本单元和来源生成建议，前端合并确定行与建议行初始化草稿。最终保存保持原完整/混合审批规则。没有正式证据时保留人工，不把金额展示分组当作来源。
