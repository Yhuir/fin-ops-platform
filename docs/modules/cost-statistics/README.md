# 成本统计模块

## 当前设计

成本统计是直接事实源读取页面，不再是 read model 消费者。

每次页面访问、手动刷新、详情查询或导出请求都执行一次独立读取：

1. PostgreSQL 开启 `REPEATABLE READ READ ONLY` 事务；
2. 在同一快照内按视图读取所需事实：`按银行`/`按标签`/`按时间`只读银行流水、标签和其独立规则，两种归因视图再读 OA、正式关联关系、人工分配和无 OA 规则；
3. `CostStatisticsPolicy` 在内存中分别生成原始银行事实视图和归因成本视图、统计、详情与导出；
4. API 返回本次快照结果，不等待 worker、不入队、不读取旧 Cost 投影。

因此页面读取不受 Cost 版本、dirty scope、outbox 或 worker 状态控制。写操作仍由各自业务模块写入统一事实源；下一次成本统计请求自然读取提交后的事实。

`按项目`/`按费用类型`使用成本 `C`；`按银行`/`按标签`/`按时间`使用 canonical 银行净支出 `N`。人工关系可另外记录不计入成本金额 `X`，恒等式必须是 `C + X = N`。项目/费用统计使用关系最新有效支出时间作为确定性事件时间锚点，但该锚点不代表 OA 单元属于某条资金来源；禁止按流水比例伪造银行、标签或月份归属。搜索在聚合和 cursor 分页之前执行；五个视图的右侧明细统一固定每页 20 条，通过显式上一页/下一页使用稳定 cursor 替换当前页，不在前端累积全量 rows。局部分页错误保留当前已确认页并只重试目标页，不触发整页 reload。

五个视图在同一扁平 HeroUI 切换区分为两组：`成本归因`包含`按项目`、`按费用类型`，`银行流水`包含`按银行`、`按标签`、`按时间`。`按银行`使用“银行账户 → canonical 银行流水明细”的两栏结构，选择账户后直接显示该账户真实流水，不再经过项目分面，也不发送 `project_name`。分组说明事实口径，不新增页面或请求链。五个视图共用同一有界内容高度和表内滚动合同。`按项目`、`按银行`、`按费用类型`、`按标签`在宽度充足时把范围选择和搜索放在同一行；窄内容区允许搜索顺序折行，但时间范围控件不得压缩或截断。`按时间`保留左侧时间栏，并复用紧凑 HeroUI `BusinessPeriodPicker` Popover，不常驻展开年份和月份矩阵。空结果只由表格内容区呈现，不在表格上方增加会造成布局位移的第二个提示。

分面列表统一使用行内长文本展开：项目名、费用类型、银行账户、主标签或子标签在折叠态保持最低 66px 高度并显示单行省略号，只有浏览器实测发生溢出时才显示 HeroUI `展开`操作；展开后当前条目按完整文字自然增高，操作切换为 `折叠`，不创建 Popover 或其它浮层。同一列表最多展开一个条目，左中栏状态互不影响；布局变化只发生在当前栏的内部滚动内容，不增加 API、持久化或跨页面 I/O。

active 正式关系中只要存在一张进行中 OA，该关系不进入成本归因，也不能转入无 OA 虚拟项目，但其银行流水仍进入银行事实视图。全部 OA 已完成时，先计算 `N = 支出原额合计 - 同关系明确“付错退款”`。`OA 合计 O = N` 时任意拓扑都按 OA 单元原金额自动形成成本，不进入待分配；`O != N` 时才进入全局人工分配队列。支付申请整张 OA 只输入一次；日常报销逐 canonical 子付款项输入一次，与支出流水条数无关。人工保存按组独立提交，要求全部 OA 单元成本 `C` 加可选“不计入成本金额”`X` 严格等于 `N`，`X > 0` 时原因必填。`N = 0` 不形成任务，`N < 0` 明确报错。canonical 事实变化会使旧分配回到待重新分配，禁止自动沿用、比例回退、默认项目或伪造 OA 单元到资金来源的归属。

人工分配使用 HeroUI 右侧 Drawer：标题行包含“待分配/人工已分配”切换；任务使用可折叠列表，折叠标题只显示业务名称、OA 合计、净支出和状态，不显示内部 ID；展开后显示紧凑 OA/流水事实、逐 OA 单元输入、条件显示的非成本金额与原因，以及仅属于当前关系的保存按钮。时间统一显示为 `Asia/Shanghai` 的 `YYYY-MM-DD HH:mm:ss`，禁止显示 `T`、`Z` 或 `+08:00`。

没有 active OA 关系的支出流水，仅在其实际标签被用户分配给某个虚拟项目时进入该项目，费用类型统一为“无 OA 分类”；候选标签只来自当前实际存在的无 OA 支出流水，纳入时仍逐笔复核无 active OA 关系。规则默认没有虚拟项目并对全部历史期间生效；同一标签在多个虚拟项目间互斥。已有 OA 的同标签流水绝不进入虚拟项目。

“按标签/按时间标签规则”与无 OA 规则完全独立：默认全部标签并自动包含未来新增标签，也覆盖历史/归档标签和“未标记流水”；改成自定义后只影响原始银行事实视图。保存任一规则只刷新受它影响的当前视图。

两种归因视图的右栏统一叫“成本明细”。OA 分摊行打开分摊详情，明确展示 OA 原始金额、分摊比例、本笔支出流水原额、关系总支出、负数付错退款、关系净支出、与 OA 总额的差额及现金比例；无 OA 行和三个银行流水视图打开真实银行流水详情。详情类型由每行 `row_kind` 决定，不能再按当前页签推断。

`按项目`、`按费用类型`中的 OA 分摊行使用 OA 申请人作为人员身份；日常报销的“报销成员”和支付申请的“申请人”统一输出为“申请/报销人”。无 OA 行以及`按银行`、`按时间`、`按标签`展示银行流水的真实对方户名。OA 未提供申请人时保持空值，不用对方户名或占位符伪装。

## 入口

- 页面：`/fin-ops/cost-statistics`
- API：`/api/cost-statistics/explorer`、`export-preview`、`export`、`bank-transactions/{id}`、`allocations/{id}`
- 原始流水标签规则：`GET|PUT /api/cost-statistics/time-tag-rules`
- 无 OA 虚拟项目规则：`GET|PUT /api/cost-statistics/no-oa-rules`
- 复杂关系人工分配：`GET /api/cost-statistics/manual-allocations?status=pending|allocated&query=&cursor=&page_size=50`、`PUT /api/cost-statistics/manual-allocations/{case_id}`
- Audit：`cost-statistics` 页面审计，直接验证 canonical relation 完整性
