## 当前信息结构

```text
成本人工分配                                      关闭
待分配 / 已完成                              搜索
项目名                     状态 · 成本项数 · 流水数
┌ OA 单据/成本项 ─────────┬ 银行流水 ─────────────┐
│ 按 oaId 分组           │ 账户、对方、时间、金额 │
│ 类型、申请人、项目、内容│ 银行标签、退款标识     │
│ 每成本项原始金额       │                      │
└───────────────────────┴──────────────────────┘
项目 | OA/成本项 | 来源流水 | 银行标签 | 分配金额 | 操作
                 新增来源 / 允许时设为零成本
退款归属（有退款时）
不计入成本（按需展开）
                                           保存分配
```

- 两栏列出关系成员，不通过行号对齐或连线暗示配对；实际配对只来自表格分配行。
- 内部 case/OA/流水 ID 不显示在标题、正文、下拉、退款和错误中，程序内部仍使用真实主键。局部序号只辅助辨认，不作持久化身份。
- 删除常驻已分/剩余、净额公式、重复原额和第二个合计输入。错误需要时出现，不能删除金额闭合或权限校验。
- 表格每行只编辑来源与金额；账户、银行标签和付款日期同源只读。源金额用满后仍能查看当前选择；禁用其他选项显示“本项已使用/已用完”。
- 无来源行的成本项仍保留新增入口。非固定任务可显式设零；新增取消零标记，删除最后一行不自动为零。固定正目标不可设零。
- 原型的 mock 保存、随机行 ID、浮点金额、模拟权限、日期截取和标签处理不进入 App。使用现有精确金额、上海时区、真实 DTO/版本/审计/权限。

## 视觉参数与边界

| 项目 | 采用值 |
| --- | --- |
| 抽屉 | min(1320px,100vw)，沿用 AppDrawer |
| 证据区 | 桌面40% OA / 60%银行，左右内边距14px，外边距16px |
| 表格 | 项目150px、OA项170px、标签160px、金额110px，来源自适应；行约40px |
| 输入 | 30px高，5px圆角，细边框；金额右对齐 |
| 颜色 | 主蓝#2454df、文字#1a2233、辅助#6b7a99、金额#92400e、边框#dce4ef |
| 背景 | 白色、浅灰蓝相邻组区分、OA证据浅底 |
| 响应式 | <=960px证据上下排列；<=640px顶部和组标题换行；仅表格横向滚动 |

样式只由 `costSourceAllocation.css` 的 Cost 类名控制，不改全站字体/reset、公共 Drawer 或其他页面。应用对业务信息的必要适配包括正式 DTO 提供的项目/事由标识、完整上海时间、来源局部序号、精确错误和非成本入口；不添加第二套数据或网络模型。

## 验证责任

Make 验证视觉和演示交互；App 使用 Vitest/Playwright 验证真实组件状态、来源表、焦点、权限、失败与请求次数。真实 PostgreSQL 验证持久化、审计、并发、跨月与三视角一致性。生产验证只读实际业务，不为了验收编造财务决定。

普通与100行任务分别记录输入、选择、增删和数据到渲染耗时，测量不与全量测试竞争 CPU；不新增截图 baseline 或性能 gate。新布局替换旧卡片/CSS/targets，保留仍有用的校验和公共能力。未实测的数据不写成达标。
