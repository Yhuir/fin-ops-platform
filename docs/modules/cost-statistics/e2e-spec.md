# 成本统计验收规格

## 核心合同

`/cost-statistics` 提供两个分组：`项目成本`包含`按项目`、`按流水标签`、`按银行账户`；`银行流水`包含`按标签`、`按时间`。三个项目成本视图共享成本事件集合，两个流水视图共享 canonical 银行流水集合；全部来自单个 PostgreSQL 一致性快照，不依赖 Cost read model、queue、worker 或缓存。

## 验收场景

| ID | 场景 | 验收标准 |
| --- | --- | --- |
| `COST-E2E-001` | 项目成本人口 | 相同 scope/query 下三个项目成本根视图的 `summary.total_amount`、`transaction_count` 一致，只改变分组维度 |
| `COST-E2E-002` | 项目下钻 | 项目→银行主标签→银行子标签→成本明细，详情使用同一成本事件合同 |
| `COST-E2E-003` | 银行标签下钻 | 银行主标签→银行子标签→成本明细，项目名和申请/报销人字段正确 |
| `COST-E2E-004` | 银行账户下钻 | 银行账户→项目→银行主标签→银行子标签→成本明细，不展示原始收入/流水列表，不调用银行明细 read model |
| `COST-E2E-005` | 账户归属 | 每行归真实支出来源账户；多账户按来源拆行；未知来源不冒充银行；无 OA 行用自身账户 |
| `COST-E2E-006` | 成本资格 | `O=N` 目标固定但多对多仍人工，来源及金额双边闭合且 `C+X=N`；进行中/不完整关系 fail closed；`N=0` 排除、`N<0` 失败 |
| `COST-E2E-007` | 无 OA 成本 | 只有明确配置到虚拟项目且无 active OA 的支出进入成本；费用类型为“无 OA 分类”；保存后当前 explorer 重新读取 |
| `COST-E2E-008` | 流水方向与标签 | `time|bank_tag` 使用相同流水人口；支出、收入分别统计，净支出严格等于支出减收入；标签路径为主标签→子标签→真实流水 |
| `COST-E2E-009` | 导出 | preview/download 接受五种正式 view；流水导出含方向并使用净支出口径，项目成本导出复用相同账户归属和成本人口，行数上限错误明确 |
| `COST-E2E-010` | 错误与权限 | 首屏失败不伪装空数据，可刷新恢复；只读用户可读/导出但无写入口；非法 cursor/参数明确失败 |
| `COST-E2E-011` | 模块隔离 | 银行明细、导入、Workbench、往来款和设置页面原 API/行为不变；成本请求不产生跨页面写 I/O |
| `COST-E2E-012` | 旧路径删除 | 原始 `bank`、旧 `expense_type` 返回 400；`/time-tag-rules` 不存在；UI 无原始按银行和旧规则抽屉 |
| `COST-E2E-013` | 性能 | repository 无 N+1；五个 view 多次生产请求报告 p50/p95/max；标签→流水与账户→项目→明细每步有界返回 |

## 来源专项验收

- 600 元跨银行跨月拆成 350/250，两月与两账户精确对账；A600/B400 与银行500/500不得自动推荐匹配。
- 每个来源不超额、不重复，退款与非成本不能遗漏来源；固定 OA 目标不得改为500/500。
- 来源保存但缺标签仍 pending，重新打开回填，银行资料补齐后读取收敛。
- 版本/事实冲突保留草稿；并发保存只有一个提交；关联撤回、来源金额更新不产生半读半写。
- Figma Make 原型浏览器验证后移植；真实 App 测试1440与390宽、来源菜单、键盘焦点、增删行、保存/错误/只读。

## 生产验证

- 核对三个成本根总額、两个银行根收支净额；从真实 facet 下钻到主/子/明细并查来源详情。
- 核对付款月份、pending/undated质量字段与任务摘要/详情；不使用真实财务数据做虚构分配。
- 抽样 preview/XLSX 的字段与合计；旧 view、退役参数、旧 time-tag API 明确失败。
- 每个主要读入口多次采样p50/p95/max，报告网络与部署机实际耗时；原银行明细、关联台、导入、设置、权限使用现有只读 smoke。
- 新保存链在独立 PostgreSQL测试库验证；生产部署沿用既有健康、worker、HTTP SLO和事务回滚探针，不增设门禁、不创建备份、不删除主库。

## 紧凑来源抽屉交互补充（2026-09-09）

1. 展开关联组：左侧按真实OA单据组织成本项，右侧银行成员列表；桌面40/60、窄屏上下，不暗示逐行配对。下方单张六列表格，每个成本项保留新增入口。
2. 选择来源及输入金额只改变本地草稿；固定金额不能被派生合计覆盖。未分配不是零，显式设零仅用于允许人工金额且无来源行的成本项。
3. 保存响应丢失时保留草稿并禁用再次提交；GET完整核实本人提交内容后更新状态；409保留草稿；成功后的统计读取失败不撤销已成功决定。
4. 银行来源已用满仍允许当前已选行编辑；删除最后一行聚焦新增入口。来源缺标签时保存仍在待分配，重开保持真实来源。
5. 桌面1320px抽屉，390px宽度无整页横溢出，表格在局部容器滚动；只读仍禁用编辑/保存。
