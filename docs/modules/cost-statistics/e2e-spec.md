# 成本统计验收规格

## 核心合同

`/cost-statistics` 提供两个分组：`项目成本`包含`按项目`、`按费用类型`、`按银行账户`；`银行流水`包含`按标签`、`按时间`。三个项目成本视图共享成本事件集合，两个流水视图共享 canonical 银行流水集合；全部来自单个 PostgreSQL 一致性快照，不依赖 Cost read model、queue、worker 或缓存。

## 验收场景

| ID | 场景 | 验收标准 |
| --- | --- | --- |
| `COST-E2E-001` | 项目成本人口 | 相同 scope/query 下三个项目成本根视图的 `summary.total_amount`、`transaction_count` 一致，只改变分组维度 |
| `COST-E2E-002` | 项目下钻 | 项目→费用类型→成本明细，详情使用同一成本事件合同 |
| `COST-E2E-003` | 费用类型下钻 | 费用类型→成本明细，项目名和申请/报销人字段正确 |
| `COST-E2E-004` | 银行账户下钻 | 银行账户→项目→成本明细，不展示原始收入/流水列表，不调用银行明细 read model |
| `COST-E2E-005` | 账户归属 | 单一支出账户归属该账户；无账户/多支出账户归入`银行账户未确定`；退款账户不参与；无 OA 行用自身账户 |
| `COST-E2E-006` | 成本资格 | `O=N` 自动、`O!=N` 人工且 `C+X=N`；进行中/不完整关系 fail closed；`N=0` 排除、`N<0` 失败 |
| `COST-E2E-007` | 无 OA 成本 | 只有明确配置到虚拟项目且无 active OA 的支出进入成本；费用类型为“无 OA 分类”；保存后当前 explorer 重新读取 |
| `COST-E2E-008` | 流水方向与标签 | `time|bank_tag` 使用相同流水人口；支出、收入分别统计，净支出严格等于支出减收入；标签路径为主标签→子标签→真实流水 |
| `COST-E2E-009` | 导出 | preview/download 接受五种正式 view；流水导出含方向并使用净支出口径，项目成本导出复用相同账户归属和成本人口，行数上限错误明确 |
| `COST-E2E-010` | 错误与权限 | 首屏失败不伪装空数据，可刷新恢复；只读用户可读/导出但无写入口；非法 cursor/参数明确失败 |
| `COST-E2E-011` | 模块隔离 | 银行明细、导入、Workbench、往来款和设置页面原 API/行为不变；成本请求不产生跨页面写 I/O |
| `COST-E2E-012` | 旧路径删除 | 原始 `bank` 返回 400；`/time-tag-rules` 不存在；UI 无原始按银行和旧规则抽屉 |
| `COST-E2E-013` | 性能 | repository 无 N+1；五个 view 多次生产请求报告 p50/p95/max；标签→流水与账户→项目→明细每步有界返回 |

## 生产验证

- 用已部署版本读取三个项目成本根视图并核对 summary 人口与金额一致。
- 读取 `time|bank_tag` 并核对流水人口、支出、收入、净支出一致，且`净支出=支出-收入`。
- 从生产标签 facet 选择一个主标签、子标签，确认明细返回的标签与选择完全一致。
- 从生产 `bank_account` facet 选择一个账户，再选择一个项目，确认返回成本明细且每次响应 view/scope/filter 正确。
- 抽样 `银行账户未确定`（若生产存在）并确认其不计入已确定账户数但金额仍计入总成本。
- 验证旧 `bank` view 400、旧 time-tag endpoint 404。
- 多次测量五个根视图及两个下钻链的 API 耗时，记录 p50/p95/max。
- 运行关键只读 runtime smoke，确认其它页面与服务保持正常。
