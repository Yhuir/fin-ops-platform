# 进项发票使用情况 以发票反提 OA 设计


> 本文件维护 `进项发票使用情况` 页面中 `以发票反提 OA` 的当前确认设计。实现或调整相关功能前必须先读取本文件、`state-machine.md` 和 `tests.md`。

## 目标

`以发票反提 OA` 要形成一个完整闭环：

1. 操作人在 FinOps 的 `待处理` 页签选择目标 OA 申请人和进项发票。
2. 操作人点击 `创建 OA 草稿`。
3. FinOps 后端使用目标 OA 申请人的已配置凭据登录 OA，并创建 `isDraft=true` 的 OA 暂存草稿。
4. 用户在另一个浏览器、浏览器 profile 或无痕窗口中登录目标 OA 申请人的 OA 账户，打开草稿并手动提交 OA。
5. 用户回到 FinOps 当前浏览器，选择 `我已在OA系统提交该草稿 / OA正在进行中` 或 `OA提交内容需修改 / 删除本次提交内容`。
6. 选择 `我已在OA系统提交该草稿 / OA正在进行中` 后，本次进入 `已提交` 历史。
7. 选择 `OA提交内容需修改 / 删除本次提交内容` 后，FinOps 只回滚本地当前草稿状态，重新显示 `创建 OA 草稿`。

## 非目标

- 不做浏览器自动化，不由 FinOps 打开或控制第二个浏览器。
- 不自动提交 OA，不自动启动 OA 流程。
- 用户选择 `未提交 OA` 时，不删除 OA 系统里已经创建的暂存草稿。
- 前端不暴露 `创建本地批次`。batch 仍保留为后端内部状态对象。
- 不在主页面展示大块 `不可提交原因` block；候选不可用原因应使用更轻量的行级状态、数量摘要或错误提示承载。

## 术语

- 操作人：当前登录 FinOps 的用户。
- 目标 OA 申请人：OA 草稿的申请人，也是 OA 系统中草稿创建 token 对应的身份。
- 内部 batch：后端保存本次选择、金额、预览 hash、草稿 id/url 和本地状态的内部对象；前端不把它当作用户操作概念展示。
- OA 暂存草稿：OA 表单接口以 `isDraft=true` 创建的数据，不代表已提交 OA 流程。
- 已提交历史：用户在 FinOps 中选择 `已提交 OA` 后形成的本地历史记录。

## 权限

反提 OA 的权限分两层：

1. 凭据维护权限：只有管理员 `YNSYLP005`，或后端判定为 `can_admin_access=true` 的用户，可以维护目标 OA 申请人凭据。
2. 创建 OA 草稿权限：当前账号必须获授“进项发票使用情况”页面；获权后按页面既有业务状态创建草稿，不再按账户拆分只读/导出/写入层级。

当前操作人不需要等于目标 OA 申请人。创建草稿时的 OA 身份来自目标 OA 申请人的凭据/token，而不是当前操作人的浏览器 token。

## 设置页凭据管理

设置页新增独立区域：`OA 申请人凭据管理`。

第一版字段只保留：

- 目标 OA 申请人
- OA 登录账号
- 凭据状态：`已配置` / `未配置`

第一版操作：

- 新增或保存凭据。
- 更新密码。
- 禁用或删除凭据。

交互规则：

- 管理员输入 OA 登录账号和密码后点击保存；保存成功后状态从 `未配置` 变为 `已配置`。
- 密码保存成功后，前端立即清空密码输入框。
- 密码不回显，GET 列表只返回 `hasCredential` 或等价布尔值。
- 凭据管理不能复用普通 `/api/workbench/settings` 整体保存 payload。必须通过独立 service、repository 和 API 管理，避免密码进入普通设置快照、前端全局状态、日志或测试 mock。

安全要求：

- 密码不能明文持久化。生产优先使用 secret reference；如果使用本地持久化，必须保存加密密文，密钥来自环境变量或部署 secret。
- API 永不返回密码、密文或 token。
- 日志和审计不得记录密码、密文或 token。
- 创建草稿时如果目标申请人未配置凭据，后端返回明确的业务错误。

## 主流程

### 待处理

- 页面顶部使用 `待处理 | 暂存 | 已提交` 切换。
- `待处理` 展示目标 OA 申请人选择、可反提发票候选和主按钮 `创建 OA 草稿`。
- 候选为全部无有效 OA 关联的单张发票，紧凑展示发票号码、日期、销方、价税合计与真实流水关联状态；按全部/已关联流水/未关联流水服务端筛选和分页。暂存占用仍计入基础数量，但显示占用原因并禁选。
- 前端不展示 `创建本地批次`。
- preview 的 `permissions.canCreateDraft` 只表达当前操作人的创建能力，顶层 `canCreateDraft` 表达当前 preview 集合是否满足业务条件，两者不得混用。当前勾选集合存在且销方唯一时，前端允许发起创建；创建前必须对精确集合重新 preview，并以新 preview 的权限、业务状态和 hash 做最终校验。
- 顶部只显示真实的成功或错误反馈；不展示截断的通用禁用原因或 preview warning chip。按钮不可用状态由选择、权限和当前业务条件直接表达。

### 创建 OA 草稿

后端流程：

1. 校验当前操作人拥有“进项发票使用情况”页面权限。
2. 校验目标 OA 申请人存在且凭据状态为 `已配置`。
3. 根据选择的发票重新计算预览，并校验 preview hash，避免用过期候选创建草稿。
4. 创建或复用内部 batch。
5. 通过目标 OA 申请人的 token provider 登录 OA，获取 bearer token。
6. 在现有 batch 事务内按版本取得持久化 draft request claim 后，复用 OA form draft client 创建 `isDraft=true` 的 OA 暂存草稿；同批并发不得重复发送。
7. 保存 `oaDraftId`、`oaDraftUrl` 和本地状态 `oa_draft_created`，该状态立即进入用户可见 `暂存`。
8. 返回确认弹窗所需的业务摘要。

候选排除 active OA 关系；精确选中发票提交时重查完整集合，任一缺失、已关联 OA 或其他未释放 batch 占用都拒绝整体创建。原始发票事实变化须重新预览，单纯银行关系状态变化不替换原始金额或销方事实。

### 用户手动提交

OA 系统不支持同一浏览器同时登录两个账户。用户需要在另一个浏览器、浏览器 profile 或无痕窗口登录目标 OA 申请人的 OA 账户，并在 OA 系统里手动提交草稿。

FinOps 不负责后续 OA 页面操作，也不自动检测 OA 是否已经提交。用户回到 FinOps 后通过弹窗确认结果。

确认弹窗打开后，用户可以选择两项处理结果，也可以点击右上角取消只关闭弹窗。页面刷新、列表轮询、父组件重渲染、preview reload 或取消弹窗都不能清空当前草稿 batch；未决 batch 必须保留在 `暂存` 页签，用户可以稍后继续选择两项处理结果。`暂存` 同时展示尚未发送、请求中、失败或结果不明的占用批次；各状态动作见 `state-machine.md`，不展示 OA 草稿链接。

### 已提交 OA

用户选择 `我已在OA系统提交该草稿 / OA正在进行中` 后：

- 内部 batch 状态变为已提交确认状态。
- 本次记录进入 `已提交` 历史。
- 已提交历史只展示业务可读信息：目标 OA 申请人、确认提交时间、金额、发票数量、发票号或销售方摘要。
- 不展示 batch id、oaDraftId、previewHash、英文状态等内部字段。

### 未提交 OA

用户选择 `OA提交内容需修改 / 删除本次提交内容` 后：

- FinOps 只清理本地当前草稿状态，重新显示 `创建 OA 草稿`。
- 保留内部 batch 的发票选择和目标申请人，便于用户重新创建。
- 清空当前 `oaDraftId`、`oaDraftUrl` 和草稿确认状态。
- 不删除 OA 系统里的暂存草稿。
- 写入最小审计事件用于生产排查，但不在 UI 展示；审计内容不得包含密码或 token。

## 后端边界

后端必须遵循现有重构方向：

- `server.py` 只做路由、依赖组装和 HTTP 映射。
- 业务逻辑放在 `InputInvoiceUsageOaReverseService` 或该模块下的新增 focused service。
- 凭据持久化通过独立 repository 实现。
- OA 登录/token 获取通过 target applicant token provider 封装。
- OA 草稿创建优先复用现有 `HttpEtcOAClient.create_form_draft(...)` 或同等平台 helper，不重复造轮子。
- service 构造函数接收明确依赖，不直接读取 HTTP header/cookie，不直接构造 Flask/HTTP response。

计划新增或扩展的后端单元：

- `OaApplicantCredentialService`：新增、更新、禁用、删除和读取非敏感凭据状态。
- `OaApplicantCredentialRepository`：保存加密 secret 或 secret reference，以及申请人、登录账号、启用状态。
- `TargetOaApplicantTokenProvider`：按目标申请人获取 OA token，处理登录、token 缓存、401 重登和日志脱敏。
- `InputInvoiceUsageOaReverseService`：继续承载预览、内部 batch、创建草稿、确认已提交、未提交本地回滚和已提交历史查询。

## API 设计口径

具体路径可以在实现计划中按现有路由命名收敛，但必须满足以下 contract：

- 凭据列表：只返回目标申请人、OA 登录账号、是否已配置、是否启用。
- 凭据保存/更新：请求可以包含密码；响应不能包含密码、密文或 token。
- 创建 OA 草稿：接收目标申请人、选中发票、preview hash/idempotency key；返回草稿入口和业务摘要。
- 确认已提交：把当前内部 batch 标记为已提交历史。
- 未提交回滚：清理本地草稿状态并返回可重新创建状态。
- 已提交历史：返回业务可读摘要，不返回内部 id 或英文状态。

## 错误处理

必须明确区分以下错误：

- 当前操作人没有创建 OA 草稿权限。
- 目标 OA 申请人未配置凭据。
- OA 登录失败或凭据无效。
- OA 创建草稿失败。
- 发票候选已过期，需要重新预览。
- 发票已存在 active OA 关系，不能重复反提。
- 历史 candidate 状态不进入页面 canonical facts，前端归入 `未关联oa`；若后端无法从 active canonical relation 确认当前状态，应返回候选已过期或结构化查询错误，而不是展示第三种 OA 关系状态或 read-model refreshing。
- 本地 batch 版本冲突或状态不允许当前操作。

错误响应面向用户时使用中文业务提示；日志中可以记录错误码、batch id、目标申请人和调用阶段，但不能记录密码或 token。

## 验收标准

- 设置页管理员可以维护目标 OA 申请人凭据，保存成功后状态显示 `已配置`。
- 非管理员不能维护凭据。
- 获授“进项发票使用情况”页面的操作人可以用已配置的目标申请人创建 OA 暂存草稿。
- 只读或导出类用户不能创建 OA 草稿。
- 前端只显示 `创建 OA 草稿`，不显示 `创建本地批次`。
- 创建成功后显示确认弹窗，弹窗提供 `我已在OA系统提交该草稿 / OA正在进行中` 与 `OA提交内容需修改 / 删除本次提交内容` 两项确认，并允许右上角取消。
- 关闭确认弹窗后，批次保留在 `暂存`；未发送与失败/未知占用也必须可见。请求中不可释放，未知结果核实并清理后可带原因释放，不自动重建。
- 选择 `OA提交内容需修改 / 删除本次提交内容` 后页面回到可重新创建状态，不展示旧草稿。
- 选择 `我已在OA系统提交该草稿 / OA正在进行中` 后记录出现在 `已提交` 页签。
- 已提交历史不展示英文 id 或内部状态。
- 密码、密文和 token 不会出现在 API 响应、日志、前端状态或测试快照中。

## 2026-09-28 候选与占用合同

候选取全部无有效 OA 关联的进项发票，不限制是否关联流水；抽屉按流水关联筛选。分页、总张数和金额在服务端计算，选择本页不等于选择全部候选。跨页选择保留并显示隐藏已选张数，提交前以精确所选发票重做 preview；部分拒绝禁止提交。申请人只取凭据 owner 的 enabled 且已配置项。

已暂存/提交中的反提占用显示在候选行且禁选，不扣除无 OA 基础张数。创建及重新创建使用既有成员锁、行锁和批次状态保证同票不能被两个未释放批次占用；创建草稿只刷新候选占用，正式关联或状态操作后重新读取当前页面。浏览器不自动提交外部 OA。

候选流水关联状态根据 active relation 的 typed 成员判断。即使流水来源详情暂不可用，也不能将既有正式关系显示为“未关联流水”；详情可用性与关系存在性分别表达。

外部请求异常或进程中断后保留 claim；超出配置 HTTP timeout 两倍的核实窗口仅显示结果不明，不等于创建失败。用户人工核实并清理 OA 后可通过既有 `manual-oa-status` 的 `not_submitted` 和明确 reason 释放本地占用。完成/释放均校验版本，迟到的外部结果不得覆盖已经释放的批次。无新增 worker、TTL 重试、数据库迁移或备份。
