# 进项发票使用情况测试矩阵

> 修改本模块前先读取本文件，确认现有测试入口和应覆盖的回归范围。实现后按实际影响更新矩阵。

## 修改前影响面清单

进项发票使用情况页面同时消费 invoice lifecycle direct/query facts、OA/银行/Workbench 关系和 OA 反提本地状态。任何改动都要先按下表做影响面评估：

| 影响面 | 当前事实源 | 需要关注的旧功能 |
| --- | --- | --- |
| 进项发票列表 | `InputInvoiceUsageQueryService` | rows/filter-options/detail/export 直接读取业务事实源；页面不得依赖 freshness 字段。 |
| legacy projection freshness | `invoice_usage_collection` repository、`已下线 input_invoice_usage.read_model.refresh` | 仅作为过渡期后端 projection/worker 覆盖；不再作为页面 API 合同。 |
| 发票生命周期 | `InvoiceLifecyclePolicy`、invoice lifecycle direct/query projection | `paymentStatus` 保持兼容；生命周期变化后由 direct API 读取最新 canonical/import/lifecycle facts，不以页面 read-model refresh 作为验收。 |
| 筛选/排序/导出 | 后端 filter config 和 export service | 前端不能从当前页 rows 推导全局筛选项；导出必须沿用当前筛选和 sort。 |
| OA 反提预览 | `InputInvoiceUsageOaReverseService.preview` | 候选发票必须排除已有 active OA 关系和关联台未配对 OA candidate；rejected invoice 必须保留展示字段供前端显示 `已关联oa` 或 `候选oa`；preview hash 过期不能创建草稿。 |
| relation candidate 展示 | `WorkbenchRelationReadFacade`、`workbench_relation` distribution、`InputInvoiceUsageQueryService` | 关联台未配对候选必须展示在进项使用页面；candidate 不得参与支付状态和 confirmed relation 判断。 |
| `+N` 详情展开 | `InputInvoiceUsageQueryService` | 页面 detail 直接读取 query service；不再保留单行 read-model detail gate。 |
| OA 反提草稿 | `InputInvoiceUsageOaReverseService`、内部 batch repository | 一键创建内部 batch 和 OA draft；不能暴露 `创建本地批次` 用户概念。 |
| 目标申请人凭据 | `OaApplicantCredentialService`、PG repository、settings UI | admin-only；密码只写不读；API、日志、前端状态和测试快照不得泄漏密码/密文/token。 |
| 目标申请人 OA 登录 | `TargetOaApplicantTokenProvider`、`OaLoginClient` | 必须使用目标申请人凭据/token，不使用当前操作人 request token。 |
| 暂存/已提交/未提交确认 | 内部 batch status、staged drafts API、submitted history API | `oa_draft_created` 进入 `暂存`；用户关闭弹窗后可从暂存继续二选一；`submitted` 进入业务历史；`not_submitted` 清理本地草稿字段后可重新创建，不删除 OA 外部草稿。 |
| 设置页交叉影响 | `SettingsPage`、独立凭据 API | 普通 `/api/workbench/settings` payload 不能包含密码；非 admin 不展示凭据入口。 |
| 下游 fan-out | invoice lifecycle、pending invoices、OA pending、tax offset、cost statistics、App Health | 发票导入、规则变化、关系变化和认证状态影响多个页面，需按下游模块继续补 UI/业务流回归。 |

## 关键 smoke flows

1. `发票导入确认 -> canonical/import facts -> /api/input-invoice-usage/rows direct refetch -> 页面表格/筛选/导出`
2. `管理员保存 OA 申请人凭据 -> full-access 用户打开反提 OA drawer -> preview -> 一键创建 OA 草稿 -> target applicant login -> OA draft created`
3. `OA draft created -> 暂存 -> 用户选择 submitted -> submitted history -> 已提交 tab 只展示业务字段`
4. `OA draft created -> 暂存 -> 用户选择 not_submitted -> 本地草稿字段清理 -> 待处理页可重新创建`
5. `关联台 candidate -> input invoice usage 显示候选证据但保持待处理；关联台 confirm -> input invoice usage 重新读取 rows -> linked 证据和已支付状态`
6. `pending invoice rules / relation confirm / tax certification 变化 -> canonical facts / lifecycle policy / direct query services -> input invoice usage / OA pending / tax / cost direct payload 收敛`

Browser e2e 当前覆盖：`direct rows -> 首屏 page_size=20 -> 全局 filter-options -> 销方筛选 -> 开票日期排序 -> page-size 切换 -> 可见行同步`、`rows 暂时 503 -> 错误 alert/错误态空行 -> 普通空态消失 -> 导出禁用 -> 用户 refetch -> rows/pagination/export 恢复`、`legacy read_model_status -> 页面不轮询、不隐藏普通空态/table`、`read_export_only -> 列表可读 -> 导出预览可用 -> 支付规则只读 -> OA reverse preview 不可创建草稿 -> payment rules save / OA draft / batch / manual status durable write endpoint 零调用`、`full_access -> 支付规则编辑 -> PUT 带 expectedVersion/idempotencyKey -> 当前 rows direct refetch -> 新支付状态可见 -> 无保存失败/同步失败残留`、`rows 首屏 -> 以发票反提 OA drawer -> 取消候选子集 -> 子集 preview hash -> 创建 OA 草稿 -> 当前 rows direct refetch -> 无错误残留 -> 确认 submitted -> 当前 rows direct refetch -> submitted history -> 无错误残留`、`relation detail detailAvailable=false -> drawer 显示详情暂不可用且不长期 loading`、`ready +N relation detail -> drawer 展示两条 OA 摘要且零 mutation`、`当前筛选导出 -> export-preview -> 真实 download event -> 下载内容包含 relation/OA/payment 字段且不带分页`、`row-limit export -> 错误可见且零下载`，以及 `candidate relation evidence -> OA reverse candidate disabled -> Workbench confirm -> input invoice usage linked evidence -> OA pending/tax/cost direct downstream payload linked evidence`。`/api/search` 当前没有独立 Browser route，relation 写入后的 search 结果由 direct `/api/search` API/runtime 测试覆盖，不再要求 Search dirty scope 入队或 worker projection。税务认证导入的 Browser 行为由 `web/e2e/tax-offset-flow.spec.ts` 覆盖；跨模块收敛由 direct payload/API/runtime 测试覆盖，不再要求页面 read-model fan-out。OA reverse `evidence_detected` 当前没有用户可见 Browser 入口，且现有 UI 流程不暴露 `canRefreshStatus` 可点击动作；service/API 覆盖 evidence payload、relation command 写入、409 no half-write 和成功 detected 后 direct response。支付规则保存的 Browser 覆盖止于当前页 rows direct refetch；`tests/test_input_invoice_usage_payment_rules.py` 覆盖保存后不再 enqueue `input_invoice_usage` / `invoice_lifecycle` page read-model refresh。暂存恢复由 service/API/Vitest 覆盖；剩余核心缺口是真实 infra direct API 收敛。

## 未测风险

- 本地测试使用 fake OA login client 和 fake OA draft client；真实 OA 登录、公钥 RSA 加密、OA 草稿 URL 打开和人工提交必须在 staging/发布前联调。
- 本轮不运行真实 Postgres/RabbitMQ/Redis 后台任务；invoice lifecycle -> input invoice usage -> 下游页面的真实 direct API 收敛需要夜间或 staging smoke。
- 本地 service page-size guard 和 Browser page-size 切换不替代真实 PostgreSQL 大数据 EXPLAIN、浏览器滚动和导出下载性能 smoke。
- rows/filter-options legacy freshness 字段忽略、relation detail unavailable 诊断、ready `+N` relation detail 正向展开、当前筛选真实下载、`read_export_only` durable write 零调用、full-access 支付规则保存后当前页 rows direct refetch、OA reverse draft/manual submitted 后当前页 rows direct refetch，以及 Workbench relation confirm 后到 OA pending/tax/cost 的 Browser fan-out 已覆盖；search 当前无独立 Browser route，relation 写入后的 Search direct group context 由 API/runtime 测试覆盖，不再要求 dirty scope 或 worker projection；税务认证导入的用户可见 Browser 行为由 tax-offset 模块覆盖，lifecycle/tax fan-out 和 Search direct payload 由 API/runtime 测试覆盖；OA reverse `evidence_detected` 当前无用户可见 Browser 入口，由 service/API 覆盖 relation 写入和 direct response；支付规则保存不再入队 `input_invoice_usage` 或 `invoice_lifecycle` page read-model refresh，由 `tests/test_input_invoice_usage_payment_rules.py` 覆盖。真实 XLSX workbook 完整解析、下载性能和真实 direct API 收敛仍需后续补齐；未来若新增 OA 状态刷新按钮、全局 search UI 或支付规则下游 UI 入口，再补 Browser E2E。
- 前端 Vitest 和 deterministic Playwright 覆盖 FinOps 内部交互和 mapper，不覆盖真实浏览器多账号/多 profile 登录 OA 的人工操作。
