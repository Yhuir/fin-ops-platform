# Phase 21.1 Context — ETC 批次正式关系归属与折叠数量闭环

## 已确认事实

- `etc_business_batch_0014` / `etc_20260622_001` 的 canonical ETC 发票数是 34，金额合计 1584.35。
- 现有 UI 的 `rowCounts.invoice=35` 是 1 条 summary 加 34 条 detail 的展示行数；`collapsedRowCounts.invoice=34` 才是业务发票数。
- OA 与银行流水的 active formal relation 已存在，但 relation metadata 缺少 ETC batch link；因此 summary 仍落在 unpaired owner。
- 当前 paired display resolver 同时接受 `amount_check` 和 `special_metadata`，unpaired exclusion 却只读取旧 `amount_check`，两个投影口径漂移。
- ETC OA canonical payload 已提供精确 `etc_batch_id`。只能使用这个精确标识；禁止金额、名称或模糊文本补关联。
- 匹配 dirty scope 默认 debounce 60 秒、matching worker poll 5 秒，不能满足 operation-to-fresh p99 3 秒。

## 边界决策

- `app.etc_business_batches` 与其 invoice membership 是 ETC 批次事实源。
- `app.workbench_pair_relations.special_metadata.etc_batch_link` 是 Workbench 中批次展示归属的 durable owner marker。
- 所有 relation metadata 写入继续走 `WorkbenchRelationCommandService` 和 `WorkbenchWriteUnitOfWork`；projection、route、OA sync 和 ETC page 不直接写 relation 表。
- matching fact repository 只做一条 bounded/set-based exact-candidate query；matcher 保持纯函数，不感知 ETC UI。
- 只复用现有 matching dirty queue、worker、relation UoW 与 read-model refresh。禁止新增表、worker、cache、API、fallback 或 OCR/附件解析。
- 快速收敛只用于 OA canonical completed 变化和 ETC business-batch status 变化；其他事件保留既有 debounce。
- 共享 canonical 事实正常传播可以改变其它页面的正确数据，但本功能不得写其它页面私有 read model 或引入跨页面 I/O。
