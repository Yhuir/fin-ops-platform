# Phase 21.1 Plan 01

## Task 1 — Lock canonical count and ownership contracts

- Change collapsed-summary expansion to prefer `collapsedRowCounts` before aggregate `rowCounts`.
- Add a regression fixture where aggregate display rows are 35 but canonical detail count is 34.
- Make active ETC batch exclusion use the same complete relation resolver as paired attachment.

## Task 2 — Add exact deterministic relation enrichment

- Add one bounded repository query for completed OA rows with exact `etc_batch_id` and exactly one submitted ETC business batch.
- Resolve candidate OA rows against existing active anchors or formal plans; discard ambiguous/unowned candidates.
- Extend the existing matching write command so relation creation and/or metadata enrichment happen through one transaction boundary.
- Add one batch command-service operation that locks affected cases, validates unique/conflict-free external IDs, merges `special_metadata.etc_batch_link`, records history and saves changed cases once.
- Keep matcher pure and avoid OCR, attachments, amount-only matching and N+1 I/O.

## Task 3 — Close trigger latency without cross-page polling changes

- Permit an explicit per-event matching debounce override while retaining the 60-second default.
- Use zero debounce only for completed OA projection changes and ETC business-batch status changes.
- Reduce only the existing `workbench-matching` worker poll to 0.25 seconds and migrate the exact old 5-second env value for that registration.

## Task 4 — Make Audit fail closed

- Add proof queries for missing exact ETC relation enrichment, conflicting relation/batch ID and duplicate active relation owners.
- Extend fake and PostgreSQL audit tests; verify queue/freshness remains part of the page pass gate.

## Task 5 — Remove retired old paths

- Run whole-repository symbol/text scans.
- Delete the two operator-only link/migration services, CLIs, dedicated tests and stale docs/guards after confirming zero runtime callers.
- Preserve the separate supported historical repair service.

## Task 6 — Verify and release

- Run targeted unit/service/repository/API/read-model/frontend/E2E/regression tests, real PostgreSQL, lint, build, docs and architecture guards.
- Review the diff for isolation, I/O pollution, dead code and over-engineering.
- Commit and push `main`, deploy with `scripts/deploy-oa.sh`, wait for migrations/workers/read models.
- Run production Page Audit, exact 34-count/unique-owner probes and Workbench latency/SLO measurements.

## Self-review

The plan is production-grade but intentionally small: it adds no new runtime component or storage model, uses one exact query and one existing UoW, limits low-latency behavior to the two relevant fact-change events, and deletes the superseded operator paths. It covers correctness, idempotency, ambiguity, Audit, rollback evidence, worker convergence and production performance without changing the meaning of paired relations for non-ETC data.
