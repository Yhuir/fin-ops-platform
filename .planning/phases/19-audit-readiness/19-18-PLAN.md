<objective>
把 `app-health-operations` 从 unavailable 升为 17 页中唯一的系统级 Audit owner：一次管理员只读请求必须在一个 PostgreSQL `REPEATABLE READ READ ONLY` snapshot 内执行其余 16 页的正式 proof、App Health 页面自身的 dashboard/database-runtime expected-set 和 current-effective registry/manifest/worker contract，绑定 system audit id、snapshot/version/evidence set；运行时进程观测和外部控制证据必须分层且 fail-closed，删除 App Health 页面遗留的进项专项 Audit 双轨。
</objective>

<grill_gate>

- 16 个页面各自独立开启/提交事务后再聚合，不是 system snapshot。现有 public proof owner 必须增加显式 caller-owned `AuditSnapshot` I/O；单页入口仍自行创建 snapshot，system owner 只创建一次并传入，禁止 nested transaction、第二连接或 snapshot 字符串伪装。
- App Health 无 own manifest read model，也不消费业务 relation；它不能再次实现 16 页 SQL。系统证明必须只调用 registry-selected finite proof owners，并要求全部 page result 的 `integrity=pass / freshness=fresh / queue=drained / database_snapshot=true`、相同 system snapshot identity 和当前 `contract_revision`。
- `system_audit_id` 是一次不可变证据的 identity，不是永久 freshness lease。报告必须包含 snapshot timestamp/version fingerprint；UI 只能声明“该系统快照内 App 内部合同通过”，不得因按钮曾经绿色而承诺后续写入后的当前状态。
- App Health 页面自身展示的 bank/invoice/OA/import inventory 必须由同一 snapshot 生成 actual dashboard database plane，并由独立 Audit SQL/collector重算 expected counts/timestamps/source families；不能只校验 payload shape或让同一个 SQL复制两份字段互比。
- manifest/read-model/worker/page registries属于代码合同，数据库 dirty/outbox/readiness/heartbeat/job 属于 durable runtime facts。系统报告必须输出稳定 registry/version fingerprint、current-effective scope/worker diff和有界样本；复用当前 manifest command-parent policy，禁止在 Audit 再写一套 `all` 特例。
- API recorder、进程内 request percentiles、RabbitMQ/Redis management、HTTP/SSE、systemd和外部 OA/provider availability不是 PostgreSQL snapshot事实。它们必须放入 `runtime_observation`/`external_evidence`，携带 `observed_at` 和 `pass/fail/unknown/not_applicable`；缺失不得被空数组或零值推导为 pass，也不得污染数据库 transaction。
- `external_evidence` 必须汇总 17 个 registration 的 external boundary，并默认 `unknown`，除非存在版本化且可核验的已登记 control evidence；App内部 overall pass 与 `end_to_end_source_truth=unproven` 可以同时成立，UI必须明确显示。
- 当前 App Health 页面 `InputInvoiceUsageAuditPanel`/`runInputUsageAudit` 是统一 page registry 完成后的遗留 page-private职责。系统 Audit 上线后 whole-repo caller scan 删除该 panel/state/client usage，不保留 fallback；通用 `fetchPageAudit` 仍供所有页面和 App Health system page调用。
- route只做 admin权限/参数/HTTP mapping；`OperationsAuditService` 编排；`PostgresOperationsAuditRepository` 和专属 system proof module拥有 snapshot/SQL；dashboard projection通过窄 builder port注入。Audit严格只读，不 enqueue、不 refresh、不 repair。
- PostgreSQL integration必须证明一个 outer transaction、17页 registry全覆盖、任何单页遗漏/field/relation/queue failure使系统 fail、外部unknown不被宣称为端到端pass、dashboard inventory drift fail closed。不得连接生产。
</grill_gate>
