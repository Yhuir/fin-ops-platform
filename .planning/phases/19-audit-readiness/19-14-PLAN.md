<objective>
把设置页面从 unavailable 升为可证明的 direct-canonical control-plane 页面：在单一 repeatable-read read-only snapshot 内，证明 settings singleton、项目/权限/Workbench/OA 配置、OA applicant credential 非敏感摘要、设置 reset job 状态与关键配置 fingerprints；不把所有受影响 read models 冒充页面消费者，不泄露 secret，不执行 provider/OA/reset I/O。
</objective>

<grill_gate>

- 设置页没有独立 manifest read model；`app.app_settings(settings_key=app_settings)` 是页面配置 singleton，`app.oa_applicant_credentials` 是独立 credential owner。Workbench/tax/cost/search 等只是在设置写后受影响，不是页面 read model keys。
- Audit 不能把 settings payload 与自己比较后声称 independent proof。必须从正式 structured version/key、归一化配置 family、独立 credential rows、正式 project/manual-import/reset job facts重算 page contract、集合和 fingerprints；没有第二表示的直接字段只证明 schema/invariant/registered membership，不能虚构 projection equality。
- credential Audit 只允许读取 target code、display identity、enabled/status、password 是否已配置、version/time 等非敏感元数据；禁止返回 encrypted password、token、password hash、raw secret 或可逆 fingerprint。
- 设置页不展示或消费 Workbench pairing relation，`relation_proof_required=false`。保存设置造成的 downstream dirty/outbox 属于写操作影响合同；本页 Audit 只检查当前 control-plane job/queue 和配置 source version，不扫描所有页面关系来替代后续 system snapshot。
- 数据 reset 是高风险异步 job。pending/processing/retryable failure 必须让 queue 非 drained，terminal failure 阻断 integrity；Audit 不创建、取消、重试、ack 或恢复 reset job。
- OA 项目同步、OA manual search/import 外部结果和真实 applicant 登录不在同一 PostgreSQL snapshot。Audit 只能证明 App 已登记项目/manual-import/credential 控制事实；外部 OA 完整性、credential 可登录性和 reset 后真实多页 smoke 属于 external/production gate。
- `server.py` 旧 inline settings handlers、内存 `_snapshot` 补字段、state JSON/full-state fallback 已删除；whole-repo scan 只删除仍能绕过 `SettingsApiRoutes` / `AppSettingsService` / reset job boundary 的实际 runtime path，保留有 owner 的 migration/audit/rollback 工具。
</grill_gate>
