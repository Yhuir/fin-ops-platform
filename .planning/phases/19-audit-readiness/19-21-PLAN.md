- 内部证明 gate：生产 System Audit 必须用一个 `REPEATABLE READ READ ONLY` PostgreSQL snapshot 直接比较 canonical facts/relation facts 与全部页面 projection/consumer；不读取外部 artifact，不要求长期保存的数据副本。

- Release gate：禁止从当前 dirty worktree 直接部署。必须先区分并保留用户改动，形成经过 review、全量验证且可追溯的单一 release commit；生产 active release 必须精确匹配该 commit。
- 凭据 gate：使用受控 deploy/migrator/operator 入口，不在聊天、日志、仓库或 report 输出连接串、token、credential 或 manifest item payload。
- 部署后只运行 System Audit GET/readonly evidence；不得顺带 refresh、drain、repair、直接 SQL mark-fresh 或修改业务/relation/read-model facts。
- 内部成功要求：release/migration currency、17 页 integrity pass/freshness fresh/queue drained、同一 snapshot/version set 和 consumer relation equality。外部 unknown 不改变该内部结论。
- 失败分流：unknown 回到缺 evidence；revoked/expired 回到 evidence lifecycle；missing/extra/field/control mismatch 区分 collector/source 错误与 App sync/canonical 错误，生成一个新的最小受控 repair plan，必须另行授权后才执行任何生产写入。
- Audit 后发生任何 App 写入或外部 snapshot 更新，旧报告自动降为历史证据，不继续宣称当前绿色。
</grill_gate>
