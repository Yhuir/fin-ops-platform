<objective>
封堵 OA 待付款与待找发票两个完整成员摘要 consumer 的跨页遗漏：在各自页面 Audit 的同一只读 snapshot 中，证明 shared linked relation 的适用 typed edges 与页面持久化 consumer summaries 双向相等。
</objective>

<grill_gate>

- 两页都持久化带 case id/status 的 OA、bank、invoice summaries，足以形成 actual edge set。
- expected set 只来自已经由 canonical equality 证明过的 `workbench_relation_groups`，不从页面 payload 反推，不创建第二事实源。
- OA 待付款只消费 App 已登记且页面合同接纳的 OA 关系，并只登记该页面业务支持的 input invoice edge。
- 待找发票以 active bank transaction 为页面 anchor；expense/income 分别把 invoice summary 解释为 input/output invoice。
- scope 复制是 shared distribution 的存储细节；consumer equality 使用 `case_id + row_id + row_type` 逻辑 union，同时保留最小 scope 作为诊断。
- 不把无 case id 的 standalone/fallback summary、candidate 或非 linked summary当成正式 relation。

</grill_gate>

<scope>

- 新增一个只读、无 HTTP/refresh/write 职责的 page-consumer relation proof repository module。
- `PageAuditContract` 显式登记 consumer proof owner；没有登记的页面不得伪称已证明 consumer projection。
- proof revision 升级，成功文案仍限定为“已登记 App 内部合同一致”，不得声称外部来源完整。
- 不修改业务 read model、relation 写路径或生产数据。

</scope>
