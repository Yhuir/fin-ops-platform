<threat_model>

- 最大风险是“已登记”被误读为“已证明”；因此 `proof_availability != ready` 必须在 service、HTTP 和 UI 任一层都不能变成 pass。
- 最大迁移风险是页面继续调用 specialized route；由 frontend literal/architecture guard 阻断。
- invoice queue 必须查 durable PostgreSQL state，不能从缺少 issue 推导 drained。
- registry 只允许有限 executor，不接受动态 import、字符串函数名或 fallback。

</threat_model>

<success_criteria>

- frontend 17 页与 backend Audit registry 集合严格相等。
- 当前 9 页通过唯一 page-key route；8 页 fail closed。
- 进项/销项 outbox backlog 会让 `queue=backlog` 且页面不能显示通过。
- 页面 runtime 不再调用两个 specialized Audit HTTP route。
- 未增加第二事实源、第二 queue 或动态插件层。

</success_criteria>
