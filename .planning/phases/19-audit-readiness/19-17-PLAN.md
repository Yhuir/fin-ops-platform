<objective>
把 ETC 发票导入页从 unavailable 升为可证明、可跨进程恢复的 direct-canonical workflow：上传 ZIP、对账任务绑定、preview expected-set、durable session/file/object、confirm job/outbox、worker 状态和导入后的 ETC task/business-batch/import-batch/invoice/canonical-link 闭包必须在清晰 I/O 边界内完整；移除进程内 preview/confirm 与旧直导 410 runtime surface，禁止 Web 进程内存成为生产事实源。
</objective>

<grill_gate>

- `/imports/etc-invoices` 没有 own manifest read model。Workbench、invoice lifecycle、tax、cost、search 等是写后 impact targets，由各自页面 Audit 证明；本页 registry 必须使用 `read_model_keys=()`，不能把下游投影冒充本页 consumer。
- 本页消费的不是 Workbench 业务配对关系，而是 ETC 对账任务→expected requirement→ZIP invoice match→ETC import session/file→business/import batch→ETC invoice→existing canonical invoice bridge 的内部 typed edges。`relation_proof_required=true` 只声明这组页面内关系，不能声称证明下游 Workbench 配对。
- 当前 `EtcService._import_sessions` 与 `Application._etc_reconciliation_import_previews` 都是进程内 dict，`snapshot()` 不持久化 session；正式 Web enqueue 后，独立 PostgreSQL worker 无法读取 ZIP/session。必须使用现有 `app.etc_import_sessions`、`app.file_objects`，并新增最小的 session-file relational metadata，ZIP bytes 只经 object/file store port；raw JSON 不保存文件 bytes。
- 路由只负责 multipart/HTTP 映射；preview application service 负责 parser/filter 与 durable session admission；session repository 负责 PostgreSQL metadata；file-object port 负责 bytes/hash/read/delete。`EtcService`/worker只能依赖窄 session port，不能读取 HTTP、整个 `Application`、SQL 或 state-store 私有字段。
- preview session 必须冻结 task id/version/confirmed-item-set hash/zip-preview generation、每个输入 ZIP identity/hash/size、included/excluded/missing/ambiguous match edge 和 preview counts/fingerprint。confirm 与 worker必须从 durable session重读，不能信任前端或进程内缓存。
- enqueue 是唯一正式 confirm 路径。queue/repository unavailable 必须在 task 仍 ready 时 fail closed；`begin_import` 移到 worker并对同一 session idempotent，消除“先把 task 标为 importing、进程在 enqueue 前崩溃”的悬挂窗口。worker retry只能复用同一 durable session/task binding。
- expected-set 必须双向证明所有非过期 durable preview sessions/files、session↔task binding、preview requirement/match edges、terminal session↔business/import batch/invoice edges，以及已登记 task/business/invoice/canonical bridge。可在同一 snapshot 复用 ETC tickets integrity collector，但 imports executor必须拥有自己的 session/job归属、preview字段和queue gate，不能复制第二套 ETC tickets SQL。
- `app.file_objects` hash/size/locator 只证明 App 已登记 ZIP；数据库 Audit 不读取对象 bytes，也不能证明外部 ETC 平台 ZIP 没有漏文件、控制总额正确或真实 OA 状态。对象可读性和外部 control evidence 单列。
- 旧 `POST /api/etc/import` 410 guard、inline `run_job`、`execute_etc_invoice_import_confirm_job` route dependency、两个进程内 preview dict 是已识别旧 runtime surface；whole-repo caller/schema scan 后删除，不保留 compatibility fallback。历史 repair/cleanup 工具若有正式运维 owner则保留且不得进入页面/API链。
</grill_gate>
