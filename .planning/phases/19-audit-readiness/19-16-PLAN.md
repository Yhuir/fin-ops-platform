<objective>
把发票导入页从 unavailable 升为可证明的 direct-canonical workflow 页面：在一个 repeatable-read read-only PostgreSQL snapshot 内，证明 input/output invoice file/session、file object registration、preview batch/row/count、confirm 后 canonical invoice identity/critical fields/manual source-link edges，以及精确归属于本页的 import job/outbox；同时删除可绕过 durable file-import queue 或制造不可证明状态的 inline confirm、batch revert 和 import-file batch-column 旧链。
</objective>

<grill_gate>

- `/imports/invoices` 没有 own manifest read model，也不展示业务配对关系。registry 必须使用 `read_model_keys=()`、`relation_proof_required=false`；Workbench、invoice lifecycle、pending/input/output/OA pending/tax/cost/search 是写后 impact targets，由各自页面 Audit 证明，不能冒充本页 consumer。
- 页面 canonical expected-set 是所有已登记 input/output invoice import files、其 preview/confirmed batches、全部 rows，以及这些 terminal rows 引用和所有 `manual_invoice_import` source-link 反向枚举得到的 canonical invoices。不能从 `app.invoices.source_batch_id` 单向猜 ownership，因为 duplicate/status-update 会把其改为最新批次；正式归属边是 `(invoice_id, batch_id, source_id)` source link 与 row reference 的集合相等。
- `created`、`status_updated`、`duplicate_skipped` terminal rows 必须引用 invoice，并具备对应 manual source link；`error`、`suspected_duplicate` 不得伪造 canonical link。多条同批重复 row 可归并到同一 source-link edge，但每条 row 仍须单独证明，且每个实际 manual source link 必须至少由一个已登记 terminal row解释。
- invoice type/number/code/digital number/date/counterparty/seller/buyer/tax IDs/amount/tax/total/tax rate/source status/identity/fingerprint 等字段必须从 structured row、normalized row 与 canonical invoice 独立比较；冲突不能因“duplicate skipped”而通过。batch decision counts 与 file/session preview audit counts必须从全量 rows重算。
- 页面共享 file API 不意味着共享 Audit queue：`file_import.confirm` job 必须按 session + selected file ids + batch type 精确归属。发票任务不得阻断银行页，银行任务也不得阻断发票页；相关 outbox 只能由归属 job id 集合筛选，禁止租户级全局误归属。
- `app.file_objects` 只证明 App 收到并登记 hash/size/object locator；不证明税务平台导出完整、文件未漏票或外部 control total 正确。外部发票 control evidence继续作为独立 gate。
- 正式部署 PostgreSQL import worker 使用 durable `job.import_jobs` + `job.outbox_events`。当前 API 将 `postgres` 配置判为非法/disabled 并退回进程内 confirm，是平行写链；file confirm 必须始终 enqueue，queue/repository 不可用时 fail closed，RabbitMQ只能作为可选 wakeup。
- `/imports/batches/{id}/revert` 没有前端正式 caller，且当前实现不会撤销 duplicate source link/merged fields，能制造无法双向证明的 canonical 状态；删除 route/client/service/tests，不以补丁保留伪回滚。只读 batch detail/download 如仍有 owner可保留。
- `app.import_files.import_batch_id` 没有生产 writer，正式 session edge在 file payload 的 preview/confirmed batch id；删除 Audit fallback、索引和列，并以 whole-repo guard 阻止反向恢复。migration/audit/rollback 工具之外不得存在第二发票池、full snapshot preview facts或 direct read-model write。
</grill_gate>
