<objective>
把税金抵扣页面从 unavailable 升为可证明的 ready 页面：在单一 repeatable-read read-only snapshot 内，以 canonical invoices 与 certified import records 独立证明全部 output/input-plan/certified/matched/outside rows、关键字段、锁定/默认选择、税额 summary、scope/source_versions 和 durable queue 状态。
</objective>

<grill_gate>

- 当前税金 read model 有五类物化 item：`output`、`input_plan`、`certified`、`certified_matched`、`certified_outside`；只验证 read-model row count 不能证明认证匹配或页面锁定状态正确。
- canonical invoice set 是当月 active `app.invoices`，certified set 是 active `app.tax_certified_import_records`；read model 或旧 TaxOffsetService snapshot 都不能反向充当 expected-set。
- certified→input-plan 匹配必须独立重算当前优先级：digital invoice number → invoice code+number → seller tax/name + issue date + tax amount；同一认证记录漏配、错配、重复配或伪造 outside 均 blocking。
- 税金页面不读取或展示 Workbench relation，因此 `relation_proof_required=true` 是错误声明，不应虚构第二 relation consumer。该页登记为 false；发票使用/关联台页面继续负责全部 shared relation edge equality。
- `app.tax_offset_plans` 是写入审计事实，但当前页面 read payload 不回读计划列表或用它生成默认集合；本页 Audit 不应把未消费 plan rows 混入页面 read-model expected-set。plan save 的权限、version conflict、idempotency 与 write target 由既有写链测试负责。
- `tax_offset/all` 是 manifest fan-out command，不是 queryable page scope；页面 proof 只审计 canonical month shards，不能要求虚假 all read model。
</grill_gate>
