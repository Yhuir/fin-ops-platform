<objective>
把 ETC 票据管理页面从 unavailable 升为可证明的 ready 直接事实页面：在单一 repeatable-read read-only snapshot 内，独立证明用户可见 business batches、ETC invoices、reconciliation tasks/files、批次↔任务↔发票关系、展示汇总和 ETC import job queue 状态；不把下游 Workbench/tax/cost 影响列表冒充本页 read model。
</objective>

<grill_gate>

- ETC 页面没有独立 manifest read model；当前页面直接读取 canonical business batch/task/invoice/file facts。Audit success 不能要求一个不存在的 page read-model status，也不能硬编码 `fresh`。统一 UI gate 只有在 `registered_read_model_keys=[]` 时才允许以 Audit 自身 freshness/queue 作为页面 fresh 证据。
- 页面实际消费三个读面：business batch list/detail、reconciliation task list/detail/source files、按 import batch 查询 ETC invoice items。`workbench`、`workbench_relation`、`invoice_lifecycle`、`tax_offset`、`cost_statistics` 是下游影响目标，不是 ETC 页自己的 read model keys，必须从 registry 页面消费清单移除。
- 本页存在真实内部 pairing：business batch ↔ linked task、business batch ↔ ETC invoice、import/submission batch ↔ invoice，以及 reconciliation card/ticket/supplement edge。`relation_proof_required=true` 只有在这些页面内关系做双向 equality 后才可保留；不得用下游 Workbench relation 正常替代内部关系证明。
- submitted business batch 的 `etc_invoice_summary` 是否完整属于 Workbench canonical inventory proof，已由 19-10 覆盖；ETC 页不显示 shared Workbench relation 状态，因此本页 Audit 不重复第二套 Workbench SQL，也不宣称 shared relation consumer equality。
- canonical list/detail expected-set 必须从 normalized columns、link tables和正式文件/任务表重算，不能把 `raw_payload` 整包同时当 source 和 consumer 后做自比较。raw payload 只用于未迁移但仍正式登记的字段，并必须与结构化列/关系表交叉验证。
- 对象存储文件字节、真实 ETC 平台归档和真实 OA 草稿不在同一 PostgreSQL snapshot；Audit 只证明 App 已登记 file metadata/object key/control totals，外部文件 hash/可读性与 OA 外部状态必须由独立 external gate 证明。
- `job.import_jobs` 中 ETC import 的 pending/processing/retryable failure 必须让 queue 非 drained；历史 completed/acknowledged/cancelled 不阻断。任何 Audit handler 不得确认、重试、删除 job 或刷新 downstream。
</grill_gate>
