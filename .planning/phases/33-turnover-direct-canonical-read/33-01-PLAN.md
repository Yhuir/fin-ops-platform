# Phase 33 Plan 01：外部往来款直接读取统一事实源

## Objective

把外部往来款的主表、详情和导出读取切换到同一个 PostgreSQL canonical snapshot，删除自身
read model、隐藏的 Bank Detail read-model 依赖、refresh worker/freshness/polling 运行时路径，
同时保持写入事实、API DTO、权限和其它页面边界不变。

## Tasks

1. 添加 direct-canonical query/service 测试，冻结一致性快照、配对 tag、API DTO 和零 queue I/O 合同。
2. 在 `TurnoverLedgerQueryService` 内复用现有事实 repository/domain service，以一个
   `REPEATABLE READ READ ONLY` transaction 读取所有输入并生成 grouped payload。
3. 让主 GET、导出和 relation detail 复用唯一 query owner；写 route/UoW 不变。
4. 删除 Turnover read-model query/refresh/projection/worker/registry/frontend polling 旧链路，
   并更新 Audit/App Health/部署配置。
5. 运行定向七类测试、lint/docs/build、性能与无关页面隔离检查。
6. 推送一个 main candidate，部署后使用 test-owned 可恢复 fixture 完成确认/撤回、关联台一致性、
   页面性能、零 Turnover fan-out、queue/worker drain 和 System Audit 生产验证。

## Verification

- Targeted backend unit/service/API/read-model-removal/integration tests.
- Targeted Vitest and the critical Turnover/Workbench Chromium flow only.
- `bash scripts/verify.sh lint`
- `bash scripts/verify.sh docs`
- frontend production build and `git diff --check`
- one candidate deploy followed by one complete production sweep before any correction.

## Success Criteria

- Direct GET returns complete canonical rows and relation tags without waiting for a worker.
- GET and post-write reload create zero Turnover refresh I/O.
- Export/detail use the same snapshot owner.
- Other page implementations and their read-model registries are unchanged.
- Retired runtime code has zero callers and is deleted rather than kept as fallback.
- Production fixture is restored and measured latency, queue, workers and Audit are recorded.
