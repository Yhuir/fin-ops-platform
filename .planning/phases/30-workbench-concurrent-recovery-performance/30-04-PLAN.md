<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| standing approval → apply runner | 只有既有 ticket、test-owned bounded fixture 和授权环境才能 mutation |
| runner → production APIs | 所有写均走正式 preview/confirm/withdraw，不允许 direct DB repair |
| relation mutation → page consumers | mutation 本身 zero fan-out，consumer 只按 scenario-specific access convergence |
| Candidate evidence → fix loop | 必须先完成全链收集，再决定唯一集中修复/Candidate B |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-30-04-01 | Spoofing/Elevation | production apply | mitigate | admin token wrapper、standing approval、test-owned IDs、actor/tenant server auth |
| T-30-04-02 | Tampering | fixture/inverse | mitigate | preimage fingerprints、expected versions、最后 preview identity、正式 withdraw cleanup |
| T-30-04-03 | Repudiation | Candidate actions | mitigate | release SHA、request IDs、idempotency、history、audit 和 issue ledger |
| T-30-04-04 | Information Disclosure | evidence | mitigate | 不把 token/业务 IDs写入仓库或日志；证据使用受控路径与 request IDs |
| T-30-04-05 | Denial of Service | preview samples/consumer probes | mitigate | samples 上限、一个默认 fixture、scenario-specific probes、最多 Candidate B |
| T-30-04-06 | Tampering | cross-page claims | mitigate | consumers/nonconsumers 由当前 impact matrix entry 驱动，禁止联集替代 |
| T-30-04-SC | Tampering | package supply chain | accept | 不安装新依赖 |
</threat_model>
