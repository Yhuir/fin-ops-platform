# Phase 5 Plan 22：成本统计局部加载与 API 直读性能优化

## 目标

在不引入 read model、缓存、新依赖或新并行链路的前提下，完成成本统计页面的局部加载体验、标签布局调整与统一事实源查询性能优化。

## 边界

- 前端：`web/src/pages/CostStatisticsPage.tsx`、成本统计组件、样式与交互测试。
- 后端：成本统计 query service、canonical repository、policy 与对应 API/repository 测试。
- 文档：成本统计模块边界、API 直读链路和验证记录。
- 不改变业务口径、权限、导出合同或其他页面行为。

## 任务

1. 先补交互回归测试：左栏只刷新中/右栏，右栏立即清空；中栏只刷新右栏；时间范围和视图切换只刷新内容区。
2. 调整页面加载状态：初次加载保留全页保护，后续请求按 surface/children/rows 局部呈现，不再清空整个页面或锁定全页。
3. 调整按标签 UI：支出在上、收入在下；零金额只隐藏数值；桌面列宽改为 20%/20%/60%，移动端保持单列。
4. 将 explorer 的 scope/view 下推至 canonical repository；时间/标签视图跳过 OA 关系读取，成本视图只扩展命中关系的成员，保留跨月份配对语义。
5. 删除被新局部加载状态替代的旧全页重载逻辑，扫描 Cost 链路确保无 read model、worker、fallback 或重复实现。
6. 更新模块边界文档，运行前后端相关测试、lint/build、性能基准和 API 合同验证。
7. 合并到 `main`、推送远端、运行生产部署，再验证生产 API 性能、统一事实源链路、页面交互和审计状态。

## 验收

- 初次加载之外，页面头部与不受影响栏位保持可交互，不出现全页 loading overlay。
- 左栏变化后右栏立即为空且无“请先选择”提示；中栏变化时左/中栏保持。
- 时间范围变化只替换三栏/表格内容。
- 标签零金额不显示数值，标签文字与笔数仍显示；桌面三栏比例为 20/20/60。
- explorer API 仍直接读取 PostgreSQL 统一事实源，响应合同保持兼容。
- 时间/标签查询不读取 OA 配对关系；项目/银行/OA 费用类型查询只读取必要 scope 和关系成员。
- 相关测试、构建、部署与生产验证通过；如未达到性能目标，提供实测数据和唯一剩余瓶颈。
