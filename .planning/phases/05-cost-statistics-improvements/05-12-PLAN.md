# 05-12 Bounded Execution Prompt：单次依赖鲜度门禁并删除请求期多 owner provider

## 本轮唯一目标

把成本统计 explorer、旧内部 month/full loader、transaction detail 在读取 Redis 或结构化 rows 前执行的
多 owner expected-source I/O，收敛为一次成本专属 PostgreSQL gate：同一 SQL 读取成本已发布 metadata/current dirty、
当前 App Settings 成本所需小型片段，以及月 scope 对应的 Workbench active generation 与 Bank Detail scope/current dirty。
query service 只从这一 gate snapshot 形成 expected source versions 和标签筛选 token，不再通过 `Application` / runtime service
逐个读取 settings、Workbench、Bank Detail。

这是一个不可拆的性能与正确性闭环：只删 provider 会形成 stale-as-fresh；只合并 SQL 而保留 provider 会继续重复 I/O；
只优化 explorer 而不覆盖 detail/内部 loader 会保留同一旧链路的旁路。本轮不处理历史 warmup/background-job/local read-model
删除、`CostStatisticsReadModelService` 迁移、Audit 下一组 SQL、导出流式化或生产索引；这些必须由后续基于本轮真实结果
生成的新 prompt 处理。保持 `DEPLOYMENT_HOLD`。

## Grill-me 门禁答案

| 问题 | 本轮答案 |
| --- | --- |
| 唯一问题 | 当前一次 fresh GET 在成本 metadata gate 之外，还经 Application/runtime provider 读取 App Settings、Workbench active generation、Bank Detail scope summary（其内部两次 SQL），随后再次读取 App Settings 取得 tag selection；这直接放大连接获取与 SQL 长尾。 |
| 直接模块 | 成本 query/runtime、成本 repository port/PostgreSQL gate、成本 SQL projection 的 source-version helper、Application 成本依赖组装、成本 API/SQL runtime/边界测试与当前模块文档。 |
| 上游/下游 | 上游仍是 App Settings singleton、Workbench active generation、Bank Detail scope/dirty；下游仍是同一 explorer/detail/month/export DTO、versioned Redis 和成本页。其他页面 read model/API 不变。 |
| 输入 I/O | gate 输入仅 `scope_key`，一次 SQL 读取 cost metadata/current dirty、settings 成本片段、月 scope 的 Workbench active source versions/current dirty、Bank Detail scope source versions/current dirty。query 不再回调其他 repository/service。 |
| 输出 I/O | gate 增加内部 `source_settings`、`workbench_source_versions`、`bank_detail_source_versions` 与 dependency status 字段；HTTP DTO 不暴露这些内部字段。fresh 后才可读 Redis/page SQL；non-fresh 继续入队并锁页。 |
| 事实源 | cost dirty/outbox 仍是 PostgreSQL durable queue；业务 source versions 仍由 worker 发布 metadata 拥有；当前依赖版本从同一 gate snapshot 的正式 SQL read models/settings singleton 读取。Redis、页面事件和 App Status 都不是鲜度事实源。 |
| 旧链路 | 删除 `Application._cost_statistics_expected_source_versions/_cost_statistics_source_versions/_cost_statistics_workbench_source_versions/_cost_statistics_bank_detail_source_versions`、runtime `source_versions_provider/expected_source_versions`、query `tag_selection_provider` 的读时 I/O，以及只为这些链路存在的测试 fixture。禁止 shim/fallback。 |
| 隔离性 | 只改 cost-owned query/gate/source helper和 Application 成本装配；不改变共享 `ReadModelQueryGateway` 顺序、全局 pool、Workbench/Bank Detail payload/worker、Tax Offset、其他页面 API/read model/cache。 |
| 反过度设计 | 不新增表、migration、索引、缓存层、SSE、worker、通用 gateway 分支或连接池；只增加一个纯 source-version helper和一个 settings owner 的无 I/O mapper，使 SQL gate 与 worker使用同一合同。 |
| 测试责任 | 证明 page/detail/month/full loader 每次只调用一次 gate，provider I/O 为零；gate 对 cost/WB/Bank Detail pending/failed/missing/schema/source mismatch fail closed；tag selection 更新改变 cache/filter token但不触发 rebuild；旧符号全仓归零。 |
| 回滚/部署 | 数据库无 schema 变化；代码回滚依赖统一 release artifact。禁止 deploy/生产访问/branch/stage/commit/push/PR/stash/reset/clean。 |

## 必须保持与补齐的生产合同

1. gate SQL 只能做 indexed singleton/point lookups；不得扫描 Workbench groups/rows、Bank Detail rows 或 canonical facts。
2. cost scope 自身的最高 durable dirty version/status 与 `published_source_version` 比较保持不变；pending/processing/failed、缺少 published version 或版本不等继续 fail closed。
3. 月 scope 必须在同一 gate snapshot 证明 Workbench active generation 存在且 source versions 非空，并证明相同月份 Bank Detail scope schema/status/source versions fresh；其 current dirty pending/processing/failed 必须阻止成本 fresh。
4. parent `active:all/all:all` 不重新读取 Workbench `all` 或 Bank Detail `all`；继续依赖已发布 cost shard manifest/metadata 与 cost dirty gate，不引入 command-parent 假鲜度。
5. App Settings singleton 缺失或成本所需 JSON shape 非法时 fail closed；bank tag rules version、bank account mapping fingerprint、OA parser/sync constants 与 worker projection 必须由同一纯 helper生成，禁止 query/worker 两套字段定义。
6. cost tag selection 仍是 query/export filter，不进入 read-model source versions、不 enqueue rebuild；但 gate 同次读取的 settings snapshot 必须生成其 effective codes/version/cache token，避免第二次 settings I/O 和跨快照混读。
7. gate 非 fresh 时绝不读 Redis/full rows/page SQL；gate fresh 后 cache key 绑定 published source version、业务 source versions、tag token 与 query fingerprint。
8. ETag、cursor、200/202/304、detail 409/404、export/API DTO、schema version、source-version conditional publish和 parent shard业务合同不变。
9. query/runtime/Application 不得保留隐藏 fallback 到旧 expected provider；repository unavailable 继续返回明确 refreshing 并经正式 gateway enqueue。
10. 不能声称生产 SLO 已达标；本轮只证明请求 round-trip/owner I/O 收敛和本地正确性，真实 EXPLAIN/p95/p99 留待统一部署窗口。

## 旧代码删除责任

- 删除四个 Application expected/source/dependency wrapper 及 imports；测试 fixture 改用 production projection/shared source helper，不保留测试专用 app shim。
- `CostStatisticsRuntimeService` 删除 `source_versions_provider`、`expected_source_versions`，并删除依赖它的无版本/按当前 expected key 删除逻辑；versioned Redis 由 gate token + TTL 自然退出，不能恢复旧 key writer/delete。
- `CostStatisticsQueryService` 删除 `tag_selection_provider` 和会触发 App Settings reload 的 `_cost_tag_selection_payload()`；标签选择只从本次 gate snapshot 的纯 mapper 得到。
- static guard 扫描 production/tests，禁止上述旧方法、constructor fields、reason=`cost_statistics_expected_source_versions` 和多 owner读路径回归。
- 不删除仍有调用的 `CostStatisticsRuntimeService`、`CostStatisticsReadModelService` 或 warmup job type；它们留待独立 prompt，避免本轮扩大到 background-job/runtime 迁移。

## 七类测试责任

1. Business core unit：适用；同一 shared helper 对 month/parent、settings fingerprint、WB/Bank Detail optional/required字段生成一致，标签 default/empty/explicit selection 口径不变。
2. Service-layer：适用；gate 一次 SQL返回依赖 snapshot，query不调用 settings/WB/Bank Detail provider；non-fresh只 enqueue、不读 cache/rows。
3. API contract：适用；fresh/refreshing/304/detail/export shapes 与错误码不变，内部 gate字段不泄露。
4. Read model/cache/worker：适用；cost/WB/Bank Detail dirty/missing/schema/source mismatch、Redis旧payload隔离、published version cache namespace、projection/query source版本一致。
5. Frontend interaction：不适用；页面、遮罩、drawer、权限与前端 API 不变。
6. End-to-end integration：适用；本地 production projection → repository gate → query/route 路径证明 settings/dependency变更会锁定，重建后新版本可读；不运行真实生产 worker。
7. Existing regression：适用；成本 API/SQL runtime/App Settings/runtime/architecture guards及 read-model合同通过；其他页面代码零行为变更。

## 停止条件与状态转换

- PASS：四种 cost query入口都只通过一次 dependency-bound gate读取当前依赖，旧 provider/runtime字段和读时 settings reload全仓归零，所有 mismatch fail closed，目标回归通过；写 `05-12-SUMMARY.md`，next_state=`IMPLEMENTING`。
- PARTIAL：无法在一个 indexed gate query内取得任一正式依赖，或标签选择只能通过第二次 I/O得到；停止扩大并进入 `GAP_CLOSURE`，不得跳过比较换速度。
- FAILED：必须修改共享 gateway、Workbench/Bank Detail读模型、全局 pool或新增 schema才能闭环，进入 `DECISION_REQUIRED`；不得越界。
- 无论结果如何，不部署、不访问生产、不创建/切换分支，不 stage/commit/push/PR，不 stash/reset/clean；整体 `/goal` 保持 active。
