<grill_me_contract>

3. I/O 是否清楚：请求只读 cost freshness gate 和 cost-owned projection；写侧只经 durable queue/source version 发布。
4. 事实源是否清楚：canonical facts、Workbench active generation、Bank Detail fresh scope、Settings version、PostgreSQL dirty/outbox。

8. 是否过度设计：每个新部件必须对应已量测热点或已复现正确性缺口；无证据的通用平台能力一律不加。

</grill_me_contract>

<threat_model>

- 最大正确性风险是旧 event 在新 source version 到达后覆盖 rows 或错误完成 dirty scope；不能用 UI refresh 或 Audit 降级掩盖。
- 最大性能风险是请求时读取完整 source versions、读取并序列化全量 JSON、首屏并发预取 `active:all`、详情全量扫描和 Audit 多组重复 SQL。
- 最大隔离风险是为成本页修改全局 pool、全局 overlay、其他页面 read model 或共享 App Shell；本计划禁止这些改动。
- 最大迁移风险是保留旧 reader/writer/cache 作为 fallback，导致双事实源；目标设计明确无双读、无隐藏 fallback。
- 共享工作树风险通过 baseline/denylist 和只写 Phase 5 独立文件控制。

</threat_model>
