## 必须保持的合同

1. 成本页面仍使用 `GET /api/operations/app-health/page-audit?page=cost-statistics`，不新增专用 route。
2. standalone page Audit 与 System Audit 都显式接收同一个 `AuditSnapshot`；不得在成本 repository 内偷偷打开第二个 snapshot。
3. 证明必须继续覆盖：canonical↔projection 双向集合、关键展示字段、summary/group/bank-account、source version/parent shards、durable queue/readiness、共享 relation、Workbench 完整性以及 Bank Detail canonical/field/version。
4. `integrity=pass + freshness=fresh + queue=drained + database_snapshot=true` 仍是正式 pass gate；issue code 和样本上限保持稳定。
5. Audit 永远只读；不得 enqueue、repair、写 read model、写 readiness 或缓存绿色报告。
6. 本轮只迁移 ownership。查询数不得高于迁移前固定基线 `35`；必须在专属测试中记录该上限，为下一轮 SQL 合并提供机械门禁，但不得冒充 `<=5s` 已完成。
