# 05-04 Bounded Execution Prompt：结构化成本流水行与直接详情读取

## 本轮唯一目标

在不改变现有成本统计 HTTP DTO、不修改其他页面 read model、也不引入双读/双写或 fallback 的前提下，把 `cost_statistics` 的 OA 成本行和全银行收支行统一收敛到 PostgreSQL 结构化行边界：

1. 新增且只新增一张 `read_model.cost_statistics_bank_flow_rows` 成本专属表；
2. 新 schema 的 parent/month metadata 不再持久化 `time_rows` 或 `bank_flow_time_rows` 大数组；
3. worker conditional publish 在同一现有事务内替换两类结构化 rows 与 metadata，父 scope 聚合只读结构化月份 rows；
4. 当前 explorer DTO 暂由结构化 rows 重建，旧 parent-array 数据不得作为 fallback；
5. transaction detail 先通过现有 cost PostgreSQL freshness/source gate，再按 `project_scope + transaction_id` 索引点查，删除 `active:all` 全量加载和线性扫描；
6. 删除 projection 的 unversioned `cost_statistics:explorer:{scope}` Redis 写入/删除。Redis 继续只由 query gateway 在 fresh gate 后写 versioned key。

本轮不实现 view-specific cursor API、streaming export、请求期 expected-source provider 删除、前端遮罩、Audit 拆分或剩余旧模块全量删除；这些必须由本轮真实结果决定下一 prompt，禁止在本文件预生成。

## 实现合同

### Migration / storage

- 新表只承载 concrete month `bank_flow_time_rows`，至少结构化 scope/project/month、stable row key、transaction identity、time/date、direction、amount、project/expense/counterparty/account、bank tag fields、source versions、generated/cache status，并保留单行 payload 作为非查询展示字段载体。
- 索引只覆盖当前已执行查询：scope 时间排序、parent project_scope/month 时间读取、`project_scope + transaction_id` 点查。标签/cursor 的更多索引留给真正实现 view query 且有 EXPLAIN 证据的切片。
- 为 `fin_ops_api` / `fin_ops_worker` / `fin_ops_readonly` / `fin_ops_migrator` 保持与现有 cost rows 等价的条件 grant。
- 给既有 `cost_statistics_rows` 补 direct detail identity index；不修改其他表。

### Conditional publish

- 继续只由 `publish_cost_statistics_read_models(...)` 在已锁定 exact active dirty source_version 的事务内写 metadata、OA rows、bank-flow rows 和 obsolete scope deletes。
- metadata storage copy 必须剥离 `time_rows` / `bank_flow_time_rows`；不得修改调用方 payload 或为兼容再保留 raw array 副本。
- month scope 精确替换两类 rows；parent scope 不物化重复 rows。obsolete month 删除必须同时删除两张 rows 表。
- stale source_version publish 仍必须零 metadata/rows/Redis 写入。

### Parent / explorer / detail

- parent builder 从两张结构化 month rows 表读取，不再解析 child `cost_statistics_read_models.payload.bank_flow_time_rows`。
- `get_cost_statistics_view()` 对 month 读 exact scope rows，对 parent 读同 `project_scope` concrete month rows；总是从两张表重建当前 DTO，零行也不得回退 parent arrays。
- repository port 新增单一、明确的 transaction point lookup；同 transaction 同时存在于 OA 与 bank-flow 表时保持现有优先级：OA cost row 优先。
- detail 先复用现有 cost metadata gate + schema/business source-version 检查；non-fresh 仍返回既有结构化 409。fresh 后只执行点查，不调用 `get_cost_statistics_view()`、不读取 Redis、不加载 all arrays。
- tag selection 对 detail 的可见性保持现有业务语义；不得因点查绕过选择规则。

### Cache / legacy deletion

- 删除 cost projection 写/删 unversioned explorer Redis key 的路径和对应错误测试合同。
- versioned Redis cache 仍由 query service/read-model gateway 在 PostgreSQL gate fresh 后拥有。
- whole-repo literal scan 证明 cost projection 不再写 `cost_statistics:explorer:{scope}`，parent rollup 不再读 child bank-flow JSON，detail 不再调用 all explorer scan。

## 验收标准

1. schema version 已 bump，旧 v8 model 不能被新 query 认证 fresh。
2. migration/table/grants/index 与 migration discovery tests 通过。
3. conditional publish 一次事务写 metadata shell + 两类 rows；parent/obsolete 删除覆盖两张表；stale publish 零写。
4. 持久化 parent/month `payload` 与 `raw_payload.normalized_payload` 均无两类大 arrays。
5. parent rebuild 只读两张 rows 表；不读 child model JSON arrays。
6. explorer 现有 API shape 与业务金额/标签口径回归通过，但 repository 数据来源只有结构化 rows。
7. detail fresh path 只有 gate + point lookup，不加载 full view/Redis；non-fresh/未找到/tag-excluded 合同保持。
8. projection 不写 unversioned Redis key；其他页面行为和 shared gateway 零变化。
9. 文档明确本轮只完成结构化存储/点查，尚未声称 cursor、streaming export 或最终 SLO 达成。
