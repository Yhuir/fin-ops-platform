# 05-06 Bounded Execution Prompt：原 explorer 路径的视图化游标读取

## 本轮唯一目标

把成本统计页面从“请求一个 scope 的完整 explorer DTO、在浏览器做五套聚合”垂直切换为“同一个 `/api/cost-statistics/explorer` 路径按当前 view 返回完整汇总、小型 facets 和至多 100 条当前层级 rows”。

本轮必须同时切换后端和前端，不新增 `/v2`、不保留页面 full-payload fallback，也不让旧 response shape 与新 response shape 并行。读取继续复用现有 cost-local PostgreSQL freshness gate、`cost_statistics_rows` / `cost_statistics_bank_flow_rows` 和 fresh 后 Redis；non-fresh 时返回空 rows/facets 并 fail closed。

本轮不实现 Impeccable 遮罩、Audit repository、请求期 expected-source provider 删除、streaming XLSX、剩余后端 class/warmup/旧 summary route 删除或生产 EXPLAIN/SLO。导出仍走其现有独立 API；导出中心需要项目/费用选项时，只能在用户动作后复用新 explorer 的 bounded project/expense facets，禁止再读 full `active:all` explorer。

## API 与游标合同

### Request

- `project_scope=active|all`；页面仍固定 `active`。
- `scope=YYYY-MM|year:YYYY|all`；拒绝非法月份/年份，不创建 year read model。
- `view=time|project|bank|expense_type|bank_tag`，必填。
- 单值层级 filter：`project_name`、`expense_type`、`payment_account_label`、`bank_tag_primary_label`、`bank_tag_sub_label`；非法组合返回 `400`。
- `page_size` 默认 `50`、范围 `1..100`；`cursor` 可选。

### Response

- `scope`、`view`、`summary`、`available_years`；
- `facets.projects|expense_types|bank_accounts|bank_tag_primary|bank_tag_sub`，只返回当前 view 必需的 bounded 聚合；
- `rows`、`row_count`（完整当前层级匹配数）、`next_cursor`；
- `read_model_status`、`read_model_scope_key`、`read_model_generated_at`、`source_versions`、stale reasons；
- HTTP `ETag`、`Cache-Control: private, no-cache`、`Vary: Authorization, Cookie`；匹配 `If-None-Match` 且 gate 仍 fresh 时允许 `304`，不得执行 rows/facet SQL。

summary/facets 必须基于完整 scope/filter 集合，cursor 只分页 rows。month scope gate 对应 `project_scope:YYYY-MM`；year/all 复用 `project_scope:all` parent gate，再在结构化月份 rows 过滤。禁止新增 year projection。

游标必须绑定 schema、scope、view、规范 filters、published source version 和最后稳定排序键。排序固定为 `trade_date desc nulls last, trade_time_text desc, transaction_id, row_key`。游标 malformed、query binding 不同或 published version 变化时返回 `400`/明确 cursor error，禁止拼接两个版本。

## Repository / SQL 合同

- 新增一个 cost-owned `get_cost_statistics_page(...)` narrow port；它只读两张 cost row 表和必要的小型 parent metadata。
- 每次 cache miss 的当前 view 使用一个 set-based PostgreSQL statement 返回 summary、facets、`page_size+1` rows 和 row count；禁止 per-row/per-facet Python SQL 循环，也禁止把全表 rows 拉到 Python 再 group。
- project/bank/expense_type 读 `cost_statistics_rows`；time/bank_tag 读 `cost_statistics_bank_flow_rows`。
- 标签选择规则继续由 query owner 规范化并作为 SQL filter/cache/ETag 输入；不得把未选标签先全量读回再在 Python 过滤。
- 银行 facet 合并 parent metadata 的配置账户，使零金额账户继续可见；只传小型账户 metadata，不读取完整 parent rows。
- 本轮不猜测新索引。先使用已有 scope/project/expense/parent-rollup/identity indexes；若本地 disposable PostgreSQL 可用才记录 EXPLAIN。生产索引只能由统一部署后的真实 `EXPLAIN (ANALYZE, BUFFERS)` 生成下一 prompt，不为未来查询预建索引。

## Frontend 合同

- 删除旧 `fetchCostStatisticsExplorer()` full DTO mapper，替换为唯一 page request/mapping。
- 当前 view/range/层级 selection 组成 request identity；每次变化取消旧请求、清除旧可操作 rows，并只允许最后一代响应写入。
- time 首屏直接显示第一页；project/bank/bank_tag 按用户选择层级重请求 facets/rows；expense_type 选择后请求 rows。
- 页面只显示服务端 summary/facets/rows，不从当前页反推总额、笔数、百分比或完整 facets。
- `next_cursor` 存在时显示 cost-local “加载更多”；追加前验证 scope/view/filter identity，失败不丢失已加载页。快速切换后的旧 page 不得追加。
- range 控件直接发送 month/year/all scope；删除完整 rows 上的年份扫描和 `filterScopeTimeRows`。
- 导出 options 在用户打开 project/expense 导出时并行读取 `scope=all` 的 project/expense_type facets；time/bank_tag 不读；不得恢复 full `active:all` DTO。
- transaction detail、tag rules、导出 preview/download 的业务合同保持不变。
