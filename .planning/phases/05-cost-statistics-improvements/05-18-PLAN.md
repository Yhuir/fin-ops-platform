# 05-18 Bounded Execution Prompt：成本 Audit exact-set 单语句收敛

## 本轮唯一目标

把成本 Audit owner 内四个独立数据库往返——scope row count、missing scope、duplicate identity、canonical expected-set——合为一条
`cost_exact_set_proofs` 只读集合 SQL。四个 proof 分支必须各自在 `UNION ALL` 前独立排序并 `limit`，保留既有 blocking issue
code、message、subject/scope/details 合同、caller-owned repeatable-read snapshot 和证明强度。删除被替代的四个旧 helper 与不再有调用方的
`_proof_query_issues`，固定 active-relation query budget 从 26 精确降到 23。不得改共享 Audit 或上游 proof owner。

## Grill-me / Ponytail 门禁答案

| 问题 | 本轮答案 |
| --- | --- |
| 根因 | 05-17 后 cost owner 仍有 7 组本地 SQL，其中四个 exact-set 类入口共享同一快照、同一输出行合同，却各自占用一次连接往返；生产基线的连接获取长尾会放大这些串行往返。 |
| 直接模块 | 仅 `cost_statistics_page_audit.py`、成本 Audit 直接测试与成本模块维护文档。 |
| 输入 I/O | caller-owned 只读 snapshot、`tenant_id`、`example_limit + 1`；canonical/Workbench/成本结构化 rows 仍是原事实源。 |
| 输出 I/O | 外部仍返回原四类 `AuditIssue` 与原 report envelope；不新增 DTO、缓存、表或状态。 |
| 证明完整性 | scope count、missing scope、duplicate identity、canonical cost/bank-flow 双向 equality 各自独立 limited CTE；不得用 count/hash 代替 exact set，也不得共享一个 union 后总 limit。 |
| 旧代码 | 删除四个旧 per-query helper 和仅由 canonical helper 调用的 `_proof_query_issues`；whole-repo 扫描必须证明无调用方，不保留 wrapper/fallback。 |
| 隔离性 | 不改 `page_business_audit.py`、Workbench/Bank Detail collectors、其他页面 read model、API、worker、前端、pool、schema/index 或部署文件。 |
| 反过度设计 | 直接使用一个显式 SQL statement 与一个 code→message 映射；不加 generic query builder、proof context/cache、repository adapter、临时表、并行连接或抽象层。 |
| 回滚 | 协调部署前是 cost-local 代码/测试/文档 diff，可按本轮 diff 回退；没有数据或 schema 回滚。 |
| 部署 | 本轮不部署、不访问生产、不运行生产性能验证；不 branch/stage/commit/push/PR/stash/reset/clean。 |
