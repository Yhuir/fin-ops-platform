# 05-20 Bounded Execution Prompt：拆除 cost/tax 混合投影旧模块

## 本轮唯一目标

把 `cost_tax_sql_projection.py` 中两个互不相属的 projection builder 原子迁移为
`cost_statistics_sql_projection.py` 和 `tax_offset_sql_projection.py`，更新生产 worker、直接测试和模块文档的 import / owner，
随后删除旧混合 module。成本与税金的 SQL、输入、输出、source versions、Redis、read model、queue、worker event、API 和页面行为必须完全不变；
不得保留 re-export、compat shim、动态 fallback 或旧 import 路径。

本轮不删除 `cost_statistics_cache_warmup`，因为仍需统一部署窗口证明 production active job 为零；也不删除旧 summary/project HTTP
合同及其 full-view loader，因为仍需覆盖正常财务周期的生产 access-log 或全部 owner 明确确认。两类生产门禁不能用本地静态分析替代。

2. Service-layer：适用；两个 builder、repository/cache调用和worker组装保持。
3. API contract：API未改；复跑成本和税金直接API回归证明shape/status无变化。
4. Read model/cache/background job：适用；cost/tax refresh builder和worker bootstrap/import边界保持，queue/registry不改。
5. Frontend interaction：不适用；前端文件和用户交互未修改。
6. End-to-end business flow：无新业务流；现有 builder→repository与worker assembly integration足以保护纯owner迁移，真实生产worker留到统一部署后。
7. Existing regression：适用；成本、税金、runtime bootstrap和architecture guards同时覆盖，防止一个页面的owner迁移污染另一个页面。
