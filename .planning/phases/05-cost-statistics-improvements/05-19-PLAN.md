# 05-19 Bounded Execution Prompt：移除 worker unchanged 判定的 full-view I/O

## 本轮唯一目标

把 `CostStatisticsSqlProjectionBuilder` 的 `source_versions_unchanged` 判定从
`get_cost_statistics_view(...)` 全量 payload loader 迁到一个 cost-local、metadata-only 的
`get_cost_statistics_scope_metadata(...)` repository port。新查询只能按唯一 `scope_key` 读取 parent 行的
`scope_key + entry_count + source_versions`，不得读取 payload/raw_payload、结构化 cost rows、bank-flow rows、dirty queue、
Workbench、Bank Detail 或 App Settings。迁移后删除 worker 对 full-view 的调用与只保护该调用的测试 stub，保持 skip 结果、
dirty-scope processing 期间的 unchanged 语义、API、页面、read model 数据、发布 CAS 与其他页面行为不变。

本轮不删除仍由旧 `GET /api/cost-statistics` 和 `/api/cost-statistics/projects/{project_name}` 合同使用的 full-view loader；
它们必须等统一部署窗口的生产 access-log/owner 证据后再独立删除，禁止以本轮性能优化破坏旧 HTTP 合同。

## Grill-me / Ponytail 门禁答案

| 问题 | 本轮答案 |
| --- | --- |
| 唯一问题 | worker 的 unchanged 快路径只需要 parent `source_versions + entry_count`，却调用 full-view loader 并无界扫描两张结构化明细表；数据越大，避免重建的快路径反而越慢。 |
| 直接模块 | `CostStatisticsSqlProjectionBuilder`、成本 repository port/summary SQL owner/manifest，以及其直接 runtime/manifest/boundary tests 与成本维护文档。 |
| 输入 I/O | 单一规范 `scope_key`；事实源仅 `read_model.cost_statistics_read_models` parent row。 |
| 输出 I/O | `scope_key + entry_count + source_versions` 小型内部 dict；外部 API/DTO、queue、cache、表和 worker event 不变。 |
| caller 完整性 | CodeGraph + whole-repo scan 证明 production full-view caller 只有 query owner 的旧 month/project 合同和 projection unchanged；页面 explorer/detail/bulk export 已迁出。 |
| 旧代码 | projection 中 `get_cost_statistics_view` dynamic lookup/call必须归零；`UnchangedCostStatisticsSaveRecorder.get_cost_statistics_view` 与 `views` tracking 删除，改为只实现 metadata contract，不保留 fallback。 |
| 隔离性 | 不改 route/server、旧 API合同、前端、共享 gateway、queue/worker wiring、schema/migration/index、Workbench/Bank Detail/Tax Offset或其他页面 read model。 |
| 反过度设计 | 只增加一个窄 port method 与一条主键/唯一 scope point query；不复用带多 dependency lateral join 的页面 gate，不加 generic metadata framework、DTO class、cache、feature flag、fallback 或第二 read model。 |
| 正确性 | source_versions 完全相等才 skip；缺失 metadata/source_versions 不 skip。dirty scope processing 不应阻止基于已发布 parent metadata 的幂等 skip，与现合同一致。 |
| 回滚与部署 | 协调部署前是 cost-local 可逆 diff，无 schema/数据回滚；本轮不部署、不访问生产，不 branch/stage/commit/push/PR/stash/reset/clean。 |

## 七类测试责任

1. Business core unit：适用；source_versions exact equality、missing/mismatch、entry_count 与 skip envelope。
2. Service-layer：适用；projection/repository port/manifest、一次 metadata I/O、dirty-processing 幂等 skip。
3. API contract：HTTP shape 未改；复跑成本 API/runtime 证明旧 month/project 和新页面合同无回归。
4. Read model/cache/background job：适用；worker unchanged 分支、parent metadata事实源、零 cache/queue/row scan。
5. Frontend interaction：不适用；页面与轻量遮罩未修改。
6. End-to-end integration：本轮无新跨模块业务流；用 projection→repository contract integration 与既有成本 API/runtime 回归覆盖，真实 worker/生产量级留到统一部署后。
7. Existing regression：适用；manifest、summary SQL owner、repository boundary、旧 full-view API caller保留和其他页面零 diff。

## 停止条件与状态转换
