# 05-14 Bounded Execution Prompt：删除成本 read model 全量 load 与无条件 save 旧表面

## 本轮唯一目标

删除成本统计仍残留在 repository port、共享 PostgreSQL repository、`PostgresStateStore`、本地
`ApplicationStateStore`、`StateStoreProtocol` 和 read-model manifest 中的
`load_cost_statistics_read_models(...)` / `save_cost_statistics_read_models(...)` 旧合同。

完成后，应用全状态启动快照不再扫描整张 `read_model.cost_statistics_read_models` 表，也不再接受通过 broad state
payload 无条件回写成本 snapshot。成本 worker 唯一写 I/O 保持为带 `tenant_id + scope_key + source_version` CAS 门禁的
`publish_cost_statistics_read_models(...)`；页面读取只保留 freshness gate、set-based page query、内部单 scope view 和
transaction point lookup。保持 `DEPLOYMENT_HOLD`。

## 必须保持与补齐的生产合同

1. `CostStatisticsReadModelRepositoryPort` 只保留当前消费者需要的
   `get_cost_statistics_freshness_gate/get_cost_statistics_page/get_cost_statistics_view/
   get_cost_statistics_transaction/active_workbench_source_versions/publish_cost_statistics_read_models`。
2. `publish_cost_statistics_read_models(...)` 必须继续锁定唯一 active `pending/processing` dirty row，source version 精确相等
   才在同一事务写 metadata、`published_source_version`、两张 structured row 表和 obsolete scope deletes。
3. stale/missing/非法 source version 必须零 read-model 写入；不得用无条件 save 作为 fallback。
4. `PostgresStateStore.load()` / `_load_snapshot_payload(...)` 不再执行成本 read-model 全表 load，也不返回
   `cost_statistics_read_models` key；`save(payload)` 不再识别该 key。
5. 本地 `ApplicationStateStore` 与 `StateStoreProtocol` 不再声明或持久化成本 read-model snapshot；历史 pickle 中的旧 key
   仅作为无人读取的 inert data 留待文件自然替换，不新增迁移或兼容清理分支。
6. read-model manifest 的成本 repository contract 不再列出 load/save，但保留 conditional publish 和全部 scoped reads。
7. 原来通过 direct save 验证结构化行、parent metadata和批量写入的测试必须改走真实 conditional publish，不直接调用私有 helper。
8. cost query、export、detail、API `200/202/304/409`、Redis gate、scope normalization、worker fan-out 和其他页面合同不变。
9. whole-repo production/tests 中 `load_cost_statistics_read_models` / `save_cost_statistics_read_models` 必须归零；历史文档可只保留明确“已删除”的迁移记录。
10. 不删除正式 PostgreSQL cost tables/rows、`get_cost_statistics_view(...)` 或历史 warmup bridge；它们属于其他独立风险和证据条件。

## 旧代码删除责任

- 删除 cost repository port 的 load/save wrapper；
- 删除 PostgreSQL summary repository 的 full-table load 与 unconditional save，以及共享 facade delegates；
- 删除 Postgres/local state store 与 protocol 的 cost snapshot methods、startup snapshot key、broad save branch；
- 从 read-model manifest 和测试 contract 删除旧方法；
- 删除只证明本地持久化、runtime snapshot fallback或旧 full loader sanitization 的测试；
- 把仍有价值的 row batching、metadata quarantine和 parent no-row 证明迁到 conditional publish；
- static guard 明确禁止上述符号和 StateStore cost snapshot key 回归。

3. API contract：行为未改；复跑成本 API/SQL runtime回归证明 page/detail/export shape不受影响。
4. Read model/cache/background job：适用；CAS publish、batch rows、parent metadata、obsolete delete、stale拒绝和启动无全表load。
5. Frontend interaction：不适用；页面、遮罩、drawer和前端 API未修改。
6. End-to-end integration：适用；本地 worker projection -> conditional publish -> fresh gate/query组合路径；真实 worker/DB因部署冻结不运行。
7. Existing regression：适用；state store、manifest、repository boundaries、成本 API/runtime/SQL和共享模块边界回归。
