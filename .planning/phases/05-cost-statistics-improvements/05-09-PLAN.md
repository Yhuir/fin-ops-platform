# 05-09 Bounded Execution Prompt：成本 Audit 重复证明与固定往返收敛

## 本轮唯一目标

在不弱化任何证明、不改变其他页面 Audit 行为的前提下，删除成本 Audit 中已确认的重复/无消费数据库 I/O：

1. 把 summary、dirty-scope sample 与 outbox sample 合并为一次只读集合 SQL；
2. 成本 Audit 复用 Workbench 完整性 collector 已执行的 relation-edge equality，不再同 snapshot 重跑相同 SQL；
3. 成本调用 Workbench collector 时不读取只用于返回 proof summary、但成本随后丢弃的 active-generation summary rows；
4. 用“存在 active relation、会触发 group-row 查询”的测试场景锁定真实查询上限，而不是继续用空数据低估预算。

本轮不把 32-query 上限冒充 `Audit p95 <= 5s` 或最终四组 SQL；不处理请求期 expected-source provider、导出、其他 legacy service、
前端、worker、schema、索引或生产部署。保持 `DEPLOYMENT_HOLD`。

## 必须保持的合同

1. caller-owned `REPEATABLE READ READ ONLY` snapshot、只读策略和统一 HTTP/CLI/System dispatch 不变。
2. canonical↔projection、key fields、summary/group/bank account、month/parent versions、queue/readiness、Workbench、Bank Detail、relation equality 全部继续执行。
3. Workbench relation mismatch 继续输出既有 `cost_statistics_relation_edge_mismatch`，不因复用改成新 code。
4. dirty/outbox sample 继续分别输出 `read_model_scope_not_fresh` / `read_model_outbox_not_drained`，summary counts、limit、排序和 details 不变。
5. Workbench collector 默认仍读取并返回 active-generation summary；只有成本依赖 proof 因丢弃 summary 而跳过该 query。
6. 查询预算以 active relation 触发 group-row query 的非空场景测量，PASS 上限必须 `<=32`；空数据可更少，但不能作为唯一门禁。
7. 不以减少 query 为理由跳过 proof、缓存绿色结论、扩大 sample truncation、降低 assertion 或添加 fallback。
