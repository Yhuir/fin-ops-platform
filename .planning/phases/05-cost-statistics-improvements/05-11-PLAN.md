# 05-11 Bounded Execution Prompt：迁移成本规则并删除 legacy live service

## 本轮唯一目标

删除已无生产调用的 `CostStatisticsService` live 组装链路，同时把仍有业务价值、但此前只由旧 service
测试表达的成本归集规则迁入唯一生产 owner `CostStatisticsSqlProjectionBuilder`。导出行数上限及结构化异常由
`CostStatisticsQueryService` 直接拥有；API 测试必须用生产 SQL projection 生成 read-model fixture，不得继续依赖、
复制或隐藏旧 live service。

这是一个不可再拆的依赖闭环：若只删 service 会丢规则和测试，若只迁规则不删 service 会继续留下并行事实源。
本轮不处理仍有生产调用的 `CostStatisticsReadModelService`、runtime warmup、请求期 source-version provider 或 Audit
后续优化；这些必须由后续基于本轮真实结果生成的新 prompt 处理。保持 `DEPLOYMENT_HOLD`。

## 必须保持与补齐的生产合同

1. projection 只消费 `paired`/active-generation 中已经落库的 OA+bank groups；open candidate 不得进入成本。
2. `special_metadata.cost_policy=exclude_all` 必须整组排除；`hint_only` 按普通成本处理。
3. `include_ticket_cost_only` 仅在 `special_type=cash_ticket_purchase`、票面成本非零、有支出流水和项目名时生成一条票面成本记录；金额不得使用整笔现金流水。
4. OA 行的 `cost_excluded=true`、`tags` 含“冲”或 `oa_bank_relation.code=oa_invoice_offset_auto_match` 均不得贡献成本上下文。
5. 借款/还款、字段不完整、多重冲突 OA context、收入流水、credit 非零或金额为零均不得进入成本。
6. `-`/`--`/`—`/`——` 继续视为空，并可从 `detail_fields` 回填费用类型、费用内容、申请人；项目名称/编号也按既有 production helper 回填。
7. `project_scope=active` 只排除 App Settings 明确完成的 project id/name，未知项目继续保留；`all` 保留完成项目；非法 scope 继续 fail fast。
8. bank tag、账户、项目/费用聚合、read-model payload shape、source-version conditional publish 与 parent shard 模型不变。
9. 导出限制保持 20,000 行，error code=`cost_statistics_export_row_limit_exceeded`，`details={view,total,limit}`。
10. API 测试不得自己复制上述业务规则；read-model fixture 必须调用 production SQL projection builder，再测试 route/query 行为。
