<objective>
只闭环成本统计读侧的 PostgreSQL-freshness-before-Redis 合同：每次 explorer/month 读取先用一个 metadata-only PostgreSQL gate 证明已发布版本等于该 scope 最新 durable dirty version 且 schema/source metadata 匹配，只有 fresh 才允许访问 Redis 或 full payload。统一事实源变化已经持久入队时，旧缓存不得继续显示；不改变任何其他页面或共享 read-model gateway 的行为。
</objective>

<grill_me_evidence>

- 当前缺陷已由 CodeGraph 证明：通用 gateway 在第 56 行先读 Redis，命中后直接返回 fresh；`get_cost_statistics_view()` 中的 PostgreSQL dirty 查询只在 cache miss 时执行。
- `job.read_model_dirty_scopes` 是 durable freshness 事实源，scope version 单调增加并保留 terminal history；05-02 已保证 cost publish 与 event version 做事务 CAS。
- `read_model.cost_statistics_read_models` 当前没有独立的已发布 queue version，不能仅凭业务 `source_versions` 证明某次 dirty 已物化。
- runtime dirty `source_version` 是发布竞态令牌，不得混入业务 projection `source_versions`。
- 通用 gateway 被多个页面复用；修改其默认执行顺序会扩大隔离风险。因此本切片只在 cost query/repository 边界增加 opt-in gate。
- full-payload loader 内旧 dirty 查询在新 gate 后成为重复 I/O，必须删除，不能让旧链路继续污染冷缓存路径。

</grill_me_evidence>

<implementation_contract>

1. migration `0105` 只作用于 cost statistics：
   - 增加 nullable `read_model.cost_statistics_read_models.published_source_version bigint` 与“非空时必须非负”的约束；
   - 不从旧 `done` history 回填：05-02 前的 completion 不足以证明 snapshot 与该版本原子发布。历史 `NULL` 必须 fail-closed 并触发一次新版 rebuild；
   - 增加按 tenant/type/key/source-version 定位最新 cost dirty record 的窄 partial index；不改变其他 scope 的索引行为。
2. 05-02 conditional publish 在同一 transaction、同一 active dirty row lock 成功后写 snapshot/rows/obsolete deletes 与 `published_source_version=event_version`；CAS 拒绝保持零写入。
3. metadata gate 单条 SQL必须：
   - 从 cost parent row 读取 schema、business source versions、generated_at、published version；
   - 读取相同 tenant/scope 的最高 durable `source_version` 对应 status/error；
   - row 或 published version 缺失为 missing/stale；pending/processing 为 refreshing；failed 或 published/latest 不相等为 stale/failed；只有 published version 已由新版 writer 建立，且没有剩余 dirty history（允许 done-history retention 已清理）或最新记录为 done 且版本等于 published，才可能 fresh。
4. query service 对 explorer 与 month 使用同一 cost-local gate helper：
   - 先 gate；missing/non-fresh/schema/source mismatch 时 enqueue 对应 cost scope，返回空的 202 refreshing envelope，且不得访问 Redis/full rows；
   - fresh 时才构造包含 `published_source_version` token 的 cache key，再复用现有 gateway 读取 Redis或 full payload；
   - token 只用于 cache namespace，不进入业务 source-version 比较或 API payload。
5. gate 线性化点之后才允许返回缓存；mutation 在 gate 前提交并成功 dirty 入队时一定被阻断。gate 后并发 mutation 可由该次 gate 的一致 snapshot 定义请求观察点，下一请求由新 version 阻断。
6. full payload loader 不再查询 dirty status；其唯一职责是读取 parent/rows 并组装 payload。cache miss 仍由现有 gateway 验证 schema/business source versions/payload shape。
7. 所有新增 I/O 均通过 `CostStatisticsReadModelRepositoryPort`，页面/route 不读取 SQL、queue 或 Redis 细节。

</implementation_contract>

<tests>

- Hot-cache performance contract：fresh gate 先执行，随后 Redis hit；full payload/rows 不执行；cache key 随 published version 变化。
- Repository：gate SQL 单次读取 metadata+latest durable version；fresh/done、refreshing、failed、version mismatch、无剩余历史；full view 不再查询 dirty table。
- Write/read model：conditional publish 在原事务写 published version；stale publish仍零写入。
- Migration：nullable fail-closed 列、非空时非负约束、无历史可信回填、cost-only partial index 均存在。
- API regression：成本页面既有 fresh/miss/stale/malformed 行为；memory repository 实现新 gate contract。
