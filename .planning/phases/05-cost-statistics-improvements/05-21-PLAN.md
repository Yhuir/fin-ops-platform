# 05-21 成本统计 all 视图关联/撤回写后可见性优化

## 目标

把正式关联确认或撤回后，成本统计页面当前 `active:all` 视图读取到新业务值的链路收敛为一条：

`relation fact commit -> Workbench exact-version publish -> cost active/all month shards -> active:all parent -> Cost page exact-target barrier -> one fresh read`。

删除 relation writer 对 Cost Statistics 的提前、重复和隐藏 fan-out；保留其他模块原有 fan-out。页面继续复用现有轻量、非弹窗、可阻止交互的成本局部遮罩。不得新增队列、worker、read model、缓存、表、endpoint、SSE、feature flag、fallback 或兼容链。

## 当前证据与基线校准

- 当前计划基于 `main/origin/main = a65fadfe114d39d28e677251c175e39c6a4b18e3`；实施前必须重新确认 SHA 和工作树。
- 已报告的确认 `19.10s` 与撤回 `11.93s` 来自当前 release 之前的生产事件，并对应中间 `all:YYYY-MM` cost event 完成时间，不是页面实际读取目标 `active:all` 的精确业务值可见时间。
- 同一批旧证据中，确认操作的 `active:all` parent 约在提交后 `20.917s` 完成，撤回约 `12.468s`；事件风暴期间单个 `all:month` handler 曾耗时 `11.960s`。
- 基线代码同时存在六类 relation-origin cost 入口/声明：Workbench UoW/facade 直接 cost target、relation repository 隐藏 cost fan-out、Turnover relation writer 直接 cost request、relation lifecycle cost domain/job、自动匹配命令 cost metadata，以及 Workbench 成功发布后的 cost fan-out。前五类会抢跑、重复投递或继续污染边界；只保留最后一类作为唯一 owner。
- 当前 Cost 页面收到 `workbenchRelationUpdated` 后立即发 explorer 请求；若 read model 正在刷新，只能等待 App Status 最长约 5 秒的下一次状态变化再重试。
- 当前 cost month -> parent 派生事件没有继续传递 `tenant_id / priority / trace_id`，必须在本计划中修正；这是既有 I/O 合同缺口，不是新增架构。

## 模块边界与 I/O

| 边界 | 输入 | 输出 | 明确禁止 |
| --- | --- | --- | --- |
| Workbench relation writer | confirm/withdraw command、canonical row ids、tenant、affected months | relation facts + `workbench` / `workbench_relation` 及其他原有 downstream durable events | 直接或隐藏投递 `cost_statistics` |
| Workbench projection owner | `workbench.read_model.refresh(scope=YYYY-MM, source_version=N)` | exact generation publish result；成功后经既有 gateway 投递该月 cost refresh | 未发布、stale 或失败时投递 cost；写 Cost 表 |
| Cost refresh owner | cost month event + tenant/priority/trace | `active:month` / `all:month` 条件发布，随后各自 parent scope | 默认租户回落、跨模块写入、第二 worker |
| Cost query/UI owner | `workbenchRelationUpdated`、当前页面 scope `active:month` 或 `active:all` | 现有 operation barrier fresh 后只读一次 explorer，遮罩解除 | 立即读旧模型、轮询 App Status 作为主路径、修改其他页面 |
