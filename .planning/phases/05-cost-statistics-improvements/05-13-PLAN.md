# 05-13 Bounded Execution Prompt：删除进程内成本 read model 旧模块并收敛失效 I/O

## 本轮唯一目标

完整删除 `CostStatisticsReadModelService` 及其进程内 snapshot/load/save/invalidate 链路。成本 projection 直接构造
repository publish 所需的单 scope write model；成本 runtime 的 invalidation 只通过现有
`ReadModelRefreshGateway -> PostgreSQL durable queue` 标记正式 scope dirty，不再清理进程内副本或把旧 snapshot 写回 state store。

这是一个有界旧链路删除切片：不改变 PostgreSQL `read_model.cost_statistics_read_models` 正式表、repository/freshness gate、
页面 API/DTO、worker conditional publish、Redis、Audit SQL 或前端。历史 `cost_statistics_cache_warmup` job type 暂不删除，
因为删除其 App Health/retry 识别能力必须先取得统一部署窗口的 production active-job=0 证据；本轮只确保该兼容桥不再依赖
进程内 read model。保持 `DEPLOYMENT_HOLD`。

## 必须保持与补齐的生产合同

1. `COST_STATISTICS_READ_MODEL_SCHEMA_VERSION` 只有一个定义，位于现有成本 source-version contract；query、runtime、projection
   与测试从同一 owner 导入。
2. projection write model 保持 `scope_key/scope_type/schema_version/month/project_scope/generated_at/cache_status/entry_count/payload/
   source_scope_keys/source_versions` 既有 shape，并继续使用 repository conditional publish；不得复制整个旧 service。
3. invalidation 不删除 SQL rows；先写 durable dirty 后，旧 rows 会被 freshness gate 阻断，worker 成功发布才恢复 fresh。
4. bare month/all 仍经现有 scope policy 归一化为两个 project scopes；未知 scope fail closed，不能伪报成功。
5. queue 不可用时返回空 invalidated scopes，derived lifecycle 必须报告 error/无 enqueue，不能把目标 scope 当成已删除证据。
6. global invalidation 精确目标为 `active:all`、`all:all`；month invalidation精确目标为对应 `active/all:YYYY-MM`，不扫描本地/SQL payload。
7. API `200/202/304`、detail/export errors、Redis fresh gate、worker conditional publish、parent/shard业务合同不变。
8. Application 启动与 reload 不再 load/instantiate `CostStatisticsReadModelService`，依赖 key 不再观察该 field，且不保留
   `_persist_cost_statistics_read_models_best_effort`。
9. 正式 PostgreSQL repository 的 `load/save/publish_cost_statistics_read_models` 本轮保留；它们是表级 repository 合同，
   不等同于已删除的进程内 service。后续是否缩窄需独立 caller proof。
10. 历史 warmup retry/recovery 仅 enqueue durable refresh并终结旧 job；本轮不删除 job type，也不新建 warmup job。

## 七类测试责任

1. Business core unit：不适用；成本归因、金额、状态规则不变。
2. Service-layer：适用；runtime queue-only invalidation、derived lifecycle accounting、Application composition与旧 owner删除。
3. API contract：适用；完整成本 API 回归保持 query/detail/export/permission shapes。
4. Read model/cache/background job：适用；projection publish shape、dirty-before-read、queue unavailable、legacy job bridge和parent/month scope。
5. Frontend interaction：不适用；页面、锁定遮罩、drawer、权限与前端 API 不变。
6. End-to-end integration：适用；本地 lifecycle -> durable refresh recorder -> SQL projection publish -> query gate路径；真实 worker/生产 DB因部署冻结不运行。
7. Existing regression：适用；成本 API/runtime/SQL、derived lifecycle、settings reset、state store、architecture guards及共享 scope contract。

## 停止条件与状态转换

- PASS：旧 class/module/test/server field/runtime local persistence 全部归零；projection 直接发布既有 write model；所有成本 invalidation
  只以 durable enqueue成功作为证据；目标回归通过。写 `05-13-SUMMARY.md`，next_state=`IMPLEMENTING`。
- PARTIAL：正式运行时仍有 caller 无法迁移，或 queue-only invalidation无法保持 lifecycle错误语义；停止扩大并进入 `GAP_CLOSURE`，
  不保留双路径。
- FAILED：必须修改共享 gateway、其他页面 read model、数据库 schema或生产数据才能删除；进入 `DECISION_REQUIRED`。
- 无论结果如何，不部署、不访问生产、不创建/切换分支，不 stage/commit/push/PR，不 stash/reset/clean；整体 `/goal` 保持 active。
