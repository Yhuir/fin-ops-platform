<objective>
Close Phase 27 with one simple production contract: ordinary writes commit canonical facts/version/audit without page read-model fan-out; each page checks and converges only its own exact read model when the user enters/re-enters the route, changes that page's query, manually reloads the browser, or explicitly retries. An already-open page does not refresh because another page writes, and focus/visibility/BFCache/domain-event/tag-broadcast signals do not trigger business page I/O.

Preserve the existing materialized read models, PostgreSQL durable queue, gateway, worker, CAS and the few explicit shared semantic dependencies required for correctness. Do not add a coordinator, second queue, second cache, generic dependency DAG, fallback read path or live synchronous rebuild.
</objective>

</completed_baseline>

<threat_model>
- Removing a shared semantic dependency can return incomplete invoice or Cost payloads as fresh.
- Leaving any focus/visibility/domain-event/tag-broadcast entry can reintroduce hidden cross-page I/O and fan-out-like load amplification.
- An unbounded browser retry loop can run forever while hidden, overload the API, or hide a failed worker.
- A stale fallback or dual old/new path can make a page appear fresh while reading different facts.
- Production mutation evidence can damage finance data unless it uses one fingerprinted, idempotent, reversible test-owned fixture and verifies restoration.
- Patching after every production finding wastes time and makes results incomparable; all Candidate A findings must be collected before any corrective code change.
</threat_model>
