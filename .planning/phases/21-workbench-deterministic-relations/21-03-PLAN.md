<objective>
把 Workbench 可见投影收敛为 active formal relation 的精确集合投影：对 canonical eligible facts 集合 C 与 active relation members 集合 R，只输出 Paired P=R 与 Unpaired U=C-R，二者不重叠且并集为 C。所有 active relation 不再因成员 pane 数、历史 case 前缀、origin、source link、candidate score、automatic group 或业务 mode 被降级；其余 canonical facts 只以 typed canonical identity singleton 显示。重写 `month=all` 为每个 active month generation 的 logical member union，并让 count/list/detail/Audit 使用同一 generation-set token。同步把 Workbench API、前端和 downstream relation status 限定为 paired/unpaired 与 linked/unlinked，恢复 520 元 active OA+invoice relation 和跨 shard 的 13 张合计 1709.49 发票，同时保留 ETC、批量核算、流水、营业额、无 OA 等业务装饰和动作。
</objective>

<must_haves>
  <truths>
    - D-01/D-11：Workbench 只有 `paired` 与 `unpaired` 两个 relation visibility state；projection 不推断、提升、降级、合并、隐藏或自动关闭关系。
    - D-02：在同一 canonical snapshot 中，P=R，U=C-R，P 与 U 无交集，P 与 U 的并集等于 C；每个 typed canonical object identity 恰好出现一次，summary/collapsed display rows 不计入 C。
    - D-04/D-05：每个 active relation 都是 paired；`case:decision:*`、`source:*`、创建 origin、rule version、relation mode 和 pane completeness 只可作为审计或显示 metadata，不得决定 zone。
    - D-07：`month=all` 枚举全部 active month scopes 和 generation IDs，把同一 logical relation 的所有 physical shard members 按 typed canonical identity 合并；unpaired 按 `(pane, object_identity_key)` 建 singleton，禁止 latest-shard winner。
    - List total、分页 rows、detail members 与 System Audit 从同一 active-generation-set owner 读取；detail 带 list 返回的 `read_model_version`，generation 已变化时返回明确 409 version conflict，绝不拼接不同 generation。
    - Workbench API DTO 只出现 `paired|unpaired` 与 `relation|unpaired`；bank details、input invoice usage、cost statistics 和 relation read model 只出现 `linked|unlinked`，不再从 candidate/source-link/automatic prefix 推导 relation state。
    - ETC、batch accounting、bank-flow、turnover、no-OA、row alignment、collapsed invoice summary、exception/ignored workflow 与 permission/action rules作为 decoration 或正交 workflow 保留，但不得改变 membership 或 zone。
    - 共享 `yunnan_lifu_520_fixture()` 中 `oa-pay-2169`、`inv_imported_0369`、发票号 `26532000000716859331` 的历史 active relation 原样 paired且不新建 relation；共享 `omitted_thirteen_invoice_fixture()` 的 13 个 identities 全部恢复，minor units 合计 170949，默认各自 unpaired singleton。
    - Wave 3 从 runtime projection 删除 candidate grouping、source-link grouping、demotion 和 automatic-group exclusion；`workbench_candidate_grouping.py`、旧表和历史 migration 仅作为 inert inventory 留到 Wave 4，不能被 production projection、API 或 frontend 调用。
  </truths>

<threat_model>
  <assets>canonical object identities, active relation membership, active generation pointers, logical all-scope member sets, list/detail totals, audit evidence, downstream relation tags.</assets>
  <trust_boundaries>raw source facts进入 object-identity arbitration；active relation rows进入 projection；month shards进入 all-scope composition；API filters/page tokens进入 parameterized repository SQL；list version由浏览器回传到 detail；System Audit在只读 repeatable-read snapshot中计算 proofs。</trust_boundaries>
  <threats>
    - case/source/automatic prefix 或伪造 candidate metadata 把 unlinked fact合并、把 active relation降级或隐藏 canonical row。
    - 同一 canonical identity跨 shard重复，latest-shard grouping 丢掉旧 shard members，或 summary row被误算为业务 fact。
    - list后 active generation切换，detail读取新 generation却显示在旧 list上下文中。
    - filter/search/sort/pagination与 detail/Audit各自实现 owner规则，造成 count、identity set或zone不一致，或把全量数据拉入 Python造成无界资源使用。
    - Redis缓存键未包含 exact generation set，返回混合版本；downstream保留 candidate导致权限、导出或业务统计分叉。
    - 清理 candidate 语义时误删 exception `candidate_evidence`、发票选择候选、OA reverse选择集合或 ETC/no-OA 等无关业务能力。
    - Audit输出 raw invoice/OA/bank payload、敏感名称或账号。
  </threats>
  <mitigations>typed canonical identity和SQL唯一性；relation-only set difference；summary-role exclusion；全部 active shard generation exact hash；read-only repeatable-read与 expected-version conflict；一套 parameterized/bounded SQL owner；fresh gate后按 version缓存；linked/unlinked enum contract；针对无关 candidate concepts和特殊 mode 的 allowlist regression；Audit仅输出 issue code、counts、scope/case/identity hashes和有限脱敏 examples。</mitigations>
  <blocking_severity>partition遗漏/重复/交叉、paired无 active relation、active relation成员进入unpaired、all-scope generation/token不一致、520降级、13成员少于13或金额不等1709.49、downstream candidate泄漏、Audit proof失败均阻断发布；不得以 prefix filter、Python post-filter、stale cache、兼容 fallback或 relaxed assertion绕过。</blocking_severity>
</threat_model>
