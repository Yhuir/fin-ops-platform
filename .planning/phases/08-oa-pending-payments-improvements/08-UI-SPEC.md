# 08-UI-SPEC：OA 待付款页「进行中 OA」视图

日期：2026-06-17
阶段：08-oa-pending-payments-improvements

## 设计目标

在 `OA待付款` 页面内，用最小信息层级展示进行中 OA 的付款进展。用户进入页面后应能快速判断：

- 哪些进行中 OA 还没有支出流水。
- 哪些进行中 OA 有候选流水但还没确认。
- 哪些进行中 OA 已确认支付且已写回 OA。
- 哪些 OA 因流程状态变更已不再属于进行中范围。

## 页面结构

顶部保持现有页面标题、刷新和同步状态区域风格。新增一个 segmented control：

- `已完成 OA`
- `进行中 OA`

默认保持现有行为，即进入页面仍展示 `已完成 OA`。切换到 `进行中 OA` 后，筛选、表格、空态、刷新状态切到新的 view mode。

## 筛选

`进行中 OA` 视图提供支付状态筛选：

- `全部`
- `待支付`
- `已支付`

筛选只影响支付状态，不改变 OA workflow scope。任何筛选下都只能显示流程状态为 `进行中` 的支付申请和日常报销。

## 表格列

表格主体为三列：

| 列 | 内容 | 目标 |
| --- | --- | --- |
| OA | OA 基本信息和流程状态 | 确认业务对象 |
| 支付状态 | 付款判定、确认动作、OA 写回状态 | 判断是否已支付与是否已同步 OA |
| 流水 | 匹配到的支出流水或空值 | 核对支付证据 |

### OA 列

显示结构：

1. 第一行：申请人 + 类型 chip + 流程状态 chip
   - 类型 chip：`支付申请` / `日常报销`
   - 流程状态 chip：`进行中`
2. 第二行：项目 + 申请日期 chip
3. 第三行：金额

金额使用现有页面金额格式。项目为空时按现有空值口径展示，不引入额外说明文案。

### 支付状态列

状态和操作：

- 无 confirmed 支出流水，或只有候选：主状态 `待支付`
- 有 confirmed 支出流水且通过现有付款判定口径：主状态 `已支付`
- 存在可确认候选且当前未 confirmed：显示 `确认已支付` 按钮
- 写回状态：`OA 写回状态：未写回` / `OA 写回状态：已写回`

按钮行为：

- 点击 `确认已支付` 后进入提交中状态，防止重复点击。
- 成功后刷新当前行或当前 view model。
- 失败时使用页面既有 toast/alert 模式，不在表格行内显示 `写回失败`。

### 流水列

有流水时显示：

1. 对方户名 + 交易时间 chip
2. 金额 + 银行/银行后四位 chip + 收支 chip
3. 流水摘要

无流水时显示：

- `-`

如果是候选流水，沿用现有关联台对候选证据的展示口径；不要在此视图重新发明候选评分 UI。

## 状态设计

### Loading

切换 view mode 或筛选时显示现有表格 loading 样式。不要清空顶部 view mode 控件。

### Empty

`进行中 OA` 无数据时展示紧凑空态，表达当前没有进行中的支付申请/日常报销需要展示。不要使用营销式插图或大面积空白。

### Error

列表加载失败时沿用现有错误样式。错误区域可以提供重试动作。

### Sync

页面可以展示同步中、最近同步时间、read model freshness。行内只显示 `未写回/已写回`，不显示写回失败。

## 响应式

桌面端保持三列表格。窄屏下每行可折叠为垂直信息块，但仍保持 OA、支付状态、流水三个区域的顺序。按钮、chip、金额文本不能互相覆盖。

## 前端数据契约

`进行中 OA` 行需要至少包含：

- `id`：平台 OA row id。
- `workflowStatus`：`in_progress`。
- `oa.typeLabel`：`支付申请` / `日常报销`。
- `oa.applicant`。
- `oa.projectName`。
- `oa.applicationDate`。
- `oa.amount`。
- `paymentStatus`：`pending` / `paid`。
- `writebackStatus`：`not_written` / `written`。
- `candidate`：可确认候选信息或空。
- `bankTransaction`：已确认或展示用候选流水信息或空。
- `readModelStatus` / `syncStatus`：用于顶部同步状态。

## UI 验收

- `已完成 OA` 视图保留现有行为。
- `进行中 OA` 视图只出现 `进行中` chip。
- `确认已支付` 只在待支付且有可确认候选时出现。
- 无流水时流水列为 `-`。
- 已支付行不显示确认按钮。
- 行内写回状态只有 `未写回` / `已写回`。
- 支付状态筛选生效且不改变流程状态范围。
