# Phase 28 Plan 01: 成本统计写后恢复热路径优化

## Goal

把生产可逆关系撤回后成本统计 `time` 页面达到完整 fresh 的 7.432 秒样本优化为有界的访问时收敛，同时保持 Phase 27 已验证的 canonical write 零 fan-out、精确 scope、Bank Detail 行独立 freshness、global statistics fail-closed 和 Workbench active-generation 原子发布合同。

## Baseline and root cause

- Phase 27 生产样本：Workbench 6.975 秒，Cost Statistics 7.432 秒。
- 同一生产月份 `2026-02` 的独立 Workbench 重建为 1.330 秒；其中 generation save 0.763 秒，不是主要异常。
- 慢样本中 Workbench handler 为 3.348 秒；Cost child 在 Workbench 完成前重试 7 次。
- Cost explorer 滚动窗口 p95 为 2.014 秒、数据库 p95 为 1.819 秒；刷新期间每次 `time` 页面重试都会无条件执行 Workbench/global statistics 全月份完整证明。
- 已有模块合同要求：statistics 已有 active recovery 时先返回独立 `statistics=refreshing`，Bank Detail rows 不受阻塞；只有没有已知 active recovery 时才执行完整 mismatch proof。

## Non-goals

- 不修改写操作、事实源、relation UoW 或写后 fan-out。
- 不新增缓存、表、索引、队列、worker、协调器、SSE 或前端轮询路径。
- 不降低完整性断言，不把 refreshing/stale statistics 伪装成 fresh。
- 不优化与本样本无关的 App Health、其他页面或全量浏览器测试。
