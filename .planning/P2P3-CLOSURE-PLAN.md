# P2/P3 Closure Plan - 17 页面一秒级同步闭环

**Created:** 2026-06-16
**Scope:** Phase 1-17 页面 P2/P3 closure
**Target:** 关键首屏 API P95 <= 1000ms；常规写操作 operation-to-fresh P95 <= 1000ms、P99 <= 3000ms；大导入/全量重建要求 job accepted/progress visible <= 1000ms。

## 约束

- 不为了性能把 stale 伪装成 fresh。
- Read model freshness/readiness、durable queue、audit 和 operation barrier 是硬约束。
- Redis 只能缓存 fresh gate 后 payload；RabbitMQ 只能作为 transport/wakeup。
- Workbench 保留 active generation 原子发布模型。
- 服务器侧默认只读审计和采样；任何写入、重启、apply、deploy 必须另出计划和回滚。
- 不把服务器密码、token、cookie 写入仓库、文档、命令输出文件或脚本。

## 分类定义

| Classification | 含义 | 处理方式 |
| --- | --- | --- |
| `auto-fixable` | 明确代码/测试/文档缺口，能本地验证 | 直接修复并跑相关测试 |
| `local-evidence` | 不是明确 bug，但可用本地 synthetic/fake/单测/Vitest 增强证据 | 补测试、工具 dry-run 或 fixture |
| `staging-required` | 需要真实 PostgreSQL/RabbitMQ/Redis/systemd/Nginx/OA 但可在 staging 跑 | 生成或运行只读/受控 smoke gate |
| `production-required` | 需要生产真实数据、生产登录态、生产 worker 或生产历史 replay | 默认只读采样；写入需批准 |
| `manual-only` | 需要人工业务确认、真实文件验收、真实浏览器下载保存确认 | 生成清单，不自动宣称完成 |
