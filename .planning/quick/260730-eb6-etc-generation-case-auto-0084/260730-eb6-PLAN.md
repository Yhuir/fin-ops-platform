# 修复关联台 ETC 汇总关联写入、generation 失败和刷新态假零

## 目标

关闭 `etc-summary-*` 合成行在关联确认时丢失 durable ETC batch identity 的写入漏洞，统一
API、worker 与 Audit 的 canonical 合同，禁止非 fresh 响应用全零 payload 覆盖上一版 active
generation，并在部署后幂等修复生产 `CASE-AUTO-0084` 与 `2026-07` dead-letter scope。

## 边界

- 保留 Workbench active-generation 和 `etc-summary-*` 合成行设计。
- 不新增 Redis、read model、queue 或通用框架。
- route 只做 HTTP 映射；业务验证在 service；SQL 与事务在 repository/UoW；worker 只构建 generation。
- 不修改 OA、银行流水、发票或 ETC canonical facts。
- 旧的重复 canonical、假零 payload、ETC identity=completion 捷径必须删除。

## 任务

1. 增加回归测试，复现折叠 ETC summary + bank 确认后 worker 无法重建，以及 refreshing
   payload 清空稳定页面。
2. 复用事务内 Workbench canonical validator，在 relation commit 前批量验证 row IDs/types，
   并从 ETC summary canonical metadata 持久化唯一 `external_etc_batch_id`。
3. 将 ETC batch identity 与 relation completion 分离；普通关系仍按冻结 requirement 判定。
4. 让 worker 与 Page Audit 按 durable ETC batch identity 重建/验证 summary，删除分叉合同。
5. 非 fresh initial 返回上一版 active generation；前端只有 fresh payload 才替换稳定数据，
   operation projection 后仅轮询 status，fresh 后再读取一次。
6. 确定性 Workbench canonical integrity 失败 fail fast，状态暴露真实 last_error，不做无效重试。
7. 更新模块边界、状态机、worker 运维文档；运行七类适用测试、lint、类型检查和生产构建。
8. commit 并 push `main`，使用 `./scripts/deploy-oa.sh` 部署；生产 dry-run/版本校验后幂等修复
   `CASE-AUTO-0084`，精确重排 `2026-07`，验证 generation、Audit、下游页面和 p95 性能。

## 验收

- 非法 synthetic relation 在事务内拒绝且无半写。
- 合法 ETC summary relation 可在 worker refresh 后重新解析并发布。
- refreshing/failed 时继续显示上一版 active generation，不显示假零。
- `CASE-AUTO-0084`、`2026-07` dead-letter 恢复，Workbench Audit 通过。
- confirm/withdraw 与首屏读取 p95 < 1s；其他 active-relation 消费页面无回归。
