# 目标

将 `/bank-details` 的账户余额、流水列表、筛选、统计和导出从
`bank_detail` / `bank_account_balance` read model 切换为页面专属 canonical
PostgreSQL query repository；保留现有权限、分类/规则写入、审计与 CAS。

# I/O 与边界

- 输入：读权限身份；`account_key`、日期、关键字、分类、分页和导出参数。
- canonical 输入：
  - `app.bank_transactions`
  - `app.bank_transaction_categories`
  - `app.bank_transaction_category_confirmations`
  - `app.app_settings` 中的账户映射和自动标签规则
  - `app.workbench_pair_relations` 中 `status = 'active'` 且与当前页/导出 row ids overlap 的正式关系
- 输出：账户与最新余额、流水 rows、分类 counts、页面 statistics、分页及 XLSX。
- 删除输出：`read_model_status`、`source_versions`、refresh enqueue/polling/202/fallback。
- 上游：银行流水导入、bank-details 分类/规则写链、workbench-relations。
- 下游：前端 bank-details；pending-invoices、bank-flow、search 等共享旧 reader 保持不动并列入 HANDOFF。

# 实施任务

1. 新增页面专属 canonical query repository/service：显式
   `REPEATABLE READ / READ ONLY`，固定查询次数，SQL 聚合/筛选/排序/分页。
2. 复用现有账户 identity/余额 SQL 口径；关系只按可见或导出 row ids 做
   canonical overlap 查询，不读取 `workbench_relation` projection。
3. 精简 `BankDetailsApplicationService` 读取与导出接线；分类、标签、规则写入继续走
   canonical writer + audit/CAS，不再触发页面 RM fan-out。
4. 删除前端 freshness 状态、202、轮询和 operation-barrier 等待，保留
   loading/empty/error 与写后重新 GET。
5. 增补 backend repository/service/API、frontend interaction、关键业务流、查询次数和性能验证；
   更新 bank-details 与 bank-account-balance 模块文档。

# 验收

- 页面代码和请求热路径不引用 `read_model.bank_detail_*`、
  `read_model.bank_account_balances` 或 workbench relation projection。
- 同一组合响应在一个显式只读可重复读快照中完成。
- category/filter/sort/page/summary/export 均由 SQL 有界执行，无 Python/浏览器全量分页。
- active relation 查询参数只含当前页或导出目标 row ids。
- 相关 backend/frontend 测试、lint、typecheck/build 通过，并记录查询次数、SQL/端点耗时和剩余风险。
