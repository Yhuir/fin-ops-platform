# Quick Task 260618-jc8: 进项发票使用情况以发票反提OA新增暂存状态闭环

## Goal

进项发票使用情况页的 `以发票反提 OA` 工作流新增用户可见 `暂存` 状态，防止用户创建 OA 草稿后关闭确认弹窗导致本地批次无法继续确认或清理。

## Scope

- 复用现有 `oa_draft_created` 作为后端统一事实状态，不新增数据库状态。
- 在 `待处理` 和 `已提交` 之间新增 `暂存` 页签。
- 用户点击 `创建 OA 草稿` 后，批次立即进入可恢复的 `暂存` 来源。
- 确认弹窗支持右上角关闭；关闭不调用 manual status，不清理 batch。
- `暂存` 列表不展示 OA 草稿链接，只展示两项处理动作：
  - `我已在OA系统提交该草稿` / `OA正在进行中`
  - `OA提交内容需修改` / `删除本次提交内容`
- 选择 submitted 后进入已提交历史；选择 not_submitted 后清除本地草稿字段并恢复可重新创建状态。

## Tasks

1. 后端事实源与 API
   - 新增 service 方法返回 `oa_draft_created` 批次。
   - 新增 staged drafts API，供前端恢复暂存批次。
   - 验证 service/API contract。

2. 前端交互闭环
   - Drawer 增加 `暂存` 页签。
   - 创建草稿确认弹窗改文案并支持关闭。
   - 关闭弹窗后将当前 batch 放入暂存视图。
   - 暂存列表只展示两个选择，不展示 OA 草稿链接。
   - 暂存中的两项选择复用 manual status contract。

3. 文档与验证
   - 更新模块状态机、设计、测试矩阵、E2E 覆盖和 API contract。
   - 增加 service/API/frontend 回归测试。
   - 运行目标测试、相关回归、构建、E2E 和 docs 校验。
