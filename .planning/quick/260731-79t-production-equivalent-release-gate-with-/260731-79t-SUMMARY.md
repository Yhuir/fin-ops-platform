# 实施摘要

## 已完成

- 发布门禁把公开页面 Audit 与候选内部 API/SLO 分离到正确 origin。
- 写操作、页面 Audit 完成后重新采样 PostgreSQL、RabbitMQ、worker 与 durable queue，避免前置快照漏掉异步放大。
- 可逆写 scenario 强制使用登记 shape、`fixture_ownership=test_owned`、confirm/withdraw checkpoint 与 inactive recovery。
- 每次 mutation 使用新的 idempotency key，避免跨 release 重用历史结果。
- 增加受控 scenario 安装入口，校验候选 release、owner、权限、大小与 symlink 后原子替换 root-owned `0600` 文件。
- Workbench canonical 搜索移除重复 paired/unpaired 查询和重复 hydrate。
- 部署仍只通过现有 `release-gate-activate` 激活；pre、T+0、T+60、T+300 任一点失败均保持或恢复上一稳定 release。

## 刻意未做

- 不自动创建生产财务事实或把真实业务关系标记为测试夹具。
- 不新增 Redis、RabbitMQ 状态事实源、第二套 worker registry 或第二套发布入口。
- 不保留宽松 legacy scenario fallback。

## 发布条件

正式部署必须产出绑定候选 release/commit 的 root-owned evidence，并通过最终合同：

- `release_gate_status=PASS`
- `unknown_worker_count=0`
- `required_worker_not_ready=0`
- `dirty_scope_count=0`
- `pending_outbox_count=0`
- `dead_letter_delta=0`
- `page_canonical_audit_status=pass`
- `queue_stable_after_300_seconds=true`

没有安全的 `test_owned` 可逆关系夹具时，发布必须在激活前失败。
