## Bundle Contract

The production browser smoke runner bundle must be a separate artifact from the normal app release archive.

### Included Files

Minimum file set:

- `web/e2e/production-route-shell.spec.ts`
- `web/e2e/fixtures/strictTest.ts`
- `web/playwright.config.ts`
- `web/package.json`
- `web/package-lock.json` if present in the repository at packaging time
- bundle manifest JSON generated by the packaging command

Excluded:

- `web/node_modules`
- Playwright browser binaries
- `web/dist`
- non-production e2e specs
- admin production spec
- screenshots, traces, videos and previous Playwright reports
- secret env files, tokens, cookies, DSNs or runtime config

### Manifest Fields

The bundle manifest must include:

- `bundle_version`
- `git_commit`
- `git_branch`
- `release_name` expected by the evidence run
- `created_at`
- `included_files`
- `sha256_by_file`
- `production_spec`
- `base_url`
- `runtime_contract`
- `artifact_redaction_contract`

The manifest must not include:

- tokens, cookies, DSNs or env secret values;
- response bodies or page body samples;
- candidate IDs, business row IDs or scenario identifiers.

### Runtime Contract

The runner must provide a pinned Playwright runtime before execution:

- either a preinstalled runner host runtime with recorded Playwright version and browser revision;
- or a pinned container image digest managed as runner infrastructure.

The evidence command must not download browsers or install packages during the smoke run. Any `npm ci` or browser install belongs to runner image preparation, not production evidence execution.

### Command Shape

The eventual runner command shape is:

```text
FIN_OPS_E2E_PRODUCTION_SMOKE=1
FIN_OPS_E2E_SKIP_WEBSERVER=1
PLAYWRIGHT_BASE_URL=https://www.yn-sourcing.com
FIN_OPS_E2E_OA_TOKEN=<in-memory only>
playwright test e2e/production-route-shell.spec.ts --project=chromium --reporter=list
```

The token must come from a reviewed in-memory broker contract. This bundle contract does not implement or execute the broker.

### Artifact Contract

Allowed evidence artifacts:

- bundle manifest;
- sanitized command metadata;
- route path pass/fail classification;
- mutating request method/path count;
- runner version and duration;
- pre/post production health and aggregate counts.

Forbidden artifacts:

- page body text;
- response body text;
- console raw details;
- page error raw stack/message;
- request URLs with query strings unless explicitly redacted;
- screenshots, traces, videos and HTML report;
- tokens, cookies, env values, DSNs or payload rows.

## Pre-Execution Contract Gap

Row302 removed `textSample` from `production-route-shell.spec.ts`, but the spec still imports `./fixtures/strictTest`.

`strictTest.ts` currently records raw diagnostic details:

- `console.error` message text;
- `pageerror` stack/message;
- failed request method plus short URL and failure text.

That is acceptable for local deterministic e2e, but production route-shell evidence must not persist raw console/pageerror detail because a production failure could contain sensitive text. The bundle contract therefore cannot proceed to a packaging implementation until production strict diagnostics are redacted or production route-shell uses a sanitized fixture.

## Decision

Do not implement a bundle packager in this slice.

The next safe boundary is:

`frontend:production-strict-diagnostics-sanitized-output-contract`

That boundary must keep local strict diagnostics useful while ensuring production route-shell smoke cannot persist raw console/pageerror/request detail.
