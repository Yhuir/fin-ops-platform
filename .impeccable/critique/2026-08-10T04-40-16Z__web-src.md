# Web UI 控件与成本统计工作区 Critique

> 本分数与问题清单是实施前基线。2026-08-10 已完成闭环：统一 HeroUI 业务周期、切换与搜索边界，删除旧 `MonthPicker` 和无调用 CSS，成本按时间改为固定高度 15/85 双栏，且通过 979 项 Vitest、181 项 Playwright E2E、生产构建与文档门禁。

## 结论

当前问题不是单页微调，而是三类共享边界失效叠加：HeroUI 默认大圆角直接泄漏到业务页；迁移到 HeroUI 后旧 CSS 外壳与死选择器没有删除；时间筛选、分段切换与搜索存在多套页面级实现。成本统计“按时间”还存在无确定祖先高度的自动加载表格，导致整页持续增长。

## P1 优先问题

### 1. 同类控件存在并行实现和旧壳

- `QuerySearch` 已经通过 HeroUI `SearchField.Group` 提供完整搜索边界，OA consumer 的 `.oa-pending-payments-table-search` 又添加 border/background/radius/padding，形成双层输入框。
- OA 已使用 HeroUI `ToggleButtonGroup`，但 group 自己又被旧 CSS 画成白色分段壳；旧 `__button*`、`month-picker__all*`、`table-search-button` 选择器已无运行 caller。
- 银行流水批次、批量账务、往来款采用“手写外壳 + HeroUI Button”，子按钮没有清理 HeroUI `rounded-3xl`。ETC 已存在清除中间圆角的可复用范例。
- 待找发票已使用 `ToggleButtonGroup`，但需要进入同一低圆角视觉合同。

用户影响：相同含义的控件看起来像不同产品，选中态、焦点态和点击边界难以预测。

### 2. 时间控件语义和实现不一致

- 旧 `MonthPicker`、成本统计页面内 `ScopeRangePicker`、关联台 `WorkbenchPaneTimeFilter`、银行明细独立 picker、OA/BankFlow 的 Button + `input type=month` 并行存在。
- HeroUI 3.1 提供 DatePicker/DateRangePicker/Calendar，但没有 MonthPicker；业务周期需要一层很薄的项目组合，而不是继续逐页复刻。
- “年月日”不能被解释为所有 API 都新增 day 精度。每个页面必须保留现有 `all/year/month` 或 exact date/range query contract。

用户影响：同样的“全部/月份”在不同页面操作方式不同，错误选择时间范围的风险高。

### 3. 成本统计按时间没有确定滚动边界

- `CostStatisticsTable` 在首帧和 rows 更新后，当 `remaining <= 160` 时自动请求下一页。
- 祖先只有 `min-h-[520px]`，没有 definite height；后代却使用 `height:100%`、`max-height:none` 和内部 `overflow-y:auto`。
- 百分比高度无法形成真正受限的滚动容器，`scrollHeight === clientHeight` 时 remaining 为 0，页面会连续取下一页直到 cursor 耗尽。

用户影响：页面无限向下增长、加载与渲染成本失控，无法保持财务工作台的稳定视口。

## 认知负荷

评估为 4/8，未通过项：信息分块、视觉层级、单一工作焦点、可见选项数量。成本统计五种视图本身是稳定业务模式，不应为了减少数量而隐藏；需要把它们从 page header 的重型表面移到扁平 content toolbar。

## 具体视觉合同

- 普通按钮/field 高 34px（允许 32-36px），圆角 6px；surface 最大 10px；每个控件只出现一条可见边框。
- 分段筛选使用 HeroUI `ToggleButtonGroup`：选中 primary 蓝底白字，未选 neutral；group 无第二背景卡、无第二 border；focus ring 只在 `:focus-visible` 出现。
- 显式提交搜索继续复用 `QuerySearch`：SearchField 与查询按钮同高，间距 0-4px；consumer 外层 form 不再画 input shell。
- 普通业务周期控件保持左“全部”、右业务周期，组合宽约 240-300px；popover 圆角 8px，无 backdrop blur；不得暴露 API 不支持的精度。
- 成本统计非按时间视图的操作条高 48-60px、最大 64px；搜索与查询在同一行。
- 成本统计按时间在桌面宽度至少 1280px 时采用约 15/85，左栏 min 192px、max 240px、gap 12px；窄屏或 200% zoom 堆叠。工作区高度使用视口约束，只让表体滚动，表头 sticky、footer 固定。

## 最小架构边界

1. 保留 `components/common/QuerySearch`，作为单字段、显式提交搜索的唯一组合。
2. 最多新增一个 `BusinessPeriodPicker`，只负责 `all/year/month`，内部复用 HeroUI Popover/Button/ButtonGroup。
3. exact date/range 直接使用 HeroUI DatePicker/DateRangePicker。
4. filter state 使用 HeroUI ToggleButtonGroup；真正内容面板使用 HeroUI Tabs，不混用 tablist 与 aria-pressed。
5. 纯日期格式移动到既有 `features/dateTime.ts`。
6. 不新增依赖，不建立全局 Button/Input facade，不修改后端 API、read model、权限或请求时序。

## Persona 风险

- 财务高频用户：顶部空白和大圆角降低扫描密度；按时间无限增长破坏稳定视口。
- 键盘/辅助技术用户：混用 tablist、pressed button 和自定义 shell 容易造成语义与焦点不一致。
- 窄屏或 200% zoom 用户：硬编码 15/85 会压缩左栏，必须有堆叠 fallback。
- 维护者：旧 CSS 与新 HeroUI DOM 同时存在，后续每次改样式都会产生新的覆盖竞态。

## 次要观察

- 成本统计 page header 同时承担标题、统计、五视图切换与动作，职责过载。
- 过度使用 `transition: width` 是潜在布局性能问题，但不属于本轮核心，只有碰到相同控件时才顺手删除，禁止扩大成全站动画重构。
- 大面积空白不是需要增加卡片，而是需要让可用高度归属明确、空态靠近当前操作上下文。

## 已锁定的设计决策

- “年月日”按当前 API 支持精度呈现，业务月度页不凭空增加日维度。
- 15/85 是桌面比例，不是所有宽度的硬约束；窄屏和 200% zoom 使用堆叠。
- 本轮只改表示层与前端交互边界，不改变业务数据、API shape、权限、read model、worker 或调用时序。
